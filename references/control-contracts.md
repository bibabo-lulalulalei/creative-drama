# 全流程生产控制合同

本文件定义正式生产的跨阶段控制规则：来源优先级、阶段状态、确认事务、版本失效、证据边界和回炉原则。纯文字创作、评阅或局部方案按 SKILL 的工作范围执行，不套用生产项目初始化与阶段状态。

## 本 Ref 关键要求

- 用户明确锁定的主体、动作、场景、风格、时长、比例、镜头方式、台词和禁止项不得被默认规则或创意优化覆盖；扩充只能发生在未锁定空间。
- 阶段必须按顺序推进；每阶段展示正式产物、等待用户明确确认后才能进入下一阶段。
- 视频与成片媒体工具默认由主 Agent 直接执行；需要释放等待或处理独立任务时可选委派，交接按 delegation.md。主 Agent 保留内容审校、参数确认与用户交付责任。
- 资产、关键帧和视频片段阶段的任何图片或视频生成产物必须生成一个交付一个；工具完成落盘与可解码检查后及时交付，主 Agent 不重复同一检查；真实尾帧依赖按顺序执行。成片阶段的裁剪片、拼接中间件、字幕测试样片和内部母版不逐项交付；每集只交付字幕策略对应的一个最终视频版本。
- 用户确认只记录真实确认事实、revision、确认原文、确认模式、影响范围和带时区时间；缺少确认记录时阻断。
- 上游修改只使实际受影响的下游失效；已确认文件不覆盖，改动创建新版本。
- 自动检查只处理阶段推进、关键产物文件、JSON 类型与枚举、计划集数与分集目录、各阶段 episode_id、时长闭合、核心 ID 去重、路径、资产引用与版本闭环、关键帧/视频覆盖关系、明确数字上限、H3 成稿存在性、manifest 映射、Prompt 与真实媒体标记、确认记录和多媒体输入清单。代码不得按字数、关键词、同义词、语速估算、文案具体程度或自然语言语义评价创意、剧情、镜头必要性、节奏、运镜、表演、口型、连续性或审美；这些只由导演规则与人工判断负责。

导演方法用于形成可执行的观看设计，创作选择直接体现在正式产物中。只记录影响执行的决定与理由，不逐镜另写推导、自证或通过报告；具体困难才补读对应方法。同一规则不在本文件重复维护。

## 1. 来源与事实锁

用户原始要求、已验证事实、未知项、推进假设和项目惯例必须分开记录：

| 状态 | 含义 | 使用规则 |
|---|---|---|
| `locked` | 用户明确要求、原台词和禁用项 | 未经确认不得改写 |
| `verified` | 用户材料、可靠来源或真实 schema 已核实 | 记录来源和日期 |
| `pending` | 会影响权限、成本、剧情或交付的未知项 | 不能伪装成事实 |
| `assumed` | 为继续规划采用的可证伪默认值 | 必须允许用户修改 |
| `convention` | 本 Skill 的项目惯例 | 不等于用户设定 |

所有用户素材、检索结果和已有文件先登记到 `source_manifest.json`。用户上传、补充、替换或指定的图片必须逐张打开查看后登记，不能只查看当前看似相关的视觉参考图；每张图按维度写可见内容摘要、素材职责、采用/剥离边界、作用域和质量风险，再拆为人物身份、状态、场景、道具、构图、姿态、媒介类型、画风、色彩、光影、材质、文字来源或无关信息。图片来源实例以 URL、附件 ID、消息位置和输入顺序区分，实际取得字节后才可用内容哈希核对，不以 `local path`、文件名、basename 或展示名确定；同名 `image.png`、相同临时路径或重复文件名但不同 URL 的图片必须逐 URL 实际查看、编号和登记，不能因名称重复漏读或覆盖。URL 与本地副本记录按 `manifests.md` 的 `source_manifest.json` 合同执行；H3 的 HTTP(S) 文件 URL 原样直传，无需为提交下载副本。图片是否进入生成工具另按当前目标筛选“足够且必要”的相关图和相关维度；登记和查看全量，传图可以精选。用户原始素材和已登记输入素材不得删除、覆盖、改写或被生成结果替换，只能复制、转存、派生新版本或标记不采用。素材 role、采用/剥离边界、授权状态和作用域由 `manifests.md` 定义；参考视频的结构、POV、运动、情绪和声音拆解由 `storyboard.md` 定义。

冲突优先级固定为：

```text
系统、安全、合规、授权、真实性、工具硬限制
> 用户最新确认
> 已确认素材与事实
> 默认创意规则
```

用户最新确认的锁定对象同「本 Ref 关键要求」首条；人物/产品身份、剧本原文、平台要求、场景、风格与声音合同只有在不覆盖更高优先级要求时生效。创意扩充只能填补用户未锁定空间并服务整部作品。第一层与用户要求冲突时停止受影响步骤并说明；其他冲突只询问无法自行消解的冲突点。

## 2. 阶段状态与确认

执行顺序固定为：

```text
planning
  -> 全局故事圣经 + 全部分集推进总纲 + 最终结局
  -> ep_1 [详细剧本 -> assets -> storyboard -> keyframes -> video（生成后登记状态、路径交人工审查） -> final + subtitle + delivery + 用户确认]
  -> ep_2 [详细剧本 -> assets -> storyboard -> keyframes -> video（生成后登记状态、路径交人工审查） -> final + subtitle + delivery + 用户确认]
  -> ...
```

先完成项目规划，再完成并确认项目级全局故事包。分集详细剧本按集即时生成并确认，再进入本集后续阶段；当前集达到目标后再启动下一集。关键帧阶段按已确认的实际用途核对（需求不等于生成配额，细则见 `references/keyframes.md`）；零需求可完成阶段检查。有需求时逐项交付，复用工具已完成的落盘与有效性结果，不重复写一份检查报告。已有合格上游可以登记复用。

阶段状态只允许 `pending|in_progress|awaiting_confirmation|confirmed|invalidated|blocked`，完整结构读取 `manifests.md`。`制作状态.json` 是唯一状态权威；项目级剧本确认后必须使用 `current_episode` 指向唯一允许推进的分集，并以 `current_stage: script` 开始该集详细剧本。

每一阶段按同一事务提交：

1. 读取当前状态、输入 revision 和实际文件。
2. 生成或修改正式产物，不覆盖已确认版本。
3. 未生成的剧本、分镜、资产计划或 Prompt 存在已发现的事实、因果、台词、连续性或执行问题时，先修相关部分再提交为合格方案。已经生成的媒体候选如实交付并说明实际观察；不能为修内容自动重复生成，也不能把候选登记当作用户接受。
4. 保存完整候选后完成当前阶段检查；分镜由盖章命令内置检查，不另重复 lint。项目级剧本只查全局故事包，逐集阶段只查当前集。通过后写 `awaiting_confirmation`；客观失败回到 `in_progress|blocked`。后续只检查状态变化涉及的约束，不因保存或查看重复整阶段检查。
5. 检查通过后展示当前需要审查的正式产物。`video|final` 目标的规划调用项目执行确认，其他目标使用普通规划确认。媒体实际生成后才检查该文件，不能在规划确认后对尚未生成的“首个产物”执行落盘检查。
6. 收到用户明确确认后，用 `scripts/stamp_confirmation.py` 将确认事实追加到 `用户确认记录.jsonl`（命令内部校验、原子写入并回读，禁止手写台账行）。普通阶段结合完整回复判断；视频生成、重生或编辑须按 interaction ref 取得当前 `generate`。`video|final` 目标的 planning 使用 `project_execution/proceed_project`，其他目标使用普通规划确认。全部片段交付后仅 `final` 目标进入拼接确认。
7. 确认记录写入成功后才推进状态，并原子同步 `current_stage`、`current_episode`、项目级 `phases` 和当前集 `stage_status`。项目级故事包确认后把 `current_episode` 设为 `ep_1`、`current_stage` 设为 `script`，并将 `episodes.ep_1.stage_status.script` 写为 `in_progress`。当前集详细剧本确认后进入本集 `assets`。当前集确认到目标阶段后，如仍有下一集，下一集始终从 `script` 开始；完整成片任务也只有当前集成片确认后才能切换。只有全部计划分集都达到 `objective.target_stage` 后才结束任务。

视频编译、独立内容审校、请求预检、生成确认与绑定执行按 `video.md` 的“执行顺序”进行。预检先于生成确认；实际提交须匹配冻结请求。修改设计、成稿、参数或输入后，使依赖绑定失效，重新预检并取得相应确认；不设置审校或修订次数配额。程序不对创意力度、节奏、审美、表演或观看效果评分。

用户修改已确认内容时，当前阶段及依赖它的下游状态变为 `invalidated`；未受影响的上游事实、资产和版本继续有效。不要手动逐个 JSON 猜改状态。规划或全剧剧本变化使用 `scripts/drama_rollback.py --project-root <项目目录> --to-stage <阶段> --reason <原因>` 做项目级回退；逐集循环中的资产及后续变化必须追加 `--episode ep_N`。若后续集仍为 `pending|invalidated`，工具只回退目标集；若后续集已启动或完成，默认拒绝以避免越权失效，只有确认跨集依赖确实受影响时才显式追加 `--cascade-later-episodes`。该工具只更新 `制作状态.json` 并追加操作日志，不删除旧产物。

用户在任一阶段追加或替换含人物、场景、道具、构图或风格等有效视觉参考维度的图片时，按采用维度、资产类别和稳定 ID 计算影响范围。若新图用于替代已确认资产或改写项目视觉类型，必须创建对应 CHR/SCN/PROP/STYLE 新版本，并使所有依赖旧版本或旧 `project_visual_mode` 的状态图、细节图、关键帧、视频输入图、分集资产引用和已生成视频片段失效；未依赖该资产或视觉类型的产物继续有效。不得只替换当前单张图片后继续使用旧关联图。

返修定位不等于执行授权。视频工具返回后实际观看，把关键问题与一般偏差直接在对话中向用户说明；观察不阻断候选展示，也不触发自动重生。凡再次调用视频生成或编辑工具，都必须由用户明确提出并重新取得当前 `generate`（确认 ref 同步骤 6）。

### 全量与增量确认

首次阶段交付始终使用全量确认。已有有效全量确认后，返修按实际影响分为：

| 类型 | 判定 | 用户可见交付 | 确认记录 |
|---|---|---|---|
| 重大修改 | 改变核心因果、人物动机或弧线、结局、集间边界、身份、风格、模型、时长、画幅或大范围下游 | 重新提供当前阶段完整文件和整体摘要 | `confirmation_mode: full` |
| 局部微调 | 错别字、单句润色、局部动作澄清、未改变含义的格式修正，且影响范围可以精确列出 | 只展示修改文件、变更摘要、修改前后和影响范围 | `confirmation_mode: incremental` |

增量确认仍必须等待用户明确回复，不能把“修改完成”自动当成同意继续。普通阶段的增量确认登记本次实际变化文件 `changed_artifacts` 和影响范围 `impact_scope`，无需复制未变化的全量产物清单。此简化不豁免视频请求绑定：影响设计、成稿、参数或输入时须更新快照、重新预检并确认。无法可靠判断影响范围、推翻方案或重做产物时，一律按重大修改处理并使用 `confirmation_mode: full`。

规划完成后必须展示参数列表和最多 `8` 行的五列预览；确认类型按步骤 5 的路由选择。

每次只允许推进一个用户确认门。规划、项目级故事包、当前集详细剧本、当前集资产、当前集分镜、当前集关键帧、当前集视频片段和当前集完整视频都必须分别展示和确认；当前集达到目标前不得进入下一集详细剧本。视频生成前按 `video-batch-confirmation.md` 展示一张本批次合并参数表和一张本批次五列分镜表，并调用视频批次 AskUserQuestion；批次容量以该文件「批次边界」节为唯一权威。视频工具成功后即时给出路径，不重复工具已完成的检查；只有依赖真实尾帧的后段必须等待前段，同批无依赖片段可依次提交异步任务，再逐项恢复收取，避免同时修改同一 manifest。全部片段交付后，只有 `target_stage=final` 才调用拼接确认；`target_stage=video` 使用普通阶段确认并结束。

面向用户的交付与内部执行记录分离。已读的阶段可见交付速记卡直接复用，缺少具体规则才读取 `skill-details.md` 对应节，不因展示或确认补载整包。进度说明实际创作进展与用户可行动的问题，技术排障或用户询问时可以解释必要的技术原因。

### 委派边界

主 Agent 负责阶段顺序、确认事务、版本失效和用户交付责任；视频和媒体工具默认直接执行；选择委派时的最小交接和依赖边界读取 `delegation.md`，本文件不重复定义。

委派执行者只能写入交接包逐文件指定的产物和必要记录，不能确认阶段、改变上游合同、扩大目标阶段或替主 Agent 解释例外；白名单外新增或修改文件按越权阻断。

## 3. 版本、引用与失效

- `project_data_card.json` 是角色、场景、道具和音色身份及状态时间线的事实权威。
- `asset_registry.json` 是共享媒体资产版本权威；`asset_usage_ep_N.json` 记录本集采用的共享资产快照、本集新建的专属/状态资产，以及从其他分集复用的 approved 资产索引。
- 分集创作默认以 `asset_usage_ep_N.json` 为资产/状态读取面；数据卡与 registry 全文不做阶段入口预载，按 ID 定点窄读（读取面合同细则见 assets.md「资产 JSON 登记」）。
- `drama_plan.json` 下游同样按顶层组/字段路径定点读取，不整读全文；整读仅限规划确认展示、规划修订与报告缺项后的定向补读（细则见 planning.md「下游读取面合同」）。
- 全局剧本包是全剧故事权威；单集剧本包只能细化，不得另建核心因果或结局。
- 下游 manifest 记录 `project_data_card_revision`、上游路径与采用版本；视频请求须满足 `manifests.md` 的预检指纹与依赖绑定合同。
- 上游正文、数据卡或共享资产 revision 改变时，只使实际依赖旧版本的下游产物失效。
- 下游只能使用 `approved` 资产；`draft|reviewed|rejected|superseded` 不得进入正式生成。
- 已确认内容修改前先保存旧版快照及变更原因。媒体、Prompt 与版本化创作文件写新 `_vNN`；固定命名的状态/索引/合同是当前工作入口，保留旧 revision 快照后原子更新，引用仍指向当前有效内容。
- 稳定 ID、`ep_N` 目录及文件后缀必须一致；完整命名规则读取 `manifests.md`。

## 4. 跨阶段交接

| 阶段 | 必须消费 | 必须产出 | 内容权威 | 失败返回 |
|---|---|---|---|---|
| 规划 | 用户要求、来源与实际工具 schema | 已确认计划、参数确认表、项目索引 | `planning.md` | 规划 |
| 剧本 | confirmed plan、来源、项目索引 | 全局剧本包、设定摘要（现场渲染）、数据卡、单集剧本包 | `scriptwriter.md` | 剧本或规划 |
| 资产 | 已确认项目级故事包、数据卡和当前集详细剧本 | 当前集采用的 approved 复用资产，以及当前集新增或变化的人物、场景、道具、音色与风格资产 | `assets.md` | 当前集资产或剧本 |
| 分镜 | 已确认剧本、数据卡和资产 | 唯一导演总控卡、十五列详细分镜、关键帧与输入计划和 planned seam；表演/色彩只写实际需要的控制 | `storyboard.md` | 分镜、资产或剧本 |
| 关键帧 | 已确认分镜和基础资产 | 按已确认用途生成或复用的 approved KF 与验收记录 | `keyframes.md` | 关键帧、分镜或资产 |
| 视频 | 已确认 shot plan、资产、KF 和入站状态 | SEG、冻结请求快照、可播放 mp4、状态登记与按需提取的 tail FRM 输入 | `video.md` | 视频或最早错误层 |
| 成片 | accepted SEG、可用 cut、最终音轨策略 | 单一最终视频：默认无字幕成片，用户明确要求时改为字幕版；内部字幕文件和客观可交付记录 | `delivery.md` | 成片或最早错误层 |

剧本证据链与 SEAM 的字段由表中对应权威文件定义，通过真实 `shot_id`/`segment_id` 追溯；调度、布光与动作合同直接写进分镜表十五列与逐段执行区，不另立 JSON 账本，也不要求稳定 ID 串联。

## 5. 运行完整性、证据与基础检查

跨阶段的“能生成”不等于“可交付”。所有阶段必须闭合以下证据链：

- 每个已确认阶段绑定当前 revision、正式产物路径和用户确认记录；下游只能消费匹配该 revision 的上游产物。
- 规划的 `OPEN001` 在第 1 集直接落到剧本开场合同，并由分镜首镜证据证明。后续集可以变体，但必须保留 `OPEN001` 引用和具体变体理由。
- 表演谱、情绪曲线和色彩脚本仅在具体执行需要时展开；无该控制时可省略，不写不适用证明，不据字段制造表演或镜头。
- planned SEAM 是生成前目标；生成后只保留按需提取的 tail FRM 输入帧（登记进下段 `reference_inputs`，不建帧注册表）与对话中说明的接缝观察，观察结论和最终切点不得提前写入分镜或关键帧产物。

接缝完整性遵循：

- `continuous` 只允许规定的不变量连续推进；`elliptical` 允许计划内时间、空间、构图或状态变化，但仍必须保持 `required_invariants`。
- 任何未登记在 `permitted_deltas` 的变化都不是允许变化；先返回分镜修订衔接卡。若责任在已生成视频，关键剧情/证据/动作/身份/台词/连续性错误直接在对话中向用户说明，片段仍可按 best available cut 进入用户可见交付链路；是否返修由用户主动决定，用户主动要求修改并完成新一轮确认前不调用视频工具。
- 跨集 `EPSEAM` 使用相同原则。`ep_2` 及以后首个 SEG 必须消费上一集结果、声音状态、未决钩子和 `required_invariants`；`continuous` 必须再消费上一集真实尾帧，`elliptical` 按已确认的新起点和允许变化执行，不能只写“保持一致”。

工具调用成功、文件存在或结构校验通过都不等于内容合格：

- `drama_lint.py` 只检查结构化且可确定的事实：文件、类型、枚举、ID、路径、版本、引用、状态、数量、顺序、时长、输入输出对应，以及实际 H3 模式字段、媒体标记、锁定台词和文件哈希等精确合同；创意语义评判的禁区同「本 Ref 关键要求」。
- 额外人工复核须覆盖剧本因果/证据可读性、镜头导演意图、生成后的关键动作/身份/台词/连续性、全片顺读和声音合同；质量判断无法被 lint 取代。
- 图片必须实际查看，音频可试听，视频具备可渲染/可播放资源。每段生成后及时交付 mp4 路径并如实说明内容观察；工具登记 `candidate`，只有用户真实接受才能设 `accepted`。用户要求返修时重新确认实际视频请求。
- 自动检查不能冒充创意与质量判断（语义评判禁区同「本 Ref 关键要求」）；这类结论由独立观看审校给出并附证据，程序只检查结构化事实，不自行推断语义，也不以固定分数替代人审。
- 结构或媒体有效性等客观检查失败可写为 `blocked` 并阻断交付；内容观察不阻断。`blocked` 不授权自动调用视频工具，返修/重生须等用户主动要求与新一轮确认。
- 当前未实际执行的黑帧、冻结帧、响度、OCR 越界或遮脸检测，不得在报告中标记为已通过。

结构校验默认静默执行。除非用户明确询问，不向用户输出内部检查统计、机器可读结构名称、机器字段、检查期望、内部文件名称、内部机制或运行配置。存在阻断问题时只说明需要用户处理的具体问题；可自主修复的结构缺口不对用户复述字段名或文件名，只说已补齐制作所需信息或追溯记录。凡是用户不能直接行动的内部原因，都不得作为对外解释。

## 失败、重试与回炉

重试预算、`V/A/F/S/N` 缺陷编号和返回层级只读取 `troubleshooting.md`。本文件保留三条跨阶段原则：

1. 只修改与证据直接相关的变量，不用多项同时变化掩盖根因。
2. 只重做失败产物及其必要上游，已确认且未受影响的产物继续复用。
3. 返回最早出错层级，不用下游裁切、转场、调色、混音或重复生成掩盖上游错误。

## 6. 文件操作与恢复

- 修改前先读正式文件、状态和输入 revision。
- 大范围本地重写先写同目录临时文件，校验通过后原子替换；失败时保留诊断。
- 外部生成无法与本地状态形成原子事务。先保存不可变的新版本并验证真实产物，再提交状态引用。
- 部分成功时盘点返回 ID 和文件，只补失败项。
- 阶段变更或非视频媒体操作追加必要操作日志；视频调用事实由任务文件与 manifest 自动保存，不另抄同一结果。字段和恢复规则读 `manifests.md`。
- 恢复任务时先读取最后一次成功操作、当前确认记录、正式文件和实际媒体证据，再从 `last_successful_operation` 后继续；聊天摘要不是完成依据。

## 7. 自动检查与交付

正式交付前必须同时满足：

- 当前阶段结构检查通过；视频和成片已完成客观可交付检查。
- 所有引用路径、版本、状态及适用的预检指纹与实际提交一致，遵循请求绑定要求。
- 受影响下游不存在未处理的 `invalidated|blocked`。
- 最终成片按 `delivery.md` 完成规定的客观可交付检查。
- 当前阶段状态已写为 `awaiting_confirmation`；按 `SKILL.md` 与 `local-runtime.md` 完成落盘、可打开/可解码检查并给出产物路径。候选展示与用户接受分开；Prompt 文件展示规则同 `skill-details.md`「Prompt 文件与可见交付」。

## 非视频生成的阶段迁移确认

本节只定义两个不执行视频生成的流程确认。它们不得复用或覆盖 `interaction-ask-video-clarification-ref.md` 的视频生成确认，也不得把 `proceed_project|proceed_assembly` 解释为 `generate`。

**项目执行确认**

- 用于目标包含视频或成片的项目，在规划参数列表和规划五列预览表展示后立即调用 AskUserQuestion；这是首次 UI 确认，不得延后到视频阶段。
- 调用 ID（记录用标识）：`project_execution_confirmation`；问题 `question`: 是否按以上参数确认方案并进入制作？`header`: 方案确认；`options`: `proceed_project`（确认方案并进入制作）/ `revise_project`（暂不推进并返回修改）；`multiSelect: false`。
- 只授权记录规划确认、产物落盘与可打开检查，以及进入项目级剧本阶段；不授权生成或编辑任何媒体。

**进入成片拼接确认**

- 当前集全部 SEG 已逐个交付后调用 AskUserQuestion。
- 调用 ID（记录用标识）：`final_assembly_confirmation`；问题 `question`: 是否按已展示顺序、切点、声音和字幕策略进入成片拼接？`header`: 拼接确认；`options`: `proceed_assembly`（进入拼接）/ `revise_assembly`（暂不拼接并返回修改）；`multiSelect: false`。
- 只授权接受当前集视频片段并进入拼接、裁剪、混音、mux 或字幕烧录；不授权生成、重生或编辑任何视频片段。
- 调用 ID、用户选择原文和带时区时间必须同时写入 `delivery_manifest.assembly_confirmation` 与该集 `stage=video` 确认记录。
