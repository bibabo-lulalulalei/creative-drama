# 剧本创作 Ref

本文件负责剧本因果、证据链、格式和内容验收。只需文字创作、完整剧本、评阅或局部方案时，直接根据用户事实和要求工作，按需查相关创作方法；不强建生产计划、数据卡、状态和机器合同，不先选媒体模型或发起生产确认。用户要求正式生产或可直接用于生产的项目时，适用下文生产门禁：定点读取已确认规划、当前状态规则和剧本/Data Card 字段；资产方法到对应检查点再读，逐镜设计交给 `storyboard.md`。

## 输入门禁

正式生产必须存在已经通过 `drama_lint.py --stage planning` 且经用户确认的：

- `00_制作控制/drama_plan.json` 内容完整，且 `制作状态.json.phases.planning == confirmed`。
- `00_制作控制/project_manifest.json`、`source_manifest.json` 及当前 `episodes/ep_N/episode_manifest_ep_N.json` 已按 `manifests.md` 建立。
- `用户确认记录.jsonl` 存在当前 `drama_plan.json.revision` 的规划确认记录。参数确认正文已按 `planning.md` 在当前对话中直接展示，不依赖 Markdown 文件。

剧本必须继承规划中的目标、事实锁、唯一主机制与辅助机制、核心卖点、类型策略、亮点策略、风格合同、情绪设计、节奏波形、规模和风险，不得自行更换受众、平台、画幅、模型、故事发动机或创意主路径。规划存在 `pending` 且会改变剧情意义、权限、成本或交付规模时返回规划阶段，不得直接补写。

正式生产尚缺必要规划确认时先补齐；纯文字任务从已有事实创作，不受媒体模型、画幅和生产目录门禁限制。下文目录、状态、机器字段和逐阶段确认均属于正式生产合同。

## 边界

承接短篇短剧、微电影、剧情短片、动画短片、单条剧情短视频，以及具备完整"目标→阻力→策略→反馈→变化"因果链的剧情宣传片、剧情预告片和广告剧情；纯商品转化广告、品牌价值观 TVC、企业宣传或真人对镜口播不属于本 Skill。也可承接多单元、几十集和跨集主线的长篇完整剧本。常规多集短剧单集通常为 1-3 分钟，极短集支持 15-60 秒；微电影通常为 5-10 分钟。最终时长必须结合用户指令与剧本容量确定；超过 10 集时须声明长篇漂移风险，先锁全局故事、全部分集推进和结局，再逐集写详细剧本并复核。

## AI 生成可拍性合同

> 面向媒体生产时，识别会影响当前情节的真实生成风险，保留故事需要的完整表演与动作。技术限制以当前模型能力和实际结果为依据，不把经验性风险写成统一拆镜配方。纯文字任务不为尚未选择的模型改写作品。

### AI 生成的七大限制与剧本应对

| AI 的限制                    | 剧本阶段的应对策略                                                                                                                    |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| **细微表演可能难以辨认** | 先保证观众拥有理解表演的前因与关系；确有歧义时补必要语境，不自动加物证、特写或解释性反应 |
| **复杂动作可能失真** | 写清行动目的、空间、关键接触及结果，保留必要连续过程；是否分镜或有意省略交给导演，不预拆成固定动作链 |
| **多人互动可能错位** | 写清人物位置、行动对象与因果，按实际风险处理；不把完整关系场默认拆成单人动作、对手反应和群体后果 |
| **口型与发声可能不一致** | 保留用户及已确认台词的逐字原文和完整语义，安排可完成的表演窗口；不为口型擅删词、拆句、插入反应或统一回避特定语言 |
| **场景/道具一致性差**  | 核心道具和场景在项目数据卡中精确锁定；分集只引用稳定 ID 和当前状态，并补本场动作与位置增量                                            |
| **有意停留可能被误当无内容** | 写清观众在等待、体验或观察什么；沉默、拒绝回应和稳定关系也可成立，不强塞手部、视线、光声变化来证明留白 |
| **渲染可能缺少质感**   | 从已确认风格出发设计主光方向、明暗层次、材质和色彩关系；不得为了“掩盖塑料感”把所有项目统一改成暗调                                  |

### 风格处理

本文件不维护导演、作品或动画流派清单。用户指定风格，或项目需要建立视觉锚点时，按需读取 `电影大师风格库.md`，把风格拆成可观察的光线、色彩、构图、材质和节奏机制；不得默认用暗调、慢推或特写掩盖生成问题。

在统一内容审校时检查当前作品确实涉及的风险，发现具体问题才定向处理，不逐场生成七项自证报告。

## 双层剧本结构

项目必须同时存在两层剧本，不能用其中一层替代另一层：

1. **项目级完整全面剧本**：保存于根目录 `01_剧本/剧本_全剧完整剧本.md`。它不需要复写每句对白和每个细动作，但必须从开端写到最终结局，完整覆盖主线、人物弧、分集/段落因果、主要场景序列、关键行动、核心台词意图、伏笔埋设与回收、高潮兑现和最终状态。禁止只写题材介绍、世界观、人物设定或一句话分集大纲。
2. **分集详细完整剧本**：保存于 `episodes/ep_N/01_剧本/`。每集必须把总览中的本集内容细化为可直接进入分镜的全部场次、动作节点、对白、旁白、声音职责、状态变化和集间承接，不得擅自改变全剧总览的核心因果与结局。

单条短片、微电影和单部长视频保留项目级与 `ep_1` 的正式文件入口，但故事与正文只创作一次；项目级总览引用或复用当前正文，`ep_1` 承载逐场动作、全部对白和声音执行，不独立重写两套内容。纯文字目标按用户要求交付一份所需成果即可。

全局故事圣经与分集推进总纲合并保存为 `01_剧本/剧本_全局设定与分集总纲.md`，不得再分别生成 `剧本_全局故事圣经.md` 或 `剧本_分集推进总纲.md`。合并文件固定包含两个一级章节：

1. **全局故事圣经**：世界观、故事规则、人物与关系、主线问题、人物弧、关键伏笔、揭示顺序、结局和不可破坏的因果链。
2. **分集推进总纲**：按全部集数依次写每集目标、阻力、策略变化、核心事件、转折、阶段兑现、结尾状态和下一集钩子；单集项目保留 `ep_1` 一行。

两章可以在同一次修改中一起更新，但必须保持标题和边界清楚。全局设定变化时复核全部分集行；局部分集调整时复核其前后承接，不把两个章节压成一段混合摘要。

项目级剧本包必须先完成并确认，内容包括全局故事圣经、全部分集推进总纲、完整主线、人物弧、伏笔账本、最终结局和 `00_制作控制/project_data_card.json` 的跨集基线。它必须覆盖全部集数，但不提前写各集逐场动作与完整台词。项目级确认后才进入 `ep_1` 详细剧本；每集详细剧本只在该集开始制作时生成并单独确认，确认后完成本集资产、分镜、视频和成片，再进入下一集详细剧本。

## 目标

纯文字任务以用户要求的剧本、评阅或局部成果为终点，直接根据已知事实创作；不要求 `selected_direction_id`、规划 JSON、数据卡、机器合同或先确认生产项目包。需要缺失信息时只澄清影响当前内容的关键事实。

以下项目包、数据卡、落盘目录和逐集确认要求仅用于正式生产：先稳定全剧故事与逐集推进，再在当前集开始制作时细化可直接进入分镜的完整剧本。

正式交付必须结合用户本轮指令、已提供素材、后续修改和已确认设定生成完整、具体内容。不得只给方法、模板、提纲或示例；不得在正式剧本中出现"略、此处略、后续依此展开、待补充、TBD、XXX、1-N、占位符"等未完成内容。项目级故事包必须完整覆盖当前确认的全部集数与最终结局；进入某集详细创作后，该集每一场、每个动作节点和全部应发声台词都必须实际写出，使下游可以不补写剧情就直接制作完整分镜表。不得把“覆盖全部分集推进”误解为在项目级阶段提前批量写完所有分集详细剧本。

动笔前先按 `control-contracts.md` 建立项目级 `01_剧本/项目_事实与假设.md`，逐字保存用户核心要求和限制，并将已验证事实、未知项、推进假设、项目惯例分栏。仅某一集成立的假设写入对应 `script_contract_ep_N.json` 的来源字段，不重复建立多份事实锁。

剧本阶段必须继承规划阶段已经向用户展示并确认的 `selected_direction_id`，不得重新暗中替换方向。若写作时发现所选方向存在无法闭合的因果、授权或可生成性问题，返回规划阶段更新候选与选择理由，不在剧本阶段另起一套未确认方案。

行动场景应能理解人物所求、阻力、选择及其后果。观察、等待、蓄压、仪式或未决关系也可构成场景价值，状态未变不自动等于无效。结合整段观看判断：若删掉或合并没有损失人物经验、时间感、空间理解或因果，再压缩；不为满足字段硬造反应、线索或转折。

正式生产正文定稿后，从 Markdown 与数据卡编译 `script_contract_ep_N.json.scenes[]` 的 `entry_goal`、`tactic`、`countermove`、`turn` 和 `exit_value`，如实描述实际场景作用，允许未决状态，不虚构攻防。Markdown 是正文权威，JSON 是派生合同；修改后仅重编受影响场次与来源哈希，不维护两套剧情。

剧本中的关键事实必须建立"台词证据链"。凡是会改变人物判断或剧情走向的身份、指控、承诺、能力、秘密、规则和结论，都要登记：

```text
台词声明 -> 事实来源或前置铺垫 -> 可见画面/动作/道具/结果 -> 揭示场次 -> 对局势的后果
```

- 不能只让角色说"他背叛了我""我有证据""我是负责人"就视为剧情成立；后续必须让观众看见证据或看见该判断造成的可观察后果。
- 角色可以撒谎、误判或隐瞒，但剧本要区分"角色所信"和"故事事实"，并规划公平线索或后续验证。
- 同一事实重复解释而没有新证据、新策略或新后果时，删除重复台词。
- 涉及真实品牌、人物、IP、地点或时效事实时，证据链来源必须是用户资料或可靠检索结果；未核实内容只能写成虚构设定、角色观点或待确认项。

本阶段不写逐镜头分镜，逐镜头规划由 `storyboard.md` 处理；但剧本必须完整到足以逐场转换，不得把剧情创作责任留给分镜阶段。

**项目级故事包与数据卡先确认，再逐集产出 2 份分集文件（完整剧本正文与 `script_contract_ep_N.json`）；全部分集缺一不可，但禁止在项目级确认前批量提前写完。**

项目级固定文件为：内部 `项目_事实与假设.md`、`剧本_全局设定与分集总纲.md`、`剧本_全剧完整剧本.md` 和内部 `project_script_manifest.json`；设定摘要按上文在确认时现场渲染，不落盘。原“剧情梗概、人物小传、主要故事场景”不再分别生成独立项目文件，统一作为 `剧本_全局设定与分集总纲.md` 中“全局故事圣经”章节的固定子章节。

### 项目数据卡

完成项目级完整剧本后，立即按 `manifests.md` 创建 `00_制作控制/project_data_card.json`。它不是人物小传的摘要，而是所有下游阶段共同读取的结构化事实源：

数据卡字段全集与取值基数以 `manifests.md` 的 project_data_card 字段表为唯一清单；场景锚点须可见、可核对并足以辨识当前空间，不另加数量配额，不预制剧本未使用的昼夜版本；状态变更写生效场次、结束范围、剧情原因和新状态。

角色面部身份、身高体型和音色默认全剧不可变。服装、发型和妆容变化必须有剧情、时间跳跃或明确造型依据；同一 SEG 内没有对应镜头时不得突然变化。表情、视线和小动作属于场面表演，随人物处境与对白自然承接，不为每句对白另建 `state_id`。分集剧本只引用稳定 ID 和当前 `state_id`，不得重新发明角色、场景、道具或音色基础设定。

项目级故事包确认时不落盘独立设定卡文件：确认前由主 Agent 从当前 `project_data_card.json` 与已确认全局剧本**现场渲染**一张设定摘要（世界观、人物关系、主要场景、关键道具、声音主体、视觉方向、禁用项）在对话中展示，供用户核对身份锁与状态基线；数据卡是机器事实源，该摘要只是确认时的投影，用户修改意见一律落回数据卡及受影响剧本，不产生需要同步维护的第二份文件。

每集固定文件为 2 份（信息全部承载于这两份产物，不再生成分集梗概、人物状态、关系张力矩阵、分集主要场景四份独立 Markdown）：

1. **详细完整剧本**（`剧本_完整剧本_ep_N.md`，用户可读）：包含全部场次、时间/内外景、人物、动作提示、对白、旁白、画外音、内心独白、情绪节拍和结果；正文头部带一段分集梗概（本集目标、阻力、策略变化、高潮、结果和下一钩子）。人物状态与场景事实不在剧本中重复登记——服装/伤痕/道具归属等可变状态写入 `project_data_card.json` 的 `state_timeline`（剧本只引用 `state_id` 并写剧情触发），本集实际使用场景引用数据卡 `scenes[]`。
2. **机器执行合同**（`script_contract_ep_N.json`，schema 见 `manifests.md`）：`relationship_tension`（每对核心关系的权力差、信息差、情感差、本集变化节点——即原“人物关系张力矩阵”的结构化承载）、`state_timeline` 引用、`highlight_ledger`、`beat` 清单、`speech_lines` 与 `inherited_world_facts`。关系矩阵格式与更新规则读取 `剧作方法与类型库.md`；每一个关系变化必须能回指具体场次。

分集创作只引用已确认项目级故事包和数据卡中的稳定 ID、人物弧、伏笔与本集目标，不得改写最终结局，也不得假定尚未生成的资产文件或 approved 版本。

## 单集创作卡

下表是创作时可查的诊断问题，按当前作品需要使用；正式生产只把必要结论写进已有合同，不另填一张重复卡，也不要求每行都有独立设计：

| 字段                 | 必须回答                                                                                                                                                                                                                                            |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 核心戏剧问题         | 主角这一集必须解决或推进什么                                                                                                                                                                                                                        |
| 故事引擎             | 欲望、阻力、失败代价、不可逆选择和本集兑现如何持续制造行动                                                                                                                                                                                          |
| 开场状态与钩子       | 绑定`opening_strategy.opening_id`。第 1 集直接继承主/辅机制、首节拍、可见承诺、升级和兑现；后续集可写强化、反转或更新型变体，但必须说明变体理由以及如何延续项目承诺。写初始局势、第一可见承诺、具体异常或冲突、升级触发，以及兑现或悬念延续的位置 |
| 主角目标、时限与代价 | 主角主动争取什么，失败会失去什么                                                                                                                                                                                                                    |
| 对立目标与资源       | 谁或什么形成阻力，为什么阻止主角                                                                                                                                                                                                                    |
| 信息差与证据         | 观众、主角、对手各知道什么，公平线索在哪里                                                                                                                                                                                                          |
| 策略与权力变化       | 旧策略如何失效，新策略如何改变局势                                                                                                                                                                                                                  |
| 情绪推进与回报       | 压力、关系或认知如何变化，最终兑现什么情绪                                                                                                                                                                                                          |
| 人物外壳、内核与执念 | 公开形象保护什么恐惧或渴望，什么信念驱动重复选择                                                                                                                                                                                                    |
| 母题与视听意图       | 关键道具、动作、色彩和声音如何改变意义                                                                                                                                                                                                              |
| 高潮、结果与下一问题 | 当前问题如何回答，角色如何反应；连续剧再建立下一问题                                                                                                                                                                                                |
| 可传播台词或母题 | 有实际作用时写明情境与支撑；可以没有独立金句或母题，不要求每集配额 |
| 可拍性风险           | 复杂动作、多人同框、微表情、长台词、场景和道具风险及处理方式                                                                                                                                                                                        |

钩子与反转须有公平前因及相称兑现；人物可以成长、失败、保持立场或暂未完成改变。传播句从角色当下行动中自然出现，可以没有，不硬补视听母题等价。高潮和结局来自前文规则、处境与人物选择，不靠临时设定或强制模板。

具体行动或关键事实无法成立时，回到最早失效的因果补足，不用金句、镜头效果或新增设定掩盖。正式生产把实际使用的结论写入 `script_contract_ep_N.json`，不把以上问题扩成逐场论证文档。

## 视觉叙事、母题与声音意图

剧本可使用道具、环境、服装、色彩、动作、台词和声音母题；重复可以变奏、累积、回扣或维持一种预期，不要求每次出现都改义。需要具体风格时查 `电影大师风格库.md`，剧本只写叙事意图。

## 画幅与竖屏写作意图

只有确认竖屏时才考虑单一视觉焦点、纵向高低关系和边缘安全；横屏继续使用横向空间、群像和环境关系。字幕、机位、运镜、布光和转场不在本阶段定稿。

## 类型变体与差异化生成

只从已确认 `drama_plan.json.type_strategy` 与 `highlight_strategy` 继承主类型、题材路由、故事发动机、项目签名、亮点支柱、采用机制和排除机制。四个创作参考库只用于把这些已确认策略细化成人物选择、冲突、信息差、场面和台词，不得重新选择或自定义另一套故事发动机、项目签名、亮点支柱、受众或风格。若现有策略无法闭合，返回 `planning.md` 更新 revision 并重新确认后再写剧本。

### 逐集亮点执行

每集根据已确认 `highlight_strategy` 建立 `highlight_ledger`。只登记真实采用的亮点与作用，不设每集 primary 名额；辅助亮点不得挤压主故事因果。每项必须能定位：前置铺垫、兑现动作、状态变化、题材职责、呈现类别表达和高潮后的余震。连续两集重复同一亮点机制时，必须说明它如何升级、反转或完成回扣。

钩子负责让人继续看，亮点负责让人记住，高潮负责完成不可逆选择，三者可以在同一场发生但职责不得混写。金句只能是亮点的表达之一，不能替代人物行为、关系变化或题材机制。

## 规划继承与澄清

剧本阶段不重新询问规划参数，直接继承已确认 `drama_plan.json` 全部字段（继承清单与禁换项见「输入门禁」）。

若关键字段缺失、互相冲突或用户在本阶段提出会改变规划的要求，返回 `planning.md` 更新完整参数确认；不得在剧本文件中维护第二套默认值或只局部口头确认。

### 长篇漂移风险继承（>10 集）

集数超过 `10` 时，`planning.md` 已要求把漂移风险和逐集机制写入同一份规划参数确认。剧本阶段只核对该确认记录并执行已确认安排，不新增第二次风险确认门：漂移通过项目数据卡和相邻分集承接复核纠正；不在剧本正文重复面向用户的风险提示，也不因后续集尚未细化而改变已确认的全局结局。逐集锁定与细化顺序按「双层剧本结构」执行。

## 输出要求

前三类项目级内容的落盘归属同「目标」节（并入全局故事圣经固定子章节，不分别落盘）；完整剧本单独保存。事实与假设、数据卡、机器合同与设定摘要按「目标」节规定生成；关系张力由 `script_contract_ep_N.json.relationship_tension` 承载。多集项目「分集推进总纲」必须覆盖全部集数，单集保留一行 `ep_1`。

### 字数与完整性门禁

剧本准出依据完整主线、清晰因果、必要事件、台词与可拍细节，不设基于规划估时的最低字数、字数预算或另一条固定字数门槛。只改变规划估时不得改变剧本准出结果；不为贴近预测删戏，也不靠重复、氛围或无功能对白凑量。

script_contract.duration_s 如保留，只记录早期预测，不传入分镜时间核算。`script_contract.scenes[].events` 保存稳定 event_id、逐字 source_excerpt 和必要事实 summary；speech_lines 继续保存逐字 line_id/主体/类型。正文与索引一起确认，确认记录绑定源文件 SHA/版本，不新增用户确认门。程序核原文定位、唯一性与覆盖，索引是否漏事仍须对照正文审校。

分集只写本集增量，身份、空间与固定音色复用数据卡，不反复铺陈基础设定。

## 剧情梗概（全局故事圣经固定子章节）

- 单一连贯叙事文本，不用小标题堆砌，也不用过多分点。允许用 3-5 个自然段落对应"起承转合"。
- 覆盖：故事起点与主角初始处境、核心冲突登场、事件升级与转折、高潮反转、落点/情感闭环。
- 必须包含：主角核心动机、反派/对立面的具体阻挠手段、主角的关键抉择、结局形态（爽感释放 / 情感和解 / 反转揭示 / 行动号召）。
- 常规短剧单集 1-3 分钟：先完成所需事件、行动和结果，不根据规划分钟数预算字数；规模冲突按真实要求处理，不擅自删结果和反应。
- 多集项目剧情梗概只覆盖全剧主线、不逐集展开；“分集推进总纲”表格覆盖全部集数（规则见本节开头）。

## 人物小传（全局故事圣经固定子章节）

常规短剧通常覆盖主角、配角、反派三类角色，每类至少一位；用户指令或实际剧情不需要某类角色时不得机械添加。微电影可将"对立力量"作为独立小传，不要求人格化反派。每位主要角色或对立力量使用以下颗粒度：

```markdown
#### [角色名]（[主角 / 配角 / 反派]）

- **一句话定位**：[年龄 + 身份 + 关键人设标签]。
- **外壳**：[角色公开呈现的身份标签、说话方式和惯常行为]。
- **内核**：[外壳保护的恐惧、脆弱、渴望或价值判断]。
- **执念**：[持续驱动选择的创伤、遗憾、承诺或错误信念]。
- **性格**：[3-5 个具体性格特质，避免抽象形容词，用行为倾向描述]。
- **动机**：[核心动机 + 底层驱动力（欲望/恐惧/执念）]。
- **策略与越界选择**：[惯用策略 + 哪个节点采用过去不会使用的新策略]。
- **成长弧线**：[开场状态 → 中段动摇/受挫 → 结局蜕变，写清转折触发事件]。
- **视觉方向**：[大方向的形象、气质与识别符号，细节由资产阶段落地]。
- **固定音色锚点**：[年龄/性别表达 + 音高与质感 + 语言/口音 + 语速 + 停顿节奏 + 基准情绪 + 句尾习惯]，同步写入 `project_data_card.json.voices[].voice_anchor`。
- **关键道具/记忆点**：[标志性物件或行为习惯]。
```

人格化反派小传特别要求：

- 必须写清"合理性动机"（反派为什么这样做，避免脸谱化）。
- 爽剧、逆袭和明确善恶对抗题材写清实质失败、代价或惩罚落点。
- 微电影、关系戏和社会议题不强制惩罚；应写清对立力量如何被理解、承受、改变、绕过或留下余韵。

## 主要故事场景（全局故事圣经固定子章节）

在动笔完整剧本之前，先把全剧反复出现的核心场景一次性锁定，作为完整剧本场次表头 `场景名 [日/夜] [内/外景]` 的取用来源。

**规模推导：**

1. 先逐场读取已确认故事中的地点变化、时间跳跃、人物出入、行动阻力和证据位置，合并空间功能相同且不影响因果的地点。
2. 单场短片、密室戏、独白或同一空间内成立的完整冲突链可以只登记 `1` 个核心场景，不为满足数量机械加场。
3. 短篇通常使用 `1-4` 个核心场景；长篇可按跨集剧情需要使用 `1-8` 个或更多场景。这里是复杂度预警范围，不是最低值或封顶值。
4. 超出常用范围时，逐个说明新增场景承担的独立剧情功能，以及为什么不能由既有场景完成；能够合并而不损害因果、节奏或视觉辨识的场景应合并。

**输出格式：**

```markdown
| 场景编号 | 场景名称 | 场景类型/功能 | 空间概念方向 | 情绪氛围基调 | 叙事性关键陈设 | 常见时间/内外景 |
|---|---|---|---|---|---|---|
| SCN001 |  | [主场景/次场景/回忆场景/梦境] |  |  |  | [日 内 / 夜 外 / …] |
| SCN002 |  |  |  |  |  |  |
```

**字段颗粒度：**

- **场景名称**：2-6 字为宜，需与后续剧本正文场次表头一字不差（如 `茶室`、`旧公寓客厅`、`天台`）。
- **场景类型/功能**：主场景（反复出现的日常/工作/家庭空间）/ 次场景（推动关键剧情的少量出现空间）/ 回忆或梦境（视觉上与现实形成区隔的特殊空间）。
- **空间概念方向**：剧本只写大方向（材质、体量、光源、时代感）；细节由分镜阶段的场景文字合同、唯一导演总控卡逐段执行区落地，主要场景布局参考图由共享标准资产检查点按 `assets.md` 生成。
- **情绪氛围基调**：本场景默认承载的情绪（压抑/温暖/悬疑/冷冽/怀旧等）；同一场景可承载不同情绪，但需列出主基调。
- **叙事性关键陈设**：与关键道具、伏笔、剧情反转有直接关系的物件（如"书架下层的深棕色铁盒"、"茶室长桌上的落款签"）。
- **常见时间/内外景**：给出该场景在剧中最常出现的 `日/夜 + 内/外景` 组合，便于剧本正文表头对齐。

**完整剧本的场景取用约束（强制）：**

- 完整剧本每一场戏的表头 `场次编号 场景名 [日/夜] [内/外景]` 中的 `场景名`，**必须严格从本清单的 `场景名称` 中选择**，禁止在剧本正文里凭空新增未登记的场景。
- 当前未确认草稿确需新场景时，按稳定 `SCNxxx` ID 同步回填清单和数据卡并继续，随本轮成果一并确认；改变已确认事实、规模或资产基线时再按实际影响处理版本与确认。
- 单场故事因果完整时只登记实际使用的场景，不为凑数增加地点，也不把同一地点内连续行动反复另起场次。

## 完整剧本（分集分场专业格式）

按下节专业剧本格式输出；纯文字任务可遵循用户指定格式。事实与虚构边界按实际内容说明，不按集数添加“幻觉声明”，也不以免责声明替代真实人物、历史或专业事实的核验。


#### 长篇逐集制作规则（>10 集时强制，短篇同样遵守逐集原则）

一次性写完全部详细剧本容易在中后段漂移，因此先锁项目级故事，再逐集细化：

- **项目级先锁定**：一次覆盖全部集数的故事圣经、分集推进总纲、人物弧、伏笔账本和最终结局，经用户确认后不得由后续分集自行改写。
- **每次只细化当前集**：内部定点读取上一集实际状态、本集目标、待兑现伏笔和结尾状态，再写当前集；不在聊天复述整套背景。正式逐集生产当前集未确认前不写下一集；纯文字全剧委托按用户约定范围交付。
- **每集完成后复核**：对照项目级故事包、数据卡、关系张力和伏笔账本检查人设、因果、节奏、伏笔与结局方向；发现漂移时只修当前集或回到真正受影响的项目级合同。
- **伏笔记录**：当前集未回收的关键伏笔继续写入内部机器合同并绑定预计回收集数；不得因后续集尚未细化而临时改变已锁定的回收方向。

## 专业剧本格式规范

完整剧本必须严格采用**分集分场专业剧本格式**，让下游分镜阶段能一场戏对一段镜头列表。**不建议再使用"章节 + 100 字梗概"这类概要式写法作为完整剧本的最终形态**——概要式内容归在“剧情梗概”子章节里。

### 剧本头（每部剧本开头一次）

```markdown
《[剧本标题]》

类型：[短篇短剧 / 微电影 / 剧情短片 / 动画短片 / 广告剧情 / 长篇短剧]（如为长篇，注明总集数）

风格：[例如：自然侧光与低饱和材质，完整关系场内观察；或二维水墨、留白空间与克制色彩]

标签：[题材关键词 + 情感关键词，例如"豪门联姻 + 先婚后爱 + 救赎"]

人设：[一句话高浓缩人设对撞，例如"年轻洒脱活泼女×年成熟稳重古板男"]

单集时长：[X 分钟]  |  剧作基调：[微电影三幕式 / 短视频钩子驱动]
```

剧本头中的时长是预测；真实用户时长要求另按合同继承，不以头部估时反推删戏。

### 风格字段填写指引（索引）

`风格` 字段必须写成可执行机制，不得只写“电影感”“高级感”。用户已经指定创作者、作品或动画流派时保留其意图，并从 `电影大师风格库.md` 选取少量光线、色彩、构图、材质和节奏特征；用户未指定时可以直接使用不绑定具体人物的机制组合，不强制选大师。后续资产、分镜和 Prompt 沿用同一份已确认视觉合同。

### 分集与分场格式

- **分集标题**：`第X集`，独占一行，不带集名（可在剧情梗概里给集名，剧本正文用集号即可）。
- **场次编号**：保留人读 `X-Y`，对应稳定 ID `E01S01`；每场使用唯一 Markdown 标题，例如 `### E01S01 1-1 茶室 日 内`，供源事件定位。
- **场景表头**：`场次编号 场景名 [日/夜] [内/外景]`，源索引用唯一 Markdown 标题携带 scene_id（如 `## E01S01 / 1-1 茶室 日 内`），便于逐场原文定位；人读格式例如 `1-1 茶室 日 内`、`1-2 茶室门口 日 外/内`。**`场景名` 严格取自「主要故事场景」清单且一字不差**；新增场景先回填该清单（强制约束同该节）。
- **人物**：单独一行，列出该场出现的人物；如有画外音使用"角色名+VO"形式，如 `白父VO`。
- **动作提示**：以三角形符号 `△` 起首，只描述人物可见动作、空间关系、道具状态和结果。**动作提示必须客观、可拍摄，不写心理活动，不预设景别、机位、焦段或运镜**；镜头设计属于 `storyboard.md`。
- **对白**：`角色名：带规范标点的可读台词`，例如 `白清枞：盲婚哑嫁，你也能接受？`。问句、感叹、停顿和强调首先由标点帮助阅读，再在机器合同中用 `delivery_intent`、`pause_plan`、`emotion` 和 `emphasis_words` 精确执行。
- 每条人声在 `script_contract_ep_N.json` 中只绑定 `voice_id`；声音锚点由数据卡 `voices[].voice_anchor` 单定义按 ID 解析，台词行不复制锚点字段；分集只写本场表演增量，不得改写固定音色描述。旁白也必须使用独立、全剧稳定的 VOICE。
- **旁白/画外音**：`角色名VO: 内容`。
- **内心独白**：`角色名OS: 内容`，只在无法由动作、关系或可见证据表达且确有叙事价值时使用。
- `VO/OS` 都属于后续视频模型必须原生生成的画外人声；画面人物不得做对应口型。剧本必须写清声音主体、起止场次、情绪、文本和对应画面职责。
- 时间跳跃、章节转换、记忆或内心状态可以按需使用短黑屏、暗场、环境空镜、物件特写或声音先行；不是强制模板。若需要显示时间、地点或章节，剧本写明上屏文字内容，分镜阶段编译为 `“画面文字”`。
- **情绪节拍记录**：用户可见剧本只用自然语言动作与表演描述情绪变化，不写任何内部元数据。供后续分镜使用的节拍标签只保存在内部机器合同中，不得进入展示给用户的剧本 Markdown。`【】` 只作为成片字幕源文本标识，不进入视频模型 Prompt。
- **场次结束**：空一行进入下一场次。

### 用户台词与台词闭环

- 用户提供的每一句原台词作为 `source_text` 逐字、按原顺序保存，且只存这一层。带标点阅读面与无标点机器串均从它现场派生。文本除标点规范外不得删改、拆句、合句、调序或替换字词。
- 问句、感叹和语义停顿由 `source_text` 渲染面保留可读性，模型表演再由 `delivery_intent`、`pause_plan`、`emotion` 和 `emphasis_words` 控制。
- **每句对白后接表情、反应或小动作。** 在阅读正文中紧接一句具体、可演的提示，交代说话人或听者如何承受、掩饰、试探或接住这句话。它要来自人物处境、正在做的事和前后情绪，不能反复套用“皱眉、握拳、嘴角微扬”。克制、拒答或没有外显回应也写成具体可观察的状态，例如“她仍看着轨道，没有接话”，不另造内心独白解释。
- 表演提示不进入逐字 `source_text`，不改变原台词。动作可承接已有行为，时长可与话音尾部自然衔接；不强加固定停顿、不逐句另起反应镜，不要求说话人和所有听者各做一遍。上游已写明的表演由分镜和 H3 成稿保留其人物、时机与情绪作用。
- 用户只给少量台词且未禁止补充时，原始 `source_text` 保持不动；新增台词遵守同一文本合同，不得插入或改写用户原句内部。
- 根据人物与具体场面写话语，确有帮助时再分析意图和语言动作；允许直说、复沓、犹豫、失语、闲谈或拒绝回应，不要求每句都有隐藏顾虑、攻防策略或新信息。
- 画面已经能够直接看到的信息不再由台词复述。潜台词通过停顿、动作、视线、距离或答非所问呈现。
- 每句承担事实、指控、身份揭示或能力证明的台词，必须能在"台词证据链"中找到前置来源、可见证据或结果反馈；找不到时改写为角色主观判断，或补足证据。
- 完整短篇以适合本片的行为、语言、声音或未决余波形成落点，不强求最后一句回扣或说出主题；连续剧当前承诺与下一问题须有因果关系。

### 分集分场格式样例（微电影向）

下面只示范场次、动作和对白格式，不代表完整成片的时长或必选结构；道具来源、人物行动和去向在场面内可以追踪。

```markdown
《收针》

类型：微电影（1 集）

风格：裁缝店的自然侧光与旧布料质感，保留人物共同工作的连续过程

标签：家庭 + 退休前一天

人设：急着帮母亲关店的女儿×不肯留下未完活计的老裁缝

单集时长：按完整创作与表演后估算  |  剧作基调：日常关系

第1集

### E01S01 1-1 裁缝店 日 内

人物：陈兰、女儿

△缝纫机已经盖好防尘布。一件深蓝外套搭在柜台上，袖口拆开了一半。女儿把封箱胶放下，拿起外套。

女儿：这件怎么装？

△她仍托着外套，等母亲指给她该放的箱子。

陈兰：还没好。老周下了班来拿。

△女儿看看门边已经封好的纸箱，把外套递回去。陈兰从针盒里取出针，试着穿线，没有穿进。

女儿：眼镜呢？

△陈兰指向纸箱。女儿将刚封好的胶带揭开，从最上面取出眼镜盒。

女儿：你刚还说都用不着了。

△陈兰戴上眼镜，把线穿好。女儿拉过一把椅子，坐到柜台另一侧，托住垂下来的衣袖。

### E01S02 1-2 裁缝店 日 内

人物：陈兰、女儿、老周

△稍后，老周进店。陈兰把针放回针盒，将缝好的外套递给他；他套上，活动手臂。

老周：这回不绷了。多少钱？

△陈兰想了想。女儿把柜台上的收款码推到他面前。

女儿：还是原来的价。

△老周付款，向两人道别。门合上，女儿将针盒放进还开着的纸箱，把眼镜盒留给陈兰。

女儿：这个你自己拿着。

△陈兰把眼镜盒装进衣袋。女儿封箱，陈兰关掉柜台灯。两人抬起最后一箱，走向门口。
```

> 两场以时间省略区分：第一场完成共同修衣的选择，第二场完成交付和关店。同一场内不因拿针、穿线、递物另拆场，也不指定固定停顿、反应镜头或运镜。示例中的沉默与动作来自正在做的事，不能复制成每个微电影的情感配方。

## 单集章节结构

章节数量由总时长、策略变化、场景跨度、关系转折和信息揭示动态决定，不设固定数量。每章必须承担独立职责并改变剧情状态；删除后不影响主线的章节合并或重写。章节只用于剧作组织，不等同于视频片段，也不得按模型时长机械切分。

**章节功能分配**：

- **微电影三幕式**：建立情感缺口与钩子 → 事件和冲突迫使主角改变 → 高潮选择、反应与落点。
- **短视频钩子驱动**：快速建立问题 → 压力升级与策略变化 → 身份、能力或事实兑现 → 当前冲突收束。

## 写作原则与策略路由

纯文字创作在本节只取内容方法，按用户指定范围和形式交付；不读取或补建生产 JSON，不为使用方法先确认项目包。下述规划字段、事实锁附录和双层路由仅在正式生产中适用。

跨类型共同要求是人物行为可信、事实关系清楚、观看内容完整且表达有依据；主动选择、策略攻防或反转并非每场必需。具体类型承诺按当前项目核验，不用同一种冲突模板覆盖观察、失败或开放结构。

短剧、微电影、爽感、钩子、留白及呈现类别变体的候选策略按需读取 `题材亮点与传播库.md`，受众假设读取 `题材受众库.md`；视觉风格机制读取 `电影大师风格库.md`；读取时机与章节定位统一以 `creative-index.md` 为准。策略候选不能覆盖本文件的因果、证据、完整性门禁与**人物口吻**；候选库互相冲突时不混用，取唯一主机制的最小充分策略。实际采用的受众假设、类型路径、风格机制和全剧信息差账本追加到 `01_剧本/项目_事实与假设.md` 的“策略选择”附录；每集独有的信息差和状态变化写入本集完整剧本头部的分集梗概段；不把未采用的候选整包写入正式交付。

### 类别 × 题材双层路由

正式写剧本前必须从已确认 `drama_plan.json.type_strategy` 逐字继承：

1. `format`：动画/卡通短剧、漫剧、AI 真人/数字人短剧、口播解说短剧、微电影/短片或用户自定义形态，决定叙述载体、场景颗粒和表演方式。
2. `subject_route` 与必要的 `subject_subroute`：决定冲突发动机、信息释放和高潮义务。合并题材词不能不分主次地同时套用。
3. `format_strategy`：四项分别说明叙述载体、场景颗粒、台词/旁白和表演/动作策略，不得只写“发挥动画优势”“电影感”等空话。
4. `intersection_strategy`：四项分别说明钩子呈现、冲突推进、高潮兑现、制作限制补偿。任一项在正文中找不到场次证据，先重写策略或正文，不得进入分镜。

执行顺序固定为：先按 `剧作方法与类型库.md` 第二部分建立类型与题材路由及结局义务，再按 `题材亮点与传播库.md` 第一部分改写为对应载体语法。更换呈现类别视为剧作层变更，至少重审场景拆分、台词/旁白比例、信息证据、动作复杂度和高潮表达，不能只在分镜阶段换画风。

## 题材与受众策略

需要受众、平台、地域或题材选择时读取 `题材受众库.md`。其中内容只作为待验证假设：

- 用户明确受众和平台时以用户信息为准。
- 涉及最新趋势、平台政策、审核、人口画像或市场偏好时必须检索并记录日期与来源。
- 不根据年龄、性别、地域机械决定题材、人物、节奏和结局。
- 不因平台名称自动开启字幕、热门 BGM、固定画幅或固定钩子秒数。
- 风险内容遵守当前法律、平台政策和宿主安全规范，不用改名或影射规避核验。

## 剧本内容质量人工评估

纯文字任务只评作品内容与用户要求，跳过生产合同、数据卡、文件哈希与媒体能力检查。正式生产的 `drama_lint.py` 只检查结构和显式合同，不能判断故事是否成立。交付前统一审读当前成果，不另做固定评分或重复清单：

按实际问题选择前提、结构、人物、关系、场景、台词、导演与可拍性等检查维度。发现哪类问题就定向修订并核结果，不规定固定轮数或每轮报告；格式校验不能代替内容复核。

| 维度           | 达标标准                                                                                                          | 失败处理                                                       |
| -------------- | ----------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| 因果           | 行动及后果可理解；观察、等待和未决关系有整段观看价值 | 修最早失效的因果；仅在删除无损时合并或压缩 |
| 钩子与兑现     | 钩子服务主线，有明确兑现位置和后果                                                                                | 补兑现或删除无关刺激                                           |
| 人物           | 行为与处境可信，人物可以主动、受困或保持立场；对立力量按作品实际存在 | 修具体动机和行为，不硬加反派或越界选择 |
| 信息与证据     | 关键事实、身份、能力和反转均有来源、公平线索与可见后果                                                            | 补证据或改为角色主观判断                                       |
| 台词与声音     | 话语符合人物处境，原文可追溯，表演窗口充分，声音主体清楚 | 保留原文，调整表演窗口、声画安排或调度，不擅自拆句 |
| 关系张力       | 相处方式、未决需要或关系变化有具体依据；恒定关系也可成立 | 修不可信或重复空转处，不因无攻防、无显性变化就重写 |
| 亮点与可传播点 | 实际亮点有因果支撑和具体表达；没有金句也可成立 | 删口号与伪亮点，修实际人物、事件和表达，不补名额 |
| 节奏与情绪     | 整段观看的压力、亲疏与时间感成立；对白后有贴合人物的表情、反应或小动作，留白可维持未决感 | 修空泛表演与突兀衔接，保留成立的停留，不为变化而加戏 |
| 完整性         | 当前委托范围内内容完整，落点符合已建立承诺；开放、无回应或局部委托按实际要求判断 | 补真正缺失的内容，不强补闭合解释或显性反应 |
| AI 可拍性      | 生产所需行动、空间和状态明确，当前模型的具体风险有处理路径 | 定点修正实际风险，保留必要完整表演，不默认拆人、拆镜 |
| 跨集一致性     | 实际已有设定、状态与集间承接一致；正式生产另核数据卡 | 修真实矛盾；正式生产仅使受影响下游失效 |
| 交付完整性     | 已交付用户要求的成果；正式生产另核正文、合同、数据卡和来源哈希 | 补实际范围内缺失项，纯文字不补生产产物 |

以上项目由创作者在交付前人工复核，不要求填写固定报告模板；发现问题时直接修改剧本并重新展示受影响内容。

## 交接

路径、命名、`project_script_manifest.json`、`project_data_card.json` 和 `script_contract_ep_N.json` schema 只读取 `manifests.md`。项目级阶段产出完整故事包与数据卡；逐集阶段只产出当前集详细剧本和机器合同。JSON 只保存执行字段、正文路径与哈希，不复制完整正文。

项目级落盘前核对全部集数、人物弧、伏笔和最终结局，将 `phases.script` 写为 `awaiting_confirmation`，展示用户可读文件并等待确认。通过后把 `phases.script` 写为 `confirmed`，设置 `current_episode: ep_1`、`current_stage: script` 和 `episodes.ep_1.stage_status.script: in_progress`。当前集完成后只将该集 `script` 写为 `awaiting_confirmation`，不要求后续集详细剧本同时存在。用户可读产物提供可打开的文件链接，聊天不重复全文，不展示机器合同、内部字段、内部控制路径或校验统计。

```text
项目级：请确认全局故事圣经、全部分集推进总纲和最终结局是否需要修改。确认后我会开始第 1 集详细剧本。
分集级：请确认当前集详细剧本是否需要修改。[仅目标还包含下游阶段时说明实际下一阶段；到达交付终点即结束。]
```

收到修改意见时只修订真实受影响范围。改变全局因果、人物弧、伏笔回收、结局或分集边界时回到项目级故事包；只影响当前集执行细节时修订当前集。确认与逐集推进顺序同上文状态机，当前集达标后才开始下一集详细剧本。
