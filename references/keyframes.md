# 关键帧阶段 Ref

当 `current_episode` 的资产和十五列详细分镜分别取得用户确认后读取本文件。本文件是剧情关键帧生成、登记、目视验收和阶段确认的唯一权威。关键帧阶段位于当前集分镜之后、当前集视频片段之前；不得跨集批量生成关键帧。

## 输入条件

必须同时具备：

- 项目级故事包、当前集详细剧本，以及当前集资产和分镜阶段均已取得用户明确确认。
- 当前集十五列详细分镜、导演总控卡逐段执行区和 `storyboard_ep_N.json` 完整。
- 分镜已按集完成高光关键帧需求清单：按实际用途选择，允许零独立需求，映射到确需高光、状态、构图或执行风险锚点的 SEG；未选中的 SEG 可以没有 `required_keyframe_roles` 或 `keyframe_requests`。所有 SEG 仍必须有 `reference_input_plan`，只在本段确有已规划 KF 时列入 `segment_highlight_reference`。不规划生成式首帧或尾帧。
- 所有出场角色、角色当前状态、需要建立 SCN 的主要场景、已升级为 PROP 的关键/复现道具和风格均引用已批准资产版本；服装、发型、妆容、伤痕、伪装或随身装具与基准不同时，必须已有对应角色状态资产。当前高光发生在某个 `SCNxxx` 场景内时，该场景必须已有 approved 四宫格布局参考图，并作为 `K1` 真实传入。一次性物件只写入关键帧 Prompt，不要求补 PROP 资产。
- 生图模型继承已确认规划，不得在本阶段自主切换；本阶段统一使用 gpt-image（知脑中转）。

任一分镜动作相位、机位、构图、角色当前状态或道具状态版本仍未确定时，返回分镜或资产阶段修复，不得先生成“通用关键帧”再让下游迁就。

## 生成时机

- 关键帧只在资产与分镜都确认后生成，位于视频生成之前；必须执行本阶段并等待用户确认。它是视频段的画面锚点，不替代分镜，也不替代视频 Prompt。
- 按剧集执行：先读本集 `storyboard_ep_N.json` 和导演总控卡逐段执行区，再按本集关键帧需求机器字段（按当前正式用途清单）生成需要的关键帧；不要跨集混用待确认关键帧。
- 只为分镜清单中被选中的 `SEG` 生成高光关键帧，按剧情重要性和片段时间顺序推进；未选中的 `SEG` 不补普通高光图。
- 如果某段复用前段已批准的同状态关键帧，可以不重画，但必须在 manifest 里登记真实复用关系。

## 数量与职责

先根据已确认设计判断哪些高光、状态、构图或执行风险确需独立关键帧。需求数量由实际用途决定，不读总时长、不设置保底/封顶/单段配额，也不因峰值少回剧本补戏。

```bash
python scripts/rhythm_engine.py kf-count --storyboard <当前分镜文件>
```

返回正式需求数、待生成数、复用数和按 SEG 的映射。零独立需求时保留空清单和绑定当前分镜的需求审查，按原关键帧阶段展示“无需生成”并取得阶段确认；不伪造媒体。有需求时仍须逐项真实生成/复用、验身份状态和用户确认，取消配额不取消来源与资产门。

KF 锁生成前高光目标，tail FRM 是生成后按需提取的下段输入事实。首段不额外画首帧；continuous 后段须等前段实物存在、选定 tail FRM 并把帧文件与时间码登记进下段 `reference_inputs` 后再编译。关键帧不冒充首尾事实，不替代完整运动路径。需要改变已确认需求时按版本流程处理，不临时增删到某个数量。

## 视频可用性标准

关键帧是后续视频可直接消费的单瞬间参考图，承担已确认高光、状态、构图或执行风险职责；不另创海报式画面。生成和验收时先过以下标准：

- **高光参考与首尾事实分离**：关键帧只锁选定瞬间的画面职责，不登记为目标视频 `first frame` / `last frame`。真实尾帧只在连续下段需要时从成品 mp4 按需提取单个 tail FRM 作为图片输入，不建帧注册表；角色图、场景图、风格图只作为参考图，不得冒充关键帧。
- **静帧可拍性**：Prompt 描述的一切必须能被摄影师在同一瞬间拍到；“先、再、随后、转身过程中、表情从 A 到 B”属于视频动作，不能写进单张关键帧。
- **高光事实不串线**：每张高光关键帧只呈现选定时间点已经成立的事实。写完后要把手位、持物、视线、站位和可见状态反查一遍，不能把尚未发生的结果提前塞进画面。
- **人物站位可接戏**：按已确认构图写实际可见人物的位置、朝向与对连续性有用的关系；持物或接触影响剧情时再写手位。不为画外、遮挡或不可辨识的人物补全眼神与微动作，也不把“不回应”改成夸张反应。
- **空间和镜头轴线稳定**：继承已确认机位、构图、空间和光源；只补本图需要的轴线、遮挡、方位或光位信息，不为填全参数改变原镜头。
- **景别承载正确表演**：远景不要求不可读的面部细节，近景不承担完整走位；只锁当前景别能读到的表演通道。
- **画幅适配**：`--ratio` 跟随目标视频选择横/竖/方参考图档，实际像素以工具返回值为准；当前横/竖档为 1536x1024 / 1024x1536，并非精确 16:9 / 9:16。构图预留目标视频画幅与已确认安全区，禁止拉伸或裁掉关键内容；参考图不充当精确尺寸首帧。
- **数量服务实际用途**：按已确认需求清单执行，高光、状态、构图或执行风险均可成立；不为每个 SEG 补图。动作过程由视频表达，不靠两张静帧替代。

## 画面创作法

先读本图已确认的用途、时刻与观看设计，再写可见画面。需要高光时让事件清楚，需要等待、留白或状态锚点时保留其静态价值，不另造冲突或动作。

1. **继承本图任务**：写清它锁定的是高光事实、状态、构图还是执行风险；任务来自分镜，不要求都是信息峰值或冲突峰值。
2. **保持原定观看焦点**：脸、手、道具、距离、空位或环境均可成为重点，保留理解该画面所需的信息。
3. **固定准确瞬间**：遵循已确认动作相位；准备、进行、完成或静止均可，只描写当下可见状态，不把连续动作塞进单帧。
4. **表演服从景别和设计**：写实际可见、确实影响画面的姿态与表情；允许克制、没有反应或看不见脸，不强配眼神和握拳。
5. **空间关系可理解**：沿用分镜的人物距离、朝向、遮挡与出入口，不为加强冲突擅自逼近、堵门或改站位。
6. **保留构图的观看作用**：前中后景、空白和景深按原设计使用，不要求每图都塞满三层物件或行动路径。
7. **适配目标画幅**：需要被读懂的脸、手、文字或道具保持可辨识；实际字幕和平台 UI 风险才触发安全区调整。远景、背影、局部与留白均可，不能一律改成中近景或把主体搬到中上部。
8. **参考图少而准**：按职责选择必要图片，冲突时按项目已确认事实优先级处理，不用堆图代替清楚映射。
9. **画面属于剧情现场**：不额外加入磨皮、无因逆光、符号、特效或宣传照姿势；已确认的对称、中心构图、空旷背景可以保留。
10. **负面约束针对本图风险**：例如不复制人物、不改变左手持物、不把门换到另一侧，不堆通用禁词。

### 可见描述密度

关键帧 Prompt 的画面主体描述长度以信息齐备为准，不设字数阈值；参考图定位另算。内容过多时优先保留主体、剧情证据、动作相位、人物关系、光线和关键材质，删除不影响视频首尾承接的装饰。

描述以可见事实为主，数量、遮挡、接触、朝向或文字确实影响身份、因果和连续性时写准确；背景纹理与匿名人群不逐物穷举。已有基准可引用，只展开本图差异。

人物只写同一瞬间看得见的姿态和表演，按景别选必要细节。轻微变化可用自然语言表达；只有容易误读或对动作承接关键时才精确到手位、重心、视线或接触点，不逐部位填清单。

材质、颜色和光影只写画面会呈现的结果。颜色稳定时写具体色名；颜色不稳定时写明暗、冷暖或部位差异；材质要绑定纹理、反光、褶皱、磨损、潮湿、透明叠加或边缘状态。光照写光源方向、照亮区域、阴影软硬和投影方向，不用“高级、超写实、电影感很强”这类评价替代视觉结果。

画面文字必须按画面可读性处理：需要准确出现的短文字用中文引号写出，并说明在信纸、牌匾、手机屏幕、档案页或墙面上的位置、字号相对关系和可见程度；长信件、档案、书页不逐字展开时，说明上面有密集中文手写或印刷文字、大致内容和少量可读关键词。没有剧情需要的文字不写进画面。

常见返修方向：

- 角色不像：减少非身份参考，强化当前角色状态图；把脸部角度、发型、服装、伤痕和年龄写成可见事实。
- 画面未实现已确认用途：先核对选点、观看焦点与可见关系，不自动加反应、压迫姿势或改动作相位。
- 视频接不上：优先检查上段真实 tail FRM、下段 `reference_inputs` 登记、站位、手位、持物、屏幕方向和光位；需要改生成前目标时只重画相关高光关键帧，不生成首帧或尾帧替代从成品提取的真实帧。
- 构图像海报：降低装饰性光效，加入前景/中景/背景和行动路径；让人物处在剧情关系里，而不是对镜头摆姿势。
- 道具漂移：单独传道具状态图，写清归属、朝向、接触点、可见面和是否有文字；文字内容不稳定时留白，后期叠字。

## 生成合同

每张关键帧必须基于已批准角色/状态、场景、已升级为 PROP 的道具和风格资产生成，工具固定使用 参考生图（`img --ref`）；按当前画面职责选择足够且必要的已批准身份/状态、场景、道具和风格参考并真实传入，不得用 text-to-image/纯文生图重新生成。当前剧情发生在已登记场景内时，必须传入对应 approved 场景四宫格，采用其空间拓扑、固定陈设、画面外补全结构、光位、材质和场景锚点；不得因为关键帧构图是近景、人物图带背景或分镜已有文字描述而省略场景图。一次性道具只写进关键帧 Prompt，不要求补道具资产。没有足够有效视觉参考图时，返回 `assets.md` 补齐并确认，不得在关键帧阶段降级为 文生图（`img`），也不得用文字临时替代。缺换装后角色状态、场景四宫格或需复现的 PROP 道具状态资产时，先返回 `assets.md` 补齐并确认。

关键帧生成前按职责收集真实可用图片：

```text
K0 当前角色状态资产：锁服装、妆发、伤痕、伪装和随身装具；无状态变化时使用身份基准图或头部身份锚点。
K1 当前场景布局或状态资产：使用 approved `SCNxxx` 四宫格，锁空间拓扑、固定陈设、画面外补全结构、门窗朝向、行动路径、光位和材质；指定格位的标记按下文 Prompt 合同执行。
K2 当前已升级为 PROP 且需要复现的道具资产：锁结构、尺寸、归属、可见面和当前状态；若来自道具多状态图，用 `<图x-第x个>（状态）` 指明具体分区。一次性道具只在关键帧 Prompt 中描述，不列为资产输入职责。
K3 STYLE001 全局 moodboard：锁主色调、色彩关系、线条、光线、材质、构图、景深、颗粒和空间氛围；不得生成剧情人物、角色脸、具体服装或剧情道具。若由 SCN/KF 明确承载，也必须记录承载关系。
K4 必要的用户/外部有效视觉参考：只采用已保存并登记的视觉信息，剥离文字、水印、品牌和无关主体。
K5 用户认可的视觉画风锚点：当任一人物、场景、道具、构图或风格图被指定为 `style_anchor_reference` 时，作为风格参考传入，只继承从该图抽取出的媒介、线条、上色、纸感/颗粒、色阶、材质、光影和设定稿质感等画风词，不继承锚点图里的无关人物、场景、道具、服装、布局、姿态和剧情状态。
```

关键帧调用的 Prompt 必须使用自然语言，第一句先写项目统一画风与可观察风格词，例如“全项目统一保持[媒介、线条、上色、纸感/颗粒、色阶、材质、光影、构图和空间氛围]”；之后按真实传入顺序用 `language_contract.video_language` 逐张写清每张图的职责、可采用内容和剥离内容。本阶段图片 Prompt 的源参考标记跟随 Prompt 语言，中文使用 `<图片1>`、`<图片2>`，英文使用 `<IMG1>`、`<IMG2>`；如果输入是宫格图，用 `<图片N - 第M格>` / `<IMGN - Cell M>` 指定具体格子，并与真实传图顺序一致；如果输入是道具多状态图，用 `<图x-第x个>（状态）` 指定当前采用的状态分区。场景、风格、道具、高光参考和主体职责必须分开写，不能把风格图误写成角色，不能把场景图继承为人物身份。每张参考图都要写明采用内容与剥离内容，默认剥离字幕、二维码、水印、平台界面、镜面文字、无关人物和无关背景。视频阶段 H3 成稿的标记另由 `h3-prompt-writing` 定义，不照抄图片 Prompt 源标记。

关键帧必须真实生成、保存为可打开的常见图片格式，目视验收，同时保存实际提交 Prompt 文件，并在 `keyframe_manifest_ep_N.json` 登记为 `approved` 后，视频阶段才允许作为 `segment_highlight_reference` 传入。分镜阶段只规划职责，不得把“待生成 KF”当作可传入图片。

用户追加或替换图片时先按采用维度判定影响：改变已锁定身份、状态、场景结构或全局画风时，回对应源阶段建版本，再按实际依赖修受影响产物；只调整本镜构图时回分镜修该设计，不重生无关资产。图片仅作补充且未改变既有决定时登记来源即可；已生成视频的返修仍按原授权流程。

画风首句必须与资产阶段已批准画风词一致，不要藏到末尾负面约束或笼统写“保持风格一致”；Prompt 语言与首句结构按上文合同。随后写清：

1. 本图已确认的画面任务与选定瞬间；高光写清具体事件，状态/构图/风险图写清需要锁定的关系，不要求证明信息峰值。
2. 所属分集、片段、镜头、高光序号和准确剧情时刻。
3. 角色版本和当前状态；按可见范围写必要位置、朝向、表演与动作相位，不列不可见面部细节。
4. 道具版本、状态资产、归属、朝向、接触关系、可见面和当前状态。
5. 场景空间拓扑、固定陈设、前中后景、遮挡关系、行动路径、时间天气、材质、主光方向、照亮区域、阴影软硬和色温。
6. 景别、机位高度、观察方向、镜头轴线、构图重心、主体屏幕位置和竖屏安全区。
7. 当前已成立的可见事实；前后因果只用于定位，不把下一拍结果画进本图。画面有剧情文字时说明载体、位置、可见程度和内容。
8. 与上一镜或入站状态的连续性，以及下一镜或后续片段必须继承的状态。
9. 单帧约束：只呈现一个确定瞬间，不做多宫格，不复制角色，不生成字幕、随机文字、水印或界面元素。
10. 高光边界声明：按「高光参考与首尾事实分离」直说本图是剧情高光关键帧、不是目标视频首尾帧。

画幅只进入内部生成参数，不写入 Prompt。只有真实传入的图片才能登记为参考依据；参考图可以来自用户上传、确有必要的检索下载、截图、已批准资产、KF/已提取 tail FRM 或外部素材，但必须已保存并登记，不得把仅存在于网页或文字描述中的图片说成已传入。

### Prompt 写法

## 用户展示与确认

每张关键帧生成、保存并通过基础可打开检查后，必须立即按 `SKILL.md` 的交付前置路由完成当前环境交付并说明画面内容、提供真实路径；主 Agent 完成落盘及可解码检查，当前关键帧未交付落盘检查前不得继续生成下一张。不得等全部关键帧完成后才第一次展示，展示语义遵循 `local-runtime.md`。全部关键帧完成内部验收后，按集数、视频片段和时间顺序确认展示结果；说明只写“第几集哪个片段的第几个高光”，例如“第 1 集第 3 段高光1”“第 1 集第 3 段高光2”；Prompt 文件入口仅在用户明确要求查看 Prompt、排查或交接时就近展示。必要时补一句极短状态，不展开用途解释，不面向用户写具体镜头号。同一类型从 `1` 开始编号，面向用户不显示内部 ID、工具名、字段、任务号或检查统计。

逐张展示、落盘检查与内部验收不构成逐张等待用户确认的门。除非用户明确要求“一张确认后再做下一张”，完成当前张展示与检查即可继续下一张，全部完成后沿用本阶段确认。
