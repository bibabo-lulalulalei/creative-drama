## 当前工具链

### 关键帧术语统一

本文件中任何遗留的 `start KF`、`story KF` 或 `tail KF` 表述均不再作为执行要求。关键帧只指 `keyframes.md` 定义的集级剧情高光 KF：并非每个 SEG 都有，不承担首帧或尾帧职责。首段起点由分镜初始状态定义；非首段先读取 planned `SEAM`，`continuous` 必须由上一段真实 `tail FRM` 承接，`elliptical` 则按明确的新时空或新认知起点开始。当前 SEG 命中分镜已规划高光时才传入对应 KF。

当前可执行能力（本地工具路由以 `local-runtime.md` 为唯一权威）：

| 能力 | 当前用途 | 禁止误用 |
|---|---|---|
| 文生图（`img`）（本地：`tools/image/img.py` 不带 `--ref`） | 无参考图时从纯中文描述生成新资产 | 不登记虚假参考图 |
| 参考生图（`img --ref`）（本地：`tools/image/img.py` 带 `--ref`） | 有参考图时生成或修订资产、KF 或承接候选图 | 不把编辑图冒充原始 FRM |
| 纯文本视频（`h3` T2VA）（本地：`tools/video/h3.py`，gen.json `mode: T2VA`、`inputs` 为空） | 当前片段没有任何媒体输入时根据 Prompt 生成视频 | 有必须继承的图片、视频或音频时不得使用；非首段仅限 `elliptical` 且无必要媒体锚点 |
| 图生视频（`h3` I2VA）（本地：`tools/video/h3.py`，`mode: I2VA/FL2VA/L2VA`） | 只有图片输入时生成视频 | 不得携带视频或音频输入 |
| 多媒体视频（`h3` Ref2VA）（本地：`tools/video/h3.py`，`mode: Ref2VA`） | 存在视频或音频输入时生成视频，可同时携带图片 | 至少需要真实视频或音频输入 |
| 视频重生成（`h3`）（本地无定点编辑能力） | 以原视频为参考槽位经 h3 重生成，Prompt 写明保留人声/音色/口型 | 语义弱于原工具，返修前向用户说明 |
| 本地音色工具（`tools/tts/qwen3tts_autodl.py`，Qwen3TTS） | 生成角色与旁白稳定音色 | 音频输入不可用时提供固定文本锚点；支持后必须传入已批准 VOICE |
| 本地媒体链路（`tools/video/ffmpeg_tool.py`） | 负责抽帧、拼接、探测、裁剪和字幕烧录 | 不改变剧情和镜头职责，不默认替换合格原生人声；本地无 ASR，字幕文本从已锁定剧本台词稿整理 |

工具路由只看本次实际输入：零媒体用 纯文本视频（`h3` T2VA）；只有图片用 图生视频（`h3` I2VA）；存在视频或音频用 多媒体视频（`h3` Ref2VA）；修改已有视频用 视频重生成（`h3`）（本地为重生成语义）。`continuous` 非首段因必须传入上一段真实 tail FRM，不属于零媒体路由；`elliptical` 非首段若确实没有任何必要媒体输入，可以使用 纯文本视频（`h3` T2VA）。本地统一由 `tools/video/h3.py` 执行，gen.json 的 `mode` 与 `inputs` 槽位区分路由，`inputs` 数组顺序即槽位顺序，上限以 `tools/video/h3.json` 能力档案为准；调用前复核 gen.json 结构，并在批次中记录 mode、槽位和输入，不得为偏好某个路由伪造或丢弃媒体。

**模式判定与定义以 `h3-prompt-writing` skill 为准（逐镜判定，不是逐片判定）。** `T2VA/I2VA/FL2VA/L2VA/Ref2VA` 五模式各自的判定条件与写法不写在本文件；本文件只负责盘点该镜真实持有的锚点（有无首帧、尾帧、参考视频、参考音频），照该 skill 的模式定义派生本镜模式，并把派生结果原样写入 gen.json 的 `mode`。同一集内不同 SEG 的模式可以不同，同一 SEG 也可能落在任一模式上，不得为统一而替某个镜头补造或删去锚点。

## 执行顺序

视频批次的用户可见确认内容必须按 `video-batch-confirmation.md` 编译；`interaction-ask-video-clarification-ref.md` 只负责随后 AskUserQuestion 的调用结构与确认有效性。
本文件中任何把“合并参数确认表、数量、逐段时长或本批次五列分镜表”归为本文件或 `interaction-ask-video-clarification-ref.md` 定义内容的旧句均废止；这些展示内容只以 `video-batch-confirmation.md` 为准。
“视频片段批次生成确认”是本文件对“两张批次展示表 + 确认文件中的视频生成确认”的组合简称，不是确认文件中的章节名。

1. 完整模式从 `project_data_card.json`、每集唯一导演总控卡、十五列详细分镜、视频片段执行表、片段衔接卡、连续性账本和已批准 `keyframe_manifest_ep_N.json` 编译 `SEGxxx` 导演交付包。轻量模式只从已确认规划、内部十五列详细分镜和真实可用的用户素材编译唯一视频导演交付包，不得伪造其他上游文件、资产或 KF 引用。
2. 盘点本次实际媒体输入，按真实锚点经 `h3-prompt-writing` skill 逐镜派生模式（`T2VA/I2VA/FL2VA/L2VA/Ref2VA`，判定与定义以该 skill 为准），并把派生结果照抄进 gen.json 的 `mode` 与 `inputs` 槽位（本地统一由 `tools/video/h3.py` 执行；视频重生成（`h3`） 为以原视频为参考槽位的重生成）。
3. 为每个 SEG 独立编译一份完整五段式导演交付包，保存为 `提示词_SEGxxx_vNN_ep_N.md`；同一长视频及同一剧集的各 SEG 必须继承剧情和因果、人物身份、声音系统及 `SEAM.required_invariants`。`continuous` 片段还继承上一段真实尾帧及连续状态；`elliptical` 片段只继承不变量和明确保留项，不复制已被允许改变的旧时空状态。结构化台词和镜头计划只有逐项进入该文件，才能进而落到 H3 成稿并真正传给模型。
4. 用 Skill 工具加载 `h3-prompt-writing`，把该 SEG 的导演交付包连同该镜 mode、`duration_s` 和素材清单转成 H3 成稿，保存为 `提示词_SEGxxx_vNN_ep_N.h3.md`；成稿的字段结构、标记与时间写法完全以该 skill 为准，本文件不复述也不替代。转换中若发现交付包信息不足以成句，打回分镜补齐，不得自行编造镜头、台词或素材关系。
5. 两份文件就位后执行一次集中客观预检：交付包五段顺序完整、每个分镜恰好出现一次、时间连续覆盖、输入标记与真实顺序一致、台词逐字一致、动作桥与切点字段齐全、尾态和禁区明确；H3 成稿存在、非空且已登记哈希。发现问题最多集中修订一次，再做一次最终客观校验；除合规、授权、真实性、工具能力、缺失输入或客观校验失败等硬阻塞外，校验后直接进入确认与生成。
6. 完整模式先按 `video-batch-confirmation.md` 展示两张表；轻量模式首次生成直接使用规划页已展示的完整参数与预览，返修或重生再使用单视频批次展示。两种模式都只按 `interaction-ask-video-clarification-ref.md` 调用标准视频生成确认，未取得当前 `generate` 时不得派发视频执行。
7. 主 Agent 为本次确认覆盖范围建立锁定执行包，写明最终 Prompt（H3 成稿）、请求快照、`gen.json`、输入媒体、工具 schema、输出白名单和禁止行为，并按 `delegation.md` 委派 subagent 串行执行实际视频工具调用。
8. subagent 只调用执行包指定的视频能力，保存可渲染结果到白名单路径，并返回真实输出路径、工具原始可渲染资源字段、URL 或短链及工具结果，同时标记“生成成功、待主 Agent 正式交付”；不得重写 Prompt、改变输入、追加片段、交付用户或再次确认。subagent 成功只表示生成完成，不表示用户已收到产物。
9. 主 Agent 收回后保存并登记 SEG，更新 `video_manifest_ep_N.json`，确认文件存在且具备可渲染/可播放资源，并按字幕策略清理模型意外生成的字幕、随机文字、水印或平台 UI；不得因为其他内容、审美、口型、身份、连续性或接缝疑似问题延迟交付。用户要求的正式字幕不在片段阶段补齐，只在最终音轨锁定后的成片阶段生成。
10. 完整模式每个 SEG 保存、登记并具备可渲染资源后，主 Agent 立即按 `SKILL.md` 的交付前置路由完成本地交付（产物落项目目录、通过可打开/可解码检查并在对话中给出相对路径）后才能继续下一段。轻量模式没有独立 SEG 交付门：字幕关闭时原始生成结果就是唯一最终视频并立即交付；字幕开启时原始无字幕结果只作为内部烧录源，不展示，完成字幕烧录后只交付字幕版。
11. 完整模式每个 SEG 交付后只进入一次本文件第二部分，完成必要 FRM 抽取、内部片段记录、接缝窗口记录和 `continuity_ep_N.json` 更新；关键内容或连续性问题按 quality_gate 阻断合格交付；非关键偏差展示并经用户明确接受后可带偏差交付。质量门不授权自动重生或编辑。轻量模式只有一个最终视频，不执行分段接缝与连续性文件流程。
12. 下一片段按工具实际 schema 选择：
   - 逐镜按真实锚点经 `h3-prompt-writing` 派生模式：没有任何媒体输入时落在 纯文本视频（`h3` T2VA）；只有图片输入时落在 图生视频（`h3` I2VA/FL2VA/L2VA）；存在视频或音频输入时落在 多媒体视频（`h3` Ref2VA）。`continuous` 非首段必须真实传入上一段 tail FRM，因此不得走 纯文本视频（`h3` T2VA）；`elliptical` 非首段按当前新起点的真实需要选择输入。完整模式再传角色身份图、场景图、必要道具/状态图及本段已规划高光 KF，并逐项记录顺序和职责。
   - 先把图片职责分为 `required` 与 `optional`。只有 optional 图片可在超过工具上限时按“角色身份 > 上一段真实尾帧 > 核心道具/状态 > 场景 > 本段已规划高光 KF > 风格”排序裁剪；required 图片数量本身已超上限时禁止调用，必须返回分镜拆 SEG、减少同段主体或重新确认可用工具方案，不能删除必需职责。
13. 完整模式本轮片段均已逐段交付并落盘检查后，若仍有未生成片段，为下一批重新展示两张表并按视频确认 Ref 取得新的 `generate`；全部片段完成后，`target_stage=final` 按 `control-contracts.md` 调用进入成片拼接确认，`target_stage=video` 则普通确认后结束。轻量模式按字幕策略完成并交付唯一最终视频后，直接进入成片普通确认。

## 批次合同

每个待生成片段必须具备：

- 完整模式必须具备当前 `episode_id`、`project_data_card.json` revision、`episode_manifest_ep_N.json`、`storyboard_ep_N.json`、`source_manifest.json` 中与本集相关的输入记录、`asset_usage_ep_N.json` 与 `keyframe_manifest_ep_N.json`。轻量模式只要求内部十五列详细分镜、当前确认记录和真实存在的用户素材。
- 完整模式当前片段命中的 `highlight_bindings`：逐字继承亮点对应的视觉兑现、表演兑现、声音兑现、余震镜头和编译说明；不得用通用“震撼、电影感、情绪拉满”替代。轻量模式直接从十五列分镜对应镜头提取可见触发、变化、反馈和结果。
- `ep_2` 及以后各集的首个 SEG 必须读取 `00_制作控制/episode_seams.json` 中对应 `EPSEAMxxx`。`continuous` 跨集接缝必须绑定上一集真实尾帧及 SHA-256 并处于 `verified`；`elliptical` 跨集接缝不强制把尾帧作为视觉输入，但必须记录上一集结果、保留的不变量、允许变化、新起点和切换策略。只有整个项目的 `ep_1` 首段使用 `START`。
- 稳定片段 ID `SEGxxx`、绝对时间范围和完整镜头 ID。
- 已确认的十五列详细分镜，其中包含镜头职责、连续性和抽帧承接要求。
- 完整模式必须具备已确认的 `导演总控卡_ep_N.md`、片段执行表和连续性账本，并使当前镜头可追溯到对应表演、声音、色彩、切镜与连续性合同；轻量模式不创建这些文件，直接使用十五列分镜中的对应列。
- 完整模式必须使用已确认的角色、需要建立 SCN 的主要场景、已升级为 PROP 的关键/复现道具、风格和当前 SEG 已规划的高光 KF；所有出场角色必须解析到数据卡身份与当前状态，主要场景和复现道具必须解析到 approved SCN/PROP 版本。一次性物件只写入 Prompt，不要求建立 PROP。轻量模式只引用真实存在的用户素材，不要求补造独立资产或 KF。
- 已确认的视频模型、片段时长和画幅参数。
- 根据本次 `input_image_ids/input_video_ids/input_audio_ids` 选择的 `tool_mode`，且输入组合满足对应工具合同。
- 当前片段已通过 `storyboard.md` 的镜头职责、连续性、时长边界及工具可执行性检查；不存在运镜类别、运镜次数或人物动作绑定门槛。
- 所有计划人声已完成朗读估时并标注类型。出镜对白要求对应角色真实开口；旁白、画外音和内心独白要求画面人物不开口。字幕默认关闭，只有用户明确要求字幕时才在成片阶段处理；视频模型阶段始终禁止直接生成字幕；不能传音色媒体不等于允许静音。

批次容量以 `video-batch-confirmation.md`「批次边界」节为唯一权威（每批只覆盖当前集接下来连续的 `1-2` 个 SEG，禁止超过 `2`）。同一批次内必须串行执行：前一个 SEG 返回、保存、登记并完成本地交付（落盘＋可解码检查＋给出路径）后，才能派发下一个 SEG。

任一项缺失、版本未确认或能力与工具 schema 不符时停止生成，返回对应阶段修复。

## 批次确认展示

合并参数确认表、数量、逐 SEG 时长、五列分镜表、展示顺序与记录要求全部读取 `video-batch-confirmation.md`。本文件不复制其 schema 或模板；任何历史重复版本均无效。

## 模型、时长与画幅

模型、片段时长、画幅、批次上限和例外理由必须直接继承已确认规划与 `storyboard.md`，并在调用前用 `tools/video/h3.json` 能力档案复核。本阶段不得重选模型、重算镜头数量或为适配调用擅自改时长。用户未指定视频模型时，所有新视频生成批次固定使用 MiniMax H3，每个 SEG 不得超过 `15` 秒。

片段边界必须落在已确认镜头切换点；画幅只进入工具参数，不写进 Prompt。本地无 `seedance 2.5` 对应模型，规划时不可选，参数确认表不出现会员/额度提示；单段上限沿用 `15` 秒合同不变。模型能力与已确认计划不兼容时停止调用并返回规划或分镜，不静默换模型、压缩剧情或突破时长上限。

## 入站连续性

场景与画面一致性由五层控制：

1. **项目数据卡**：SCN 锁定空间拓扑、固定陈设和基础光位，状态时间线记录合理变化。
2. **共享场景参考**：每个主要 SCN 使用同一批准布局图，不在各集重新生成。
3. **生成前 KF**：完整模式每集只使用分镜阶段规划并经确认、按 `kf-count` 公式区间确定的剧情高光 KF；并非每个 SEG 都有 KF，KF 不承担 `start|tail` 首尾帧职责。
4. **生成后 FRM**：上一段生成后提取首帧、场景锚点帧和尾帧，以实际视频作为事实来源，并记录与 KF 的偏差。
5. **下一段承接**：从实际 `tail FRM` 继续角色位置、姿势、朝向、动作相位、道具状态、构图、镜头角度和光位。

### 长视频逐段连续继承算法

对同一长视频、同一集的 `SEG002` 及以后每段执行；跨集首段同时读取 verified `EPSEAM`。目标是把“上一段真实发生了什么”转换成“下一段 0 秒从哪里继续”，而不是复制一句“保持一致”。

1. **读取五类来源**：读取项目数据卡与 approved 资产的稳定身份；上一段已保存视频；上一段 `start|scene|tail FRM` 及观察记录；当前 `SEAM` 的 `seam_mode|required_invariants|permitted_deltas|transition_anchor`；下一段分镜的首态、动作、台词、状态变化和 `reference_input_plan`。`continuous` 缺真实尾帧时停止编译；`elliptical` 不把尾帧设为必需输入，但接缝合同、新起点或必要状态资产缺失时仍返回上游补齐。
2. **建立继承表**：逐项列出剧情因果与已发生动作、角色身份、服装/妆发/伤痕、屏幕位置/朝向/视线/姿势、产品与包装、道具归属/开合/接触、场景拓扑/固定陈设、主光方向/色温、摄影机轴线/运动、声音主体/音色/环境声/BGM，以及未决钩子。每项同时写“上游锁定值、上一段真实尾值、下一段计划值、允许变化、采用值”。
3. **按优先级比较**：身份、授权、用户锁定项和 `required_invariants` 不能被真实生成偏差改写；上一段真实尾帧决定下一段可见起点；`permitted_deltas` 只允许计划内变化；下一段计划负责从真实起点推进到新状态。若真实尾值与计划值只存在可剪切的小偏差，采用真实尾值作为 0 秒基准并在动作过程中回到计划；若偏差改变身份、因果、道具归属、轴线或未允许状态，不伪写一致，记录冲突并返回分镜调整承接。不得自动重生上一段。
4. **选择真实输入**：`continuous` 把上一段 tail FRM 作为 `previous_tail_as_start_frame`；`elliptical` 不强制传 tail FRM，按新起点选择角色身份/状态、SCN、PROP/状态、本段高光 KF 和必要风格图。**锚图充分性**：选定 tail FRM 后，逐项对照该 SEAM 的 `required_invariants` 与 `proof_requirement`：凡 tail FRM 画面中不可读出的不变量（多桌/多人布局、群体衣着分布、远景人物、画外陈设等），必须把上一段当前采用版本（即 tail FRM 所属版本）的 scene FRM 作为 `previous_scene_anchor_reference` 一并选入真实输入；该 scene FRM 不存在时先按本文件第二部分补抽并登记，不得跳过。交付包第一段必须分别声明每张锚图各自承载的事实：tail FRM 只承接其画面中实际可见的内容，布局、群体衣着与画外主体等事实挂到 scene FRM。槽位不足时按执行顺序第 12 步的 required/optional 规则拆 SEG、减少同段主体或返回用户，不得省略。按工具实际上传顺序重排 `reference_inputs[].order` 和 `<图片N>`；任何本段已声明 required 的输入无法传入时停止，不得用文字假装已继承。
5. **写入五段导演交付包**：第一段写每个输入职责和 0 秒真实基准；第二段写稳定身份、当前状态、场景、光线和声音事实；第三段第一时间窗先写上一段尾态，再写“从该相位继续”的动作路径、反馈和新结果；第四段写当前 SEAM 的入点、段内切点和本段尾态；第五段复写整段不可漂移项与禁区。每一项继承事实只能有一个权威来源，不在不同段落写互相冲突的值。
6. **写回执行记录**：在批次快照和 `video_manifest` 中保存采用的上一段版本、tail FRM、数据卡 revision、状态资产、`reference_inputs` 顺序和继承摘要；生成后再把本段真实 `start|scene|tail FRM` 写入 `continuity_ep_N.json`，供下一段重复同一算法。
7. **检查闭环**：生成前逐项核对继承表中的每个采用值是否进入真实输入或五段导演交付包。生成前核对还必须逐条验证交付包第一段中每个“承接/采用/逐格承接”声明的事实，能在其引用的锚图（`<图片N>`）中实际看到：看不到的内容必须改挂到能显示该事实的锚图；没有任何锚图能显示时，降级为明示文本约束并在第五段禁区/约束清单中单列；两者都做不到时阻断编译，返回分镜。每个“承接”声明不得覆盖锚图中不存在的主体、布局、衣着或陈设。生成后比较本段 start FRM 与上一段 tail FRM，并记录 `accepted|rework`。`rework` 若涉及关键内容/连续性即阻断合格交付；不授权自动调用视频工具。
8. **失败回退**：缺真实证据返回抽帧/登记；计划首态与真实尾态不兼容返回分镜改 SEAM；资产版本冲突返回资产阶段；剧情因果冲突返回剧本。不得用“自然衔接”、模糊景别、黑场、强光、声音桥或后期转场掩盖未解决的不变量冲突。

尾帧参考规则：

- `continuous` 非首段必须把上一段真实尾帧和分镜声明为必需的角色、场景、道具/状态图片放入视频工具的真实图片请求字段；`elliptical` 非首段只传新起点所需图片。本段命中已规划高光 KF 时再传对应 KF。缺任一分镜已声明必需的图片时停止调用。
- 使用 参考生图（`img --ref`） 处理尾帧时，原始尾帧和编辑候选分开保存；只有视频工具真正接收该图片时才算“首帧参考输入”。
- 单靠文字承接不能保证像素级一致，批次确认和内部记录必须明确该风险。

## 生成质量目标

每个 `SEGxxx` 在提交生成前写入：

```json
{
  "quality_target": {
    "engagement_driver": "",
    "exit_function": "",
    "hook": "",
    "evidence_or_clue": "",
    "credible_action": "",
    "visual_payoff": "",
    "closing_beat": ""
  }
}
```

- `engagement_driver`：本段真实观看动力，如目标/阻碍、动作变化、信息揭示、关系/情绪变化、兑现、未完成动作或真实悬念。
- `exit_function`：段尾职责，如结果落点、动作继续、信息暂悬、情绪余韵、声画承接、转场或真实钩子。
- `hook`：真实存在时填写的悬念/吸引点，可为空；不得为每个技术 SEG 伪造。
- `evidence_or_clue`：本段必须被看见的证明、线索或关系证据。
- `credible_action`：符合人物动机、空间和物理规律的关键行动。
- `visual_payoff`：本段实际兑现的揭示、反差、动作结果或情绪回报。
- `closing_beat`：明确尾态以及下一段可继承的动作、视线、物件、场景或声音。

五项必须是可观察内容并绑定镜头。调用数量、总生成时长和重试上限进入批次确认；本地不计费，不展示额度信息。

## 片段内镜头与运镜执行

把分镜按 `SEGxxx` 分组后逐镜编译，禁止摘要式合并。每个时间段按以下顺序写：

```text
承接事实 -> 观看方式与画面起点 -> 景别与机位 -> 摄影过程 -> 场景/光线/前中后景 -> 主体位置和朝向 -> 动作起点、过程、接触、反馈和结果 -> 信息或关系变化 -> 为什么此时切 -> 承接锚点 -> 后镜开始状态 -> `{}` 中对应类型的原生人声 -> 尾态
```

- 每个镜头独占一个首尾相接的时间区间，总和等于片段时长。
- 每个切点必须写清为什么此时切、用什么承接前一镜、切后增加什么新信息；承接锚点从动作、方向、主体位置、视线、形状、光色、声音、文字、遮挡或产品状态中选择。
- 跨镜动作必须完整覆盖“前镜状态 -> 动作发起 -> 运动路径 -> 合理切点或镜内调度 -> 后镜续接 -> 接触/反馈 -> 结果”，禁止手、人物、产品或道具无路径瞬移。
- 相邻镜头的观看方式、构图、景别、视点、摄影过程或焦点职责形成有意图的关系；不要求逐镜更换运镜。
- 真正一镜到底只能有一个镜头，必须从头到尾同一次连续拍摄，禁止硬切、隐藏切、遮挡伪切、匹配剪辑和时间跳跃；通过连续摄影机路线、观看对象、空间、主体关系、光影/焦点或可见信息形成至少三个可读节点，不要求节点由人物动作触发。
- 场景和角色描述使用稳定名称，不使用“同上”“还是那里”“那个人”等模糊指代。
- 先继承分镜确定的观看方式和摄影过程，再写景别、机位及镜头变化。分镜若包含多个连续摄影阶段，须按实际先后完整编译，不得压缩成一个主运镜家族；按需要说明摄影机路径、方向、速度质感、焦点变化、停留、切镜触发和最终画面。只写“电影感运镜”等抽象词而无法想象画面变化，视为未编译。
- 摄影标签如已填写，仅供内部索引；最终 Prompt 使用自然导演语言，完整描述已选摄影过程，不把标签当作镜头动作指令或单一类别限制。

## 镜头密度与片段内切镜

镜头密度与切镜规则以 `storyboard.md` 为准。Prompt 阶段不得重新规划镜头数量或修改已确认内容，只执行 `shot_plan`；摄影家族标签和统计不构成执行阈值。上游交付包与 H3 转换使用同一摄影意图合同：完整保留已确认的镜头内阶段、摄影机动作、观察对象变化、焦点/构图变化、停顿及其触发关系。外部 H3 格式要求只约束字段与写法，不得把组合摄影阶段压成单一类别；如工具模式对镜头数或连续性的能力有限，明确说明具体限制，并在上游选择可执行的表达，不静默删除导演意图。

- 保持镜头顺序、绝对时间、摄影过程、路径与方向（如适用）、速度质感、焦点变化、停留、动作桥、切镜原因、承接锚点和新增信息完整；保留同镜内多个连续摄影阶段，不因 manifest 的可选标签压缩设计；每个已确认镜头恰好编译一次。
- 不因生成方便合并计划镜头、截断台词或把多个镜头退化成统一慢推。
- 生成后是否兑现计划镜头和运镜，由 `video.md` 的实际片段内部记录观察；关键镜头导演意图未兑现时阻断合格交付；非关键偏差列入用户接受项。

## 导演交付包（五段式）

五段式是**交给 `h3-prompt-writing` 的输入包**，五层信息合同，不是五个镜头，也不是五个时间段；**它不是提交给视频模型的文本**，提交物是下一节的 H3 成稿。每个 纯文本视频（`h3` T2VA）、图生视频（`h3` I2VA） 或 多媒体视频（`h3` Ref2VA） 的 SEG 都必须先有这份交付包，包含以下五段，顺序固定，不能调整、合并、拆分或省略；实际文本由五个空行分隔的自然段组成，不写“第一段”等说明性标题；视频重生成（`h3`） 改用后文编辑合同。

导演交付包必须原样保存到当前 SEG 的 `compiled_prompt_file`，作为成稿的可追溯源；它必须从已校验的完整分镜编译，不能临时重新发明镜头、台词或素材关系。分镜中的每个镜头必须在第三段恰好编译一次，不能遗漏、重复或被摘要合并；内部 SHOT ID 只用于 manifest 覆盖校验，不强制写入自然语言文本。

1. **输入资产定位与 0 秒基准**：说明 `<图片1>`、`<视频1>`、`<音频1>` 分别承担什么职责；明确哪张图是真实首帧、参考图或上一 SEG 的真实尾帧。没有真实输入时不得虚构素材编号。`continuous` 后续片段明确上一段真实尾帧是本段 0 秒视觉基准；`elliptical` 后续片段明确转场锚点及允许变化。
2. **参考主体绑定与生成目标**：锁定人物、产品、包装、Logo、场景和已确认的视觉风格；完整模式从唯一导演总控卡继承，轻量模式从已确认规划和十五列分镜继承。写明必须保持的身份、服装、妆发、状态、空间、光线、材质和声音事实；排除无关人物、错误字幕、水印、竞品元素及参考图中不采用的内容，并写清本段生成目标。
3. **逐时间段动作、声音与脚本**：连续覆盖完整时长，按真实镜头和画面阶段展开，不按五段平均切时间。每个时间段写承接的上一状态或起始构图、主体位置（适用时）、完整的动作或画面发展过程、反馈或有意停留、景别/机位/角度及分镜设计的摄影阶段、新增信息、台词/BGM/拟音/画面文字，以及切出时的画面状态。不得因单一运镜标签而删减已确认的镜头变化。只有动作跨镜延续时，才按“前镜状态 -> 动作发起 -> 运动路径 -> 合理切点或镜内调度 -> 后镜续接 -> 接触/反馈 -> 结果”形成动作桥。可听文本写成 `说话人：{原文}`，例如 `旁白：{门已经开了}`；字幕源使用 `【】` 且不得进入视频生成画面；标题、品牌字、时间地点等画面文字使用 `“”`。
4. **转场与尾态收束**：逐切点写“前镜结束状态 -> 为什么此时切 -> 使用什么承接锚点 -> 后镜开始状态”，并写明切后增加的新信息。锚点可来自动作、方向、主体位置、视线、形状、光色、声音、文字、遮挡或产品状态；不得只写“自然转场”“快速切换”。非最终 SEG 留下可被下一段使用的角色、产品、道具、场景、动作和声音状态；最终 SEG 完成动作、声音和人物/产品/品牌落点。
5. **全片一致性与禁区**：复写全片必须保持的人物身份、产品与包装、服装妆发、道具、场景、光线、材质、音色和视觉风格；禁止随机字幕、乱码、水印、额外主体、产品变形、身份漂移、手部异常、闪烁和无来源特效。抽帧是生成后的检查动作，不写成模型要执行的画面内容。项目级禁项清单（由各 SEG 返修沉淀的禁项汇总而成，如“严禁玻璃马灯”“炕上严禁被褥”）必须全文注入每个 SEG 交付包的本段；任一 SEG 的返修中沉淀新禁项时必须回写项目级清单，并对后续所有 SEG 的编译生效，不得只留在单个 SEG 的修订记录里。

证据可见性合同同样按上一条的全文注入惯例消费（不删减依据同见本节防丢条款）：编译第三段（逐时间段）时，凡镜头命中 `causal_ledger` 的 `evidence_shot_ids|reaction_shot_ids`，必须把该链 `visibility_contract` 转写为本镜可执行条款写进对应时间段（例：「肿唇从指缝与嘴角可见，手部不得完全遮口」）；第五段「全片一致性与禁区」汇总全段证据可见性禁区。`causal_ledger` 未登记的镜头不新增禁区。轻量模式无台账时，禁区来自剧本-分镜对照审校第⑤项的三锚自查结论（反应有源/证据可达/指称有锚），写法相同。传导链为：分镜 JSON → 交付包 → H3 成稿，模型生成时「不许遮」成为显式约束。

五段职责属于导演编写规则。完整模式由主 Agent 对照已确认分镜和唯一导演总控卡人工复核；轻量模式只对照内部十五列分镜复核。`drama_lint.py` 只检查可客观验证的交付包文件、分镜覆盖、真实媒体标记、台词原文、路径与哈希，不以标题同义词判断创意质量。

画幅是工具参数，不在交付包末尾写比例。没有音频输入时，交付包不写 `<音频N>`，只逐字复用 `voice_anchor`；使用已批准 VOICE 时必须路由到 多媒体视频（`h3` Ref2VA），并按真实顺序使用 `<音频N>`。

## H3 成稿（提交给模型的文本）

**写法、字段结构、参考标记、台词与时间标注一律以 `h3-prompt-writing` skill 为准，用 Skill 工具加载；本文件不复述其模板、字段表和模式定义。** 本 skill 只负责在需要时调用它，并把结果登记进 manifest。

- **输入**：当前 SEG 的五段导演交付包、该镜经判定的 mode、`duration_s`、真实素材清单（含各素材在交付包中的职责与顺序）。
- **输出**：`h3-prompt-writing` 交给本文件的成稿文本，原样保存为 `提示词_SEGxxx_vNN_ep_N.h3.md`；该文件是提交给 `tools/video/h3.py --prompt` 的唯一文本，也是 `h3_prompt_sha256` 的计算对象。
- **不自补**：转换中若交付包信息不足以成句，打回分镜补齐，不得自行编造镜头、台词或素材关系；不得为了迁就成稿格式而删减交付包里的表演、声音、色彩、尾态或禁区信息——信息应完整落到成稿对应位置，成稿是同一批导演决定的另一种写法，不是精简版。
- **调用时机**：在交付包编译完成之后、集中客观预检之前（预检要连成稿一起核）。同一 SEG 的交付包与成稿 `_vNN` 版本号必须一致，成稿返工不改变交付包版本或分镜计划。
- **失败处理**：`h3-prompt-writing` 报出上游信息缺失时，按 `执行顺序` 第 4 条打回分镜补齐，不阻断其他 SEG 的编译。

## 人声与文字合同

- 完整模式每个声音主体在 `project_data_card.json.voices[]` 中只有一个当前 `VOICE ID` 和 `voice_anchor`，每条 `speech_lines.voice_anchor` 必须逐字复制数据卡中的该值。轻量模式不创建项目数据卡，所需声音描述直接继承已确认规划和十五列分镜。声音描述至少包含年龄/性别表达、音高与质感、语言/口音、语速、停顿节奏、基准情绪和句尾习惯。
- `audio_input_supported: false` 表示本次没有音频媒体输入，不表示视频应静音。此时每句台词前必须逐字写入 `speech_lines.voice_anchor`，并按其他实际媒体选择 纯文本视频（`h3` T2VA） 或 图生视频（`h3` I2VA）。
- 使用已批准 VOICE 音色资产时必须路由到 多媒体视频（`h3` Ref2VA）；`audio_inputs` 保存真实资源与文件，`voice_inputs` 映射 `voice_id/resource_id`。已传 VOICE 是音色权威，文字锚点不得与其冲突。
- 有任何人声的片段必须先确认 `native_audio_supported: true`；不支持时停止并返回参数确认，由用户决定是否改模型或接受无声/后配方案，禁止自主换模型。
- 有已确认人声时设置 `speech_mode: native_required`，`speech_lines` 的 `type` 只能是 `on_screen_dialogue`、`narration`、`voiceover`、`inner_monologue`；每句同时保存 `voice_id`、`voice_anchor`、原始 `source_text`、带标点 `display_text` 和无标点 `spoken_text`，用 `delivery_intent`、`pause_plan`、`emotion`、`emphasis_words` 表达表演增量。该段没有已确认人声时允许空数组，并按合同标记 `no_human_voice` 或 `ambient_only`；不得为通过生成模板补写任何词句。
- 四类人声均由视频模型原生生成并使用 `{完整文本}`；出镜对白驱动指定角色口型，其余三类明确“画面人物不开口”。
- `speech_lines` 中每条 `spoken_text` 必须逐字以 `{spoken_text}` 出现在 `compiled_prompt_file`。只有结构化字段中存在、但交付包里没有对应花括号台词，按“台词未提交给模型”阻断。转成 H3 成稿后，同一批台词必须原样带到成稿（写法以 `h3-prompt-writing` 为准），交付包与成稿的台词集合必须一致。
- 出镜对白必须在同一镜头写“角色名真实开口说出{完整文本}”；旁白、画外音和内心独白必须写声音主体、类型、`{完整文本}` 以及“画面人物不开口”。`【】` 是字幕源标识，禁止代替 `{}` 进入实际视频 Prompt。
- 字幕与人声独立：默认最终 `subtitle_enabled: false`，同时视频调用固定 `video_generation_subtitles: false`；只有用户明确要求字幕时，才在成片阶段按 `subtitle_render_stage: final_ffmpeg_burn` 处理。必须保留全部计划人声，视频画面中禁止模型直接生成逐句字幕。
- 生成后逐句试听；静音、漏句、串角色、类型错误、截断、画外音触发人物张嘴或出镜口型明显错误只记录为内部返修风险和后续用户主动修改时的建议，不自动重生或编辑已返回的可渲染视频。
- 音色资产始终生成并保持稳定；不传音频时由固定文字锚点保底，传入音频时必须使用 多媒体视频（`h3` Ref2VA） 并以该资产为准。

## 动态执行硬门

关键帧只定义若干静态状态，不会自动产生画面发展。实际 Prompt 必须描述状态之间如何变化；变化可以来自人物、其他主体、空间、环境、光线、物件、焦点、遮挡、构图或声音与画面的关系：

- `observable_state_changes` 记录本 SEG 中对观看有意义的可观察发展；条目数量由内容决定，不设最低配额。它们可以是人物行动结果，也可以是空间揭示、环境变化、物件状态、信息可见性、光线/焦点变化或声音引导的观看变化。填写后须在 `compiled_prompt_file` 中对应表达，允许自然改写，不要求逐字粘贴。
- 每镜必须说明观众如何观看，以及画面在镜内如何推进或为何有意停留。人物动作是可选来源；可用 `visual_process` 描述非人物主导的变化，`subject_action` 仅在人物行动构成观看重点时填写。
- 固定机位可以承载人物/环境发展，也可以有意保持静止。静止镜头须能说明停留的观看对象、时长作用或叙事目的；无需人为添加动作、焦点漂移或摄影机移动来证明它“不是静态”。
- 禁止用没有观看意图的空泛定格填时长；也不得仅因人物静止就判定镜头无效。确属停顿、空镜或观察镜时，写清其承担的悬念、空间、情绪、信息或节奏作用。
- 多张关键帧不能替代镜头发展描述。逐镜写清起始画面、摄影/画面如何发展、关键观察点及收束状态；没有变化的镜头说明有意停留的理由，不虚构动作路径。

## 表演、声音与色彩编译硬门

第三段不是只写动作的镜头清单。完整模式的每个镜头从唯一 `导演总控卡_ep_N.md` 和十五列分镜提取；轻量模式只从十五列分镜提取。按当前模式已有来源写入：

- **表演**：发生原因、表面策略、内在压力、每拍基准态、一个主要可见脸部动作、目光与一个主要肢体动作、呼吸/停顿节奏、说话前后状态、听者反应及双方尾态和禁止的夸张表演。关键表演镜头按已确认表演谱保留时间段变化，并保证下一拍基准态承接上一拍尾态；AU 只有在同时写出可见自然动作时作为辅助校准。无演员镜头明确写“无表演主体”。
- **声音**：基础环境声保持空间连续，叙事性环境声绑定线索或动作，情绪性环境声只在主观化节点使用；BGM 写清进入、增强、抽离和退出；静默写清被移除的声层和恢复触发；跨镜/跨 SEG 声音桥写清前后范围。
- **色彩**：写当前主辅色、色温/对比、主体分离和光源依据，以及人物认知、关系或危险变化触发的色调偏移；继承色彩脚本规定的跨镜关系。不得把“冷蓝=疏离、暖橙=回忆”当成不看剧情的固定字典。

任何一项在本镜无变化时仍写基准状态，不得空缺或用“同上”。同一表演指令不得同时要求互斥反应，例如“强忍不哭”与“泪流满面”；同一声音频段不得让对白、强拟音和 BGM 同时争夺主体。

声音设计在每个时间轴台词前使用固定格式，`{}` 内使用无标点 `spoken_text`，而语气意图继承带标点的 `display_text`：

```text
声音设计：
- 林晓（VOICE001；25岁年轻女性 声音清亮 普通话标准 略带紧张感 语速偏快）：{什么规矩啊姐}
- 陈默（VOICE002；28岁男性 声音低沉偏冷 平静无情绪起伏 语速缓慢 字句间有停顿）：{欢迎回家}
- 旁白（VOICE003；中性偏男性低沉播音腔 语速平稳 略带悬疑感 句尾微降）：{她打开了门}
```

### 文字符号

| 通道 | 强制符号 | 示例 |
|---|---|---|
| 出镜对白、旁白、画外音、内心独白 | `说话人：{原文}` | `旁白：{门已经开了}`，画面人物不开口 |
| BGM | `()` | (低频弦乐缓慢进入) |
| 环境声、拟音 | `<>` | 门锁转动<金属咔哒声> |
| 逐句字幕源文本 | `【】` | 仅用户明确要求字幕时，从已确认 `speech_lines` 派生为【门已经开了】供成片 SRT；可在第五段声明其为后期字幕源，但必须明确视频模型不渲染 |
| 标题、章节、时间地点等画面文字 | 中文双引号 `“”` | 黑屏中央出现“十年前” |

同一内容默认只进入一个声音或画面文字通道。默认无字幕；只有用户明确要求字幕时，才在成片阶段生成无标点 SRT，且它不属于视频模型画面文字；`{}` 中的人声照常生成。只有用户明确要求气泡对话等剧情内文字时，才允许同一句同时作为人声和画面文字。

## 可选叙事过渡

可按剧情选择短黑屏、暗场、环境空镜、物件特写、声音先行或声音延续，承载时间跳跃、章节转换、记忆和内心活动；不是每段必用。黑屏/暗场必须写时长、叙事职责和进入/离开方式，不能替代应拍剧情。时间、地点或章节提示使用 `“画面文字”`，旁白或内心独白使用 `{人声文本}`；默认不生成逐句字幕，只有用户明确要求字幕时才留到成片阶段生成无标点 SRT。

## 不同场景类型的交付包侧重点

所有类型仍使用同一份五段导演交付包，只调整第三段逐镜时间轴的重点：

| 场景类型 | 交付包重点 | 注意事项 |
|---|---|---|
| 对话戏 | 建立轴线、视线匹配、说话动作、倾听反应和策略变化 | 不执行“每句台词一镜”；只有说话权、策略或反应发生变化时切镜 |
| 动作戏 | 起势、位移、接触/落空、受力反应和结果，保持屏幕方向 | 复杂动作拆成可验证拍点，不能让一个镜头承担过多并行动作 |
| 情感戏 | 眼神、手部、距离、停顿、呼吸和光线变化 | 微表情不是唯一信息载体；用动作、空间和声音共同表达 |
| 悬疑戏 | 遮挡、POV、失焦/对焦、线索可见性和信息克制 | 公平线索先出现，不用镜头效果直接替代谜底铺垫 |
| 爽点/反转戏 | 压力累积、证据出现、对手反应、权力关系变化和结果停留 | 慢动作、特写或定格只在强化结果时使用，不机械套用 |
| 空镜/转场 | 场景固定锚点、天气、光位、环境变化和声音桥意图 | 有图片锚点用 图生视频（`h3` I2VA），无媒体输入可用 纯文本视频（`h3` T2VA）；无角色不等于无叙事职责 |

## 视频重生成编辑合同

## 单 SEG gen.json 最小样例

`tools/video/h3.py` 必读 `--gen <gen.json>`：

```json
{
  "model": "MiniMax H3",
  "duration_s": 12,
  "seed": 0,
  "mode": "I2VA",
  "inputs": [
    {"kind": "image", "path": "episodes/ep_1/02_资产/CHR001_林远_身份图.png", "role": "identity_reference"},
    {"kind": "image", "path": "episodes/ep_1/04_视频片段/FRM/FRM003_tail.png", "role": "previous_tail_as_start_frame"},
    {"kind": "audio", "path": "episodes/ep_1/02_资产/VOICE001_林远_样音.wav", "role": "voice_input_reference"}
  ],
  "extra": {
    "workflow": "<AutoDL workflow id>",
    "base_url": "https://autodl.art",
    "resolution": "768p横",
    "options": {},
    "poll_interval_s": 10,
    "timeout_s": 1800
  }
}
```

- `extra.workflow` **必填**，是部署侧事实（AutoDL 上的 ComfyUI workflow id），按实际接入填写；缺失时 `h3.py` 直接报 `BackendError` 退出。
- `inputs[]` 按 `kind`（`image`/`video`/`audio`）分组，数组序即槽位序（`ref_image_N`/`ref_video_N`/`ref_audio_N`）；`role` 与交付包中的职责、H3 成稿中的参考标记必须一一对应。
- `inputs[].path` 相对路径按**项目根**（运行时 cwd）解析；http(s) URL 原样传递。
- `mode` 写该镜经 `h3-prompt-writing` 判定的模式；`duration_s` 必须与交付包和成稿的时间轴总长一致，且不超过 15 秒。
- 该文件路径登记为 `segments[].gen_file`；同批次内每个 SEG 一份，不合并。

## 第二部分：生成后抽帧与连续性

本部分只适用于完整模式的分段视频。轻量模式只有一个最终视频，不创建 FRM、接缝窗口或 `continuity_ep_1.json`，生成结果直接按字幕策略进入最终交付；第一部分步骤 10 的抽帧与连续性流程对轻量模式不适用。

当一个 `SEGxxx` 已由 纯文本视频（`h3` T2VA）、图生视频（`h3` I2VA）、多媒体视频（`h3` Ref2VA） 或 视频重生成（`h3`） 生成、保存并交付后读取本文件。本文件是 FRM 和 observed SEAM 内部记录的唯一权威，负责从实际视频提取首帧、场景锚点帧和尾帧，为场景连续性、下一片段承接和用户主动修改时定位提供证据。KF 是生成前目标，FRM 是生成后事实；本部分不是阻断交付的最终质检门。

`KF 关键帧目标`负责生成前计划，`FRM` 只记录生成后的实际画面。

### 权威引用

本文件第二部分只适用于完整模式的分段视频。轻量模式不创建 FRM、接缝窗口或 `continuity_ep_1.json`；生成后的唯一视频直接按字幕策略进入最终交付。

- planned seam、镜头计划和资产需求：`storyboard.md`。
- 视频请求、真实输入和 Prompt：`video.md`。
- FRM、双侧帧窗口、实际片段内部记录和 observed seam 由本文件唯一规定。
- 路径、命名和 `continuity_ep_N.json` schema：`manifests.md`。
- 重试预算与缺陷编号：`troubleshooting.md`；成片消费 verified cut：`delivery.md`。

### 抽帧目标

每个已生成片段至少保存：

1. **首帧检查图**：验证片段是否从分镜要求的首状态开始。
2. **场景锚点帧**：从场景结构、固定陈设、角色位置和主光最清楚的稳定时刻提取；每次明显换场或空间关系变化至少一张。
3. **尾帧**：从最后一个稳定、可解码且无转场污染的画面提取，用于记录本段最终角色、道具、场景、构图、光位和动作状态。
4. **接缝窗口**：对每个相邻片段额外抽取上一段末 `12` 帧和下一段首 `12` 帧，生成逐帧序列或接触表，用于寻找真实剪切点。单张 tail/start 只说明状态，不能证明两段连续。

尾帧不等于视频文件最后一个编码帧。片尾若有黑帧、转场、运动模糊或压缩异常，应向前选择最近的稳定帧，并记录实际时间码。

### 工具顺序

1. 抽帧统一使用 `tools/video/ffmpeg_tool.py`：单帧用 `frame <mp4> <png> [--tail|--at S]`，帧条/接触表用 `strip`。首尾帧使用 `--at 0` 与 `--tail`，任意时间点使用 `--at S`。
2. `frame/strip` 为本地同步执行：命令返回即消费输出文件；不存在 task_id 异步轮询。
3. 接缝窗口需要逐帧精确控制时用 `strip` 按实际帧间隔抽取；先用 `tools/video/ffmpeg_tool.py probe` 取得帧率和精确时间基。输出帧数不足或能力不支持时阻断并返回成片/接缝处理，不得降级到手工截屏。
4. 抽取后必须实际查看。帧模糊、黑屏、遮挡严重或处于转场中时，调整时间码重新抽取。
5. 不使用 参考生图（`img --ref`） 美化原始抽帧后冒充视频真实状态。确需制作“下一段首帧候选”时必须另存为编辑版本，并与原始尾帧同时保留。

接缝窗口按实际帧率抽取，不把 `12` 帧误写成固定秒数。实际使用时先用 `probe` 取得帧率和精确时间基；输出帧数不足或能力不支持时阻断并返回成片/接缝处理，不得降级到其他命令。

### 场景一致性记录

场景一致性由“共享 SCN 布局参考 + 数据卡状态 + 分镜文字合同 + 实际视频抽帧 + 下一段承接 Prompt + 成片复看”共同维持。

每张场景锚点帧记录：

- 场景 ID/名称、所属 `SEGxxx`、时间码和文件路径。
- 空间拓扑：入口、出口、墙面、窗户、家具及固定物相对位置。
- 摄影机：高度、方向、景别、焦段感、轴线侧和主体屏幕位置。
- 光线：主光来源、方向、色温、曝光、阴影方向和环境色。
- 角色：身份版本、位置、朝向、视线、姿态和动作相位。
- 道具：`PROPxxx` 状态版本、持有者、可见面、方向和接触点。
- 下一片段必须继承项与允许变化项。

下一片段 Prompt 必须从该记录复制具体事实，不得只写“保持上一段一致”。

### 尾帧承接

下一片段生成前按 `video.md` 根据真实输入选择视频工具：

- `continuous` 接缝在工具支持图片输入时，把上一片段已保存 tail FRM、全部出场角色身份图和分镜声明为必需的场景、道具/状态图作为实际图片输入；`elliptical` 接缝从新起点所需资产开始，不强制传上一段 tail FRM。本段命中已规划高光 KF 时再传对应 KF，并记录资源 ID、文件路径、顺序和职责。
- Prompt 中使用对应 `<图片N>` 标签，明确每张图采用什么、不采用什么；`continuous` 声明 0 秒承接上一段结尾，`elliptical` 声明通过已确认转场锚点进入新状态、只变化 `permitted_deltas`，两者都逐项保留 `required_invariants`。
- 若需要只推进一拍，可用 参考生图（`img --ref`） 基于原始尾帧制作“下一段首帧候选”，但必须保留原始尾帧并记录编辑范围。
- 若 `continuous` 接缝所选工具不支持所需图片输入，停止并说明能力缺口；返回分镜调整分段或由用户重新选择可接收图片的工具方案，不得静默改成文字降级。`elliptical` 接缝按实际输入正常路由。

### 接缝窗口内部记录

每个 `SEAMxxx` 在两个片段都生成并已交付后记录；它不要求用户逐 SEG 确认，也不阻断已生成视频展示。记录结果用于下一段承接、质量门与剪点选择。关键接缝未验证、窗口不合格或没有安全剪切点时必须阻断合格交付；best available cut 仅限已向用户说明并接受的非关键偏差，不授权自动重生或编辑：

1. 并排查看上一片段末 `12` 帧和下一片段首 `12` 帧，并以 `0.25x` 慢放跨接缝。
2. 标记候选切出帧和切入帧，不默认采用文件最后一帧与第一帧。
3. 先核验 `required_invariants`，再逐项确认变化是否只发生在 `permitted_deltas` 中：角色屏幕位置/朝向/视线、动作相位、运动方向与速度、摄影机运动、道具接触、轴线、光位和环境声不能一律假定为必须连续。
4. `continuous`：连续动作只允许同相位或略微推进，禁止动作完成后回到起势、手部脱离后重新接触、人物跨屏瞬移；未列为不变量的维度也不得无理由变化。
5. `elliptical`：允许计划中的时间、空间、构图、光线、人物/道具状态或声音变化，但必须由 `transition_anchor` 可见地连接，且不得改变未列入 `permitted_deltas` 的事实。按主转场核验：动作匹配检查相位、方向和速度；遮挡切检查遮挡物方向、面积和解除时机；相似构图检查形状、主体位置、视觉重心或色块关系；甩镜检查同向运动、模糊强度和入画落点；视线/物件匹配检查目标或接触关系。
6. 声音桥只能服务已批准的切法，不能掩盖未允许的身份、动作相位或光位错误。

将结果写入：

```text
episodes/ep_N/04_视频片段/质检/质检_接缝_SEAMxxx_SEGxxx_SEGyyy_vNN_ep_N.md
```

至少记录：`SEAM ID`、`上一片段`、`下一片段`、`主转场`、`衔接模式`、`转场锚点`、`不变量`、`允许变化`、`尾部窗口`、`头部窗口`、`候选切点`、`最终切点`、`动作相位`、`屏幕位置与运动方向`、`摄影机运动`、`道具接触`、`轴线与光位`、`声音桥`、`结论`、`修复动作`。

### 命名与存储

抽帧属于视频阶段派生证据，不进入共享或分集资产目录。目录、文件名和 `continuity_ep_N.json` schema 只读取 `manifests.md`；本文件只规定帧的选择、观察、比较和内部记录。`FRMxxx` 保持全项目唯一，时间码来自源视频，重抽时建立新版本。

每个 `start FRM` 对照分镜起始状态；`continuous` 非首段同时对照上一段真实 tail FRM，`elliptical` 非首段对照接缝声明的新起点和保留不变量。`scene/tail FRM` 在当前时间点存在已规划高光 KF 时可绑定该 KF，否则对照分镜状态和数据卡。偏差不等于失败；角色身份、道具因果、场景方向、动作相位或接缝职责变化时，只记录为用户主动修改时的返修定位，关键偏差阻断合格交付；轻微偏差须由用户明确接受。

### 相邻片段首尾并排记录

生成并交付 `SEG002` 及之后每个片段后，`continuous` 接缝把上一段实际 `tail FRM` 与本段实际 `start FRM` 并排查看；`elliptical` 接缝检查上一段结果、新起点、保留不变量和允许变化。两者都与衔接卡、分镜起始状态和项目数据卡核对；本段起始时间点恰好对应已规划高光 KF 时再一并参考该 KF：

| 检查维度 | 通过标准 |
|---|---|
| 人物身份与状态 | `required_invariants` 中的身份一致；状态变化仅可发生在 `permitted_deltas`，且数据卡有有效原因 |
| 人物位置与姿势 | `continuous` 时位置、身体朝向、视线和动作相位连续；`elliptical` 时按锚点与允许变化核验，无计划外跳变 |
| 镜头与轴线 | 景别、机位高度、观察方向、轴线侧和摄影机运动符合预定切法与不变量 |
| 场景与光线 | 仅要求规定不变量连续；允许的 SCN、时间天气、主光方向和色温变化必须符合转场锚点 |
| 道具 | 未列为允许变化的归属、可见面、开合/破损状态和手部接触连续 |
| 声音 | 对白尾音、环境声、拟音或 BGM 的桥接点符合衔接卡；声音变化必须在允许项中 |

逐项结果写入 `continuity_ep_N.json.seams[].comparison`。若身份、位置/姿势、动作相位、镜头轴线、场景布局或关键道具偏差影响剧情、空间理解或已确认导演意图，该接缝不得按合格版本进入交付链路。非关键偏差可作为带偏差候选展示并由用户明确接受。返修/重生仍须遵守用户授权和生成确认。

### 片段与接缝内部记录

- **单片段质量审查**：每个 SEG 生成后抽取 `start / scene（中间代表帧）/ tail`，记录角色面部与 CHR、当前状态与数据卡、道具与 PROP、场景与 SCN、KF 偏差、声音主体与固定 `voice_anchor`。按阻断级/可接受偏差分类；关键问题先解决或向用户明确呈现，不能只写内部返修线索后照常标记 accepted。对 `continuous` 非首段，还必须把入段 SEAM 的 `required_invariants` 逐项在本段 scene FRM 上复核，并记录证据。
- **全片衔接内部记录**：本集所有 SEG 生成并交付后，覆盖全部 `N-1` 个边界，逐一并排比较前段 tail FRM 与后段 start FRM。不得抽样跳过接缝；发现问题只记录责任片段，用户主动要求修改前不调用视频工具。
- 最终成片只按 `delivery.md` 做基础可交付检查并立即交付。

逐 `SEGxxx` 的内部记录至少覆盖：

| 维度 | 记录内容 | 记录触发 |
|---|---|---|
| 剧情完整性 | 片段职责、冲突、线索、回报或收束是否实际出现 | 核心职责缺失 |
| 角色可信度 | 动作符合动机，表情和反应自然，身份稳定 | 身份或关键反应错误 |
| 连贯性 | 内部镜头和相邻片段的场景、位置、动作、道具、光位可剪 | 无法找到有效接点 |
| 情绪传达 | 目标情绪由表演谱中的可见脸部/目光/肢体/声音变化、空间、镜头和节奏共同兑现 | 情绪反向、关键反应缺失或只有抽象情绪词 |
| 视觉质量 | 清晰度、构图、色彩、光影和人体/生物结构 | 影响叙事或身份识别 |
| 镜头执行 | 计划镜头顺序、期望时长和运镜实际可辨；切点按 `cut_tolerance_s` 容忍窗判定（闭区间，默认 ±1.0 秒、`duration_s < 2.5` 秒的镜 ±0.5 秒），超出才计偏差，且只在影响口型、动作衔接或段总时长时升级为失败；模型自发把长镜切碎不判失败 | 关键镜头遗漏或错误 |
| 声音执行 | 原生人声完整，主体、类型、文本、声线和口型职责正确 | 静音、漏句、错人或职责错误 |

### 检查

- 抽帧来自当前采用的视频版本，时间码可追溯。
- 首帧、场景锚点帧和尾帧都已实际查看，不是黑帧、模糊帧或转场污染帧。
- 场景拓扑、固定陈设、光位、角色位置和道具状态已写成可执行事实。
- 下一片段 Prompt 明确继承哪些事实、从哪一个动作相位继续。
- 图生视频（`h3` I2VA） 的 `reference_inputs` 与 Prompt `<图片N>` 顺序一致，且全部是真实文件。
- 原始抽帧与任何 参考生图（`img --ref`） 编辑候选分开命名、分开保存。
- 每个相邻 SEG 均有接缝窗口内部记录；关键接缝的最终切点来自有效真实帧窗口并已验证；无安全切点时不得以 best available cut 或默认文件边界标记为合格。
