# 视频阶段 Ref：生成与人工审查

在项目级故事包、`current_episode` 详细剧本、资产、分镜和关键帧均已确认后读取本文件。本文件负责当前集真实输入、H3 成稿、生成确认、视频执行与可交付登记；工具检查媒体有效性，主 Agent 对照源分镜核对内容并把成品交人工审查。成片拼接、混音和字幕交给 `delivery.md`。当前集达到目标前不得启动下一集工作。

## 权威引用

- 观看与摄影设计：`storyboard-design.md`；时间语义：`storyboard-timing.md`；planned SEAM：`storyboard-segments.md`。
- 每集唯一导演总控卡及表演、声音、色彩、风格方法：`storyboard-design.md`，逐段执行增量见 `storyboard-segments.md`。
- 人物、场景、道具、音色和风格的 approved 版本：`assets.md`；KF 的 approved 版本：`keyframes.md`。
- 批次路径与文件命名、`video_manifest_ep_N.json` schema：`manifests.md` 统一目录。
- 失败重试和返回层级：`troubleshooting.md`；成片、字幕与 SRT：`delivery.md`。

## 当前工具链

`prepare_video.py` 读取本段源文件并派生机器元数据；`h3-prompt-writing` 负责真实模式、媒体映射与成稿；`h3.py` 负责授权检查、提交、恢复、下载、可解码检查和 candidate 登记。工具映射与配置排障才读 `local-runtime.md`，选择委派才读 `delegation.md`。

### 关键帧术语统一

KF 指分镜已规划的高光、状态、构图或执行风险参考，不是逐段必备。continuous 后段使用上一段成品中选定的单个稳定尾帧，作为 `previous_tail_as_start_frame` 真实图片输入；不建帧注册表。elliptical 按已确认的新起点与允许变化制作。

## 执行顺序

正常路径只有以下五步；同阶段规则只读一次，项目事实按本段取材。

1. **取材**：`python scripts/prepare_video.py --project-root <根> --episode ep_N --segment SEGxxx --context`。读取工具返回的当前段分镜原文、导演要求、台词、素材计划及用户锁定项；只补工具明确指出的缺项。需要真实尾帧时先从已交付视频选取一帧。
2. **编写**：将上述已确认源信息一次交给 `h3-prompt-writing`，取得实际模式、真实输入映射与纯 H3 成稿。成稿保留整场观看设计及本段在其中的位置，如实转写已确认切点、摄影起停、停留、画外事件、未展示的反应、完整台词、音色与必要首尾状态；主 Agent 对照源分镜核对一次。直接复用已确认导演卡和分镜，不再重写五段式交付包。
3. **准备**：`python scripts/prepare_video.py --project-root <根> --episode ep_N --segment SEGxxx --request-file <候选请求.json> --prompt-file <H3成稿>`。工具派生段对象、执行客观能力与素材校验、冻结实际请求与 Prompt，并输出确认证据及两表文本；模型不复制镜头表、状态引用、哈希或确认结构。默认写入，`--check-only` 仅用于排查。
4. **确认**：原样展示工具返回的两表，一次 AskUserQuestion 取得本批 `generate`；用 `stamp_confirmation.py --stage video --video --evidence-file <确认证据.json> --episode ep_N --revision <当前版本> --segments SEGxxx --confirmation-id <本次ID> --user-message <用户原文> --project-root <根> --append` 登记。用户确认后立即执行，不重读源码、schema 或旧批次。
5. **生成与交付**：主 Agent 直接运行 `python tools/video/h3.py --project-root <根> --episode ep_N --segment SEGxxx --out <新版本.mp4>`。工具持久化任务、轮询、下载、检查可解码并登记 candidate；成功后立即给用户视频路径。中断使用同一命令或 `--resume` 恢复，不重复提交、不重复登记；用户明确要求重生时用准备工具 `--replace-generated` 与执行器 `--new-task`，须新授权及新输出版本；需要释放主对话时可用 `--submit-only`。全部片段完成后仅跑一次视频阶段 lint 并进入目标阶段确认。

单条命令不强制委派。已通过准备检查不再额外跑 h3 --check-only、全阶段 lint、hash 脚本或 dry-run；执行前的同源绑定检查由工具完成。失败按具体错误修当前项，不因后续尚未生成而反复修聚合覆盖缺口。

## 批次合同

保留直接影响质量与授权的门：当前集上游已确认；逐镜摄影、动作因果、精确台词与声音设计未丢失；真实角色/场景/道具状态与高光 KF 采用 approved 版本；continuous 使用真实尾帧；请求满足工具能力且当前用户已授权。程序校验结构、覆盖、来源和绑定，主 Agent 对照源分镜审校内容，不以 lint 代替创作判断。

每批最多当前集连续 1–2 个输入就绪 SEG。两个独立段分别准备后用 `prepare_video.py --segment SEG001,SEG002 --combine-evidence`（另传 project-root 和 episode）生成合并两表，一次确认。依赖未知尾帧的下段另批处理。无依赖且已授权的同批任务可依次 --submit-only 提交，再逐项 --resume 收取，避免同时修改同一 manifest。详见 `video-batch-confirmation.md`。

## 模型、时长与画幅

模型、片段时长、画幅、批次上限和例外理由直接继承已确认规划与 `storyboard.md`，调用前用 `tools/video/h3.json` 能力档案复核；用户未指定时新批次固定 MiniMax H3，每 SEG ≤ `15` 秒。本阶段不得重选模型、重算镜数或为适配调用擅改时长；片段边界必须落在已确认镜头切换点，画幅只进工具参数、不写进 Prompt。能力与已确认计划不兼容时停止调用并返回规划或分镜，不静默换模型、压缩剧情或突破时长上限。

## 入站连续性

场景与画面一致性由四层控制：

1. **项目数据卡**：SCN 锁定空间拓扑、固定陈设和基础光位，状态时间线记录合理变化。
2. **共享场景参考**：每个主要 SCN 使用同一批准布局图，不在各集重新生成。
3. **生成前 KF**：仅分镜规划并确认的集级剧情高光 KF（术语见「当前工具链」，不承担首尾帧职责）。
4. **下一段承接**：从上一段成品 mp4 提取单个稳定尾帧（`ffmpeg_tool.py frame`），按 `previous_tail_as_start_frame` 真实传入，承接位置、姿势、朝向、动作相位、道具状态、构图、镜头角度和光位。

## 长视频逐段连续继承算法

对同一长视频、同一集的 `SEG002` 及以后每段执行；跨集首段同时读取 verified `EPSEAM`。目标是把“上一段真实发生了什么”转换成“下一段 0 秒从哪里继续”，而不是复制一句“保持一致”。

1. **读取五类来源**：经本集 `asset_usage_ep_N.json` 读取 approved 资产的稳定身份（数据卡文字事实按 ID 定点窄读，读取面合同见 assets.md「资产 JSON 登记」）；上一段已保存视频；上一段尾帧（需要时现场提取）；当前 `SEAM` 的 `seam_mode|required_invariants|permitted_deltas|transition_anchor`；下一段分镜的首态、动作、台词、状态变化和 `reference_input_plan`。`continuous` 缺真实尾帧时停止编译；`elliptical` 不把尾帧设为必需输入，但接缝合同、新起点或必要状态资产缺失时仍返回上游补齐。
2. **对照继承事实**：结合上一段实际尾态和本段计划，核对剧情因果、角色身份与状态、位置/朝向/动作相位、道具归属/接触、场景布局、光位、摄影轴线、声音及未决钩子；只将本段需要的采用事实带入 H3 输入，不另建重复表格。
3. **按优先级比较**：身份、授权、用户锁定项和 `required_invariants` 不能被真实生成偏差改写；上一段真实尾帧决定下一段可见起点；`permitted_deltas` 只允许计划内变化；下一段计划负责从真实起点推进到新状态。若真实尾值与计划值只存在可剪切的小偏差，采用真实尾值作为 0 秒基准并在动作过程中回到计划；若偏差改变身份、因果、道具归属、轴线或未允许状态，不伪写一致，记录冲突并返回分镜调整承接。不得自动重生上一段。
4. **选择真实输入**：`continuous` 把上一段尾帧作为 `previous_tail_as_start_frame`；`elliptical` 不强制传尾帧，按新起点选择角色身份/状态、SCN、PROP/状态、本段高光 KF 和必要风格图。**锚图充分性**：选定尾帧后，逐项对照该 SEAM 的 `required_invariants` 与 `proof_requirement`：凡尾帧画面中不可读出的不变量（多桌/多人布局、群体衣着分布、远景人物、画外陈设等），必须把上一段当前采用版本的场景锚点图作为 `previous_scene_anchor_reference` 一并选入真实输入；该图不存在时先用 `ffmpeg_tool.py frame --at` 从成品补提取。H3 输入说明每张锚图承载的事实：尾帧只承接可见内容，布局或画外主体等事实由对应场景锚点图支持。按工具实际上传顺序登记媒体标记；缺必需输入或槽位不足时停止，返回分镜调整，不得用文字假装已继承。
5. **直接编入 H3 成稿**：首个时间窗从真实尾态继续，保留身份/状态、入点、已确认省略与可见过程、切点、必要尾态和声音桥。只有动作接续确实无法理解或出现无依据的位置/接触变化时才补足路径说明，不把所有动作展开成完整过程。使用本段源导演信息，不再复写五段交付包。
6. **自动登记**：准备工具保存尾帧及输入文件、数据卡 revision、状态资产、顺序和 SEAM；执行器保存任务与实际输出，不另写继承报告。
7. **检查闭环**：生成前对照真实输入与成稿，核对每个承接声明能在对应锚图中实际看到；看不到时改用正确锚图，或明确标为源导演信息的文本约束；两者都做不到时阻断编译，返回分镜。每个“承接”声明不得覆盖锚图中不存在的主体、布局、衣着或陈设。
8. **失败回退**：缺真实证据返回提取尾帧/登记；计划首态与真实尾态不兼容返回分镜改 SEAM；资产版本冲突返回资产阶段；剧情因果冲突返回剧本。不得用“自然衔接”、模糊景别、黑场、强光、声音桥或后期转场掩盖未解决的不变量冲突。

尾帧参考规则（职责枚举与锚图充分性以上文算法第 4 步和「图片输入合同」为唯一权威，此处只列硬门）：

- `continuous` 非首段必传上一段尾帧及分镜声明必需的角色/场景/道具状态图，缺任一必需图片即停止调用；`elliptical` 非首段只传新起点所需图；命中已规划高光 KF 才传该 KF。
- `img --ref` 处理尾帧时原始帧与编辑候选分开保存；只有视频工具真正接收的图片才算首帧参考输入，编辑图不得冒充原始尾帧。
- 单靠文字承接不保证像素级一致，批次确认必须明确该风险。

## 图片输入合同

交给 H3 编写工具的参考必须是真实文件或原样 HTTP(S) URL；准备工具派生 `video_manifest_ep_N.json` 段对象，不新增交接报告；模式、参考用法与成稿一律以 `h3-prompt-writing` 实际返回值为准（强制门见「当前工具链」）。

图片、音色样音均可作为真实参考，不以“缺真实视频”否定参考输入；准备工具校验数量、槽位、时长、标记、路径与能力档，不静默删除输入。校验失败按具体错误修对应源信息或映射，再准备当前段。

真实模式与媒体映射由 H3 Skill 返回，`prepare_video.py` 从源分镜和这些实际输入派生 video manifest；正常路径不查完整 schema 或重填镜头表。

`shot_plan`、`planned_shot_count` 及已确定的摄影过程由准备工具从源分镜派生，不逐镜手填或复制。`motion_family` 等可选索引不参与创作决策；只有 H3 实际返回的模式、媒体映射与成稿需要登记，按真实提交媒体填写：

- `reference_inputs` / `video_inputs` / `audio_inputs` 分别映射本次真实提交的图片、视频和音频；未提交的种类保持空数组，不按数组种类推断模式。
- `voice_inputs` 把已批准音色映射到真实音频输入；Ref2VA 下台词声部有 approved 样音时该映射为强制项（硬门见「人声与文字合同」），音色样音不要求同时有真实视频输入。
- 视频重生成（`h3`）：`video_inputs` 仅含一个待编辑源视频（重生成合同见「视频重生成编辑合同」）。

批次文件的位置、命名与 manifest 引用以 `manifests.md` 为唯一权威。

`incoming_episode_seam` 只在 `ep_2` 及以后各集的 `episode_segment_index: 1` 上必填，结构与 `episode_seams.json` 对应记录一致；它不替代集内 `incoming_seam`。后续集首段的集内 `incoming_seam` 仍写 `START/not_applicable`，跨集状态由 `incoming_episode_seam` 单独承载。

当前 SEG 按已确认 `reference_input_plan` 传必要身份、状态、场景、道具、风格和 KF 图片；同一职责已由登记的充分可见真实承接帧承担时，不叠加全部旧图。`continuous` 非首段必须加入上一段实际尾帧（`elliptical` 不强制）；尾帧承载不了 SEAM 不变量时按入站连续性锚图充分性条款加 `previous_scene_anchor_reference`。

已声明必需的图片是实际输入，不是 Prompt 文本引用。`reference_basis` 与 `reference_inputs` 逐项登记真实文件、职责与 `passed_to_tool: true`；只写资产 ID、source_id 或文字引用而工具未带图，均按未传入阻断。超槽位上限时报告具体职责冲突，返回分镜或参数方案处理；不得自行删必需图、删主体、拆镜或改用户锁定拍法。

`reference_inputs` 按真实调用顺序逐张登记，每项含连续 `order`、稳定 `source_id`、项目内真实文件或原样 HTTP(S) URL、唯一 `role` 与非空 `adopt`/`exclude`（采用/剥离边界，含义同分镜 `reference_input_plan` 同名字段）。图片 role 清单（11 项，drama_lint 按此集合校验）与三类输入完整 role 枚举以 `manifests.md` 为唯一清单，本处不复制；返修/重生动用 `video_inputs`（单源 `source_video_for_edit`，合同见「视频重生成编辑合同」），`reference_inputs` 不设返修角色。`video_inputs`/`audio_inputs` 每项与上条同构（`resource_id` 对应 `source_id`）。槽位上限读 `tools/video/h3.json` 的 `mode_ref_limits`，不得跨模式套用：T2VA 不接受任何参考；I2VA/FL2VA/L2VA 仅图片 ≤2、无音频/视频参考；仅 Ref2VA 允许图片 ≤9、视频 ≤3、音频 ≤3（总文件 ≤12）。

## 片段内镜头与运镜执行

先理解整场观众被允许看见、听见和暂时不知道什么，再按 `SEGxxx` 编译已确认镜头。保留原定视点、画面范围、切点及摄影过程，表达顺序由具体画面决定，不为每镜套同一组动作或解释字段。

- 每个镜头保留已确认的时间区间，镜头时间总和等于片段时长；不能为填满生成时长擅加反应镜、插入镜或运动。
- 切点服从整场观看安排：可以转移注意，也可以延宕、保留未知、让声音先行或停在未反应的脸上。只转写实际选择及必要承接，不要求每次切后都出现新信息或明显变化。
- 已确认的动作省略、画外行动、延迟反应和不反应如实保留。观众能从前后状态、空间关系或声音理解发生了什么即可；只有实际出现无依据的瞬移、接触关系错误或接续歧义时才补路径，不强迫展示起势、接触、反馈和结果全套过程。
- 相邻镜头可以变化，也可以维持相同景别、构图和速度；关系由场内注意力、人物距离与时间感决定，不用类别差异证明镜头设计。
- 真正一镜到底保留同一次连续拍摄，不编造切镜或时间跳跃；摄影机可以运动、停下或一直不动，按已确认设计保留观看时长和画面范围。
- 场景和角色使用稳定名称，使指代可理解；场内共同状态可集中说明，镜头内只补实际变化与执行必需信息。
- 摄影起点、启动时机、路径、速度、停止、停留和最终画面只要已在源分镜确定，就按原意进入成稿；带时间标记的摄影事件保留其时间关系。急推、慢移、稳住或保持固定均可，速度不由 beat 强度或情绪标签自动推导，也不要求每镜有一个主导运动动词。发现已确认摄影过程难以执行时指出具体冲突，不能在转换中自行改写。
- 摄影标签只供内部索引；成稿用能看见的自然导演语言表达原选择，不把类别或词表变成运镜菜单。

## 导演输入与可选交付包

导演输入直接使用已确认整场观看设计、当前段分镜、导演总控卡、素材职责与用户锁定项。包含执行所需的 0 秒起点与入站连续性、主体身份/状态、摄影起停与停留、可见或画外的行动声音、切点、必要尾态和全片禁项；有意不展示的动作或反应同样保留。共同状态只组织一次，交给 `h3-prompt-writing` 编写唯一模型成稿。

不再要求每个 SEG 重写独立五段式中文交付包。已有交付包可以复用；只有源导演信息缺少必要表达、用户要求查看或返修需要时才补充，格式由内容决定。`compiled_prompt_file` 可指原导演卡或可选交付包；H3 成稿始终独立、纯净且真实落盘。

有 approved 音色且实际模式支持音频输入时传真实样音；无样音或模式不支持时采用已确认文字声音锚点，不虚构音频。

## H3 成稿（提交给模型的文本）

**模式判断、参考使用方式、写法、字段结构、参考标记、台词与时间标注一律交给 `h3-prompt-writing` Skill，必须用 Skill 工具实际调用；调用按批进行——每个批次一次调用覆盖本批全部 SEG（1-2 个），同批不逐 SEG 重复调用。** 本 Skill 不复述其模板、字段表和模式选择规则，只负责提供导演决定、登记返回值并核对内容保真。

- **输入（按批一次传入）**：本批全部 SEG 的已确认分镜与导演要求、内容计划时长与 `request_duration_s`、真实素材清单（文件或 URL、职责和顺序）及用户锁定项，逐 SEG 成组、一次调用传入；不预先指定由本 Skill 推断的模式。
- **输出（逐 SEG 回传、各自落盘）**：该 Skill 在同一次调用内逐 SEG 返回模式、输入对应关系与成稿，分别登记进各自的 `video_manifest_ep_N.json` 段对象；每份成稿原样保存为独立的 `提示词_SEGxxx_vNN_ep_N.h3.md`，是该 SEG 经 `h3.py` 执行时读取的唯一文本及哈希对象。成稿须为纯净 H3 正文；允许对应模式的合法锚帧首行及空行，不含导演包、围栏、分隔符或复制说明。
- **产出物校验（硬门，逐 SEG 不漏）**：主 Agent 对照源分镜与整场导演安排核对一次：镜头及切点未被增删，摄影起停、速度与停留按原意保留，画外声音、动作省略和不反应未被模板改成露脸、补拍或解释；已知台词在实际发声块逐字齐全，音色与真实素材标记对应正确。保持固定的画面可以只写保持，已确认的多阶段摄影也不能压成单一运动标签。成稿只含 H3 正文字段，不混入交付包、编译说明或分隔符；必须通过本批实际 `h3-prompt-writing` 调用取得。发现具体内容遗漏、原意被改写或客观格式错误时，只修受影响段，不以同义词差异或缺少某个强动词判退。
- **不自补**：下游转换不补发明剧情、镜头、台词、素材关系或人物反应。源信息已足以理解时允许简洁表达；只有关键观看选择、声音归属或连续关系确实有歧义时，才回到分镜澄清该处，不把未填写模板字段当成缺项。
- **调用时机**：本批已确认分镜、导演要求与真实素材备齐后、请求快照冻结之前，每批调用一次；直接使用源导演卡即可。成稿按自身 `_vNN` 版本保存；单个 SEG 成稿返工时只重新转换该段，分镜计划仅在创作决定改变时修订。
- **失败处理**：`h3-prompt-writing` 报出某个 SEG 上游信息缺失时，该 SEG 按 `执行顺序` 第 1、3 条打回分镜补齐，同批其他 SEG 照常取得成稿、不被阻断；补齐后以该 SEG 单段成一批重新调用。产出物校验失败同样打回重转，不放宽标准。

## 人声与文字合同

- 每个声音主体在 `project_data_card.json.voices[]` 中只有一个当前 `VOICE ID` 和 `voice_anchor`；台词行只存 `voice_id`，lint 按 voice_id 解析数据卡锚点（voice_id 不存在或锚点为空即 error），不维护行级副本。声音描述至少包含年龄/性别表达、音高与质感、语言/口音、语速、停顿节奏、基准情绪和句尾习惯。
- `audio_input_supported` 登记本次是否真有音频媒体输入，必须与 `audio_inputs` 实际内容一致；为 false 只表示本次无音频媒体，不表示视频应静音，原生人声仍由 H3 生成，每句台词按 voice_id 从 `voices[].voice_anchor` 解析同一锚点。
- **wav 音色参考优先（硬门）**：H3 音频参考是**音色参考**而非对口型输入——模型理解样音音色，并让该角色的全部台词都使用这个音色。Ref2VA（当前唯一 `audios_max>0` 的模式）片段中，台词声部只要在共享 registry 或本集采用的 usage 中存在 approved 样音，就必须经 `audio_inputs`（`role=voice_audio_reference`）上传样音并在 `voice_inputs` 完成 `voice_id/resource_id` 映射，lint 以 `voice_audio_input_missing` 硬阻断；文字锚点回退只在两种条件合法：模式物理不支持音频（T2VA/I2VA/FL2VA/L2VA），或该声部没有 approved 样音。
- 上传已批准 VOICE 时，把样音本体（共享 registry 或分集 usage 登记、复用追溯原批准来源）与声音参考职责交给 `h3-prompt-writing` 决定用法：`audio_inputs` 登真实资源、`voice_inputs` 映射 `voice_id/resource_id`，HTTP(S) URL 原样传递、不要求下载副本；已传 VOICE 是音色权威，文字锚点不得冲突；样音只锁声线、不当本句时长证据，禁止为单句台词临时生成音频冒充参考；`qwen3tts_autodl` 仅用于资产阶段样音生成。
- 有任何人声的片段必须先确认 `native_audio_supported: true`；不支持时停止并返回参数确认，由用户决定是否改模型或接受无声/后配方案，禁止自主换模型。
- 有已确认人声时设置 `speech_mode: native_required`，`type` 枚举见 `manifests.md`；每句保存 `voice_id` 与用户原文 `source_text`（只存这一层，带标点阅读面与无标点机器串均现场派生，不入库），用 `delivery_intent / pause_plan / emotion / emphasis_words` 写表演增量（字段结构以 `manifests.md` 为准）。无人声时空数组并标记 `no_human_voice` 或 `ambient_only`，不得为通过生成模板补写词句。
- 四类人声均由视频模型原生生成：出镜对白在同一镜头写“角色名真实开口说出{完整文本}”并驱动口型；旁白、画外音、内心独白写声音主体、类型、`{完整文本}` 与“画面人物不开口”。每条台词去标点后必须逐字进入成稿实际 `<d>…</d>` 发声块，不能只出现在摘要或说明中；导演包源台词花括号不构成 H3 发声格式；`【】` 仅字幕源标识，禁止代替 `{}` 进入视频 Prompt。
- 字幕与人声独立：默认 `subtitle_enabled: false`、视频调用固定 `video_generation_subtitles: false`，禁止模型在画面直接生成逐句字幕；仅用户明确要求时按 `subtitle_render_stage: final_ffmpeg_burn` 在成片阶段处理，全部计划人声必须保留。
- 人工试听发现的静音、漏句、串角色、类型错误、截断、口型问题只作为返修线索告知用户，不阻断当前片段登记与交付，是否返修由用户主动决定。

## 动态执行硬门

关键帧提供静态参考，时间如何经过仍按整场观看设计与本段分镜编译。画面可以发展，也可以保持；不为证明“动态”而添加动作、风、焦点漂移或摄影机移动。

- `observable_state_changes` 只登记本段实际存在且有意义的发展，没有变化时允许为空，不设数量或动作种类要求。
- 成稿保留已确认的观看对象、可见范围和持续时间。画外发生、暂不回应、看不到结果或不立即解释均可成立，不补反应镜或道具特写替观众下结论。
- 固定、慢移、快速运动、长停留和短切均由场内关系与观看意图决定；同一种摄影方式可以贯穿一场，也可以因具体时刻改变。
- 动作路径只有在前后状态实际矛盾、接触关系错误或模型已出现具体连续性失败时才补足。计划中的省略让观众能够理解即可，无需展示完整动作链。

## 表演、声音与色彩编译硬门

从已确认整场导演卡与本段分镜提取执行所需内容，场内共同约定集中表达，镜头内写实际发生的变化：

- **表演**：保留已确认的人物策略、压力、目光、姿态、呼吸与停顿，也保留迟迟不回应或不展示反应的选择。不要求每拍都有脸部动作和肢体动作，不替画外人物补表演；AU 仅在已有自然动作需要校准时使用。
- **对白后的承接**：逐句保留源稿已写的表情、反应或小动作，以及它由谁完成、与台词的先后或重叠关系；这些提示放在 H3 画面/表演描述中，不混入 `<d>` 台词原文。不为省 Prompt 删成人物只说话，也不把每条表演改成独立反应镜或统一慢推。
- **声音**：保留发声归属、空间关系、进入与离开、静默及声音桥。人物可以在画外继续说话，画面无需跟随发声者；具体台词、音色及原生人声规则仍按「人声与文字合同」执行。
- **色彩**：继承场内已确认的光源、色彩关系与实际变化；变化由剧情和场景决定，不把情绪或 beat 标签自动换算成色温、对比或光型。

同一状态无需逐镜重抄，指代可理解即可；不同时间的变化要能分辨。同一时刻避免互斥表演要求，并保留导演确定的对白、环境与音乐主次。

以下仅示范导演源文本的声音表达，已有分镜和 voice_id 足够时不另抄一份。`{}` 内从 `source_text` 现场派生，表演继承原句意图；H3 成稿的发声块、参考标记和时间格式一律沿用 `h3-prompt-writing` 实际返回，不把本示例作为第二套提交模板：

```text
声音设计：
- 林晓（VOICE001；25岁年轻女性 声音清亮 普通话标准 略带紧张感 语速偏快）：{什么规矩啊姐}
- 陈默（VOICE002；28岁男性 声音低沉偏冷 平静无情绪起伏 语速缓慢 字句间有停顿）：{欢迎回家}
- 旁白（VOICE003；中性偏男性低沉播音腔 语速平稳 略带悬疑感 句尾微降）：{她打开了门}
```

### 文字符号

| 导演源文本通道 | 源文本符号 | 示例 |
|---|---|---|
| 出镜对白、旁白、画外音、内心独白 | `说话人：{原文}` | `旁白：{门已经开了}`，画面人物不开口 |
| BGM | `()` | (低频弦乐缓慢进入) |
| 环境声、拟音 | `<>` | 门锁转动<金属咔哒声> |
| 逐句字幕源文本 | `【】` | 仅用户明确要求字幕时，从已确认 `speech_lines` 派生为【门已经开了】供成片 SRT；可声明其为后期字幕源，但必须明确视频模型不渲染 |
| 标题、章节、时间地点等画面文字 | 中文双引号 `“”` | 黑屏中央出现“十年前” |

上表仅用于源稿区分通道，不覆盖 H3 提交语法。同一内容默认只进入一个声音或画面文字通道；字幕默认关闭（字段门随 video_work 条件装载），成片 SRT 不属于视频模型画面文字，`{}` 人声照常生成；只有剧情内气泡对话等明确要求才允许同一句兼作人声与画面文字。

## 可选叙事过渡

可按剧情选择短黑屏、暗场、环境空镜、物件特写、声音先行或声音延续，承载时间跳跃、章节转换、记忆和内心活动；不是每段必用。黑屏/暗场必须写时长、叙事职责和进入/离开方式，不能替代应拍剧情。时间、地点或章节提示使用 `“画面文字”`，旁白或内心独白使用 `{人声文本}`；字幕规则随 video_work 条件装载。

## 视频重生成编辑合同

本地无定点编辑工具。只有已经存在待修改视频，且目标是局部视觉或声音编辑而不是重新生成剧情时，按以下重生成合同执行：

- `video_inputs` 只包含一个真实源视频，并记录资源编号和文件路径；该视频连同修改目标交给 `h3-prompt-writing` 决定模式与参考用法，再经 `tools/video/h3.py` 重生成。
- 编辑指令写明时间范围、目标对象、需要修改和必须保持不变的内容；Prompt 必须明确要求保留原视频人声、原音色和原口型关系。
- 提交前向用户说明本地无定点编辑能力、按重生片段处理；该语义弱于原定点编辑工具。
- 输出建立新 `_vNN`，不得覆盖源视频；重生段按普通新段重新冻结快照、确认并登记。
- 需要增加/删除镜头、改变时长、改变比例、修正剧情因果或重做复杂动作时，不使用 视频重生成（`h3`），返回分镜或重新生成 SEG。

## 视频生成失败处理

失败类型、`V/A/F/S/N` 编号、重试预算和返回层级统一读取 `troubleshooting.md`。本阶段只负责保存旧 Prompt、修改变量、预期改善和实际结果；每轮只改变与证据直接相关的变量。

## 生成后处置：登记与人工审查

生成前发现源分镜、输入或成稿的实质问题先修对应源，不把已知缺陷提交给模型。`h3.py` 成功即表示文件已保存、通过客观视频有效性和可解码检查，并完成 candidate 与工具事实登记。主 Agent 直接给出视频路径，把实际观察到的剧情、身份、口型、声音、连续性或意外文字问题如实说明；人工看片决定是否返修，不自动重生、不另建质量评分或连续性清单。

continuous 下段确实需要尾帧时才提取单个稳定帧。无疑点不重复 probe、全流解码、抽帧条或重跑阶段 lint。

全部片段交付后运行一次 `drama_lint.py --project-root <根> --stage video`，再按目标进行视频阶段或拼接确认；accepted 仍需相应阶段确认。技术检查不能证明剧情、表演或审美通过。

## 请求快照冻结与 stamp 写入面

新段通过 `prepare_video.py` 一次完成源分镜派生、客观校验、请求冻结及确认预览。候选请求只填写 H3 实际返回的 mode、duration_s、inputs，以及用户已锁定 model/aspect/resolution/seed/options/workflow/base_url；音视频参考保留实际探测的 duration_s。输入项使用 kind/path/role/source_ref 与必要的 label/slot/duration_s；数组序即槽位序。

冻结调用 `h3_contract.prepare_request`，保存解析后的真实部署、请求与 H3 SHA。能力、媒体槽位、时长、纯净度、台词与来源不满足时直接报具体错误。HTTP(S) 原字符串直传，冻结仅证明 URL 字符串；本地媒体绑定实际字节。用户确认后更改成稿、参数或本地素材必须重新准备并确认。

局部状态维护按需使用 `stamp_confirmation.py --video-status|--op-append`；直接 `--append` 内部校验、原子写入及回读。正常准备与生成分别由 prepare_video.py 和 h3.py 完成，不要求模型另写日志、候选段对象或确认副本。

视频确认只完整写用户确认台账；生成门与 lint 只读这一来源。SHA、数量、时长与 attempt 由确认命令派生。

## h3-prompt-writing 返回值登记示例

不再要求手工组装完整 video manifest。将实际模式、媒体映射与成稿交给 `prepare_video.py`，由它从源分镜与资产登记派生镜头、台词、状态、连续性、引用和请求。确需扩展特殊输入时才按 `--help` 或具体报错查 `manifests.md`；不得用旧批次对象猜新 schema。
