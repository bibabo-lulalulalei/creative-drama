# 完整分镜交付与内容审校

用于汇总、核算和 SEG 执行设计完成后的整集交付。创作中的十五列候选只需本镜实际内容，先按逐场接口保存。

## 完整分镜表（用户确认门面）

每集只落一份 `episodes/ep_N/02_分镜/分镜_完整分镜表_ep_N.md`，同时承担内部制作表与用户确认门面，不再另建分镜阅读稿。文件结构固定三部分：审查门面（`## 第X集：[可读标题]` → `### 本集故事提要`（一段话：主线/冲突/高潮/钩子）→ 每章 `### 第N章：[章节名]（本章时长 / 起止）` 配一行叙事功能引用 → 每片段 `#### 片段N：起止时间（含镜数）` 导航）→ 十五列完整分镜表（逐镜行就是用户审查的镜头列表，不另写散文版镜头行）→ 文末两个确认附录。门面文字不展示内部 JSON、哈希、字段名或校验结果。

- 章节按照剧本的章节与场次映射排列，不能只写“第一章、第二章”的空标题；可保留自然语言章名、片段名和故事提要，但不得省略完整镜头列表，不得用参数确认表的剧情预览替代正式分镜。
- 片段起止时间一律写引擎 `pack` 校验与写回后的内容计划值，不按 15 秒填满。单段请求时长遵守 `tools/video/h3.json` 的实际能力范围；内容时长与技术尾余量分开，无法合法承载时返回设计重划。
- 镜头按整场观看确定后再分组；时间首尾相接并覆盖内容计划，不以片段为单位凑镜数。
- 标题、品牌字、时间地点等画面文字用中文引号 `“”`；字幕源使用 `【】`，只在用户明确要求字幕时登记，并明确不由视频模型渲染。
- 文末固定附两个确认附录，均由 `pack --write` 从当前 `storyboard_ep_N.json` 同源渲染、不手工另写：`## 附录 A：剧本节拍去向` 渲染 `beat_coverage`，逐条列节拍、处置和真实目标镜头；已确认源不允许靠覆盖表删戏，须先返回剧本修订确认。`## 附录 B：资产使用摘要` 渲染 `asset_usage_plan`，逐条列资产、类别、版本与绑定片段。附录与完整分镜随同一确认门提交，不另建文件。

详细分镜保留十五列；只写本镜实际需要的信息，未使用项写“无”，场内已建立的稳定基准可直接引用，不重复长篇描述。本表与参数确认表预览表职责不同，格式不得互改。

## 十五列逐镜要求

### 各列要求

逐场候选沿用下面的创作要求，时长/视频片段先写“待核算/待分组”；全集汇总并 allocate/pack 后再写正式时间与 SEG。完整交付的故事提要、章节导航和附录在汇总后补齐。

- **场次**：稳定 ID 使用 `E{集号}S{场号}`，并保留剧本中的人读编号。
- **视频片段**：稳定 ID 使用 `SEG001`、`SEG002`；同一片段内镜头总时长不得超过所选模型上限。
- **镜号**：稳定 ID 使用 `E01S01-SHOT001`，末尾序号在当前场内连续、不重复、不跳号。
- **镜头职责**：说明这次观看的作用，可是信息、关系、空间、压力、主观感受或时间体验；无需每镜证明新增事实，也不把抽象“推进剧情”当作选择依据。
- **时长**：写绝对起止时间和本镜持续秒数，与台词、动作、停顿和切点匹配。
- **画面描述**：写本镜实际看见的主体与连续过程；空间或动作有误读风险时补位置、方向、接触和阶段，不要求单镜演完完整动作或戏剧链。
- **景别**：明确大特写、特写、近景、中景、全景、远景、大远景、过肩或 POV。
- **机位/角度**：明确摄影机高度、观察方向、主客观视角和镜头感。
- **光影氛围**：继承本场已确认光源与风格基准，只写必要变化；不为填列新增天气、时辰或情绪变色。
- **对白·旁白**：写明说话人、声音类型和完整文本；用户文本逐字按原顺序保留。
- **音效**：环境声和拟音使用 `<具体声音>`，BGM 使用 `(具体音乐)`，写清进入、持续、淡出或承接时机。
- **摄影过程**：写清画面如何开始、变化、结束；按需描述机位路径、朝向、运动质感、焦点变化、停留与剪切。多阶段设计按时间顺序完整表达，不强行归并成一个运镜标签；复杂执行可为关键起停或交叉点标局部时间。
- **切入/切出动机**：用自然语言说明为何此刻换看、后镜怎样接住；`cut_motivation` 可选，若填按既有枚举，不为归类而设计切点。
- **连续性要点**：记录屏幕位置、视线、轴线、动作方向、道具状态、光位、环境声和台词尾音。
- **承接要求**：说明生成前关键帧目标与下段 tail FRM 承接义务；不规划生成后抽帧时刻，尾帧在视频阶段按需提取并登记 `reference_inputs`。
- 同一片段内相邻镜头形成可理解的观看关系，不要求更换运镜类别。保留整场设计中的可见/可听过程或有意停留，不凑变化次数。片段边界落在镜头结束处，下一片段从新镜头开始，不重复上一片段已完成动作。

## 分镜内容人工复核

完整候选先保存，再按一场连续观看顺读源剧本与实际分镜。暂时忽略 SEG 标签、摄影术语和表格列，想象观众先看到/听到什么、此刻在等什么，注意力与情绪如何来到下一镜：切得太早、反应被解释过满、不断重新开场或没有理由的运动，会在连看时显露。

接着核具体断点：空间、视线、运动方向、动作相位与接触是否可理解；摄影机为何起动、如何连续经过、为何停；等待/停留中实际在经历什么，过程估时与发声是否可信。对照源稿核 `compressed`/`moved` 事件是否保真、世界感官细节是否矛盾、台词指称在当前语境是否可理解；有意保留的未知无需补解释。必要事件、逐字台词和用户意图仍由源版本约束，不以“更有电影感”改写。

只修发现的设计或时间问题，受影响时重跑 allocate/pack，再连看相关整场。无需逐镜证明新信息、强制反应或填写通过清单。完成复核、无未解决问题后直接执行：

```bash
python scripts/stamp_review.py --project-root <项目根> --episode ep_N --i-did-the-review
```

命令内部做结构检查并绑定源、设计和时间输入指纹，`content_review` 不手填；无需先运行一次无旗标预检或额外全阶段 lint。报错修具体项，设计改变后重看受影响整场再盖章。结构通过只证明声明一致，不能证明情绪、摄影物理或审美成立。

## 存储与阶段确认

正式交付保存到当前 `ep_N` 分镜目录；本节用于完整候选完成内容复核并盖章后的阶段确认。

通过后状态进入 `awaiting_confirmation`，展示用户可见完整分镜 Markdown 和简短镜头方案说明，使用真实可访问路径；不展示哈希、机器字段或内部检查报告。请求用户明确确认；收到修改意见只修分镜，修改设计/时间/接缝时重看受影响整场并重新盖章。明确确认后才进入 `keyframes.md`，不提前生成媒体。
