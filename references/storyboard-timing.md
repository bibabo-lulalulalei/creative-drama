# 分镜时间与源处置

模型声明实际过程、演读估计与先后关系；程序只核算，不寻找最短排程或填满生成容器。

## 节奏设计

节奏来自观众如何经历事件、等待、证据、反应与摄影过程。先写拍法再估过程，不用规划估时分配场次或镜头额度；beat_type、intensity、speech_pace 都是可选注释，改动它们不改变时间结果。

### 时间推导与真实约束

规划估时是设计前预测；内容计划时长是本次设计的累计估计；请求时长是接口申请长度；媒体实测时长只来自实际文件 probe。累计值不得称为“真实需要”或摄影物理证明。初估偏差不触发准出错误、分数或免责说明，也不自动覆盖已确认 planning。

用户未限定时长则保留初估记录，更新 episode 的 planned_content_duration_s 并展示当前设计计划。真实 exact/target_band 合同由确认 ID 回溯，在独立约束核对层说明冲突，不反推逐镜预算；确需改内容/拍法或目标，由用户按既有流程取舍，不自动压短。

### 源覆盖与先后并行

非人声过程可回指 beat、chain 或 asset_state；after 固定表示本事件开始不早于引用事件结束，可跨镜。程序核声明的依赖、环和引用，不能猜未声明的物理互斥。空隙、有意等待、静止观察不自动删除。具体估计是否可信，回到本次摄影与表演顺读审校。

### shot 机读字段

具体时间输入与派生字段见 `manifests.md` 的 rhythm_input/storyboard 对应字段合同；摄影叙事保存在正文，不为可选标签制造时长或镜头。

## 对白时长预算

所有实际人声都回指稳定 line_id，以本次演读的导演估计或实存本句音频测量登记为 utterance。估计含本次设计的呼吸/停顿，不自动加固定起势/句后秒数；音色样音不是本句时长证据，不为估时调用 TTS。

speech 与动作、摄影、阅读、反应根据已形成设计安排先后或并行，每镜取最大结束点；不把它们一律相加。连续一句跨镜分片须恰好覆盖完整 utterance 且在集绝对时间首尾连续，不逐镜重启或补停顿。优先避免跨独立 SEG 拆连续发声，确需跨 SEG 时要有真实可执行声音承接方案。

无人声、环境声、静默和无 BGM 都合法；不以人声占比、汉字速度或单句字数判空转。已确认台词逐字保留，窗口不足返回具体设计，不加速或删字。人声主体、类型和口型职责保持原合同；导演包可用现有花括号表示源文本，H3 的实际发声块以并列 Skill 为准。

## 片段与时长

- 镜头内容时间由同源过程累计，不要求等于规划初估。各镜头内容区间按正式顺序相接；镜内过程可以并行或有意留空。
- SEG 是一次生成容器；内容时长保留小数，请求时长按 h3.json 的整数能力承载，tail_handle_s 记录差值。余量只延续既有末态，不补戏、不延长或重复台词。
- 合法组边界由导演确定；超能力即报告具体冲突，保留原设计，不自动切镜、重排、改语速或换模型。

## 汇总核算

### 节奏流水线（rhythm_input → 引擎 → 写回）

`rhythm_input` 中的过程、语音估计、先后与组边界由导演创作，`kind` 只用 `visual|speech|camera|hold` 全称。逐场通过 `storyboard_draft.py save` 保存、全场 `assemble` 仅合并既有设计并复制真实源身份，不替模型创作或估时。已有标准输入可直接沿用；输入齐备后在 **skill 根目录**依次执行，项目路径走显式 `--project-root` 绝对路径：

```bash
python scripts/rhythm_engine.py allocate --project-root <root> --input <input> --storyboard <storyboard> --write
python scripts/rhythm_engine.py pack --project-root <root> --input <input> --storyboard <storyboard> --write
```

allocate `--write` 写派生镜长/区间/依据并同步十五列时间，先于 pack；派生结果漂移时 pack 拒写，不改镜内设计。第一次 pack 创建真实 SEG 骨架并把身份同步到十五列；按 `storyboard-segments.md` 补该段执行设计后，再运行同一条 pack 命令，同源写回已明确的资产使用聚合和附录 A/B。未填写参考计划时程序保留未知，不生成虚假空计划或资产对账。

任何错误不部分写回。`shot-count` 只用于实际需要查镜数或源引用时。组设计未变，pack 保留已有执行字段；组内容/摄影/时间变化则按真实依赖失效，不能只凭 SEG 序号继承旧 KF、输入、审校和绑定。是否完成内容复核仍由导演判断，核算不代替它。

## 源事实与覆盖

### 世界事实承接合同（inherited_world_facts）

`storyboard_ep_N.json.inherited_world_facts` 从已确认源剧本投影季节、节日、时辰、天气等物理事实，`assemble` 负责原样复制，不要求模型重抄。源缺必要事实时返回剧本修订；模型显式填写而与源冲突时拒绝合并。字段结构以 `manifests.md` storyboard schema 为准。

- 分镜表与总控卡中任何季节/天气/温度/时辰/节日感官细节必须能引用本表一条；lint 强制本表存在且要素齐全，语义矛盾由顺读语义审校拦截。

分镜中客观呈现的季节、天气、温度、时辰和节日均须有源依据；无出处则删除该细节或回剧本确认。把“夜凉”等文学感官描写落实为霜、雨或其他具体视觉元素前，核其是否与源世界事实一致，不把文学比喻扩成未确认物理事实。

### beat_coverage（节拍去向）

`storyboard_ep_N.json` 顶层必须登记 `beat_coverage`：剧本每条动作/事件的去向，并渲染为分镜表附录 A 随同一确认门提交。

字段与样例以 `manifests.md` 的 `beat_coverage` 为唯一清单，本处只补创作判断：

- `disposition` 只允许 `kept/compressed/moved`，必须给真实 `target_shots`。删除已确认事件先返回剧本修订源版本并重新确认，再按新源生成覆盖表；不设可用一般剧本确认解锁的 `dropped` 捷径。
- **过渡性动机动作**（解释角色为何在某处、某状态的动作，如小解、添灯、拢火、栓门）默认保留，或 `compressed` 为视觉提示——不推动冲突却支撑观众理解空间与动机，拆节拍时最易被误删。
- 全剧剧情靠本表核销：每条剧本 beat 有登记行并与已确认 script.events 双向对账；全部目标须在时间项以 source_refs 回指源事件，无登记即漏拆。
