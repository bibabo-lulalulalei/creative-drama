# 分镜阶段 Ref

完整模式在项目级故事包、`current_episode` 详细剧本和当前集资产分别取得用户确认后读取本文件。本文件是镜头规划、运镜阈值和 planned SEAM 的唯一权威。本阶段只处理当前集；不得在当前集达到目标前提前制作后续集分镜。轻量模式在规划页取得视频生成授权后读取本文件，只把已确认的最多 `8` 行简洁预览扩充为与完整模式同列定义、同填写标准的内部十五列详细分镜，用于逐镜编译视频 Prompt。

## 本 Ref 关键要求

- 分镜只规划镜头、片段、连续性、已确认资产编排和关键帧需求，不生成关键帧、视频或最终 Prompt；正式分镜覆盖当前确认范围内全部剧情。
- 阅读稿结构、`density_profile` 选择与镜数推导：见「用户可见分镜阅读稿」「动态镜头数量」。
- 关键帧总量与选点（`kf-count` 公式、不规划首尾帧）：见「关键帧需求决策」。
- `reference_input_plan` 数组、锚图充分性闸门与 `asset_usage_plan` 对账：见「视频参考输入计划」「资产使用对账（asset_usage_plan）」。
- planned SEAM 是生成前目标；真实 FRM、observed seam 和剪切点只能在视频阶段记录。
- 元规则（数值与公式）：本文件所有数值示例必须差异化并标注「数值仅演示格式」；凡可用公式表达的数量/时长，正文给公式 + 引擎子命令 + 白话说明，示例必须展示引擎调用而非手算结果；节奏计算常数一律引用《节拍类型库》（`references/节拍类型库.md`）§5 参数名，不在本文写死第二份。

## 目标

把 `current_episode` 已确认的完整剧本和当前集采用资产逐场转换为可直接指导视频生成和生成后抽帧的分镜交付包。正式交付必须覆盖当前集全部剧情，不得只提供样例、部分镜头、简略提纲或夹带后续集镜头。

本阶段只规划镜头、片段、连续性、已确认资产编排和关键帧需求，不生成角色图、场景图、道具图、音色、关键帧或视频。必须引用 approved 人物/状态、场景、道具、音色和 `STYLE001` 全局 moodboard；完整模式每集必须按 `kf-count` 公式算出的张数区间规划高光 KF，同时说明为什么这些时刻值得成为关键帧，规划视频必需图片职责和生成后 FRM 抽取职责。

每集唯一导演总控卡锁表达策略并解释“为什么这样看、如何剪、如何连续”，分镜主表写“观众看到什么”；最终视频 Prompt 只在 `video.md` 编译。分镜阶段不得写伪最终 Prompt。

分镜阶段只能继承已确认视觉锚点；`style_contract` 缺少可执行风格机制时必须停止并返回 `planning.md` 补齐、递增 revision 和重新确认，不得在分镜阶段自行补选风格。已确认风格存在但需要诊断漂移时，才读取 `电影大师风格库.md`，且只用于解释和校准原有光线、色彩、构图、材质和节奏机制。本文件规定事实、交付结构和执行边界；边界内的镜头职责、观看方式、摄影和剪辑由导演针对当前内容独立设计，不把示例或分类当作必选方案。

写具体分镜时，先执行本文件、`scriptwriter.md`、`assets.md`、`manifests.md` 和 `control-contracts.md`。四个创作参考库只读取与当前分镜问题直接相关的部分：用 `剧作方法与类型库.md` 校准场景功能、攻防关系、信息释放和必要场面；用 `题材亮点与传播库.md` 校准开场钩子、反转、爽点/泪点、传播句和片段节拍；用 `题材受众库.md` 校准观看焦点、情绪回报、平台观看场景和表达禁区；用 `电影大师风格库.md` 校准光线、色彩、构图、材质、声音和节奏机制。不得因分镜阶段读取候选库而改写已确认剧情、结局、人物身份、受众定位、风格合同或资产版本。

## 输入条件

必须具备：

- 已确认并存入 `01_剧本/` 的 `剧本_全局设定与分集总纲.md`、全剧完整剧本和 `项目_事实与假设.md`（读取其已验证事实、未知项、推进假设与项目惯例分栏，分镜不得与其冲突；发现冲突时返回剧本阶段修订）；合并文件必须同时包含“全局故事圣经”和“分集推进总纲”两章。另需已确认并存入 `episodes/ep_N/01_剧本/` 的完整剧本和 `script_contract_ep_N.json`（关系张力与人物状态从 `script_contract.relationship_tension` 和数据卡 `state_timeline` 读取，读取本文件前的输入要求见「输入条件」）。
- 已确认的 `00_制作控制/project_data_card.json`；本集所有出场角色、角色当前状态、需要建立 SCN 的主要场景、已升级为 PROP 的关键/复现道具及声音主体均能解析到稳定 ID 与 approved 当前版本。一次性物件只进入分镜和 Prompt，不要求建立 PROP 资产。
- 已确认且已向用户展示或明确标注复用的当前集人物、场景、道具、音色和风格资产；资产必须来自当前集新增项、共享 approved 库或已完成分集的 approved 复用项，不得引用尚未生成的未来集资产。
- 已确认的项目固定画幅。
- 已确定且已经按 `planning.md` 完成参数确认表的视频模型与片段时长上限；本阶段只继承，不自主切换。
- 用户原始指令、后续修改、原台词、必须出现项和禁用项。

剧本存在未写出的剧情、场次、台词或世界物理事实（季节、节日、时辰、天气、温度）时，返回剧本阶段补齐，不得由分镜阶段猜测。分镜表、总控卡、执行表中出现的任何季节、天气、温度、时辰、节日类感官细节（如霜、雪、雨、暑、腊、三伏、清明），必须能引用 `inherited_world_facts` 中的一条；无出处的世界细节视同猜测剧情，必须删除或返回剧本阶段确认。把剧本的文学性感官描写（如“夜凉”）落实为具体视觉元素时，先核对该具体元素是否与世界事实冲突，再落笔。

上列输入条件只适用于完整模式。轻量模式只读取已确认规划、五列预览、用户原始指令与真实可用素材，然后创建 `episodes/ep_1/02_分镜/分镜_完整分镜表_ep_1.md`。十五列逐镜要求与完整模式完全一致，不能删列、空列或用五列预览代替；扩充只能补足镜头、动作过程、表演、声音、连续性和素材职责，不得改变已确认的故事方向、动作结果、台词、模型、时长、画幅或素材边界。轻量模式不创建项目数据卡、分镜 JSON、导演总控卡、视频片段执行表、连续性账本、参考输入计划或关键帧需求清单，也不新增用户确认门。

## 分镜产物分层

完整模式内部生成唯一导演总控卡、十五列分镜表、视频片段执行表、连续性账本、关键帧需求清单和结构化索引；面向用户展示分镜阅读稿及随阅读稿同批提交的确认文件（转换差异台账、因果链摘要、资产使用摘要，见「用户可见分镜阅读稿」），不点名其余内部制作支撑物、哈希、路径或检查过程。轻量模式只生成十五列分镜表，且不向用户展示。两种模式都不得用参数确认表中的五列分镜预览表/剧情节奏预览表替代详细分镜。

各文档职责：

- **导演总控卡**：拆镜前唯一的导演决策中心，统一锁定本集视觉叙事、核心意象、场面调度、节奏波形、表演、声音与风格系统；不得另建导演阐述卡或强风格系统卡。
- **完整分镜表**：一行一镜，固定十五列，包含镜头职责、画面、声音、运镜、连续性和抽帧承接。
- **视频片段执行表**：一行一 `SEGxxx`，记录模型调用容器、片段内时间轴、切镜触发、首尾状态、承接方式和生成风险。
- **连续性账本**：追踪角色、道具、空间、轴线、光线、动作、声音和世界事实（季节/节日/时辰/天气，全片一致，从剧本继承不得改动）的跨镜头、跨片段连续性。
- **关键帧需求清单**：把已确认基础资产映射到镜头和视频片段，并定义每张待生成关键帧的职责、构图、状态和连续性。
- **转换差异台账**：逐条登记剧本每个动作/事件的去向（保留/压缩/移动/删除及理由），随阅读稿一起提交用户确认。
- **因果链台账与摘要**：`causal_ledger` 登记跨镜头因果链（触发→证据→反应→结果）与可见性合同（内部 JSON）；并渲染用户可读的 `分镜_因果链摘要_ep_N.md`，随阅读稿、转换差异台账、资产使用摘要同批提交用户确认。

## 完整模式工作顺序

1. **拆剧情节拍**：逐场标出钩子、欲望、阻力、策略变化、权力转折、代价、信息差和兑现或悬念。
2. **写导演总控卡**：按本文件“导演总控卡字段合同”锁定本集视觉、意象、调度、节奏波形、表演、声音、色彩、材质、字体/版式和剥离项；后续所有镜头只落实这一个决策中心。
3. **定章节与镜头组（beat-first）**：先按剧本章节/场次职责排出本集阅读稿顺序，再**按剧情节拍把每场的镜头划成"镜头组"**——每组就是一次 4-15 秒的视频生成任务（组目标 8-13 秒、上限 15 秒，作设计指南而非硬规则），组边界放在真实剪辑点（动作单元结束、信息揭示、角色反应、场景切换、声音过门）。**戏剧转折点尽量划进同组**（同一次生成内部连续，不产生接缝）；组间缝落在观众本来预期有切的地方。每场把组声明写入 `rhythm_input_ep_N.json` 的 `beat_groups`（每组 `group_id` + `shot_ids`，schema 见 `manifests.md`）。**禁止先按模型上限把本集切成均长 `15` 秒段再往里填内容**——组划分是导演的剧情决定，不是技术配平。
4. **推导节奏与覆盖方案（填 rhythm_input 并运行引擎）**：LLM 只做语义判断——选择 `density_profile`、列不可移动节点、判断信息密度/动作强度/阅读时间、确定重拍，逐场写节奏卡，逐镜标注 `beat_type`/`intensity`/`spoken_text`/动作单元/反应单元/合并/角色标记，填入 `rhythm_input_ep_N.json`。随后运行 `shot-count`、`allocate --write`（仅按语义计算镜长，不传 `--total` 或 `--segment-budgets`；组内镜长保持 `0.5` 秒网格）。`allocate` 不按总长或已有 SEG 预算修改镜长。镜数、镜时长、极值以引擎输出为准；用户目标只作范围校验，不做配平目标。节奏健康度是诊断，不得触发镜长再平衡。高密度镜头数量依据可见信息事件与职责判断，不由恰好 `15` 秒触发硬配额；不得为镜数拆断完整动作。
5. **写完整分镜表**：一行只承担一个不间断观看位置；显著换机位、景别、视角、时间或信息焦点时拆成新镜；同一组内各镜头首尾相接，总和等于该组时长。组内切换由视频模型在同一次生成内执行（成稿写法以 `h3-prompt-writing` 为准，产出物完整性由 `video.md`「H3 成稿」的产出物校验硬门保证）；高动作镜的摄影过程可按镜内时间标记编排运镜事件（见「运镜与镜头差异化」）。逐镜填写 `causal_role` 主职责；被因果链台账列为反应/结果/证据位的镜头按交叉规则补齐 `responds_to`/`establishes`/`evidence_visibility`（字段与交叉规则见 `manifests.md`，台账推导见下文「因果链台账」）。
6. **切视频片段（引擎 pack 校验）**：运行 `python3 scripts/rhythm_engine.py pack --storyboard storyboard_ep_N.json --input rhythm_input_ep_N.json --write`：引擎校验导演声明的镜头组——组覆盖完整、顺序连续、组时长在 `[4, 15]` 秒且**为整数秒**（视频 API 只接受整数 duration；组时长非整秒时，导演在组边界上做 ±0.5 秒的镜长取舍使组整——这是创作决定，不是算法取整）。`--write` 把 SEG 划分与每镜 `segment_id` 写回 storyboard（段划分的唯一写入路径，手改会被 lint 按 `pack_drift` 重算对账；既有段的 `density_profile`/`tail_mode` 等人工元数据按同 `segment_id` 保留，新段需补齐）。未声明 `beat_groups` 时 pack 直接报错（`beat_groups_missing`，机械装箱路径已废弃）——回到 rhythm_input 各场补镜头组声明。**禁止摊薄镜时长凑满组上限，也禁止为填满上限塞入无关镜头**；组不足上限按真实值，是正常输出。
7. **补连续性和导演控制**：在唯一导演总控卡内明确轴线、视线、动作方向、道具状态、光位、声音桥、动作桥和每个切点的动机。
8. **规划关键帧、输入图和抽帧需求**：先登记 `asset_usage_plan`（每个资产绑定到哪些 `SEGxxx`、为什么，全局资产用 `["*"]` 表示全部片段），再把已确认人物、角色状态、场景、道具、音色和风格资产绑定到镜头，定义待生成高光关键帧职责；先运行 `kf-count` 得到本集张数区间与建议张数（真实峰值数低于下限时先回剧本补强峰值，不得凑数），再从整集选择剧情高潮、信息揭露、动作不可逆点或关系断裂瞬间，映射到对应 `SEGxxx`，写清它为什么是信息峰值或冲突峰值；列出视频阶段必须传入的图片职责、实际传入顺序建议、采用/剥离边界，并列出生成后需要抽取的首帧、场景锚点帧、必要角色状态帧、必要道具状态帧和尾帧。

轻量模式只执行其中与十五列分镜直接相关的步骤：拆剧情节拍、推导镜头与时长、逐镜填写十五列、检查时间连续与每列非空，然后交给 `video.md` 编译 Prompt。不得因此创建上述完整模式配套文件。

除“完整分镜表”及其十五列填写规则外，本文件后续关于导演总控卡、结构化分镜索引、片段执行表、参考输入计划、关键帧需求、表演谱、色彩脚本、连续性账本、SEAM 和阶段确认的文件要求均只适用于完整模式。

## 节奏类型与镜头数量推导算法

对每个 SEG 在拆镜前执行一次，并把结论写入片段执行表和 `storyboard_ep_N.json.segments[]`。不得先决定镜头数再往里填内容。

1. **读取依据**：读取本段剧本目标、完整台词、`viewer_takeaway`、`hook_landing`、不可移动内容节点、用户指定的平台/风格/镜头方式、总时长和相邻 SEAM。先把用户明确要求的一镜到底或剪辑方式锁定，不能由密度规则覆盖。
2. **选择主导负载**：判断本段最不能被压缩的内容是什么。短时间内需要连续给出异常、行动、反馈、证据和结果，且删除任一事件都会削弱观看动力，选 `high_density_short`；意义主要来自说话策略、倾听反应和关系距离，选 `dialogue_emotional`；意义主要来自线索可见性、延迟揭示和等待压力，选 `suspense_build`；意义主要来自连续行为、环境观察、生活质感或余韵，选 `micro_film`；用户定义的规则无法被前四类准确描述时选 `custom` 并写清自定义判断标准。题材名称、平台名称和时长本身不能单独决定类型。
3. **冲突时取舍**：同一段同时命中多类时，选择“若被压缩最先损坏核心证明”的一类作为 `density_profile`，其余只作为执行倾向。例如对白中藏证据时，若观众必须听清攻防才成立，主类仍是 `dialogue_emotional`；若台词只是为连续揭示服务，才选 `high_density_short`。记录采用理由和未采用类型的排除理由。
4. **拆不可移动事件**：把本段写成按因果排序的事件节点，每个节点必须至少改变信息、行动、关系、危险、空间或道具状态之一。再把每个节点拆成不可再分的动作单元：起点、动作过程、接触或反馈、可见结果。一个动作单元只有在改变观察位置、信息焦点或关系时才允许跨镜；为了多一镜把“伸手 -> 接触”无理由切断不成立。
5. **从单元生成镜头**：先为每个需要独立观察位置的动作单元分配一个镜头；说话权改变、听者反应改变策略、证据从不可读变为可读、空间关系或时间跳跃时新增镜头。相邻单元若观察位置、信息职责和动作连续性相同则合并；删除后不损失剧情、关系、信息或连续性的镜头删除。
6. **检查高密度执行效果**：`high_density_short` 是内容诊断，不设置仅在恰好 `15` 秒触发的最低镜数硬门。核对前段信息事件是否可见、动作/证据/反馈是否完整、每镜职责是否有效；缺少真实信息推进时回到内容判断，不增加无功能镜头、不为满足秒数或数量改写节拍。黄金三秒检查按项目已确认观看形态应用，不从总时长边界机械推导。
7. **检查其他类型**：`dialogue_emotional|suspense_build|micro_film|custom` 不追求数量。逐镜执行删除测试和动作完整性测试；若删除镜头会丢失策略、反应、线索、等待压力、空间关系或余韵则保留，否则合并。长镜只有在连续时间本身承担压力、选择或观察价值时成立。
8. **输出与回退**：记录 `density_rationale`、`indivisible_action_units[]`、每个单元对应的 SHOT、删除测试结论和最终镜头数。若时长容不下完整台词、动作和反应，先拆 SEG 或返回剧本缩减非锁定内容；不得提高语速、截断动作或压掉反馈。

### 黄金三秒事件设计

仅当已确认的 `opening_strategy` 明确选用“信息流黄金三秒”机制时参考本节（窗口与首镜参数见《节拍类型库》§5）。不由 `high_density_short` 标签或 H3 15 秒技术上限自动触发；三事件是可选开场诊断，不是固定镜数/节拍配额：

1. **事件一，给出异常或承诺**：让观众在首镜看见或听见一个具体事实，知道“哪里不对、谁有风险或这次会看到什么”。不得只用标题、滤镜、空镜或音效假装钩子。
2. **事件二，让主体采取行动或暴露目标**：主体必须因事件一做出可见动作、语言策略、视线选择或位置变化，使观众知道谁被卷入以及他想做什么。
3. **事件三，给出反馈并改写观看关系**：对手、环境、证据或道具回应主体，使信息差、权力、危险、焦点或空间关系至少一项变化；这一步同时构成前 `3` 秒内的有意义切镜或镜内观看关系变化。

采用时可把真实事件写入 `opening_event_chain` 并绑定时间范围、SHOT、前态、事件和后态。三个事件可以落在多个镜头，也可在连续镜头运动中完成；不得把同一事实的重复特写、文字卡加音效或纯景别变化算作不同信息。若机制不适合本故事，按 opening contract 的真实首个叙事节拍设计，不为通过公式压缩台词或制造事件。

## 节奏设计

节奏不是随机，而是时长分布由 beat 情绪驱动、切换点对齐注意力波峰。本节把 planning 的 `rhythm_design` 波形与 `1-5` 强度序列落到段与镜：每镜基准值由引擎按《节拍类型库》强度锚点在生效区间内插值得到（蓄压类强度越高越长，惊吓/切口类强度越高越短），不手算。本节不新建集级结构——开场节拍归 `opening_contract`（`high_density_short` 另按黄金三秒事件链），集尾归尾态选择算法；本节数值规则与本文件其他条文冲突时，其他条文优先。

### 分场节奏卡（rhythm_card）

每场开写分镜前先定调，填四行节奏卡，写入 `rhythm_input_ep_N.json` 对应 scene 的 `rhythm_card`：

1. **波形（waveform）**：本场情绪波形（如「蓄压 → 刺点 → 回落」）；
2. **主重拍（main_accent）**：本场唯一主重拍镜头（shot_id）；
3. **最快拍（fastest_beat）**：本场最快拍镜头（shot_id）；
4. **最长拍（slowest_beat）**：本场最长拍镜头（shot_id）。

规则：

- 先定调再填镜头：节奏卡在逐镜标注之前完成，禁止列完镜头再补卡。
- 卡内必须声明本集 beat 校准：本场（或本集）需要偏离库默认区间时，把校准写入顶层 `beat_duration_overrides`（三层优先级见「beat 类型核心速查」）；不声明就按风格档案/库默认执行，不允许第四套私设区间。
- **对账**：卡声明的 fastest/slowest 会由 lint 与引擎 `stats` 实际输出的最快/最慢 `3` 镜对账，声明落空即 warning——节奏卡是承诺，不是装饰。

### 段级结构

- 段首镜时长按 seam 类型分流：`elliptical` 或动作已完整收尾的 `cuttable_completion` 边界，段首镜可偏短（`1.5-3` 秒）接住钩子；`continuous_motion` 边界的段首镜时长由完成被切出动作的剩余相位与结果反馈决定，不得为追求短镜截断完整动作单元。
- 段尾镜按钩子落点定：悬念收尾用揭示长镜，情绪收尾用余韵镜。
- 设计目标（非硬规）：开场段与高潮段的整体平均镜长应短于铺垫段。
- 集尾留扣：在情绪最高或最意外处短促切断属于"未完成动作结尾"例外路径，须在 `tail_selection_reason` 或转换差异台账中登记；未登记例外的最终 SEG 仍默认 `stable_hold`。

### 段落镜数与时长分布

1. 段内镜数由动作单元/反应单元/合并的真实计数决定，并用校验式对账：**实列镜数应等于 Σ动作单元 + Σ反应单元 − Σ合并**，由 `shot-count` 对账。高密度提示不构成额外最低镜数配额。
2. 段内镜头时长不得全部相同；相邻镜头时长差 ≥`0.5` 秒的组合至少出现一次，且 ≥`3` 镜段的段内时长极差（最长减最短）不得小于 `1` 秒（`health.segment_min_range_s`，以《节拍类型库》§5 为准）。无 beat 依据的微小抖动不算变化。内容确实需要均匀节奏时，可在 segment 的 `rhythm_uniform_exempt_reason` 记录原因；豁免不依赖运镜类别。
3. 全片镜头时长至少落在 `3` 个不同区间（短 <`2.5` 秒 / 中 `2.5-4.5` 秒 / 长 >`4.5` 秒），且任一 `2` 秒宽度时长窗内镜头占比不得超过 `70%`（`health.flatline_window_s`/`flatline_max_share`）；含快节奏节拍（《节拍类型库》§4 `fast_pole_capable=yes` 的惊吓/动作/切口类，是否触发只看库显式标记）时最短镜 ≤`3` 秒（`health.fast_pole_max_s`），总时长 ≥`5` 分钟的片子最长镜 ≥`6` 秒（`health.slow_pole_min_total_s`/`slow_pole_min_s`）——节奏极值锚：快极与慢极都必须真实存在并各有剧情归属，缺任一极即分布扁平。以上阈值均以《节拍类型库》§5 为准，由引擎 `allocate` 自检与 lint 复核执行，不靠口算。完整模式且总镜数 ≥`4` 时适用。
4. 镜数推导约束与演算例：段内各镜按《节拍类型库》基准区间下限累加不得超过段预算（`shot-count` 一并输出本项校验），塞多了拆段或回剧本删内容，不许压扁；长区间 beat（悬念/余韵）堆叠时实际镜数上限随之收紧；单段镜数达到 `shot_count_risk_threshold` 即触发生成端合并相邻镜/丢弱镜风险提示，批次确认中标注。校验式演算例（数值仅演示格式）：13s 段 3 个动作单元 + 1 反应 − 1 合并 = 3 镜（5.5+3.5+4）；11s 段 4 个动作单元 + 1 反应 − 1 合并 = 4 镜（2.5+3+2.5+3）；9s 段 4 个动作单元 + 0 反应 − 0 合并 = 4 镜（2+2.5+2+2.5）。
5. 连续 ≥`3` 个 SEG 镜数相同视为段落级节拍器；允许例外但需在转换差异台账（beat_coverage）说明理由。
6. 时长赋值禁项：禁止以「段总时长 ÷ 镜数」均分，禁止口算、估算，禁止为满足第 2 条做无 beat 依据的对称抖动。时长一律由引擎 `allocate` 计算：节拍基准（`beat_type` + `intensity` 在生效区间内插值）、台词下限（`spoken_text` 字数 ÷ 语速档 + 起势/反应留白，`speech.*`）、角色下限（高光兑现镜/集尾镜，`role_floors.payoff_s`/`final_s`）三者取最大 → 网格取整（`rounding_grid_s`）→ 夹进单镜硬边界（`shot_bounds.min_s`/`max_s`）→ 镜头时长就此锁定；不得按 SEG 预算或作品总长配平。每镜时长必须能回答「这个 beat 为什么是这个时长」——答案由引擎写进 `duration_basis` 发票；确需短促切断（留扣式收尾）时按段级结构登记例外，不改角色下限值。

### beat 类型核心速查

`beat_type` 只标记单镜主要叙事功能并提供时长参考，与段级 `density_profile` 正交；它不是摄影、剪辑或表演指令。导演先依据故事和场景独立设计观看过程，再决定是否标注节拍。完整 `30` 类分类学、基准时长区间、强度锚点与时长校准以《节拍类型库》（`references/节拍类型库.md`）为准；本速查只列 `8` 个核心类型名与一句话定义，不列秒数。不得因节拍类型新增、删除或拆分镜头，也不得由类型推导景别、机位、运镜、构图、焦点、切法或表演调度。

| beat_type | 一句话定义 |
|---|---|
| `opening_hook` 开场钩子 | 集首用最短时间制造「必须看下去」的问题、冲突或奇观 |
| `transition` 过渡/转场 | 只承担空间/时间/状态搬迁、不产生新冲突的连接镜 |
| `exposition` 说明/信息铺陈 | 交代人物关系、处境、规则等背景信息，信息读完即切 |
| `dialogue` 对白 | 以台词交流为主体，台词完整性优先于节奏档位 |
| `suspense_reveal` 悬念/揭示 | 管理未决问题与关键信息显现的节拍 |
| `action_chase` 动作/追逐 | 通过空间位移推进目标与障碍冲突的节拍 |
| `scare_climax` 惊吓/冲突高点 | 威胁或冲突在关键节点兑现的节拍 |
| `emotional_aftermath` 情绪余韵 | 高强度事件之后的消化镜，也是留扣式收尾的承载拍 |

生效区间三层优先级（上层覆盖下层）：**本集声明 `beat_duration_overrides` > 风格档案 > 库默认值**；区间插值、台词下限、角色下限与时长分配全部由 `rhythm_engine.py allocate` 执行，本文件不出现第二套秒数。基准区间为设计基准而非逐镜承诺——实际切点按 `cut_tolerance_s` 容忍窗判定；选类流程、强度缩放方向与「先问功能再看时长」等禁项以《节拍类型库》§1 为准。

### 单镜硬边界

1. 下限：设计下限 `0.8` 秒（`shot_bounds.min_s`）。短镜可以包含连续的摄影变化，但必须让观众读清主要画面过程；`0.8-1.5` 秒只允许作为惊吓/快切段的期望描述，不进 lint 合规判定；`duration_s < 2.5` 秒的镜 `cut_tolerance_s` 默认收紧为 `0.5`。
2. 计划时长通常受 `shot_bounds.max_s` 约束，一镜到底及确有连续时间表达价值的长镜按节拍库规则处理。较长镜头应有与场景相称的镜内发展或有意停留；`info_injection_threshold_s` 可用于提示复核，不自动触发拆镜。是否拆分由导演按观看效果、连续性和实际生成能力判断。本节时长数值以《节拍类型库》§5 为准。
3. AI 生成约束：较长或多阶段镜头可能增加生成漂移风险，这是执行评估依据，不是创意上限。导演先决定镜头需要经历的完整变化，再判断视频工具能否清楚呈现；只有连续性、可读性或工具限制确实要求时才简化或拆镜，并保留改变后的表达意图。不得仅因时长超过某值就禁止焦点、视点、路径或画面关系继续变化。
4. 镜头以一个主导戏剧过程保持可读；同一过程可以包含多个连续动作、信息揭示和摄影变化。若变化之间形成新的观看任务或无法连续执行，再考虑切镜。

### 切点动机优先级

在既有七类切点动机中按以下优先级选用；硬切仍须为 `motivated_hard_cut`，不存在无动机硬切：

1. 动作切换（动作进行中切，最不易察觉，优先级最高）；2. 视线切换；3. 声音先导（J-Cut/L-Cut）；4. 遮挡/反应/空间/信息变化切换；5. 有动机硬切。连续相同动机类型的切换不超过 `3` 次。

生成端执行置信度（±`1` 秒切点漂移下，由高到低）：声音先导 > 视线切换 > 动作匹配切——动作匹配切要求切点落在动作相位中途且两侧相位连续，漂移直接破坏对齐；关键动作匹配切配 `cut_tolerance_s: 0.5`，漂移超窗后按视线切或反应切降格为合规。

### 节奏健康度设计目标

- `high_density_short`：段不参与 ASL 下限判定；镜数按有效信息/动作职责判断，不因 15 秒上限强制配额。
- `dialogue_emotional`/`suspense_build`：段 ASL 目标 `2.5-4` 秒（`asl_targets.dialogue_emotional`/`asl_targets.suspense_build`）。
- `micro_film`：段 ASL 目标 `3-6` 秒（`asl_targets.micro_film`）。
- 通用（豁免单镜硬边界第 2 条所列长镜）：最长镜头 ≤`8` 秒（`shot_bounds.max_s`）；镜头时长众数不得与均值相同（不允许全部镜头同一时长）；连续相同动机类型切换 ≤`3` 次；时长分布须含真实快慢两极（见「段落镜数与时长分布」第 3、6 条），`70%` 以上镜头压在任一 `2` 秒窗内即为分布扁平（`health.flatline_window_s`/`flatline_max_share`），必须按 beat 情绪强度重分配，不得以台账登记接受代替重分配。ASL 目标与健康度数值均以《节拍类型库》§5 为准。

### shot 机读字段

`shots[]` 每镜机读字段（schema 见 `manifests.md`）：`beat_type`（可选；枚举以 `scripts/beat_types.json` 的 beat_types keys 为准，由《节拍类型库》生成，核心 `8` 类速查见上表）、`intensity`（语义字段，LLM 填，`1-5`）、`spoken_text`（有台词必填，供引擎台词下限与 lint 语速检查）、`duration_s`（算术字段，只由引擎 `allocate` 写回；lint 以它为权威）、`duration_basis`（必填，时长构成发票：分项用 `+` 连接、括号内注释不参与加总、加总恒等于 `duration_s`）、`camera_family`（必填摄影执行标签；固定机位统一标为 `static`，复合或新颖拍法选最显著的主导方式；整集 `static` 超过 40% 时触发 lint 硬阻断，详见「运镜与镜头差异化」）、`cut_motivation`（可选，八值枚举，段内末镜与一镜到底段唯一镜免填）、`time_range`（可选期望区间，仅供 QC 容忍窗判定）、`cut_tolerance_s`（默认 `1.0`；`duration_s < 2.5` 秒的镜默认 `0.5`；高节拍精度镜收紧 `0.5`；容忍窗为闭区间）。顶层另有 `rhythm_extremes`（引擎写：fastest/slowest 各 `3` 镜及剧情归属）、`beat_duration_overrides`（可选，本集校准声明）与 `engine_output_hash`（引擎写，快速篡改检测）。**铁律：语义字段（beat_type/intensity/spoken_text/动作单元/角色标记）由 LLM 填进 `rhythm_input_ep_N.json`；算术字段（duration_s/duration_basis/镜数/段划分/rhythm_extremes）只由引擎写入，lint 重算对账，手改算术字段报 `engine_drift`。**计划层只承诺镜头顺序、每镜期望时长与段总时长；切点精确位置是期望值，不是承诺项。

## 每集导演总控卡

详细拆镜前只生成一份 `episodes/ep_N/02_分镜/导演总控卡_ep_N.md`。它同时承担原导演阐述、导演控制与风格系统职责，不得再创建平行决策卡。**字段清单、九步推导方法与逐字段职责以「导演总控卡字段合同」节为唯一权威**：至少包含视觉叙事策略、开场承诺与情绪曲线、核心意象、场面调度总纲、节奏设计、节奏波形推导、视觉风格系统与亮点转译；推导按"建立输入表 -> 推导观察者立场 -> 推导核心意象 -> 推导场面调度 -> 推导节奏与表演 -> 推导声音 -> 推导色彩和风格 -> 绑定执行范围 -> 一致性检查"顺序执行。总控卡不能只列形容词：每项必须绑定场次、镜号范围或剧情触发点，并在完整分镜表和 `storyboard_ep_N.json.director_control_card` 中可追溯。

### 亮点绑定检查

分镜前读取本集 `script_contract.highlight_ledger`，按 `manifests.md` 的 schema 在 `storyboard_ep_N.json.highlight_bindings` 中逐项绑定。每个 `role=primary` 的亮点至少包含一个兑现镜头、一个结果/反应镜头和一个高潮后余震镜头；同一长镜可承担多个职责，但对应可观察阶段必须写清。绑定必须填写视觉、表演、声音和视频编译说明，某一维度不适用时写清理由，不能统一填写“加强氛围”。任何剧本主要亮点找不到镜头，先返回剧本调整或重拆分镜，不得直接删除。

每个主要亮点按“触发 -> 变化 -> 反馈 -> 结果”推导，不从“需要一个高光画面”倒推装饰性镜头：

1. **触发**：读取 `setup_evidence` 和当前场次前态，选择真正迫使人物或局势改变的台词、证据、动作或规则事件，并绑定观众可见/可听的镜头。
2. **变化**：写清触发后谁采取了什么不可忽略的策略，人物位置、道具控制权、信息归属、关系或危险如何发生可见变化；只写情绪形容词不成立。
3. **反馈**：给出对手、听者、环境或规则的即时回应，让观众确认变化被世界接住。反馈必须改变下一拍策略或认知，不能只补一个无后果惊讶特写。
4. **结果**：写清本场或后续场次留下的代价、权力重排、选择后果或余震。结果可延迟到后续集，但必须通过 `deferred_aftereffect_ref` 指向明确回收点。

四步按顺序写入该亮点的 `causal_chain` 并绑定 SHOT；再把变化/兑现镜头映射到 `payoff_shot_ids`，反馈镜头映射到 `reaction_shot_ids`，结果或余震映射到 `aftereffect_shot_ids` 或跨集引用。同一 SHOT 可以承担相邻两步，但必须分别写出可观察状态；若缺触发、反馈或结果，返回剧本补因果，不得用慢动作、强音乐、发光或群众惊叹替代。

### 受众执行检查

分镜只能继承已确认 `drama_plan.json.audience_plan`，不得重新选择受众、平台或地域。在 `storyboard_ep_N.json.audience_execution` 中按 `manifests.md` 分别登记观看焦点、情绪回报、平台观看场景和表达禁区的执行合同，并把每项绑定到真实场次或镜头。四项都必须可追溯；仅写“符合受众”“适合平台”或重新引用受众库标签不算落地。

## 导演总控卡字段合同

> 本节规定每集正式拆分镜前必须完成的唯一导演判断，以及这些判断如何进入逐镜表和视频 Prompt。不得另建第二份导演控制包或强风格系统卡，也不把整张总控卡塞进每个 Prompt。

### 职责边界

- `导演总控卡_ep_N.md`：每集唯一整体创作判断，先于逐镜表完成，并在同一文件内把判断落实为每个 SEG 和 SHOT 的调度、布光、表演、声音、动作与剪辑合同。
- `storyboard_ep_N.json`：保存总控卡文件指针和可执行字段，不复制长篇说明。
- `video.md`：只编译已确认导演总控卡和分镜，不重新发明导演方案。

### 每集导演总控卡

固定文件：`episodes/ep_N/02_分镜/导演总控卡_ep_N.md`。至少包含：

- **视觉叙事策略**：回答观众如何被安排去看，包括主要观察距离、主客观视角、空间压力、运动与静止分工、何时拒绝特写、何时让环境压过人物。禁止只写“电影感、压迫感、高级感”。
- **开场承诺与情绪曲线**：继承 `script_contract.opening_contract`，写清首个叙事节拍如何被看见、谁先反应、什么动作或信息使其升级、在哪个场次兑现或延续；再把项目级 `emotion_design` 细化为关键角色的入场状态、压力来源、转折触发、可见证据、关系后果和尾态。
- **核心意象**：选择 1-2 个道具、动作、空间、色彩或声音母题，记录“首次含义 -> 变奏 -> 高潮重释 -> 结尾余韵”。每次出现必须增加信息或改变意义；无变化的装饰不算核心意象。
- **场面调度总纲**：继承人物关系张力表，说明权力差、信息差和情感差如何通过距离、屏幕位置、纵深、遮挡、出入口和道具控制权变化。允许反讽调度，不能机械套“强者站高、弱者站低”。
- **节奏设计**：标记需要快切、连续表演、停顿、长镜或突然中断的段落及戏剧原因。快切用于信息压缩或失控，长镜用于让选择和反应无法逃避；不得用速度掩盖场景没有转折。
- **节奏波形推导**：依次记录不可移动内容节点、每个节点的信息密度/动作强度/阅读时间、唯一主重拍、切镜或镜内连续选择、动作与核心证明优先后的时长分配，以及 `1-5` 强度序列。可选“快起 -> 稳证 -> 快收”“逐级加速 -> 高光 -> 短停”“快慢交替 -> 汇聚”“连续推进 -> 节点变速”“结果前置 -> 倒推线索 -> 原因揭示”“稳态建立 -> 突然打断 -> 连续应对 -> 新稳定”“单点触发 -> 层层扩散 -> 整体响应 -> 回收”“两线交替 -> 节奏对齐 -> 汇合”“问题脉冲 -> 回答脉冲 -> 证据停留”“克制积累 -> 局部释放 -> 完整爆发 -> 余韵”“建立规则 -> 两次变奏 -> 打破规则 -> 新规则收束”“起点 -> 偏离 -> 回归 -> 无缝 Loop”或自定义波形；不得固定切成 `0-3 / 3-7 / 7-11.5 / 11.5-14 / 14-15`。
- **视觉风格系统**：媒介形态、构图骨架、光线方向、色彩关系、材质、镜头质感、字体/版式、明确剥离项。它是总控卡的一部分，不单独维护风格系统卡。
- **亮点转译**：逐项读取本集 `script_contract.highlight_ledger`，写清观众先看到什么、哪个动作兑现、表演如何泄露真实意图、声音何时进出、哪个镜头保留余震。信息重释重证据和反应，关系攻防重距离/遮挡/道具控制权，专业能力重流程和策略修正，母题重重复变奏，表演瞬间重表面策略与泄露动作，情绪余震重高潮后的结果镜头。

### 总控卡逐字段推导方法

按下列顺序从上游事实推导，不允许先写形容词再找镜头佐证：

1. **建立输入表**：读取 `creative_proposition`、`opening_contract`、`highlight_ledger`、人物关系张力矩阵、场次 entry/exit state、`emotion_design`、`rhythm_design`、`style_contract`、数据卡空间/状态和用户镜头禁令。每条输入标记来源场次；互相冲突时回到最早权威阶段，不在总控卡中私自折中。
2. **推导观察者立场**：先问观众应比谁知道得多、与谁同处压力、何时需要看清证据。由答案决定主客观视角、主要观察距离、环境与人物的画面占比，再绑定场次范围；这形成“视觉叙事策略”。
3. **推导核心意象**：从会重复出现且意义会改变的动作、道具、空间、色彩或声音中选 `1-2` 个，分别写首次含义、变奏触发、高潮重释和结尾余韵。删掉后不影响理解或意义不变化的对象不选。
4. **推导场面调度**：把每个关系节点的权力差、信息差、情感差翻译成世界坐标中的距离、纵深、遮挡、出入口、视线和道具控制权；先写 T0，再只记录触发后的 T1/T2 变化。机位随后服务调度，不允许为了构图暗中移动人物或房间。
5. **推导节奏与表演**：从不可移动节点和主重拍分配快切、连续表演、停顿和静默；再对承担转折的角色写“表面策略 -> 内在压力 -> 泄露动作 -> 对方反馈 -> 尾态”。没有因果触发的表情、呼吸或停顿删除。
6. **推导声音**：先锁基础环境声，再为会改变信息的动作配置叙事声，只在主观感知触发时加入情绪性声音；最后决定 BGM 入退、静默和声音桥。若声音与对白争夺同一信息，把非主信息后移或降低，不同时强调。
7. **推导色彩和风格**：逐项继承 `style_contract`，先写基础光源、主辅色、材质和构图骨架，再只在有世界内原因或剧情触发时写变化。无法指出光源、时间、天气、实景灯、服装或空间原因的自动变色删除。
8. **绑定执行范围**：每项决策必须落到场次、SEG、SHOT 范围或明确触发点，并在逐段执行区写首态、尾态、删除损失和专项合同。若一项无法绑定任何镜头，它不是本集执行决策，应删除或返回上游补依据。
9. **一致性检查**：逐项问“它服务哪个剧情问题、在哪一镜可见、变化由什么触发、视频 Prompt 需要继承哪部分”。四问任一无答案时重写；不同字段要求互斥动作、光线、声音或观看立场时，以核心证明和用户锁定项为先，不能同时保留。

### 表演指导合同

AI 表演使用可观察层次，不依赖抽象形容词或只有微表情。每个关键镜头至少写清：镜号、角色、表面策略、内在压力、可见情绪层次、主要脸部/目光/肢体/呼吸变化、触发点、尾态和禁止表演。

- 表面策略决定人物在做什么；内在压力解释动作为什么泄露。
- 微表情只作增强，关键信息同时由动作、距离、道具、声音或结果承担。
- 一镜最多突出一个主要表演转变，复杂变化拆成可观察节拍。
- 有听者时单独写听者反应及尾态，不能只细化说话者。
- 禁止“夸张震惊、持续流泪、机械点头、全员同一表情”等默认失控表演。
- 关键表演镜头可绑定 `performance_scores` 和 `performance_coverage`；AU 只作辅助强度标尺，不替代自然语言动作因果。

### 声音设计方案

每集先写整体声音命题，再逐段落实三层声音：

- **基础环境声**：房间底噪、空调、电流、远处车流等，用于空间和连续性，不抢对白。
- **叙事性环境声**：钟声、雨声、脚步、门锁、机器停转等，每次出现必须改变信息或预期。
- **情绪性主观声**：心跳、耳鸣、闷化、呼吸放大等，只在人物感知被触发时短暂进入，并写退出点。

BGM 不得持续填满，也不得只写“低频 BGM”“紧张音乐”“悬疑感音乐”。每条 BGM 写清入点、退点、乐器/音色、速度或节奏、音量、质地、情绪职责和对白避让；跨 SEG 延续时，下一段复用上一段已确认 BGM 描述或 `bgm_descriptor`。

- 静默写明移除哪些声音、保留哪些身体或空间声、持续范围、人物感知和结束触发。
- 完全静默只在世界逻辑或主观听觉成立时使用；通常保留呼吸、布料、空间反射更可信。
- 声音桥登记来源镜头、目标镜头、声音主体、跨越时长、叙事作用和淡入淡出。优先使用环境声、拟音、动作声或非语义人声尾音；音乐桥只在剧情确实需要时使用。台词尾音只写声尾、气口或混响状态，不复制完整台词，不得写“自然衔接”。

### 色彩叙事合同

色彩首先是项目已确认风格的子系统，其次才承担本集变化。禁止把冷蓝、暖橙、红色等机械等同于固定情绪。

色彩脚本写清基础主色、辅色、禁用色/冲突色、人物色彩归属、变化触发、光影路径和高潮状态。色彩变化必须能在光源、时间、天气、实景灯、服装、人物移动或空间转换中解释；认知改变不等于画面自动变色。关键段记录基准主辅色、色温/对比、肤色与主体分离、可见触发、跨镜继承或允许偏移，不要求固定色值。

### Prompt 编译

- 视频 Prompt 不照抄十五列分镜表；以分镜阅读稿的逐镜语言为骨架，抽取景别、机位、运镜、时长、声音、动作桥、连续性和抽帧承接等硬信息，结合 `reference_input_plan` 的真实图片职责，改写为 `video.md` 的项目语言五段式导演交付包；交付包再由并列 skill `h3-prompt-writing` 转成提交给模型的 H3 成稿。每个镜头恰好编译一次。
- 每个 SEG 只采用与该段直接相关的导演总控卡内容：视觉策略、节奏原则、色彩基线、人物色彩归属、场景光源、核心意象、道具状态、表演节拍、三层声音、BGM 入退点、静默、声音桥、禁止表演、禁止色彩跳变和尾态。
- 阅读稿、十五列表和 JSON 不一致时，先回分镜修订；视频阶段不得自行取舍。
- 编译时凡镜头命中 `causal_ledger` 的证据/反应位，必须把该链 `visibility_contract` 随镜头一并交给视频阶段（转写规则见 `video.md` 五段式导演交付包节）。

## 场次、片段与镜头

“场次、视频片段、镜头”不得混为一层：

- **场次**：连续戏剧空间或连续戏剧行动，使用 `E{集号}S{场号}`，例如 `E01S01`。
- **视频片段**：一次视频模型调用容器，使用 `SEG001`、`SEG002`；它可以包含一个或多个完整镜头。
- **镜头**：一次不间断观看位置，使用 `E01S01-SHOT001`；单个镜头不得跨两个视频片段。

模型时长只决定提交方式，不反向决定剧情节奏。不得为了填满模型上限把无关镜头塞进同一片段，也不得把重复裁切、数字推拉或无信息变化的构图算作新镜头。

群众/群体出现在分镜中时，先判断它是已登记的稳定群体还是一次性匿名背景人群。稳定群体的 CHR 作为一个集体 actor ID 写入该镜 `actors`，不得为匿名成员虚构单体 CHR；具名、发言或承担独立因果动作的成员另列单体 CHR。逐镜调度另写实际可见人数、前中后景分布、站位区域、运动方向和群体反应时序；群像画像只锁群体构成和视觉特征，不替代逐镜调度或 SCN 空间布局。需要跨镜维持成员位置/服饰/人数时，在 `reference_input_plan` 指定可见布局锚点；非首镜和 `continuous` 接缝按真实 FRM/SCN 锚图合同补齐。

## 片段与时长

- 交付规模按用户意图伸缩：单条剧情短片通常为 15-60 秒；常规多集短剧单集通常为 1-3 分钟，极短集支持 15-60 秒；微电影通常为 5-10 分钟。具体时长结合用户指令、剧本事件量、对白预算和自然切点确定，并在规划阶段以准确秒数确认。
- 每个镜头组（= SEG = 一次视频生成任务）时长必须在 `[4, 15]` 秒且**为整数秒**（视频 API 只接受整数 duration；上限以 `tools/video/h3.json` 能力档案为准）；组目标 8-13 秒是设计指南，不是硬规则。组实际时长 = 组内镜时长之和，由引擎 `pack` 校验。
- 所有镜头使用绝对时间戳，首尾相接，总和等于本集确认时长。
- 组时长一律按真实内容书写：组不足上限是正常输出，无需例外登记；总时长尾数、自然切点、动作复杂度、生成稳定性或用户明确时长要求都可能让组短于上限。任何理由都不得用于自主切换模型或突破对应时长上限，也不得为凑满上限摊薄镜时长或填充慢动作、无效镜头。
- 组间边界放在真实剪辑点（动作单元结束、信息揭示、角色反应、场景切换、声音过门）——观众本来预期那里有切的地方；戏剧转折点优先划进同组（同一次生成内部连续）。跨组的真连续动作按 SEAM 连续合同承接（见「开场、转场与角色表演控制」）。
- 不得在一句台词、一个连续动作或关键反应中间强行截断。
- 每个片段至少呈现一个可观察的推进、变化或有效承接；变化数取决于剧情负载，不规定统一的“两次变化”配额。连续动作 SEG 可以在同一动作链中途结束，只要下一段按合同接续。
- 仅当规划合同明确选择“信息流黄金三秒”观看目标时，才检查开头是否迅速建立问题/行动并出现足以维持注意的可见变化；不得由 H3 的 15 秒单段上限自动触发固定三事件数或 1.2 秒首镜指标。
- 中间 SEG 默认使用 `continuous_motion` 或 `cuttable_completion` 尾态，让下一段从动作相位、视线、声音或状态继续，不强制停住。只有剧情确需停顿时才使用 `stable_hold` 并写理由。最终 SEG 默认使用 `stable_hold` 保留 `0.6-1.0` 秒稳定结果帧；无缝 Loop 或未完成动作结尾按真实切点处理。
- 每个片段写明 `viewer_takeaway`、`engagement_driver` 和 `exit_function`：说明本段给观众什么事实/体验、真实观看动力是什么、段尾负责落点还是承接。真实钩子保留；动作继续、信息暂悬、情绪余韵或自然转场可以承担技术段尾，不为格式硬造悬念。连续 SEG 合看须确认前段问题/动作由后段承接、兑现或有意转向。
- 短剧节奏必须紧凑，但不得默认每段都有人声。已确认台词遵守人声时长预算；纯动作、静默、环境声、音乐蒙太奇或抒情段按剧情/声音设计成立时允许无人声，不能为填充音轨新增词句。安静段须提供与段落功能一致的可观看内容，或说明有意停留的观看对象与作用；不得无目的填时长。
- 真正一镜到底是唯一允许单镜覆盖整段或整片的例外：从头到尾必须是同一次连续拍摄，禁止硬切、隐藏切、遮挡伪切、匹配剪辑和时间跳跃。可以连续跟拍、平移、推拉、升降、环绕或穿越空间；连续摄影机路线、观看对象、空间、主体关系、光影/焦点或可见信息共同形成至少三个可读节点。只有缓慢推镜、发光或无观看意图的轻微动作不构成合格长镜头。

### 尾态选择算法

在定稿每个 SEG 的末镜前执行：

1. 先判断是否为最终 SEG、无缝 Loop，或后续仍需承接同一动作/视线/声音/状态。
2. 后段必须接同一动作且完成态会失去动势时，选 `continuous_motion`，把尾点放在动作进程 `30%-70%` 的清晰相位，并写方向、速度、接触状态和下一段从何相位继续。
3. 当前动作已经完整，但下一段可从结果、反应、视线、物件位置或声音尾音接入时，选 `cuttable_completion`；结果必须可读，但不额外停住等待。
4. 只有最终落点、剧情明确要求停顿，或中间段的停顿本身会改变判断/关系时选 `stable_hold`。最终 SEG 默认留 `0.6-1.0` 秒；中间 SEG 必须在 `tail_hold_reason` 写清停顿制造的具体信息或压力。
5. 只有首尾画面与动作能形成真实无缝循环时选 `loop_continuation`，同时写明末态如何回到首态；“画面相似”但动作、道具、光线或声音状态不闭合时不得使用。
6. 将所选模式写入末镜动作、声音、SEAM 出段 cue 和下一段入段 pickup。若下一段无法从该尾态自然开始，先改尾点或转场；不得在 Prompt 中同时要求“稳定停住”和“持续高速运动”。

### 真正一镜到底的场面调度算法

仅在用户明确要求或连续时间本身承担叙事价值时使用 `shot_mode: true_one_take`：

1. **画路线而非列镜头**：先在 `blocking_map` 标出摄影机起点、终点、可通行路径、角色 T0/T1/T2 位置、出入口、遮挡物、光源和必须看清的证据；全段只登记一个 SHOT。
2. **安排至少三个连续节点**：节点必须依次改变空间、关系、信息、观看对象或动作结果，例如“从门内暗处侧移显出门缝 -> 停住让影子先经过 -> 后退揭示门外有人”。每个节点写触发、摄影机路径或停留方式、画面发展、新信息和进入下一节点的自然动力；主体行动仅在该节点以人物动作为观看重点时填写。
3. **为观看意图设计摄影**：摄影机的移动、停顿、观察对象和焦点变化由当前场面的信息、空间、关系、情绪、节奏与观众视点共同决定。人物动作可以触发摄影变化，也可以由环境、物件、光线、遮挡、声音、构图关系或导演安排的观察节奏触发；不得预设摄影机必须跟随人物，也不得无叙事意图地移动或只靠持续慢推撑满时长。
4. **维持连续世界**：逐节点核对轴线、屏幕方向、角色速度、道具接触、光位、声音距离和背景锚点。遮挡可以作为真实空间经过，但不得借遮挡伪造切换、换时空、换演员或重置动作。
5. **分配时间与可生成性**：为每个节点保留完整动作和反应时间；复杂多人同步、跨楼层、不可连续通过的空间或需要时间跳跃时判为不可执行。用户未锁定一镜到底时改为 `edited`；用户已锁定时停止并说明具体冲突，返回调整动作或空间，不能偷偷使用隐藏切。
6. **编译与检查**：Prompt 只写一条连续摄影机路线，节点之间使用“摄影机继续/转向/绕行/停下后再跟随”等连续语言，不写“切到、转场、匹配剪辑、蒙太奇”。检查任一时间点是否都能从前一位置物理到达；无法回答时重做路线。

## 高密度剧情与运镜

分镜阶段要把镜头机制写成叙事功能，不把紧凑误解为机械碎切。连续微事件可以合并为剧情动作组：每个 `2-5` 秒动作组可承载多个微事件，但必须在同一行写完整“切入触发、画面发起或变化、主体/环境/物件反馈、结果变化和切出落点”；没有人物动作时，按实际画面过程填写，不能只写抽象标签或“镜头跟随”。

动作、追逐、对峙、技能、商业攻防或家庭冲突等高密度段，应先弄清这一段的戏剧过程和空间事实，再由导演决定观众如何经历它。可连续观察、突然改变视点、让摄影机落后或脱离人物、借环境或物件组织画面，也可使用剪辑；这些都是开放选择，不与特定情绪、人物动作或剧情阶段固定绑定。保留完整动作因果与观众所需的信息，不把技术切段误当成创作方案。

机位、构图、距离、空间层次和画面重心可以随局势变化，也可以有意保持稳定。观众可以先于角色、与角色同时或晚于角色获得信息；信息顺序应服务本场戏的观看体验，不要求每场都制造信息差。摄影机可以关注人物，也可以让空间、物件、光影、遮挡、环境运动或声音成为画面变化的来源。设计时先判断观众此刻应看见什么、何时看见、以何种距离和视点经历；再决定摄影机是移动、改变焦点、等待、保持静止、离开人物或切镜。动作与镜头之间可以同步，也可以错开、反向或互不直接绑定，只要观看关系清晰且有场面依据。

## 动态镜头数量

镜头密度从内容节点和完整动作推导；每镜通常服务一个可观察的信息、动作、反应或关系变化，具体秒数由对白朗读、动作起势、动作完成、反应停顿和切点决定。所有密度类型都用删除测试、动作完整性和观看关系证明镜头必要性；不因某个 SEG 恰为 15 秒而增加最低镜数。任何类型都不得为达到数量拆断完整动作，也不得把慢推、发光、凝视、轻微呼吸、重复反应或无信息变化的数字裁切算作镜头变化。

- 镜头必须足以清楚表达当前片段实际承担的钩子、目标、阻力、策略变化、高潮或反转、反应和收束。
- 两个以上关键职责只能靠一句台词或静止画面带过时，应增加镜头或镜内变化。
- 删除后不影响剧情、关系、信息或连续性的镜头应合并。
- 不为镜头数量碎切，不用慢动作、重复反应或无意义空镜填时长。
- 一镜到底只能登记一个镜头，且必须满足真实连续拍摄定义；镜内仍须包含连续变化的摄影机路线、主体行动、关系、空间或信息节点。
- 镜头可由一个或多个连续摄影阶段构成，阶段可以在移动、停顿、改变方向、改变观察对象或焦点中自然演进；不要求一镜只出现一种运镜，也不以增加运动次数作为丰富度目标。片段内允许切镜，每个切点应有可理解的观看或叙事作用。
- 剧情片段默认包含可听人声：出镜对白、旁白、画外音或内心独白按剧情选择，句句推动剧情、关系、信息或反应。每句可跨相邻镜头连续，但不能靠拖长停顿填时长，也不能靠加速语速塞进过短镜头。字幕生成、样式和烧录只继承 `delivery.md`；视频模型阶段仍禁止画面字幕和自动转写。
- 高密度短片不因恰好 `15` 秒强制最低镜数。真实一镜到底不把镜内节点伪报为多个镜头；所有配置按剧情节点与动作完整性决定。任何时长都不得用一个状态、一个动作、统一慢推、发光或轻微动作填满。

## 动作桥与观看关系

每个跨镜动作和每个切点都按以下链条设计：

```text
前镜状态
-> 动作发起
-> 运动路径
-> 合理切点或镜内调度
-> 后镜续接
-> 接触/反馈
-> 结果
```

每次切镜必须明确回答“为什么现在切”“用什么承接前一镜”“切后增加了什么新信息”。承接锚点只能来自动作、方向、主体位置、视线、形状、光色、声音、文字、遮挡或产品状态中的实际可见/可听事实。动作桥示例包括“拿取 -> 移向入口 -> 接触 -> 收纳结果”“刷头靠近 -> 接触表面 -> 连续涂抹 -> 结果展示”“取料 -> 上脸 -> 使用反馈 -> 放回”“铺垫 -> 触发特效 -> 环境响应 -> 结果停留”。不得从动作发起直接跳到结果，也不得让手、人物、产品或道具在切后无路径换位。

## 单镜因果检查

每镜检查：

```text
谁想达成什么 -> 遇到什么阻力 -> 使用什么动作或语言策略 -> 收到什么反馈 -> 局势发生什么变化
```

无法回答且删除后不影响剧情的镜头必须删除或重写。对话镜头不能只做机械正反打；情感场景依靠视线、距离、动作和停顿；悬疑场景分别呈现线索、错误理解和揭示；动作场景保持空间、受力和结果连续。

## 运镜与镜头差异化

导演先判断整段内容最值得如何被观看，再设计镜头。画面变化可以由摄影机、人物、物件、空间、光线、遮挡、声音或剪辑共同形成；不要求运动围绕人物，也不要求每镜都发生变化。运镜描述应让人能想象镜头的起始画面、过程中发生的变化和最终画面；根据方案需要写明摄影机位置/路径、朝向、速度质感、焦点和停留，但不为未使用的维度填参数。复合运动可以按真实先后写成连续阶段，不必压成单一运镜名称。

导演可以从不同视点构思：摄影机观察、接近、等待、离开或重新发现画面中的对象；也可以让观众注意到原本不在主体上的空间、物件、光影或环境变化。这些只是创作可能性，不构成待勾选的镜头清单。运动名称用于准确表达已经选定的拍法，不用来推导剧情或替代画面描述。

运镜、镜头、焦点和剪辑术语是准确表达方案的词汇，不是从剧情类型查找拍法的索引。不要先选一个名词再给它配戏；先形成完整的画面设想，再选择最贴切的语言描述。允许组合已知手法，也允许写出混合、非典型或不易归入单一类别的摄影过程。

`camera_family` 是每镜必填的粗略执行标签，用于检查整集固定机位占比，不代替摄影过程描述。复合或混合运动可用最显著的主导方式标记，不因此限制实际设计。`static` 表示摄影机在该镜中保持固定；人物、物件、光线、环境或焦点移动不改变此分类。每集 `static` 镜头必须不超过全部镜头的 40%；超过 40% 时 lint 触发硬阻断，退回导演重新检查观看方式并改写分镜，未通过前不得进入关键帧或视频阶段。恰好 40% 不触发。该门槛约束固定机位总占比，不要求每镜移动，也不规定其他运镜类别配额；只有分镜修订后重新统计不超过阈值才能解除阻断。

视频工具对不同摄影设计的执行稳定性可能不同；这属于方案定稿后的实现判断，不形成运镜家族清单或创作限额。

执行原则：

- 运镜速度、力度和稳定性按画面表达需要决定，不要求相邻镜头递进，也不要求整场戏形成统一速度阶梯。
- 执行风险应在选定拍法后评估。若工具难以稳定呈现，先写清会损失的表达，再提出保留、拆分或转换的可执行选项；不能静默改成更保守的运动。

检查整场戏是否形成有意图的视觉节奏和观看关系；若镜头相似，判断重复是否服务于观察、等待、对比或连续性。若方案单调，回到故事重新寻找画面机会，不按分类表补运动。多个摄影动作可以在同镜连续发生；只有表达、可读性或实际执行需要时才拆开。

### 镜内运镜编排

高动作、追逐、打斗、揭示或钩子镜可以把摄影机工作编排为**镜内节拍**：写明起始状态，按真实先后列出带镜内时间标记的运镜事件，每个事件锚定一个可观察的动作/信息/反馈时刻，最后收束落点。视频模型能执行单镜内的多个时间戳摄影机事件；与"每镜一条主运镜"相比，运镜事件打在动作峰值上正是"电影感"的来源。非动作镜不要求使用本写法——纯固定镜（如隔道对望）的戏剧就是"不动"，堆运镜反而毁戏。

- **写法**：起始状态 → 逐个运镜事件（带镜内时间标记，如 `00:01.4 甩镜右`、`00:03.0 抽刀瞬间急推`）→ 收束落点（settle/hold 稳定帧，为下一镜/下一组留干净接点）。示例：`起始中景固定。00:01.5 随拎狐上提快速上摇；00:03.0 抽刀瞬间急推至刀与狐颈；00:05.0 抛接刀出手持抖动跟随；00:06.2 回落稳定中景，收在咧嘴狞笑`。
- **锚定规则**：每个运镜事件必须对应画面里真实发生的动作峰值或信息揭示时刻，不是无锚堆运动——"不以增加运动次数作为丰富度目标"的防滥用条款在本写法下同样生效。
- **进入成稿**：十五列「摄影过程」列按此写法填写；视频编译时镜内时间标记与事件如实进入导演交付包与 H3 成稿，编译不得抹平为单一运镜标签。
- 静态占比检查（`static ≤ 40%`）不受本写法影响：用了镜内编排的镜按主导方式标 `camera_family`。

采用 POV 第一人称时，写明所属角色、眼睛高度、视线方向，以及可见的手部、衣袖、伤痕或手持道具；POV 内不得出现该角色完整正脸，也不得混写为自拍、监控或过肩镜头。运镜词库只是决策候选，不是必选清单；生成后若实际运镜未发生、方向错误或退化成统一慢推，按镜头执行失败处理。

## 对白时长预算

每句台词在进入分镜前必须朗读估时，不能只按字数猜测。尚无最终音色时，可用目标语速试读或临时语音样本估算；音色资产完成后再复核一次。

```text
镜头时间预算 = 台词实际朗读时长 + 句前起势 + 句中自然停连 + 句后反应 + 必要动作时间
```

- 人声由已确认剧本与声音设计决定。有台词时完整保留并登记；无台词的纯动作、静默、环境声或纯音乐段允许 `speech_lines` 为空。不得为满足模板而新增对白、旁白、内心独白、呼吸或反应声。明确区分“无人声”“无声音”“无 BGM”；安静段可由可见表演/动作、环境/空间/光线/物件/焦点变化或有意停留承担设计功能，不得用声音替代剧本中明确发生的剧情动作。
- 台词密度按朗读时长上限控制，不按句数下限堆叠。普通 SEG 的计划人声总朗读时长建议不超过片段时长的 `health.speech_voice_max_share_normal`；对话交锋、审问、告白、独白高潮等确需高密度人声的 SEG 也不得超过约 `health.speech_voice_max_share_dense`（数值以《节拍类型库》§5 `health.*` 为准），其余时间必须留给表演、动作、反应、换气和剪辑。
- 语速按短剧场景动态调整，但必须有硬上限。中文台词只统计 `spoken_text` 中实际发声的汉字，标点、镜头描述、动作描述和画外音类型标注不计入字数：普通剧情、情感、悬疑、古风、品牌剧情化、旁白和抒情段建议 `speech.chars_per_s_normal` 的区间下限到上限之间，硬上限 `speech.chars_per_s_normal`；追问、争吵、逃跑、喜剧反差、强压迫交锋等快节奏段硬上限 `speech.chars_per_s_rapid`；告白、压抑威胁、病弱、哭腔、老年/儿童角色、重要揭示后的停顿段应主动低于普通上限（数值均以《节拍类型库》§5 `speech.*` 为准）。任何镜头或台词行都不得超过对应 profile 的硬上限，不得写“较快语速”“快速说完”“加速念完”等方式规避字数限制。
- 语速上限不是放慢剧情：当台词减少或拆短时，必须用角色行动、听者反应、证据特写、道具状态变化、空间调度、切镜、环境声、拟音或声音桥补足信息密度；不能把省出的时间变成无信息凝视、空镜或纯氛围拖延。快节奏段可以快，但必须听得清、看得懂、让关系或局势真实变化。
- 单句优先短而有钩子：中文出镜对白通常控制在 `6-18` 个汉字，旁白或内心独白通常控制在 `8-24` 个汉字；更长的句子优先拆成多镜、跨 SEG 或改成画外音覆盖动作空镜。不得为了塞完整台词要求模型加速朗读。
- 台词窗口必须容纳完整发声，并为开口前动作、换气、重音、对方反应和切镜留下时间。
- 避免机械匀速念稿：速度可以随策略变化，但不能靠全句加速挤进过短镜头。
- 人声必须始终清楚高于 BGM 和非关键环境声；重音词附近不得安排抢占听觉的强拟音。
- 台词超时优先拆分到相邻镜头或相邻 SEG、缩短非必要动作、改为画外音覆盖动作空镜，或回到规划/分镜延长片段；用户原台词不得擅自删字、改字或用同音字替换。
- 出镜对白、动作和反应的时间区间必须首尾相接；旁白、画外音和内心独白可以跨镜连续，但必须标明起止镜头，且画面人物不做对应口型。

### 叙事过渡、画外音与内心独白

- 旁白、画外音和内心独白由视频模型原生生成，文本放入 `{}`，明确声音主体、类型、情绪、起止时间及“画面人物不开口”。
- 可按剧情使用黑屏、短暂暗场、环境空镜、物件特写、声音先行或声音延续表现时间跳跃、记忆、章节转换和内心状态，但不是每段必用。
- 黑屏或暗场必须有明确职责和短时长，不能替代应拍摄的剧情。需要显示时间、地点、章节时使用画面文字 `“三年前”`、`“翌日清晨”`，不使用 `【】` 字幕通道。
- 同一句内容默认只走一个声音或剧情内文字通道：听见的人声用 `{}`；时间/章节文字用 `“”`；默认不生成逐句字幕，也不写入视频模型 Prompt。只有用户明确要求字幕时，才从已确认人声文本派生无标点 SRT 供成片阶段处理。

## 用户可见分镜阅读稿

`分镜_阅读稿_ep_N.md` 必须使用适合用户审查的顺序，不展示内部 JSON、哈希、字段名或校验结果。格式至少等价于：

```markdown
## 第X集：[可读标题]

### 本集故事提要
[用一段话说明本集主线、冲突、高潮和结尾钩子/落点]

### 第一章：[章节名]（本章时长：约90秒 / 00:00 - 01:30）
> 本章叙事功能：[世界观铺陈 / 冲突升级 / 反转兑现 / 高潮落点等]

#### 片段一：00:00 - 00:13（本段包含 3 个分镜；秒数为引擎 allocate/pack 输出的渲染，数值仅演示格式）
- **镜头1 (00:00-00:05.5)**：[景别｜视点｜摄影设计｜机位/角度] 给出第一个可见信息事件和画面如何展开。
- **镜头2 (00:05.5-00:09.0)**：[景别｜视点｜摄影设计｜机位/角度] 写清过程中的画面变化、反馈或策略变化。
- **镜头3 (00:09.0-00:13.0)**：[景别｜视点｜摄影设计｜机位/角度] 写清结果、代价或关系变化，以明确尾态留下下一片段可承接的画面、动作、声音或情绪。
```

- 章节按照剧本的章节与场次映射排列，不能只写“第一章、第二章”的空标题。
- 片段起止时间一律写引擎 `pack` 校验与写回后的真实值：`00:00 - 00:13`、`00:13 - 00:26` 这类非 15 秒段是正常形态（数值仅演示格式）；段不足上限无需解释，顶满模型上限（如恰好 15 秒）反而必须能用镜时长之和解释。
- 每个片段必须按“动态镜头数量”列出足量分镜，镜头时间首尾相接并覆盖完整片段。
- 每个镜头行必须包含：镜头编号、绝对时间、景别、视点、摄影过程、画面动作、声音、人声文本或“无”、切入/切出方式。摄影过程按该镜实际设计填写；静止镜头可说明构图与画面内变化。
- 听得见的人声一律写成 `说话人：{原文}`，例如 `旁白：{门已经开了}`；音效用 `<具体声音>`；BGM 用 `()` 或 `（）`；标题、品牌字、时间地点等画面文字用中文引号 `“”`。字幕源使用 `【】`，只在用户明确要求字幕时登记，并明确不由视频模型渲染。
- 分镜阅读稿可以保留自然语言章名、片段名和故事提要，但不得省略完整镜头列表，不得用参数确认表的剧情预览替代正式分镜。

## 完整分镜表

内部详细分镜固定使用以下十五列。每一个镜头必须填写；无对白、旁白、音效或抽帧/承接要求时明确写“无”，不得留空。该表与参数确认表中按内容形态选择的五列分镜预览表/剧情节奏预览表职责不同，不得互相改写格式。

|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| E01S01（1-1） | SEG001（分镜01） | E01S01-SHOT001（镜1） | 钩子/证据/反应/反转/压迫/收束等具体职责 | 00:00-00:04（4s） | 写清人物、场景、位置、朝向、动作起点、过程、反馈、结果及与下一镜关系 | 特写/近景/中景/全景等 | 眼平/低机位/高机位/过肩/POV/俯拍等，可写焦段感 | 时间、内外景、主光方向、色温、明暗、材质和情绪 | 说话人：`{完整台词}`；无则写“无” | `<具体环境声/拟音>`；BGM 写 `(具体音乐)`；无则写“无” | 写清本镜画面从何开始、如何变化、最终停在哪里；按需写摄影机运动、焦点和停留 | 动作切/视线切/遮挡切/声音先行/反应切等 | 轴线、视线、动作方向、道具状态、光位和声音接点 | 首帧检查/场景锚点/尾帧承接及目标时间 |

### 各列要求

- **场次**：稳定 ID 使用 `E{集号}S{场号}`，并保留剧本中的人读编号。
- **视频片段**：稳定 ID 使用 `SEG001`、`SEG002`；同一片段内镜头总时长不得超过所选模型上限。
- **镜号**：稳定 ID 使用 `E01S01-SHOT001`，末尾序号在当前场内连续、不重复、不跳号。
- **镜头职责**：写可验证的剪辑职责，不得写“推进剧情”“增强氛围”等空泛词。
- **时长**：写绝对起止时间和本镜持续秒数，与台词、动作、停顿和切点匹配。
- **画面描述**：写清主体、空间位置、朝向、视线、动作起点、轨迹、反馈、结果和剧情变化。
- **景别**：明确大特写、特写、近景、中景、全景、远景、大远景、过肩或 POV。
- **机位/角度**：明确摄影机高度、观察方向、主客观视角和镜头感。
- **光影氛围**：明确日夜、内外景、主辅光方向、色温、明暗层次、材质反射、天气和情绪效果。
- **对白·旁白**：写明说话人、声音类型和完整文本；用户文本逐字按原顺序保留。
- **音效**：环境声和拟音使用 `<具体声音>`，BGM 使用 `(具体音乐)`，写清进入、持续、淡出或承接时机。
- **摄影过程**：写清观众实际看到的画面如何开始、变化和结束；按需要描述机位路径、朝向、运动质感、焦点变化、停留与剪切。多阶段设计按时间顺序完整表达，不强行归并成一个运镜标签；高动作/钩子镜可用「镜内运镜编排」写法（带镜内时间标记的运镜事件，见「运镜与镜头差异化」节）。
- **切入/切出动机**：由动作、视线、遮挡、物件、声音、反应、空间或信息变化驱动。
- **连续性要点**：记录屏幕位置、视线、轴线、动作方向、道具状态、光位、环境声和台词尾音。
- **抽帧/承接要求**：说明生成前关键帧目标和生成后实际抽帧时刻；两者不得互相覆盖。

### 节奏流水线演示（rhythm_input → 引擎 → 写回）

以下演示同一 SEG 从语义输入到引擎写回的完整链路；数值仅演示格式，实际一律以引擎输出为准。

第一步，LLM 只做语义判断，填写 `rhythm_input_ep_N.json`（片段）：

```json
{
  "episode_id": "ep_2",
  "total_duration_s": 13,
  "engine_version": 2,
  "beat_library_version": 2,
  "style_profile": null,
  "scenes": [
    {
      "scene_id": "E02S01",
      "rhythm_card": {
        "waveform": "中—低—中",
        "main_accent": "E02S01-SHOT001",
        "fastest_beat": "E02S01-SHOT002",
        "slowest_beat": "E02S01-SHOT001"
      },
      "beat_groups": [
        {"group_id": "G01-威胁", "shot_ids": ["E02S01-SHOT001", "E02S01-SHOT002"]},
        {"group_id": "G02-抉择", "shot_ids": ["E02S01-SHOT003", "E02S01-SHOT004"]}
      ],
      "boundary_candidates": ["E02S01-SHOT003"],
      "shots": [
        {"shot_id": "E02S01-SHOT001", "beat_type": "dialogue", "intensity": 1, "spoken_text": "这扇门背后藏着的秘密，你今天必须说清楚。", "action_units": 1, "reaction_units": 0},
        {"shot_id": "E02S01-SHOT002", "beat_type": "dialogue", "intensity": 5, "spoken_text": "我发誓，我真的没有骗你。", "action_units": 1, "reaction_units": 0},
        {"shot_id": "E02S01-SHOT003", "beat_type": "dialogue", "intensity": 3, "spoken_text": "那你告诉我，钥匙到底在哪儿。", "action_units": 1, "reaction_units": 0}
      ]
    }
  ]
}
```

第二步，依次运行引擎三个子命令（镜数对账 → 时长分配写回 → 镜头组校验写回）：

```bash
python3 scripts/rhythm_engine.py shot-count --input rhythm_input_ep_2.json
python3 scripts/rhythm_engine.py allocate --input rhythm_input_ep_2.json --storyboard storyboard_ep_2.json --write
python3 scripts/rhythm_engine.py pack --storyboard storyboard_ep_2.json --input rhythm_input_ep_2.json --write
```

第三步，引擎写回 `storyboard_ep_2.json` 的镜头时长与发票（`duration_basis` 分项加总恒等于 `duration_s`）：

```json
{"shot_id": "E02S01-SHOT001", "duration_s": 5.5, "duration_basis": "台词5.5(18字@4/s)"}
{"shot_id": "E02S01-SHOT002", "duration_s": 3.5, "duration_basis": "台词3.5(10字@4/s)"}
{"shot_id": "E02S01-SHOT003", "duration_s": 4.0, "duration_basis": "台词4.0(12字@4/s)"}
```

`pack --write` 把 SEG001（00:00-00:13，共 13s、3 镜）的划分与每镜 `segment_id` 写回 storyboard；节奏卡的 `fastest_beat`/`slowest_beat` 会被 lint 与 `stats` 实际极值（3.5s / 5.5s）对账。

### 视频参考输入计划

每个 `SEGxxx` 必须在 `storyboard_ep_N.json.segments[].reference_input_plan` 中写入视频阶段的图片输入计划数组。它不是最终 Prompt，也不是已传图证据；它用于提前规定“要传哪些图、按什么职责传、开头如何定位、哪些内容必须剥离”。数组可以为空，但只表示当前片段没有任何真实图片输入：首段可据此走 纯文本视频（`h3` T2VA）；非首段仅当 planned `SEAM=elliptical`，且当前新起点不需要任何媒体锚点时才可为空。`continuous` 非首段必须规划上一段真实 tail FRM。视频阶段真实调用时仍以 `video_manifest_ep_N.json.reference_inputs` 和工具 schema 为准，但不得无理由删除分镜已列为必需的输入职责。

每条计划至少写：

```json
{
  "order": 1,
  "role": "previous_tail_as_start_frame|previous_scene_anchor_reference|previous_character_state_reference|previous_prop_state_reference|segment_highlight_reference|identity_reference|character_state_reference|scene_layout|prop_structure|prop_state_reference|style_reference",
  "planned_source": "KF001|FRM003|CHR001_v01|SCN001_v01|PROP001_v01|STYLE001_v01|用户素材 SRC001",
  "opening_binding": "[project-language binding for localized marker <图片1>/<IMG1> and its reference duty]",
  "adopt": "[project-language adopted subject, state, space, material, light, or style facts]",
  "exclude": "[project-language excluded subtitles, QR codes, watermarks, UI text, unrelated background, or unrelated people]",
  "required": true
}
```

- `order` 是计划顺序；视频阶段若工具实际上传顺序调整，必须同步改写最终 Prompt 的图片编号标记和 `reference_inputs[].order`，不能照搬旧编号。
- 第一段不规划生成式首帧关键帧；视频从已批准资产、已规划高光关键帧（若有）和文字动作合同启动，生成后再抽取真实 `start FRM` 作为事实记录。
- 非首段先读取对应 `SEAMxxx.seam_mode`。`continuous` 时必须把上一段已抽取、保存并登记的真实 `tail FRM` 作为 `previous_tail_as_start_frame` 并优先放在首位；tail FRM 缺失时停止下一段编译并先补齐，不得用上一段视频、其他帧或高光 KF 冒充。`elliptical` 时根据转场锚点和新起点选择当前场景、角色状态、道具或其他真实参考，不要求把上一段 tail FRM 当作 0 秒画面。
- **锚图充分性闸门**：规划 `continuous` 非首段的输入前，先读该 `SEAMxxx` 的 `required_invariants` 与 `proof_requirement`（转场设计合同），并对照上一段末镜景别与画面内容：凡末镜为中景以下（近景/特写/大特写），或 tail 画面不含全部不变量主体（多人布局、群体衣着、远景人物、画外陈设）时，`reference_input_plan` 必须增加一条 `previous_scene_anchor_reference` 条目，`planned_source` 写“上一段真实场景帧，视频阶段生成后补抽登记”（分镜阶段不得伪造 FRM ID），`required: true`，`opening_binding` 与 `exclude` 按本条上方 schema 照常填写，并在 `adopt` 中写明该帧承载哪些布局/衣着事实；视频阶段补抽登记后将该条 `planned_source` 回写为真实 FRM ID。未通过本闸门的 SEG 不得提交分镜用户确认。连续性账本“同场景/角色状态/道具延续时补 scene、character_state、prop_state FRM”覆盖三类帧，本闸门是其中 scene FRM 义务在 `continuous` 接缝上的强制化触发条款，两处对 scene FRM 的登记必须一致。
- 当前镜头或片段使用的角色状态、以及已升级为 PROP 且会复现的道具状态，必须提前解析到 `project_data_card.json` 的 `state_id` 和 approved 状态资产；查找范围包含共享资产库、本集 `episode_assets` 和其他分集已 approved 且在当前集登记为 `reused_episode_assets` 的资产。`reference_input_plan` 里用 `character_state_reference` 或 `prop_state_reference` 指向对应状态图，不能只写角色基准图、道具基准图再靠文字描述需复现状态。一次性道具状态只写入镜头动作和视频 Prompt 意图，不升级为 PROP 输入。
- 场景参考只锁空间、灯光、陈设和布局；风格参考只锁色彩、材质、光线、构图、景深和颗粒/线条语言，不承载剧情人物或道具；道具参考只锁结构、尺寸、材质、当前状态和可见面；不得把不同职责的图片混写成同一个主体。
- 任何用户或外部图片都必须写 `adopt/exclude`。图片中的字幕、二维码、水印、平台界面、无关人物、镜面文字和背景杂物默认剥离，除非用户明确要求保留且权限、剧情和平台风险均已确认。

### 资产使用对账（asset_usage_plan）

`storyboard_ep_N.json` 顶层必须登记 `asset_usage_plan`：它是资产需求清单的结构化同源数据，资产需求清单 Markdown 和视频片段执行表"必需图片输入"列都由它渲染，不得手工另写造成三方分叉。

```json
"asset_usage_plan": [
  {"asset_id": "PROP003", "version": "v01", "segments": ["SEG001", "SEG002", "SEG016"], "reason": "毛驴：赶路/拴喂/骑逃全程伴随主角"},
  {"asset_id": "STYLE001", "version": "v01", "segments": ["*"], "reason": "全局风格 moodboard，每段必传"}
]
```

- `segments` 列出该资产必须显式传入的 `SEGxxx`；`["*"]` 表示全部片段（供 STYLE001、贯穿主场景等全局资产使用）。
- 登记即声明"此资产在这些片段必须显式传入"，lint 双向对账：登记了但某段 `reference_input_plan` 未计划传入是 error；某段计划使用了未登记的绑定是 warning，临时增补必须回头补登。若判断某段靠上一段尾帧携带即可，不登记该段即可——对账强制的是声明与执行一致，不强制必须声明。
- 只登记需要显式图片输入的资产；一次性物件不升级为 PROP，也不进本表。

### 世界事实承接合同（inherited_world_facts）

`storyboard_ep_N.json` 顶层必须登记 `inherited_world_facts`：从剧本继承的季节、节日、时辰、天气等世界物理事实，全片一致，分镜不得改动。

```json
"inherited_world_facts": [
  {"fact_id": "WF01", "category": "festival", "statement": "时为中元节（农历七月十五）", "source": "剧本1-5"},
  {"fact_id": "WF02", "category": "season", "statement": "初秋，夜凉有露", "source": "剧本1-4/1-9"}
]
```

- `category` 枚举：`season|festival|date|time_of_day|weather|location_fact|other`；每条必须写明 `source`（剧本场次/行）。
- 分镜表、总控卡、执行表中的任何季节/天气/温度/时辰/节日类感官细节必须能引用本表一条；lint 强制本表存在且要素齐全，语义矛盾（新增细节与继承事实冲突）由剧本-分镜对照审校步骤核查。

### 转换差异台账（beat_coverage）

`storyboard_ep_N.json` 顶层必须登记 `beat_coverage`：剧本每条动作/事件的去向，同时渲染为用户可读的 `分镜_转换差异台账_ep_N.md` 随阅读稿提交确认。

```json
"beat_coverage": [
  {"beat_id": "1-8-a", "scene": "1-8", "summary": "谭九出门小解", "disposition": "kept", "target_shots": ["E01S08-SHOT001"], "reason": ""},
  {"beat_id": "1-9-a", "scene": "1-9", "summary": "谭九靠墙根躺下", "disposition": "compressed", "target_shots": ["E01S09-SHOT002"], "reason": "压缩为一个动作提示"}
]
```

- `disposition` 枚举：`kept|compressed|moved|dropped`。`kept/compressed/moved` 必须给出 `target_shots`（真实存在的镜头）；`dropped` 必须给出具体理由。
- **过渡性动机动作**（解释角色为何在某处、为何处于某状态的动作，如小解、添灯、拢火、栓门）默认不得 `dropped`，只能 `compressed` 为视觉提示——这类动作不推动冲突，在戏剧节点拆节拍时最容易被当成冗余删掉，而观众恰恰靠它理解空间与动机。
- "必须覆盖全部剧情"靠这张表核销：每条剧本 beat 都有登记行，删除必须有理由，无登记即漏拆。

### 关键帧需求决策

关键帧需求清单在分镜阶段完成，由主 Agent 根据已确认剧本、导演总控卡、十五列分镜、片段执行表和连续性账本决定。用户只确认可读分镜稿和镜头方案；确认后关键帧阶段按清单生成，不再临时挑普通画面代替。若关键帧阶段发现分镜选点缺少剧情峰值、缺状态资产或画面任务混杂，返回分镜或资产阶段修正。

关键帧按集规划而不是按 SEG 配额：每集张数由 `kf-count` 公式按集总时长算出区间与建议张数（公式与演算例见 `keyframes.md`，常数以《节拍类型库》§5 `kf.*` 为准），只落在观众必须看懂的高潮画面，例如证据露出、动作落点、关系反转、危险逼近或不可逆选择，不落在普通首帧、普通尾帧、角色展示或纯气氛镜头。未选中的 SEG 不补关键帧；多 SEG 项目中单个 SEG 通常 `0-1` 张，单段上限以《节拍类型库》§5 `kf.per_seg_max` 为准，只有同段承载两个独立集级峰值时才允许顶到该上限；整集只有一个 SEG 时，该段承载本集公式区间内全部互不重复的高光职责。第一段仍不额外生成首帧；`continuous` 非首段由上一段真实 tail FRM 承接，`elliptical` 非首段按已规划新起点开始。

优先生成关键帧的场景：

- 信息揭露、身份暴露、证据露出、文字证据可读、误会被推翻或观众认知改变。
- 角色做出不可逆选择、抢夺/推开/跪下/拔刀/按下发送等动作落点，或动作前一拍已经无法回头。
- 两人关系发生空间性变化：堵门、逼近、退到墙边、遮挡出口、夺走道具、站位高低翻转。
- 角色状态或已升级为 PROP 的道具状态会延续到后续片段：换装、受伤、血迹、开合、破损、易主、内容物露出、屏幕/信件/牌匾出现文字。一次性道具状态变化不触发资产补图。
- 多人同框、复杂遮挡、POV、过肩、镜面、门窗前后景、低光或强色温变化，视频容易漂移。
- 片段中后部承担悬念、危险逼近、声音桥或状态变化时，优先选择能让观众读懂结果和代价的高光瞬间；下一段承接仍以真实 tail FRM 为准。

通常不单独生成关键帧的场景：

- 删除后不影响剧情理解的纯氛围、纯运镜、纯场景展示或装饰性空镜。
- 只有“看向远方、低头沉思、站在原地”等弱动作，且没有新信息、道具状态或关系变化。
- 已由人物、场景、道具资产稳定覆盖的外观展示镜头。
- 可由视频 Prompt 稳定完成的简单动作过程，例如普通走路、坐下、转头、拿起杯子。
- 同一片段内重复的反应特写；除非第二次反应带来新的认知、选择或关系后果。

每张待生成关键帧在需求清单中写清：所属 `SEG` 和镜头、高光序号、准确时间点、单一戏剧任务、选择理由、画面焦点、主要人物屏幕位置和关系、必须传入的角色/状态/场景/道具/风格参考、画面内文字要求、从上一镜继承什么、给下一镜留下什么。画面任务不能同时塞入身份介绍、情绪展示、证据特写和动作高潮；冲突过多时增加第二张高光关键帧，或回到分镜拆镜。

### 因果链台账（causal_ledger）

`beat_coverage` 回答「每条剧本 beat 去了哪」；`causal_ledger` 回答「**跨镜头的因果链条是否闭合**」。它要截住的问题是**因果断点**：观众在某个观看点上用来理解「为什么会这样」所需的事实，在该时间点既不可见也不可得——要么从未被任何镜头建立，要么虽建立过但当前调度把它遮挡/改写，要么以指称（人称、方位、物品名）出现而没有视觉锚点承接。典型事故形态：剧本写「捂嘴进门，满堂哄笑」，分镜忠实 staging 了捂嘴这个遮挡动作，却没给「肿唇」留可见通道——触发反应的证据被遮挡，哄笑、模仿和明知故问全部失去画面依据。

判定断点的三个锚（审校与台账共用，据此前推，不靠感觉）：

1. **反应必有源**：任何反应类画面（哄笑、围观、震惊、害怕、态度转变、明知故问）都必须能指出一个先建立或同镜可见的触发事实；
2. **证据必可达**：链条依赖的证据在消费它的镜头时间点必须可见或可听，调度（遮挡、景别、焦外、背身）不得把它切断；
3. **指称必有锚**：台词/叙述中的指称在观众侧必须有已建立的视觉锚点或明确的延迟兑现登记。

断点分类学（`breakpoint_risk` 取值，审校归类与台账登记共用）：

| 类型 | 定义 |
|---|---|
| C1 反应无源 | 反应类镜头无已建立的可见/可听触发 |
| C2 证据遮断 | 调度（遮挡/景别/焦外/背身）把下游依赖的证据切断 |
| C3 状态无源/无果 | 状态变化无原因镜头，或原因已演但结果永不出现 |
| C4 指称悬空 | 台词指称无视觉锚点且未登记延迟兑现 |
| C5 动作无果 | 剧情节拍依赖的动作没有反馈/结果镜头 |

台账只登记**含反应/态度转变/证据依赖的链**，不全量复制 beat；schema 与各字段权威定义见 `manifests.md`。在完整分镜表与关键帧需求决策完成后、剧本-分镜对照审校与用户确认前，按以下顺序推导：

1. 逐镜扫 `causal_role`：凡 `reaction|result` 镜，必须有链可归；归不进既有链就新建。
2. 每条链倒查三锚：触发事实是否已建立（前序镜头/资产状态/世界事实）？证据在反应镜时间点是否按 `visibility_contract` 可见？结果是否有落点镜头（可跨 SEG；跨集登记 `cross_episode_refs`）？
3. 台词指称单独过一遍：每个非常规指称登记锚点镜头或延迟兑现。
4. 链合并与拆分：同一触发引发多次反应只建一条链；一个镜头可出现在多条链、一条链的多个角色位。
5. 与 `highlight_bindings` 对账：被亮点覆盖的链只写 `highlight_binding_ref`，不重复登记四步。
6. 关键帧联动：`visibility_contract` 关键的证据镜头列入 KF 优选（适用上文关键帧需求决策的「证据露出」条款）。
7. 跨 SEG 的 `visibility_contract` 条款在分镜定稿时同步派生写入对应 `SEAMxxx.required_invariants`；台账仍是唯一权威，SEAM 卡为派生引用，lint 对账两处一致。

台账同时渲染为用户可读的 `分镜_因果链摘要_ep_N.md`（一两屏可读，每链三列：链｜触发→证据→反应→结果｜可见性合同），随分镜阅读稿、转换差异台账、资产使用摘要同批提交用户确认——它是用户发现「反应无视觉依据」类错误的入口。剧本-分镜对照审校第⑤项（见 `SKILL.md` 分镜硬门五项编号清单）逐条对照本台账核查。轻量模式不建台账：由主 Agent 按同一三锚（反应有源/证据可达/指称有锚）在内部十五列分镜自查，结论随交付包禁区落地，不落 JSON。

### 片段内镜头执行表要求

逐片段另列“片段内时间 / 镜号 / 景别 / 机位 / 前镜状态 / 动作发起 / 摄影过程 / 合理切点或镜内调度 / 后镜续接 / 接触或反馈 / 结果 / 新增信息 / 可选摄影标签 / 焦点变化 / 切出落点”。它必须与完整分镜表一一对应，确保同一片段里的多个镜头不会在视频阶段被合并成一个长画面。

- 每个时间段首尾相接，总和严格等于该片段实际时长。
- 每个镜头都有切入触发和切出落点。
- 相邻镜头在观看距离、构图、视点、摄影过程、画面内变化或节奏上形成有意图的关系；不要求每镜更换运镜类别。
- 每个片段呈现与剧情负载相称的可观察变化；单镜片段可通过摄影、表演、空间、光线、声音或信息变化承载过程，不要求凑足变化次数。
- 片段边界必须落在镜头结束处，下一片段从新镜头开始，不重复上一片段已完成动作。
- 摄影过程不能只填“电影感”或“镜头移动”。应具体写出画面经历和摄影机如何实现它；例如从什么画面开始，沿何种路径或以何种方式改变，过程中什么进入/离开视野，最后停在哪里。示例用于说明描述精度，不作为构图或运镜模板。

## 导演总控卡的逐段执行区

在唯一 `导演总控卡_ep_N.md` 内逐片段填写以下执行区，不另建 `分镜_导演控制包.md`：

| 片段 | 戏剧目标 | 首态 | 尾态 | 镜头职责与删除损失 | 世界坐标/轴线 | 光源锁 | 声音交接 | 专项合同 |
|---|---|---|---|---|---|---|---|---|
| SEG001（分镜01） | 可观察的戏剧目标 | 片段开始的角色、道具、空间和声音状态 | 片段结束的角色、道具、空间和声音状态 | E01S01-SHOT001：删除后观众将不知道具体信息 | 轴线、人物屏幕侧、视线方向和摄影机活动区 | 光源来源、方向、色温和变化 | 台词尾音、环境声或 BGM 如何交接 | 无 / blocking_map / lighting_plan / action_ledger |

- **叙事节拍**：按下节记录钩子、欲望、阻力、策略变化、权力转折、代价、信息差和兑现/悬念，并绑定证据镜头。
- **片段吸引力与段尾功能**：每个 SEG 写 `viewer_takeaway`、`engagement_driver` 和 `exit_function`。观看动力可以是目标/阻碍、动作变化、信息揭示、关系或情绪张力、兑现、仍在进行的行动或真实悬念；段尾可为结果、动作承接、暂缓、转场或钩子。真实 `hook_landing` 保留为可选字段，不能为技术分段伪造悬念。相邻 SEG 合看时必须检查前段留下的动作/问题由后段承接、兑现或有意转向，不能因切段造成断裂。
- **台词证据链**：把关键身份、指控、承诺、能力、秘密和判断绑定到前置来源、可见证据镜头及其剧情后果；角色撒谎或误判时明确标记。涉及关键台词的链条用 `causal_chain_ref: CLxxx` 挂到 `causal_ledger`：证据镜头引用与可见性合同以台账为唯一权威，本条目只保留台词真假/误判标记、剧本来源场次与后果语义，不再列证据镜头号；纯画面链只进台账。
- **场面调度**：双人以上交互、走位、遮挡、道具传递、追逐或打斗必须建立 `blocking_map`，用 T0/T1/T2 记录人物、道具、摄影机和 180 度轴。
- **布光**：复杂光线、昼夜切换、情绪转折或跨片段同场景必须建立 `lighting_plan`，每个光源写清来源、方向、色温、照亮区域和首尾连续性。
- **表演指导**：从导演总控卡继承本集表演总纲，再逐镜落实；同一镜有多角色时每个角色单独一行。

| 镜号 | 角色 | 表面策略 | 内在压力 | 情绪层次 | 微表情目标 | 肢体语言 | 呼吸节奏 | 禁止表演 |
|---|---|---|---|---|---|---|---|---|
| E01S01-SHOT003 | 林远 | 假装平静结束谈话 | 害怕承认自己仍在等待 | 克制的崩溃 | 眼眶红但不落泪，下颌短暂收紧 | 手指无意识攥住衣角，肩线不塌 | 呼吸变浅，回答前停一拍 | 嚎哭、持续瞪眼、夸张颤抖 |

逐镜声音必须能回指导演总控卡的三层环境声和 BGM 曲线；静默写清移除哪些声音、持续多久、结束触发是什么。逐镜色彩与光线必须回指色彩叙事合同的基准色或触发节点，不得只写“冷色高级感”。
- **动作账本**：打斗、追逐、抢夺、跌落、复杂接触或多人同步动作必须建立 `action_ledger`，按“起势 -> 位移 -> 接触/落空 -> 反应 -> 结果”拆拍；超出生成稳定性时拆镜或改用反应、遮挡、声音暗示。
- **剪辑动机**：每个切点必须由动作、视线、遮挡、物件、声音、反应、空间或信息变化驱动；“为了丰富镜头”不是动机。
- **片段内镜头执行表**：按上文「片段内镜头执行表要求」的固定十五列逐片段列出（定义与各列要求见该节，不另建第二份列清单），确保分镜表中的每个镜头恰好一次编译进视频 Prompt，不遗漏、不重复，也不合并成无节点长镜头。

## 开场、转场与角色表演控制

### 开场镜头合同

每集第一个可观看节拍必须把 `script_contract.opening_contract` 转译为镜头，而非只在台词或旁白中声明。第 1 集必须直接兑现规划 `OPEN001`；后续集可采用剧本中已解释的变体，但仍要在首镜建立与项目承诺的关系。开场类型只确定观众首先被什么抓住，仍必须服务人物目标、阻力和后续兑现：

| 主开场机制 | 首个可观察承诺 | 镜头设计重点 | 禁止替代 |
|---|---|---|---|
| 悬疑问题 | 可被看见的异常、缺口或未解问题 | 线索可读、视点克制、人物对异常作出行动或错误判断 | 用模糊滤镜、惊吓音效代替线索 |
| 世界观震撼 | 规则、尺度或秩序与人物处境的碰撞 | 奇观必须落到人物目标、代价或行动 | 只有空镜和设定说明 |
| 人物塑造 | 人物独有策略、习惯或失控裂缝 | 先让人物做选择，再解释背景 | 靠旁白贴标签 |
| 视觉奇观 | 一个无法被普通画面替代的视觉事件 | 构图、尺度、反应和后果连续出现 | 只展示漂亮场景 |
| 冲突驱动 | 双方目标立刻相撞 | 明确谁要什么、谁阻止、第一轮反馈是什么 | 无来源的争吵或突发事件 |

每个开场至少登记：首个时间范围、第一可见承诺、人物或世界的即时反应、升级触发，以及本集兑现或悬念延续的场次。把这些内容同步写入导演总控卡的 `opening_proof`：`opening_scene_id` 必须等于剧本合同的场次，`first_shot_id` 必须是该场次第一个承担开场职责的镜头，其余三项写明实际画面证据。短片不套固定秒数；按实际时长把开场作为首个完整叙事节拍。

开场按已确认 opening contract 执行；只有明确选用黄金三秒机制时才参考该事件检查。任何题材都须尽早建立观众可读的问题、人物、奇观或冲突，但不由精确时长触发固定事件数。最终结尾必须完成结果、反应和落点；除已规划无缝 Loop 外，不得只是回到与开头相似的画面。

### 转场设计合同

转场是两个镜头或两个 SEG 之间的叙事动作，不是后期遮掩错误。每个 `SEAMxxx` 选一个主转场，必要时可附声音桥，但不能把多种无关技巧堆在同一切点。跨 SEG 转场必须采用“双锚单主导”：上一段尾部负责把画面送到可剪切状态，下一段开头负责从该状态迅速接入。由于相邻 SEG 实际上是分开独立生成，双侧 cue 都必须自洽写清画面、方向、速度、遮挡、动作相位和落点，不得写“同上”“相同”“保持上一段”“自然接上”等需要读取另一段 Prompt 才能理解的省略词。

分镜阶段必须先做一次 seam-first 设计，再定稿视频片段执行表：逐个边界判断它是 `continuous` 还是 `elliptical`，选择唯一主锚点，并写清出点动作相位与入点动作相位。连续边界优先使用上一段实际尾态可继承的动作、视线、道具接触、屏幕方向或遮挡物；省略边界优先使用相似构图、物件、声音或明确叙事动机。不要把“自然衔接”“后期看情况”写成转场策略。

| 转场类型 | 出点与入点必须匹配的锚点 | 适用场景 |
|---|---|---|
| 动作匹配 `action_match` | 同一动作相位、方向、速度或受力结果 | 连续行动、交接、反击 |
| 遮挡切 `occlusion_cut` | 前景遮挡物的方向、面积和解除时机 | 过门、掠物、人物交错 |
| 相似构图 `graphic_match` | 画面形状、主体位置、视觉重心或色块关系 | 时空跳跃、意义对照 |
| 甩镜同向 `whip_pan_match` | 同向运动、模糊强度和入画落点 | 失控、追逐、能量转移 |
| 视线/物件匹配 `eyeline_match|object_match` | 视线目标或道具形态、位置、接触关系 | 对话、线索、联想 |
| 声音桥 `sound_bridge` | 声音来源、进入/退出点和画面关系；台词尾音只写声尾性质，不复制完整台词；BGM 必须写可复用的乐器/节奏/音量/情绪职责 | 时间/空间转换、余韵；默认只辅助视觉转场 |
| 有动机硬切/叠化 `motivated_hard_cut|dissolve` | 明确的策略、信息或时间关系 | 不应伪装连续性的转场 |

衔接卡必须先选 `seam_mode`：`continuous` 用于同一行动、空间或无跳跃的时间推进，`elliptical` 用于明确的时间/空间/认知跳跃。再填写 `transition_anchor`、`outgoing_prompt_cue`、`incoming_prompt_pickup`、`required_invariants`、`permitted_deltas`、`proof_requirement`：分别说明匹配什么、上一段末镜如何把动作/运镜/声音送出、下一段 0 秒如何接住同一锚点、无论切法如何都不能变化的事实、计划允许变化的维度、要在首尾窗口中怎样核验。`continuous` 的 `permitted_deltas` 必须为空；`elliptical` 至少登记一项允许变化，且只验收不变量与计划变化的正确性。连续动作优先动作匹配、遮挡切或甩镜同向；跨时空优先相似构图、物件/声音匹配或有动机硬切。无法满足锚点时回到分镜；若视频已生成，则只记录返修建议，等待用户明确确认后再重生或编辑，不能让声音桥掩盖未允许的身份、动作相位或光位错误。

`outgoing_prompt_cue` 与 `incoming_prompt_pickup` 必须成对但不重复：前者写“上一段最后 0.5-2 秒发生什么出画、遮挡、甩动、视线、物件接触或声音延续”；后者写“下一段 0 秒从哪个屏幕边缘、哪种运动模糊、哪个遮挡物、哪个物件位置、哪个动作相位或哪个声音桥快速进入，并在 0.3-0.8 秒内落到本段新主体或新信息”。下一段开头不得再写一个新的转场名或完整重复上一段运镜，只能用可独立理解的具体画面接住该 `SEAMxxx` 的主锚点并继续剧情。衔接卡必须把摄影机运动方向转译成屏幕入画方向：例如上一段“向右甩镜至运动模糊，把门框遮满画面”，下一段应写“迅速从画面左边运动模糊和门框遮挡中接入，遮挡解除后停到新主体”，而不是只写“同向甩镜接上”。

方向必须拆开写清：摄影机运动方向、画面中模糊或遮挡物的流动方向、主体从哪一侧入画或出画、停在哪个景别和位置。不得只写“同向运动”。具体左右、上下、前后按该接缝实际画面设计填写，不套固定方向；若方向无法稳定判断，改用遮挡切、物件匹配、视线匹配或有动机硬切。

常见双锚写法：

| 主转场 | `outgoing_prompt_cue` 写什么 | `incoming_prompt_pickup` 写什么 |
|---|---|---|
| 动作匹配 | 动作切到未完成相位、方向、速度、受力点 | 从略微推进的相位开始，完成结果，不重做起势 |
| 遮挡切 | 哪个前景从哪侧进入、遮挡面积、遮满时机 | 从哪侧遮挡中开场，遮挡如何迅速解除并露出新主体 |
| 甩镜同向 | 摄影机甩动方向、模糊强度、切出前画面被什么吞没 | 从对应方向的运动模糊进入，短时间内停到新景别和新信息 |
| 相似构图 | 形状、主体位置、色块或视觉重心如何占满尾帧 | 以对应形状/色块/重心开场，并立刻揭示新时空或新意义 |
| 视线/物件匹配 | 视线目标或物件接触点在尾帧的位置 | 从目标物/接触点开场，说明看见者或持有者如何变化 |
| 声音桥 | 台词尾音、环境声、拟音或 BGM 的出点；台词尾音只写尾音性质和结束时机；BGM 只在剧情需要时写可复用的具体描述 | 声音从 0 秒继续，但只写非语义尾音、呼吸、环境声或拟音；BGM 逐字复用上一段描述，不把上一段完整台词再写一遍；画面动作仍要有具体入点 |
| 有动机硬切 | 上一段以明确结果、反应或信息落点收住 | 下一段快速建立新时空和变化原因，不伪装为连续动作 |

高风险边界必须预先设计桥接方案：当角色太多、同一动作难以由下一段 0 秒稳定承接、场景/光位跨度大、上一段尾帧无法作为真实图片输入，或预定为 `dissolve` 但当前成片工具只支持普通拼接时，增加 `1-2` 秒桥接镜头或独立 `bridge SEG`。真正重叠两侧画面的视觉转场会消耗两侧有效帧，叠加类光效或声音桥不改变主时间轴；分镜必须在 `duration_s` 和接缝卡中提前写清，不能到成片阶段用效果遮掩未设计的跳变。桥接镜头优先使用手部接触、门/墙/衣料/前景遮挡、关键道具特写、同向甩镜、视线目标或声音尾音；它必须承担剧情信息或情绪余波，不能只是空转场。

### 角色表演谱与情绪曲线

关键表演镜头在导演总控卡逐段执行区和 `performance_scores` 中使用时间段表演谱。先在 `performance_coverage` 声明哪些镜头必须有表演谱；确实没有关键表演时使用 `not_applicable` 并说明为什么。每拍使用相对镜头的 `start_ms/end_ms`，首尾连续、不重叠、不得超过该镜时长；内容按“发生原因 -> 基准状态 -> 人物策略 -> 可见脸部动作 -> 目光与身体 -> 声音/呼吸/停顿 -> 听者反应 -> 结束状态”编写；台词只在其触发或改变表演时出现。

| 时间段 | 发生原因/策略 | 基准状态 | 情绪状态与变化 | 可见脸部动作 | 目光与身体 | 声音/呼吸/停顿 | 台词触发 | 听者反应 | 结束状态 |
|---|---|---|---|---|---|---|---|---|---|
| 0-2 秒 | 听见意外称呼，先假装没听见 | 视线落在桌面，双唇自然闭合，肩线稳定 | 防御开始松动 | 嘴唇轻抿后松开，眉心短暂收紧 | 低头，视线避开对方，手指停在衣角 | 呼吸变轻，开口前停半拍 | 无 | 对方停住追问并观察她的手 | 视线准备回到对方 |
| 2-4 秒 | 对方继续逼问 | 视线准备回到对方 | 试探转为亲近或反击 | 眼神变软，嘴角只起极轻微弧度 | 偷看对方后微偏头，肩线轻收 | 声音略拖，句尾保留气息 | 说出关键台词 | 对方听到后收回逼近动作，视线转向她攥住衣角的手 | 维持可被下一镜继承的关系状态 |

- `cause` 必须来自台词、动作、道具、信息或对方反应，不能只写“情绪来了”。
- 每拍 `baseline_state` 写动作发生前观众能够看到或听到的状态；第一拍继承镜头入态，第二拍起必须逐字承接上一拍 `end_state`。变化太复杂时拆拍，不允许用“继续上一状态”绕过。
- 有明确听者、对手或共同在场角色时，`listener_response.mode` 使用 `covered`，逐人写 `character_id`、反应发生时机、可见反应和尾态；独白、无人回应或本拍确实不适用时使用 `not_applicable` 并写具体原因。听者不能只作为静止背景，反应应改变距离、视线、动作、认知或下一轮策略中的至少一项。
- 先写任何观众都看得见的脸部、目光、手势、姿势和呼吸，再按需要以 `AUxx + 1-5 强度 + 时机` 作为辅助校准。AU 不单独传意，不替代自然语言。使用 AU 时必须标为 `human|stylized_human` 且 `face_visibility: clear`；非人、遮脸、远景或无法辨认面部的镜头只写可见行为，不得伪造 AU 精度。
- 一拍只突出一个主要变化；复杂情绪拆成连续拍点。先用 `emotion_curve_coverage` 列出承担转折的角色，或写不适用原因；每条曲线写清 `character_id`、入场状态、压力来源、场次级触发、前后状态、可见证据、关系后果和尾态，分别与项目级曲线、场景攻防和 BGM 曲线对应，但不得让 BGM 或色调替代人物变化。
- 说话前的口唇、下颌、眉眼和身体预备应与语气一致；台词结束后的闭口、视线、呼吸或姿势也必须成为下一拍可继承的状态。

## 连续性账本与片段衔接卡

逐视频片段记录：

| 片段 | 时间范围 | 实际时长 | 首状态 | 尾状态 | 角色与造型 | 道具 | 场景/光线 | 动作趋势 | 声音承接 | 上一段抽帧与承接方法 |
|---|---|---:|---|---|---|---|---|---|---|---|
| SEG001（分镜01） | 00:00-00:12 | 12s | 完整写明 | 完整写明 | 脸部、发型、服装、伤痕、位置、朝向、视线 | 持有者、可见面、开合或破损状态 | 场景时间、天气、主光方向、色温、固定背景锚点 | 动作向量、速度、下一拍 | 台词尾音、环境声或 BGM 入点/出点 | 起始片段；生成后抽取 start/scene/tail，命中换装或复现道具时加 character_state/prop_state |
| SEG002（分镜02） | 00:12-00:24 | 12s | 完整写明 | 完整写明 | 完整写明 | 完整写明 | 完整写明 | 完整写明 | 完整写明 | SEG001 连续性抽帧组中的 tail FRM 作为本段 0 秒首帧视觉基准；同场景/角色状态/道具延续时补 scene、character_state、prop_state FRM，并写动作匹配/遮挡切/甩镜/物件或视线匹配/明确省略剪辑 |

追踪角色身份/状态、服装伤痕、位置朝向、轴线、手持物、道具状态、场景光线、环境声和音乐。**“上一段抽帧与承接方法”列必填**：首段写抽帧计划；`continuous` 非首段写上一段连续性抽帧组如何作为真实图片输入，其中 tail FRM 是 0 秒首帧视觉基准，同场景/角色状态/道具延续时加 scene、character_state、prop_state FRM；`elliptical` 非首段写清时间/空间/认知跳跃、允许变化、新起点及转场锚点，不强制 tail FRM。若连续承接所选工具无法接收 tail FRM，必须改分段方案或返回用户重新选择可接收图片的工具方案，不得静默降级。

每个跨片段接缝必须建立唯一 `SEAMxxx` 片段衔接卡，显式写出“上一片段结尾状态 → 本片段 0 秒开场状态”，并记录：

1. 上一段计划尾态、本段 0 秒开场状态和相关高光 KF；实际 `tail/start/scene/character_state/prop_state FRM` ID 在视频生成后写入 `continuity_ep_N.json`，不得在分镜阶段伪造。
2. 上一段结尾与本段 0 秒开场的角色屏幕位置、姿势、身体朝向、视线方向及当前 `state_id`。
3. 道具持有者、可见面、开合/破损状态及手部接触点。
4. 主光方向、色温、曝光、SCN 场景版本和固定背景锚点。
5. 摄影机轴线侧、机位高度、景别、观察方向、镜头角度和运动家族。
6. 动作向量、速度、接触状态和动作相位；连续动作优先在动作进行到 `30%-70%` 时切出，下一段从同一相位或略微推进的位置切入，禁止动作重做或回弹。
7. 预定切法：动作匹配、视线匹配、物件匹配、遮挡切、相似构图、甩镜同向接入、叠化、声音桥或有动机硬切；不得写“自然衔接”或“后期看情况”。同时写转场锚点、允许变化和首尾帧窗口中的核验方式。
8. 上一段尾部检查窗口与下一段头部检查窗口，默认各 `12` 帧；视频阶段在两段生成后从窗口内选择并记录实际剪切点，成片阶段消费 verified cut；窗口不足、未选出剪切点或接缝未通过连续性验证时，关键接缝标记 blocked，不得以 best available cut 或文件边界兜底；非关键偏差按质量门说明并由用户接受。
9. 原生人声尾音、环境声或 BGM 在切点前后如何延续，以及声音桥的入点/出点；BGM 只有剧情需要同一情绪或同一声源跨段时才使用，并写成可逐字复用的具体描述。
10. `outgoing_prompt_cue` 和 `incoming_prompt_pickup`：上一段导演交付包结尾使用前者，下一段导演交付包开头使用后者；两者必须共享同一 `transition_anchor`，禁止双转场、反向运镜或动作重复。

连续性账本为每个接缝追加：

```text
SEAM ID / 上一片段 / 下一片段 / 上一段计划尾态 / 本段 0 秒开场状态 / 相关高光 KF / 预定切法 / 转场锚点 / 出段 Prompt cue / 入段 Prompt pickup / 允许变化 / 核验要求 / 尾部窗口帧数 / 头部窗口帧数 / 动作相位 / 屏幕位置与方向 / 摄影机角度与运动 / 道具接触 / SCN 与轴线光位 / 声音桥 / fallback
```

若文字继承无法稳定保持同一画面，不追求伪像素连续；应把边界设计成遮挡切、甩镜、动作匹配、视线匹配、物件匹配、桥接镜头或明确换机位，让差异成为有动机的剪辑。分镜定稿前逐个接缝做“硬切预演”：如果按普通拼接直接相接会显得跳变，就必须修改出入点、增加桥接段或改为明确省略剪辑，不能把问题留给成片阶段。

## 参考资料与参考视频

分镜阶段接收用户图片、视频、脚本或风格参考时，先按 `manifests.md` 的 `source_manifest.json` 分类并写明采用什么、不采用什么；跨阶段冲突优先级仍按 `control-contracts.md`。

针对 Seedance 运镜模板类资料：

- 采用：逐镜“景别 + 机位 + 运镜 + 动作”的结构、跟拍/环绕/升降/手持/焦点转移/甩镜/匹配剪辑等候选，以及动作匹配切镜和接缝重复帧排查思路。
- 不采用：默认 `4K/60fps`、固定三秒定格、所有动作都缓慢、每句最多两种运镜等与当前工具 schema 或剧情职责冲突的模板；最终参数以实际工具能力和项目节奏为准。
- 组合名称不能直接复制成模糊 Prompt。必须拆为相邻镜头，或在模型已验证、路径简单时拆成同镜先后两段运动。

参考视频必须拆成六项可迁移导演信息：

```text
reference_structure：段落结构、信息顺序、切点逻辑
reference_pov：机位、景别、视角和观察者身份
reference_motion：主体或环境的可见运动、摄影机轨迹、速度和节奏
reference_emotion_arc：情绪起点、升级、翻转和回报
reference_audio_logic：台词、环境声、拟音、音乐和声音桥关系
reference_risk：需剥离的品牌、人物身份、字幕、口号、水印、平台 UI 和未授权内容
```

只迁移已声明的结构、视角、运动、情绪或声音机制，不复刻原人物、场景、品牌和文字。

## 与关键帧和视频阶段的边界

分镜阶段不生成关键帧、不写最终视频 Prompt，只提供关键帧可执行、视频可编译的事实：

- 稳定场次、镜头和片段 ID。
- 每镜画面、职责、时长、景别、机位、光影、对白、音效、运镜、切点动机、连续性和抽帧/承接要求。
- 每个 `SEGxxx` 的片段内镜头执行表、首尾状态、衔接方法、必需图片职责和预计输入素材类型。
- 人物、角色状态、主要场景、音色、道具状态、风格、关键帧需求清单，以及生成后的 FRM 抽帧计划；状态变化必须绑定已生成或待补生成的 approved 状态资产，不能只留文字状态。

关键帧阶段按已确认职责生成并验收图片；视频阶段再把分镜、资产和已规划 KF 编译成项目语言时间轴 Prompt。每个 SEG 必须具备可传入的当前角色/状态、场景、必要风格依据，以及已升级为 PROP 且本段需要复现的关键道具依据（若有）；只有被选为集级高光的 SEG 才必须具备可传入的高光 KF。这些依据可来自共享资产、本集资产或项目内其他分集已 approved 的复用资产。角色服装、妆发、伤痕、伪装、装具等状态与基准不同，或已升级为 PROP 的道具开合、破损、内容物、归属、可见面等状态与基准不同且会复现，必须在该 SEG 的参考计划中列出对应 approved 状态资产。一次性道具状态只进入镜头动作和 Prompt。非首段还要消费上一段已验收连续性抽帧组。人声必须写明主体、音色锚点、类型、逐字文本和发声窗口；出镜对白要求口型，其余人声要求画面人物不开口。

### 分镜内容人工复核

交付前由创作者逐项查看，不要求代码判断或填写固定报告模板：

| 评估维度 | 达标标准 |
|---|---|
| 镜头职责 | 删除后会损失明确剧情信息，否则合并或删除 |
| 开场承诺 | 第一个叙事节拍实际呈现开场问题、人物、奇观或冲突，并已绑定后续兑现 |
| 摄影表达 | 整场戏的视点、构图、运动、停留和画面变化是否有意图；固定机位占比不得超过 40%，超限按摄影设计规则返工 |
| 切点动机 | 每个切点都有动作、视线、遮挡、声音、反应、空间或信息触发 |
| 连续性 | 轴线、视线、动作、道具、光位和场景拓扑无冲突 |
| 信息密度 | 持续产生行动、反馈、关系、线索或情绪变化，不按固定秒数打点 |
| 风格落地 | 能指出色彩、光影、构图、材质和运镜的证据镜号；STYLE001 只作为视觉语言参考，不引入剧情人物或道具 |
| 表演层次 | 核心角色逐镜具有基准态、表面策略、内在压力、微表情、肢体、呼吸和尾态；有听者时反应可见，且不依赖夸张表演传意 |
| 情绪曲线 | 关键角色的触发、可见表演变化、关系后果和尾态与场景攻防一致 |
| 转场策略 | 每个 SEG 接缝的主转场、锚点、允许变化和帧窗口核验要求明确 |
| 声音叙事 | 三层环境声、BGM 曲线、静默和声音桥均有入点、出点及剧情职责 |
| 色彩叙事 | 主辅色、色温/对比、主体分离和色调偏移有触发节点，并与人物认知或关系变化一致 |
| 可生成性 | 复杂动作、多人同框和长镜有拆镜或降级方案 |
| 抽帧承接 | 每个 SEG 有 start/scene/tail 计划；命中换装、妆发/伤痕/伪装变化或复现道具状态变化时加 character_state/prop_state 计划；每个相邻 SEG 有 SEAM 接缝合同、双侧帧窗口和明确切法；`continuous` 非首段的 `reference_input_plan` 已通过锚图充分性闸门 |

每项填写“通过/不通过/存疑、证据镜号、修改建议”。镜头职责、时间轴、连续性或可生成性失败时阻断进入关键帧阶段。

## 存储与阶段确认

本阶段产物统一进入当前 `ep_N` 的分镜目录；路径、命名和 `storyboard_ep_N.json` schema 只读取 `manifests.md`。

完整模式落盘前检查：

- 当前确认范围内全部剧本场次和剧情均已进入分镜表。
- 导演总控卡可追溯到关系矩阵、镜号或剧情触发点。
- 十五列分镜表完整，时间戳连续，总时长正确，片段时长不超过模型上限。
