# 分镜阶段 Ref

在项目级故事包、当前集详细剧本和资产分别确认后读取本文件，只处理当前集。

## 本 Ref 关键要求

- 分镜只规划镜头、片段、连续性、已确认资产编排和关键帧需求，不生成关键帧、视频或最终 Prompt；正式分镜覆盖当前确认范围内全部剧情。
- 阅读稿结构、`density_profile` 选择与镜数推导：见「用户可见分镜阅读稿」「动态镜头数量」。
- 关键帧总量与选点（实际需求统计、不规划首尾帧）：见「关键帧需求决策」。
- `reference_input_plan` 数组、锚图充分性闸门与 `asset_usage_plan` 对账：见「视频参考输入计划」「资产使用对账（asset_usage_plan）」。
- planned SEAM 是生成前目标；真实 FRM、observed seam 和剪切点只能在视频阶段记录。
- 时间来自本次拍法的过程估计；程序累计并核一致性，不查动作或节拍秒数，不以精度证明真实性。

## 目标

把 `current_episode` 已确认的完整剧本和当前集采用资产逐场转换为可直接指导视频生成和生成后抽帧的分镜交付包。正式交付必须覆盖当前集全部剧情，不得只提供样例、部分镜头、简略提纲或夹带后续集镜头。

本阶段只规划镜头、片段、连续性、已确认资产编排和关键帧需求，不生成角色图、场景图、道具图、音色、关键帧或视频。必须引用 approved 人物/状态、场景、道具、音色和 `STYLE001` 全局 moodboard；按实际用途规划高光 KF，无独立用途时记录零需求并完成该阶段确认，同时说明为什么这些时刻值得成为关键帧，规划视频必需图片职责和生成后 FRM 抽取职责。

每集唯一导演总控卡锁表达策略并解释“为什么这样看、如何剪、如何连续”，分镜主表写“观众看到什么”；最终视频 Prompt 只在 `video.md` 编译。分镜阶段不得写伪最终 Prompt。

分镜阶段只能继承已确认视觉锚点；`style_contract` 缺少可执行风格机制时必须停止并返回 `planning.md` 补齐、递增 revision 和重新确认，不得在分镜阶段自行补选风格。已确认风格存在但需要诊断漂移时，才读取 `电影大师风格库.md`，且只用于解释和校准原有光线、色彩、构图、材质和节奏机制。本文件规定事实、交付结构和执行边界；边界内的镜头职责、观看方式、摄影和剪辑由导演针对当前内容独立设计，不把示例或分类当作必选方案。

四个创作参考库只在遇到具体分镜问题时按 `SKILL.md` 读取协议窄读相关章节，不整库通读；不得因读取候选库改写已确认剧情、结局、人物身份、受众定位、风格合同或资产版本。

## 输入条件

必须具备：

- 已确认并存入 `01_剧本/` 的 `剧本_全局设定与分集总纲.md`、全剧完整剧本和 `项目_事实与假设.md`（读取其已验证事实、未知项、推进假设与项目惯例分栏，分镜不得与其冲突；发现冲突时返回剧本阶段修订）；合并文件必须同时包含“全局故事圣经”和“分集推进总纲”两章。另需已确认并存入 `episodes/ep_N/01_剧本/` 的完整剧本和 `script_contract_ep_N.json`（关系张力从 `script_contract.relationship_tension` 读取，人物状态先取本集 usage 分卡的状态投影，分卡不足时按 ID 定点窄读数据卡 `state_timeline`）。
- 已确认的 `00_制作控制/project_data_card.json`；本集所有出场角色、角色当前状态、需要建立 SCN 的主要场景、已升级为 PROP 的关键/复现道具及声音主体均能解析到稳定 ID 与 approved 当前版本。一次性物件只进入分镜和 Prompt，不要求建立 PROP 资产。
- 已确认且已向用户展示或明确标注复用的当前集人物、场景、道具、音色和风格资产；资产必须来自当前集新增项、共享 approved 库或已完成分集的 approved 复用项，不得引用尚未生成的未来集资产。
- 已确认的项目固定画幅。
- 已确定且已经按 `planning.md` 完成参数确认表的视频模型与片段时长上限；本阶段只继承，不自主切换。
- 用户原始指令、后续修改、原台词、必须出现项和禁用项。

剧本存在未写出的剧情、场次、台词或世界物理事实（季节、节日、时辰、天气、温度）时，返回剧本阶段补齐，不得由分镜阶段猜测。分镜表与总控卡中出现的任何季节、天气、温度、时辰、节日类感官细节（如霜、雪、雨、暑、腊、三伏、清明），必须能引用 `inherited_world_facts` 中的一条；无出处的世界细节视同猜测剧情，必须删除或返回剧本阶段确认。把剧本的文学性感官描写（如“夜凉”）落实为具体视觉元素时，先核对该具体元素是否与世界事实冲突，再落笔。

## 分镜产物分层

内部只生成三份 Markdown 加结构化索引：唯一导演总控卡（含逐段执行区，统一承接片段规划与跨片段连续性）、十五列完整分镜表、关键帧需求决策（登记进 `storyboard_ep_N.json`，不另建文件）；面向用户只展示分镜阅读稿，beat 去向与资产使用摘要作为阅读稿附录 A/B 同批提交确认（见「用户可见分镜阅读稿」），不点名内部制作支撑物、哈希、路径或检查过程。不得用参数确认表中的五列分镜预览表/剧情节奏预览表替代详细分镜。

各文档职责：

- **导演总控卡**：拆镜前唯一的导演决策中心，统一锁定本集视觉叙事、核心意象、场面调度、节奏波形、表演、声音与风格系统；逐段执行区一行一 `SEGxxx`，承接首尾状态（含角色造型、道具、场景锚点、动作向量、声音）、入段承接与 SEAM、专项合同与生成风险；不得另建导演阐述卡、执行表、连续性账本或强风格系统卡。
- **完整分镜表**：一行一镜，固定十五列，包含镜头职责、画面、声音、运镜、连续性和抽帧承接；片段内镜头按 `SEGxxx` 分组阅读，不另建片段内执行表。
- **关键帧需求决策**：把已确认基础资产映射到镜头和视频片段，并定义每张待生成关键帧的职责、构图、状态和连续性，机器字段登记在 `storyboard_ep_N.json`。
- **阅读稿附录**：附录 A 逐条登记剧本每个动作/事件的去向（保留/压缩/移动/删除及理由，由 `beat_coverage` 渲染），附录 B 渲染 `asset_usage_plan` 资产使用摘要，随阅读稿一起提交用户确认。

## 工作顺序

读取按 `SKILL.md` 阶段路由执行，不凭上下文残余编译；lint 报错照 issue 的 message/path 就地修；压缩后按 `recovery.md` 恢复，先核时长合同、源 revision/SHA 与确认来源。

1. 从当前已确认剧本建立源事件与 line_id 索引，整理必要事实、状态和人声；不先锁镜数、SEG 数或秒数。
2. 在唯一导演总控卡明确整场观看关系、观众视点、调度、摄影和剪辑意图；简单设计简单写，复杂空间按风险展开。
3. 形成镜头起始画面、连续发展、人物/物件过程、证据显露、切点和末态。一个 SHOT 是一次连续观察；景别或焦点变化本身不必拆镜，不连续机位须明示切点。
4. 根据已经形成的动作、对白、证据阅读、反应、摄影过程和有意停留估计过程时长，声明起点、先后与并行。允许迭代，不能先发布锁定时间再补摄影理由。
5. 由节奏引擎（rhythm_engine）累计：每镜取所有过程结束的最大值，镜头按正式顺序累计。保留等待/空隙，不自动紧排、删事件、改语速或缩短。规划初估不进入核算。
6. 在真实合法切点声明镜头组，用 pack 核真实能力；内容时长保持原值，请求时长按接口整数合同向上承载。非零技术尾余量须有末镜末态的非人声延续设计，不新增剧情。
7. 登记多对多 beat_coverage、因果/资产/连续继承与真实 KF 需求；实际出点及对应帧在生成后锁定，不能预造未知 FRM。
8. 独立重新读取源剧本和实际分镜，按观众顺序检查整场，再核空间、表演时间、证据、停留及跨 SEG 继承。解决具体问题后绑定本次设计投影和源版本，提交既有分镜确认。
9. 机器工序固定（命令见「节奏流水线」）：改设计只改导演设计与 `rhythm_input`，再 allocate → pack → lint 0 error → 两项语义审校 → `stamp_review.py` 盖章；镜长/区间/依据/SEG 装箱/请求秒/尾余量/`design_sha256` 只由 allocate/pack 写，禁止逆向手填；`content_review` 只由盖章命令写。

## 节奏类型与镜头数量推导算法

先确定观众需要看见、听见和持续观察的内容，再选择连续观察或切换视点。事件与镜头多对多：一个镜头可承接多个事件，同一事件可以跨镜；不以动作/反应计数决定镜数。

`density_profile` 仅可选描述内容负载，不决定秒数、镜数或摄影方法。静止、重复、长观察、极短切点、低信息和无人声均可成立。删除测试要同时考虑空间、压力、时间体验和有意停留，不能只数新信息。必要事实、台词、因果与已确认意图不得因估时偏差被删改。

开场按照当前故事的观看承诺设计，不设固定几秒内的事件数或首镜长度。真实用户明确要求的开场形式按其来源继承。

## 节奏设计

节奏来自观众如何经历事件、等待、证据、反应与摄影过程。先写拍法再估过程，不用规划估时分配场次或镜头额度；beat_type、intensity、speech_pace 都是可选注释，改动它们不改变时间结果。

### 时间推导与真实约束

规划估时是设计前预测；内容计划时长是本次设计的累计估计；请求时长是接口申请长度；媒体实测时长只来自实际文件 probe。累计值不得称为“真实需要”或摄影物理证明。初估偏差不触发准出错误、分数或免责说明，也不自动覆盖已确认 planning。

用户未限定时长则保留初估记录，更新 episode 的 planned_content_duration_s 并展示当前设计计划。真实 exact/target_band 合同由确认 ID 回溯，在独立约束核对层说明冲突，不反推逐镜预算；确需改内容/拍法或目标，由用户按既有流程取舍，不自动压短。

### 源覆盖与先后并行

非人声过程可回指 beat、chain 或 asset_state；after 固定表示本事件开始不早于引用事件结束，可跨镜。程序核声明的依赖、环和引用，不能猜未声明的物理互斥。空隙、有意等待、静止观察不自动删除。具体估计是否可信，回到本次摄影与表演顺读审校。

### shot 机读字段

时间输入、派生结果与设计投影见 manifests 的 rhythm_input/storyboard 合同。duration_basis 是结构化最大结束事件依据；camera_family 可选，只作执行注释；不设固定机位占比、平均镜长、极值分布、角色时间地板或标签时长表。

## 每集导演总控卡

详细拆镜前只生成一份 `episodes/ep_N/02_分镜/导演总控卡_ep_N.md`，同时承担导演阐述、导演控制与风格系统职责，不得再创建平行决策卡。**字段清单（视觉叙事策略/开场承诺与情绪曲线/核心意象/场面调度总纲/节奏设计/节奏波形推导/视觉风格系统/亮点转译）、九步推导顺序与逐字段写作职责以「导演总控卡字段合同」节为唯一权威（随 artifact_write 条件装载）**，此处不重复。总控卡不能只列形容词：每项必须绑定场次、镜号范围或剧情触发点，并在完整分镜表和 `storyboard_ep_N.json.director_control_card` 中可追溯。

## 亮点绑定检查

分镜前读取本集 `script_contract.highlight_ledger`，按 `manifests.md` 的 schema 在 `storyboard_ep_N.json.highlight_bindings` 中逐项绑定。每个 `role=primary` 的亮点须绑定其兑现、结果/反应及后续影响；同一长镜可承担多个职责，跨集余震用 `deferred_aftereffect_ref` 追溯，不为字段凑额外镜头。对应可观察阶段必须写清。绑定必须填写视觉、表演、声音和视频编译说明，某一维度不适用时写清理由，不能统一填写“加强氛围”。任何剧本主要亮点找不到镜头，先返回剧本调整或重拆分镜，不得直接删除。

每个主要亮点按“触发 -> 变化 -> 反馈 -> 结果”推导，不从“需要一个高光画面”倒推装饰性镜头：

1. **触发**：读取 `setup_evidence` 和当前场次前态，选择真正迫使人物或局势改变的台词、证据、动作或规则事件，并绑定观众可见/可听的镜头。
2. **变化**：写清触发后谁采取了什么不可忽略的策略，人物位置、道具控制权、信息归属、关系或危险如何发生可见变化；只写情绪形容词不成立。
3. **反馈**：给出对手、听者、环境或规则的即时回应，让观众确认变化被世界接住。反馈必须改变下一拍策略或认知，不能只补一个无后果惊讶特写。
4. **结果**：写清本场或后续场次留下的代价、权力重排、选择后果或余震。结果可延迟到后续集，但必须通过 `deferred_aftereffect_ref` 指向明确回收点。

四步按顺序写入该亮点的 `causal_chain` 并绑定 SHOT；再把变化/兑现镜头映射到 `payoff_shot_ids`，反馈镜头映射到 `reaction_shot_ids`，结果或余震映射到 `aftereffect_shot_ids` 或跨集引用。同一 SHOT 可以承担相邻两步，但必须分别写出可观察状态；若缺触发、反馈或结果，返回剧本补因果，不得用慢动作、强音乐、发光或群众惊叹替代。

## 受众执行检查

分镜只能继承已确认 `drama_plan.json.audience_plan`，不得重新选择受众、平台或地域。在 `storyboard_ep_N.json.audience_execution` 中按 `manifests.md` 分别登记观看焦点、情绪回报、平台观看场景和表达禁区的执行合同，并把每项绑定到真实场次或镜头。四项都必须可追溯；仅写“符合受众”“适合平台”或重新引用受众库标签不算落地。

## 导演总控卡字段合同

> 本节规定每集正式拆分镜前必须完成的唯一导演判断，以及这些判断如何进入逐镜表和视频 Prompt；不把整张总控卡塞进每个 Prompt。

### 职责边界

- `导演总控卡_ep_N.md`：每集唯一整体创作判断，先于逐镜表完成，并在同一文件内把判断落实为每个 SEG 和 SHOT 的调度、布光、表演、声音、动作与剪辑合同。
- `storyboard_ep_N.json`：保存总控卡文件指针和可执行字段，不复制长篇说明。
- `video.md`：只编译已确认导演总控卡和分镜，不重新发明导演方案。

### 每集导演总控卡

固定文件：`episodes/ep_N/02_分镜/导演总控卡_ep_N.md`。至少包含：

- **视觉叙事策略**：观众如何被安排去看：主要观察距离、主客观视角、空间压力、运动与静止分工、何时拒绝特写、何时让环境压过人物。禁止只写“电影感、压迫感、高级感”。
- **开场承诺与情绪曲线**：继承 `script_contract.opening_contract`，写清首个叙事节拍如何被看见、谁先反应、什么使其升级、在哪场兑现或延续；再把项目级 `emotion_design` 细化为关键角色情绪曲线（六项要素与 `emotion_curve_coverage` 见「角色表演谱与情绪曲线」）。
- **核心意象**：按实际用途选择道具、动作、空间、色彩或声音母题，记录“首次含义 -> 变奏 -> 高潮重释 -> 结尾余韵”。每次出现必须增加信息或改变意义；无变化的装饰不算核心意象。
- **场面调度总纲**：继承关系张力表，说明权力差、信息差、情感差如何通过距离、屏幕位置、纵深、遮挡、出入口、道具控制权变化。允许反讽调度，不套“强者站高、弱者站低”。
- **节奏设计**：标记需要快切、连续表演、停顿、长镜或突然中断的段落及戏剧原因。快切用于信息压缩或失控，长镜让选择和反应无法逃避；不得用速度掩盖场景无转折。
- **节奏波形推导**：记录必要内容、观看意图、切镜/连续观察选择与从具体过程推导的时间；波形与强度序列仅为可选描述，不预分配额度。波形从不可移动节点与主重拍的关系推导命名（如“蓄压 -> 刺点 -> 回落”“结果前置 -> 倒推线索 -> 原因揭示”），不自建固定菜单逐一点菜；不得固定切成 `0-3 / 3-7 / 7-11.5 / 11.5-14 / 14-15`。
- **视觉风格系统**：媒介形态、构图骨架、光线方向、色彩关系、材质、镜头质感、字体/版式、明确剥离项。它是总控卡的一部分，不单独维护风格系统卡。
- **亮点转译**：逐项读 `script_contract.highlight_ledger`，写清观众先看到什么、哪个动作兑现、表演如何泄露真实意图、声音何时进出、哪个镜头保留余震。信息重释重证据反应，关系攻防重距离/遮挡/道具控制权，专业能力重流程与策略修正，母题重重复变奏，表演瞬间重表面策略与泄露动作，情绪余震重高潮后的结果镜头。

### 总控卡逐字段推导方法

按下列顺序从上游事实推导，不允许先写形容词再找镜头佐证：

1. **建立输入表**：读取 `creative_proposition`、`opening_contract`、`highlight_ledger`、`script_contract.relationship_tension`（关系张力）、场次 entry/exit state、`emotion_design`、`rhythm_design`、`style_contract`、本集 usage 分卡投影的数据卡空间/状态（不足时按 ID 定点窄读数据卡）和用户镜头禁令。每条标记来源场次；冲突时回到最早权威阶段，不在卡中私自折中。
2. **推导观察者立场**：先问观众应比谁知道得多、与谁同处压力、何时看清证据；据此定主客观视角、观察距离、环境与人物画面占比，再绑定场次范围，形成“视觉叙事策略”。
3. **推导核心意象**：按「核心意象」标准，从重复出现且意义会改变的动作、道具、空间、色彩或声音中选实际需要的对象；删掉不影响理解或意义不变的不选。
4. **推导场面调度**：把关系节点的权力差、信息差、情感差翻译成世界坐标中的距离、纵深、遮挡、出入口、视线、道具控制权；先写 T0，只记录触发后的 T1/T2 变化。机位服务调度，不得为构图暗中移动人物或房间。
5. **推导节奏与表演**：从不可移动节点与主重拍分配快切、连续表演、停顿、静默；对承担转折的角色写“表面策略 -> 内在压力 -> 泄露动作 -> 对方反馈 -> 尾态”。无因果触发的表情、呼吸、停顿删除。
6. **推导声音**：按下方三层声音的顺序推导，再决定 BGM 入退、静默和声音桥。若声音与对白争夺同一信息，把非主信息后移或降低，不同时强调。
7. **推导色彩和风格**：逐项继承 `style_contract`，按「色彩叙事合同」写基础光源、主辅色、材质、构图骨架；无世界内原因或剧情触发的自动变色删除。
8. **绑定执行范围**：每项决策落到场次、SEG、SHOT 范围或明确触发点，并在逐段执行区写首态、尾态、删除损失、专项合同。无法绑定任何镜头的不是本集执行决策，删除或回上游补依据。
9. **一致性检查**：逐项问“服务哪个剧情问题、在哪镜可见、变化由什么触发、视频 Prompt 继承哪部分”，任一无答案即重写；不同字段要求互斥动作、光线、声音或观看立场时，以核心证明和用户锁定项为先，不并留。

### 表演指导合同

AI 表演用可观察层次，不靠抽象形容词或只有微表情。关键镜头按逐段执行区表演指导表固定字段写齐（镜号、角色、表面策略、内在压力、情绪层次、脸部/目光/肢体/呼吸变化、触发点、尾态、禁止表演）。

- 表面策略决定人物在做什么；内在压力解释动作为什么泄露。
- 微表情只作增强，关键信息同时由动作、距离、道具、声音或结果承担。
- 表演变化按观看顺序展开；连续镜头可承载多个变化，是否切镜由观察关系与动作完整性决定。
- 有听者时单独写听者反应及尾态（机器写法见「角色表演谱与情绪曲线」`listener_response`），不得只细化说话者。
- 禁止“夸张震惊、持续流泪、机械点头、全员同一表情”等默认失控表演。
- 可绑定 `performance_scores`/`performance_coverage`，但不替代自然语言动作因果（写法同见表演谱）。

### 声音设计方案

每集先写整体声音命题，再逐段落实三层声音：

- **基础环境声**：房间底噪、空调、电流、远处车流等，用于空间和连续性，不抢对白。
- **叙事性环境声**：钟声、雨声、脚步、门锁、机器停转等，每次出现必须改变信息或预期。
- **情绪性主观声**：心跳、耳鸣、闷化、呼吸放大等，只在人物感知被触发时短暂进入，并写退出点。

BGM 不得持续填满，也不得只写“低频 BGM”“紧张音乐”“悬疑感音乐”。每条 BGM 写清入点、退点、乐器/音色、速度或节奏、音量、质地、情绪职责、对白避让；跨 SEG 延续时下段复用上段已确认 BGM 描述或 `bgm_descriptor`。

- 静默写明移除哪些声音、保留哪些身体或空间声、持续范围、人物感知和结束触发。
- 完全静默只在世界逻辑或主观听觉成立时使用；通常保留呼吸、布料、空间反射更可信。
- 声音桥登记来源镜头、目标镜头、声音主体、跨越时长、叙事作用、淡入淡出，优先环境声、拟音、动作声或非语义人声尾音；音乐桥仅限剧情确实需要。台词尾音写法见转场设计合同声音桥行。

### 色彩叙事合同

色彩首先是项目已确认风格的子系统，其次才承担本集变化。禁止把冷蓝、暖橙、红色等机械等同于固定情绪。

色彩脚本写清基础主色、辅色、禁用色/冲突色、人物色彩归属、变化触发、光影路径和高潮状态。色彩变化必须能在光源、时间、天气、实景灯、服装、人物移动或空间转换中解释；认知改变不等于画面自动变色。关键段记录基准主辅色、色温/对比、肤色与主体分离、可见触发、跨镜继承或允许偏移，不要求固定色值。

### Prompt 编译

- 视频 Prompt 不照抄十五列分镜表；以阅读稿逐镜语言为骨架，抽取景别、机位、运镜、时长、声音、动作桥、连续性、抽帧承接等硬信息，结合 `reference_input_plan` 真实图片职责，改写为 `video.md` 的五段式导演交付包；交付包连同真实媒体及职责交给 `h3-prompt-writing` Skill 判断模式与参考用法并编写 H3 成稿。每个镜头恰好编译一次。
- 每个 SEG 只采用总控卡中实际绑定本 SEG 的条目，不整卡搬运。
- 阅读稿、十五列表和 JSON 不一致时，先回分镜修订；视频阶段不得自行取舍。

## 场次、片段与镜头

“场次、视频片段、镜头”不得混为一层：

- **场次**：连续戏剧空间或连续戏剧行动，使用 `E{集号}S{场号}`，例如 `E01S01`。
- **视频片段**：一次视频模型调用容器，使用 `SEG001`、`SEG002`；它可以包含一个或多个完整镜头。
- **镜头**：一次不间断观看位置，使用 `E01S01-SHOT001`；单个镜头不得跨两个视频片段。

模型时长只决定提交方式，不反向决定剧情节奏。不得为了填满模型上限把无关镜头塞进同一片段，也不得把重复裁切、数字推拉或无信息变化的构图算作新镜头。

群众/群体出现在分镜中时，先判断它是已登记的稳定群体还是一次性匿名背景人群。稳定群体的 CHR 作为一个集体 actor ID 写入该镜 `actors`，不得为匿名成员虚构单体 CHR；具名、发言或承担独立因果动作的成员另列单体 CHR。逐镜调度另写实际可见人数、前中后景分布、站位区域、运动方向和群体反应时序；群像画像只锁群体构成和视觉特征，不替代逐镜调度或 SCN 空间布局。需要跨镜维持成员位置/服饰/人数时，在 `reference_input_plan` 指定可见布局锚点；非首镜和 `continuous` 接缝按真实 FRM/SCN 锚图合同补齐。

## 片段与时长

- 镜头内容时间由同源过程累计，不要求等于规划初估。各镜头内容区间按正式顺序相接；镜内过程可以并行或有意留空。
- SEG 是一次生成容器；内容时长保留小数，请求时长按 h3.json 的整数能力承载，tail_handle_s 记录差值。余量只延续既有末态，不补戏、不延长或重复台词。
- 合法组边界由导演确定；超能力即报告具体冲突，保留原设计，不自动切镜、重排、改语速或换模型。
- 真实钩子、动作承接、自然转场、结果或余韵都可以承担段尾；不为技术切段强造悬念或停留秒数。
- 一镜到底只登记一个 SHOT，路线、观察与停留按内容展开，无节点数量配额。用户锁定的一镜到底不得静默改成剪辑。

### 尾态选择算法

先看下一段是否继续同一行动/空间，再选择 continuous_motion、cuttable_completion、stable_hold 或 loop_continuation。写清可见动作相位、方向、接触、声音与下一段如何继续；不套百分比或固定尾停。停留本身有观看作用即可保留。

### 真正一镜到底的场面调度算法

先明确起始画面、连续可通行路线、观察对象、遮挡/出入口、轴线及终点；复杂走位按「调度、布光与动作合同」写清世界坐标，简单固定观察不填复杂坐标。顺读每个位置到下一个位置，必要过程完成后估时；无法连续通过时设计明示切点，用户锁定连续观察时说明冲突。

## 高密度剧情与运镜

紧凑不等于机械碎切。连续微事件合并为一个剧情动作组，同一行写完整“切入触发、画面发起或变化、主体/环境/物件反馈、结果变化和切出落点”；无人物动作时按实际画面过程填写，不写抽象标签或“镜头跟随”。先弄清戏剧过程和空间事实再决定观众如何经历，保留完整动作因果与所需信息，不把技术切段当成创作方案。

## 动态镜头数量

镜头密度从内容节点和完整动作推导：每镜通常服务一个可观察的信息、动作、反应或关系变化，秒数由对白朗读、动作起势与完成、反应停顿和切点决定。一律用删除测试、动作完整性和观看关系证明必要性，不因某个 SEG 恰为 15 秒而设最低镜数，不为凑数量拆断完整动作，也不把慢推、凝视、轻微呼吸、重复反应或无信息变化的数字裁切算作镜头变化，不用慢动作或无意义空镜填时长。删除后不影响剧情、关系、信息或连续性的镜头合并；关键职责被一句台词或静止画面含糊带过时，重新设计观看过程。

一镜到底只登记一个镜头且须满足真实连续拍摄定义，镜内仍包含连续变化的摄影机路线、主体行动、关系、空间或信息节点。镜头可由多个连续摄影阶段构成（移动、停顿、转向、改变观察对象或焦点中自然演进），不要求一镜一种运镜，也不以增加运动次数为丰富度目标；片段内允许切镜，每个切点须有可理解的观看或叙事作用。

人声按剧情需要选出镜对白、旁白、画外音或内心独白，句句推动剧情、关系、信息或反应；可跨相邻镜头连续，但不靠拖长停顿填时长、不靠加速语速塞进短镜。字幕生成、样式和烧录只继承 `delivery.md`，视频模型阶段禁止画面字幕和自动转写。

## 动作桥与观看关系

每个跨镜动作和每个切点都按以下链条设计：

```text
前镜状态
-> 动作发起
-> 运动路径
-> 合理切点或镜内调度
-> 后镜续接
-> 接触/反馈
-> 结果
```

每次切镜必须明确回答“为什么现在切”“用什么承接前一镜”“切后增加了什么新信息”。承接锚点只能来自动作、方向、主体位置、视线、形状、光色、声音、文字、遮挡或产品状态中的实际可见/可听事实。动作桥示例包括“拿取 -> 移向入口 -> 接触 -> 收纳结果”“铺垫 -> 触发特效 -> 环境响应 -> 结果停留”（涂抹、上脸等同类连续操作同构，按同链路补位移与反馈节点）。不得从动作发起直接跳到结果，也不得让手、人物、产品或道具在切后无路径换位。

## 单镜因果检查

先对整场核人物目标、阻力、策略、反馈和局势变化，再看各镜实际承担哪一部分。并非每镜都要完成整套戏剧链；空间观察、环境、静默、反应或有意重复可以独立成立。关键反应有来源、证据可达、指称有锚。

## 运镜与镜头差异化

导演先判断整段内容最值得如何被观看，再设计镜头。画面变化可由摄影机、人物、物件、空间、光线、遮挡、声音或剪辑共同形成，不要求运动围绕人物，也不要求每镜都变化。运镜描述必须让人能想象起始画面、过程变化和最终画面：按需写明摄影机位置/路径、朝向、速度质感、焦点和停留，不为未使用的维度填参数；复合运动按真实先后写成连续阶段，不必压成单一运镜名称。

运镜术语是准确表达已选拍法的词汇，不是按剧情类型查拍法的索引：先形成完整画面设想，再选最贴切的语言，允许混合与非典型手法，不先选名词再配戏。`camera_family` 只是可选粗略注释，不代替摄影过程，不以运动占比证明质量；固定镜或重复构图是否有效按当前观看意图独立审校。工具执行稳定性是定稿后的实现判断，不形成运镜清单或创作限额，技术风险不能静默改掉已确认意图。

需要运动时，先问摄影机为何此刻接近、离开、跟随、落后、等待或改变观察对象；速度、力度和稳定性来自具体路线与场面关系，不从 beat 标签对位，静止也可承担压力和时间体验。整场质感相似可以是有意选择，发现单调时回到观看过程找具体问题，不按原型表补急推、甩镜或快慢配额。

「镜内运镜编排」写法：先用自然语言形成起始画面、连续发展与最终画面，再按已形成过程添加局部时间标记；过门/车、镜面或屏幕、多人交叉、手与道具操作、绕障碍和跨轴等风险需要更细说明，beat 标签不触发事件数量要求。多个摄影阶段可同镜连续发生，路线不连续时明示切镜，不压成一个标签。采用 POV 时写清所属视点和实际可见身体部分，不能同镜无因跳为自拍或外部机位。

## 对白时长预算

所有实际人声都回指稳定 line_id，以本次演读的导演估计或实存本句音频测量登记为 utterance。估计含本次设计的呼吸/停顿，不自动加固定起势/句后秒数；音色样音不是本句时长证据，不为估时调用 TTS。

speech 与动作、摄影、阅读、反应根据已形成设计安排先后或并行，每镜取最大结束点；不把它们一律相加。连续一句跨镜分片须恰好覆盖完整 utterance 且在集绝对时间首尾连续，不逐镜重启或补停顿。优先避免跨独立 SEG 拆连续发声，确需跨 SEG 时要有真实可执行声音承接方案。

无人声、环境声、静默和无 BGM 都合法；不以人声占比、汉字速度或单句字数判空转。已确认台词逐字保留，窗口不足返回具体设计，不加速或删字。人声主体、类型和口型职责保持原合同；导演包可用现有花括号表示源文本，H3 的实际发声块以并列 Skill 为准。

## 用户可见分镜阅读稿

`分镜_阅读稿_ep_N.md` 必须使用适合用户审查的顺序，不展示内部 JSON、哈希、字段名或校验结果。结构固定为：`## 第X集：[可读标题]` → `### 本集故事提要`（一段话：主线/冲突/高潮/钩子）→ 每章 `### 第N章：[章节名]（本章时长 / 起止）` 配一行叙事功能引用 → 每片段 `#### 片段N：起止时间（含镜数）` 下逐行列镜头：`**镜头K (绝对时间)**：[景别｜视点｜摄影设计｜机位/角度] 首镜给可见信息事件、中镜写过程变化、末镜写结果代价与尾态承接`。

- 章节按照剧本的章节与场次映射排列，不能只写“第一章、第二章”的空标题。
- 片段起止时间一律写引擎 `pack` 校验与写回后的内容计划值：非 15 秒段是正常形态；段不足上限无需解释，顶满模型上限（如恰好 15 秒）反而必须能用镜时长之和解释。但单段不得低于 `tools/video/h3.json` 能力档案的 `min_duration_s`（4 秒，`max_duration_s` 15 秒，仅整数秒），过短段必须合并或重划。
- 每个片段必须按“动态镜头数量”列出足量分镜，镜头时间首尾相接并覆盖完整片段。
- 每个镜头行必须包含：镜头编号、绝对时间、景别、视点、摄影过程、画面动作、声音、人声文本或“无”、切入/切出方式。摄影过程按该镜实际设计填写；静止镜头可说明构图与画面内变化。
- 听得见的人声一律写成 `说话人：{原文}`，例如 `旁白：{门已经开了}`；音效用 `<具体声音>`；BGM 用 `()` 或 `（）`；标题、品牌字、时间地点等画面文字用中文引号 `“”`。字幕源使用 `【】`，只在用户明确要求字幕时登记，并明确不由视频模型渲染。
- 分镜阅读稿可以保留自然语言章名、片段名和故事提要，但不得省略完整镜头列表，不得用参数确认表的剧情预览替代正式分镜。
- 镜头列表之后固定附两个确认附录，均由 `storyboard_ep_N.json` 现场渲染、不手工另写：`## 附录 A：剧本节拍去向` 渲染 `beat_coverage`，逐条列节拍、`disposition` 四枚举、目标镜头或删戏确认依据；`## 附录 B：资产使用摘要` 渲染 `asset_usage_plan`，逐条列资产、类别、版本与绑定片段。两份附录是用户发现映射类错误（剧情被删改、资产漏绑定）的入口，随阅读稿同一确认门提交，不另建文件。

### 各列要求

- **场次**：稳定 ID 使用 `E{集号}S{场号}`，并保留剧本中的人读编号。
- **视频片段**：稳定 ID 使用 `SEG001`、`SEG002`；同一片段内镜头总时长不得超过所选模型上限。
- **镜号**：稳定 ID 使用 `E01S01-SHOT001`，末尾序号在当前场内连续、不重复、不跳号。
- **镜头职责**：写**可验证**的剪辑职责，判据是删除损失具体可指：删掉这一镜观众失去什么具体信息/因果/关系变化（“删后不知道钥匙在爸手里”合格；“推进剧情”“承载叙事功能”不合格，同义词平移不算）。
- **时长**：写绝对起止时间和本镜持续秒数，与台词、动作、停顿和切点匹配。
- **画面描述**：写清主体、空间位置、朝向、视线、动作起点、轨迹、反馈、结果和剧情变化。
- **景别**：明确大特写、特写、近景、中景、全景、远景、大远景、过肩或 POV。
- **机位/角度**：明确摄影机高度、观察方向、主客观视角和镜头感。
- **光影氛围**：明确日夜、内外景、主辅光方向、色温、明暗层次、材质反射、天气和情绪效果。
- **对白·旁白**：写明说话人、声音类型和完整文本；用户文本逐字按原顺序保留。
- **音效**：环境声和拟音使用 `<具体声音>`，BGM 使用 `(具体音乐)`，写清进入、持续、淡出或承接时机。
- **摄影过程**：写清画面如何开始、变化、结束；按需描述机位路径、朝向、运动质感、焦点变化、停留与剪切。多阶段设计按时间顺序完整表达，不强行归并成一个运镜标签；高动作/钩子镜可用「镜内运镜编排」写法（见「运镜与镜头差异化」节）。
- **切入/切出动机**：登记为 `cut_motivation` 八枚举之一，lint 按枚举校验：`match_on_action` 动作、`eyeline` 视线、`occlusion` 遮挡、`sound_bridge` 声音、`reaction` 反应、`spatial` 空间、`information` 信息、`motivated_hard_cut` 有动机硬切；物件引导切点按实质归 `eyeline` 或 `information`。
- **连续性要点**：记录屏幕位置、视线、轴线、动作方向、道具状态、光位、环境声和台词尾音。
- **抽帧/承接要求**：说明生成前关键帧目标和生成后实际抽帧时刻；两者不得互相覆盖。
- 同一片段内相邻镜头必须在观看距离、构图、视点、摄影过程、画面内变化或节奏上形成有意图关系，不要求每镜换运镜类别；每片段呈现与剧情负载相称的可观察变化，单镜片段可由摄影、表演、空间、光线、声音或信息变化承载，不凑变化次数。片段边界落在镜头结束处，下一片段从新镜头开始，不重复上一片段已完成动作。

## 片段规划与机器合同

`SEGxxx` 级规划不另建执行表文件：时间范围、实际时长、包含镜头、`density_profile`/`tail_mode` 由节奏引擎 `allocate`/`pack` 渲染进 `storyboard_ep_N.json.segments[]`，首尾状态、片段职责、生成风险与入段承接写进导演总控卡逐段执行区，图片输入职责以 `reference_input_plan` 为唯一清单。每个非首段在执行区“入段承接与 SEAM”写入入段承接；每个非尾段的出段转场落在末镜切出落点（十五列切入/切出动机）。二者必须来自同一个 `SEAMxxx`，不能各自发明转场。

### 节奏流水线（rhythm_input → 引擎 → 写回）

`rhythm_input` 是导演创作产物、不是脚本生成物：按 `manifests.md` 的 rhythm_input schema 由模型直接写 JSON，`kind` 只用 `visual|speech|camera|hold` 全称（自造简写与未知字段引擎直接拒），禁止生成器/批处理脚本拼装或转换（SKILL.md 第 7 条）。先登记已形成的过程与语音估计，再在 **skill 根目录**依次执行；项目路径走显式 `--project-root` 绝对路径，不依赖 shell 当前目录：

```bash
python scripts/rhythm_engine.py shot-count --project-root <root> --input <input>
python scripts/rhythm_engine.py allocate --project-root <root> --input <input> --storyboard <storyboard> --write
python scripts/rhythm_engine.py pack --project-root <root> --input <input> --storyboard <storyboard> --write
```

硬顺序不可调换：shot-count 只读报事实与源引用；allocate `--write` 写派生镜长/区间/依据并同步十五列时间，先于 pack——pack 发现派生字段与重算不符直接 `timing_output_drift` 拒写；pack 只核合法组、请求能力与技术余量。任何错误不部分写回。分组或设计变化按实际依赖失效，不得只凭相同 SEG 序号继承旧 KF/输入/审校/绑定。

### 视频参考输入计划

每个 `SEGxxx` 必须在 `storyboard_ep_N.json.segments[].reference_input_plan` 写图片输入计划数组（传哪些图、职责、开头定位、剥离什么），它不是最终 Prompt 或已传图证据。数组可空仅表示该片段无真实图片输入，用法由视频阶段调 `h3-prompt-writing` 判断、不从空数组推断；非首段仅当 planned `SEAM=elliptical` 且新起点无需图片锚点时可空（`continuous` 非首段 tail FRM 义务见下条）。视频阶段以 `video_manifest_ep_N.json.reference_inputs` 与工具 schema 为准，不得无理由删除已声明的必需输入职责。

字段结构与 `role` 枚举以 `manifests.md` 的 `reference_input_plan` 为唯一清单，下列只讲分镜侧判断规则。

- `order` 是计划顺序；视频阶段实际上传顺序调整时必须同步改写最终 Prompt 图片编号标记与 `reference_inputs[].order`，不得照搬旧编号。
- 第一段不规划生成式首帧关键帧；视频从已批准资产、已规划高光 KF（若有）和文字动作合同启动，生成后再抽真实 `start FRM` 作事实记录。
- 非首段先读 `SEAMxxx.seam_mode`（tail FRM 基准与工具不支持时的阻断规则见「片段衔接（SEAM）合同」）：`continuous` 把上段锁定 `adopted_cut_out` 的真实 tail FRM 以 `previous_tail_as_start_frame` 登记并置于首位——排他出点前最后保留帧、非物理末帧；出点或帧缺失即停止，不得用上段视频、其他帧或高光 KF 冒充。`elliptical` 按转场锚点选当前场景、角色状态、道具等真实参考，不强制 tail FRM。字段按 `manifests.md` 登记。
- **锚图充分性闸门**：规划 `continuous` 非首段输入前，先读该 `SEAMxxx` 的 `required_invariants` 与 `proof_requirement` 对照上段末镜：末镜为中景以下（近景/特写/大特写），或 tail 不含全部不变量主体（多人布局、群体衣着、远景人物、画外陈设），计划必须加一条 `previous_scene_anchor_reference`：`planned_source` 写“上一段真实场景帧，视频阶段生成后补抽登记”（分镜阶段不得伪造 FRM ID），`required: true`，`opening_binding`/`exclude` 按 `manifests.md` 填，`adopt` 写明承载的布局/衣着事实；视频阶段补抽后回写真实 FRM ID。未过闸的 SEG 不得提交确认。本闸是衔接卡 scene FRM 义务在 `continuous` 接缝的强制触发，两处登记一致。
- 会复现的角色状态与 PROP 道具状态必须解析到 `project_data_card.json` 的 `state_id` 与 approved 资产（共享库、本集 `episode_assets`、已登记 `reused_episode_assets`），计划用 `character_state_reference`/`prop_state_reference` 指向状态图，不得只给基准图加文字描述；一次性道具状态只进镜头动作与 Prompt，不升级 PROP 输入。
- 场景参考只锁空间、灯光、陈设、布局；风格参考只锁色彩、材质、光线、构图、景深、颗粒/线条语言，不承载剧情人物或道具；道具参考只锁结构、尺寸、材质、当前状态、可见面；不同职责的图片不得混写为同一主体。
- 任何用户或外部图片必须写 `adopt/exclude`；字幕、二维码、水印、平台界面、无关人物、镜面文字、背景杂物默认剥离，除非用户明确要求保留且权限、剧情、平台风险均已确认。

### 资产使用对账（asset_usage_plan）

`storyboard_ep_N.json` 顶层必须登记 `asset_usage_plan`：阅读稿附录 B 资产使用摘要由它渲染，手工另写即双方分叉。

字段与样例以 `manifests.md` 的 `asset_usage_plan` 为唯一清单，本处只补判断规则：

- `segments` 列出该资产必须显式传入的 `SEGxxx`；`["*"]` 表示全部片段（供 STYLE001、贯穿主场景等全局资产使用）。
- 登记即声明“此资产在这些片段必须显式传入”，lint 与各段 `reference_input_plan` 双向对账、两方向均为 error（细则见 `manifests.md`）；临时增补必须回头补登。某段靠上段尾帧携带即可时不登记——对账强制声明与执行一致，不强制声明。
- 只登记需要显式图片输入的资产；一次性物件不进本表（PROP 升级规则见参考输入计划条）。

### 世界事实承接合同（inherited_world_facts）

`storyboard_ep_N.json` 顶层必须登记 `inherited_world_facts`：从剧本继承的季节、节日、时辰、天气等世界物理事实，全片一致、分镜不得改动。字段、`category` 枚举与样例以 `manifests.md` storyboard schema 为唯一清单，每条写明出处 `source`。

- 分镜表与总控卡中任何季节/天气/温度/时辰/节日感官细节必须能引用本表一条；lint 强制本表存在且要素齐全，语义矛盾由顺读语义审校拦截。

### beat_coverage（节拍去向）

`storyboard_ep_N.json` 顶层必须登记 `beat_coverage`：剧本每条动作/事件的去向，并渲染为阅读稿附录 A 随同一确认门提交。

字段与样例以 `manifests.md` 的 `beat_coverage` 为唯一清单（含 `disposition` 四枚举），本处只补创作判断：

- `kept/compressed/moved` 必须给 `target_shots`（真实存在的镜头）；`dropped` 需具体理由加指向当前源版本的修订/用户确认，单填理由不解除缺失。
- **过渡性动机动作**（解释角色为何在某处、某状态的动作，如小解、添灯、拢火、栓门）默认不得 `dropped`，只能 `compressed` 为视觉提示——不推动冲突却支撑观众理解空间与动机，拆节拍时最易被误删。
- 全剧剧情靠本表核销：每条剧本 beat 有登记行并与已确认 script.events 双向对账；非 dropped 目标须在时间项以 source_refs 回指源事件，无登记即漏拆。

### 关键帧需求决策

关键帧需求由主 Agent 依已确认剧本、总控卡逐段执行区与十五列分镜决定；用户只确认可读分镜稿与镜头方案，关键帧阶段按清单生成，不临时挑普通画面代替；选点缺剧情峰值、缺状态资产或任务混杂时回分镜或资产阶段修正。

关键帧按实际高光、状态、构图、执行风险选择，无固定张数、单段配额或时长反推。用 `kf-count --storyboard <file>` 统计正式需求、生成项与复用项；无独立用途可为零，仍保留需求审查与阶段确认。首尾事实以生成后 FRM 为准（continuous 后段 adopted_cut_out 见基线衔接卡）。

优先生成关键帧的场景：

- 信息揭露、身份暴露、证据露出、文字证据可读、误会被推翻或观众认知改变。
- 角色不可逆选择的动作落点（抢夺/推开/跪下/拔刀/按下发送），或动作前一拍已无法回头。
- 两人关系发生空间性变化：堵门、逼近、退到墙边、遮挡出口、夺走道具、站位高低翻转。
- 角色或已升级 PROP 的状态会延续到后续片段（状态资产义务见基线「与关键帧和视频阶段的边界」）：列入 KF 优选；一次性道具状态变化不触发补图。
- 多人同框、复杂遮挡、POV、过肩、镜面、门窗前后景、低光或强色温变化，视频容易漂移。
- 片段中后部承担悬念、危险逼近、声音桥或状态变化时，优选让观众读懂结果与代价的高光瞬间；下段承接按基线衔接卡 tail FRM 规则。

通常不单独生成关键帧的场景：

- 删除后不影响剧情理解的纯氛围、纯运镜、纯场景展示或装饰性空镜。
- 只有“看向远方、低头沉思、站在原地”等弱动作，且无新信息、道具状态或关系变化。
- 已由人物、场景、道具资产稳定覆盖的外观展示镜头。
- 视频 Prompt 可稳定完成的简单动作（普通走路、坐下、转头、拿起杯子）。
- 同片段重复的反应特写；除非第二次反应带来新认知、选择或关系后果。

每张待生成 KF 在清单写清：所属 `SEG` 和镜头、高光序号、准确时间点、单一戏剧任务、选择理由、画面焦点、主要人物屏幕位置与关系、必须传入的角色/状态/场景/道具/风格参考、画面内文字要求、从上一镜继承什么、给下一镜留下什么。画面任务不得同时塞入身份介绍、情绪展示、证据特写、动作高潮；冲突过多时加第二张高光 KF 或回分镜拆镜。

## 导演总控卡的逐段执行区

在唯一 `导演总控卡_ep_N.md` 内逐片段填写执行区，不另建 `分镜_导演控制包.md`、执行表或连续性账本：

| 片段 | 戏剧目标 | 首态 | 尾态 | 镜头职责与删除损失 | 世界坐标/轴线 | 光源锁 | 声音交接 | 入段承接与 SEAM | 专项合同与生成风险 |
|---|---|---|---|---|---|---|---|---|---|
| 逐 SEG 一行 | 可观察的戏剧目标 | 片段开始的角色造型/道具/场景锚点/动作向量/声音状态，完整写明 | 片段结束的对应状态，完整写明 | 逐镜写“删除后观众不知道什么” | 轴线、屏幕侧、视线与摄影机活动区 | 光源来源/方向/色温/变化 | 台词尾音、环境声、BGM 交接 | 首段写抽帧计划；非首段写 `SEAMxxx`、seam_mode、tail FRM 义务与出入点 cue（硬门见「片段衔接（SEAM）合同」） | 无 / 轴线 / 叙事光 / 动作拆分；有生成风险（口型、文字、漂移等）时同格标注 |

- **叙事节拍**：按下节「叙事节拍与证据链」字段记录并绑定证据镜头。
- **片段吸引力与段尾功能**：每个 SEG 必须有可指出的观看动力（目标/阻碍、动作变化、信息揭示、关系或情绪张力、兑现、进行中的行动或真实悬念）和明确段尾功能（结果、动作承接、暂缓、转场、钩子）；悬念必须由真实已建动作或问题落地，不得为技术分段伪造。相邻 SEG 合看须检查前段留下的动作/问题由后段承接、兑现或有意转向，不得因切段断裂。
- **台词证据链**：把关键身份、指控、承诺、能力、秘密、判断绑定到前置来源、可见证据镜头及剧情后果；角色撒谎或误判时明确标记。
- **场面调度**：按「调度、布光与动作合同」先固定世界坐标与 180 度轴，写进十五列与逐段执行区，不另立账本。
- **布光**：按「调度、布光与动作合同」的叙事光规则写清光源与首尾连续性。
- **表演指导**：从导演总控卡表演总纲逐镜落实为下表。

| 镜号 | 角色 | 表面策略 | 内在压力 | 情绪层次 | 微表情目标 | 肢体语言 | 呼吸节奏 | 禁止表演 |
|---|---|---|---|---|---|---|---|---|
| 逐镜一行（多角色各占一行） | 写人物在做什么 | 动作为何泄露 | 基准态与变化 | 一个主要可见脸部动作 | 一个主要肢体动作 | 停顿与节奏 | 该镜禁止的失控表演 |

逐镜声音必须回指导演总控卡三层环境声与 BGM 曲线（静默写法见「声音设计方案」）；逐镜色彩与光线必须回指色彩叙事合同的基准色或触发节点，不得只写“冷色高级感”。
- **剪辑动机**：每个切点必须由 `cut_motivation` 八枚举之一驱动（枚举见完整分镜表「切入/切出动机」列）；“为了丰富镜头”不是动机。
- **单镜单次编译**：十五列分镜表按 `SEGxxx` 分组即视频编译的唯一镜头源，每个镜头恰好一次编译进视频 Prompt，不遗漏、不重复、不合并成无节点长镜头（编译流程见 `video.md`）。

### 叙事节拍与证据链

每场或每个可生成片段按字段一行枚举记录（人工总控卡填写模板，非机器 JSON schema；机器字段以 `manifests.md` 为准）：`scene_id`、`source_form`（`script|outline|sketch|oral`）、`assumptions`、`hook`、`want`、`obstacle`、`strategy_shift`、`power_turn`、`cost`、`information_gap`、`entry_state`、`exit_state`、`cliffhanger_or_payoff`、`evidence_shots`、`dialogue_evidence_map`。

字段必须对应画面、动作、台词或声音中的可观察事实。关键身份、指控、承诺、能力、结论继承 `scriptwriter.md` 证据链，再绑定实际揭示镜头及后果；不得只写“反转很强”“推进剧情”。

### 调度、布光与动作合同

这三类设计直接写进十五列分镜表与 `导演总控卡_ep_N.md` 逐段执行区，不另立 JSON 账本：

- **调度先于机位**：双人以上交互、走位、遮挡、道具传递、追逐或打斗时，先固定世界坐标（屏幕左右、纵深、视线、遮挡、出入画）和轴线关系再选机位；换机位后按世界坐标重新计算屏幕关系，不得为保持画面左右而暗中移动人物或房间。跳轴、换手、瞬移的修正路径按 `troubleshooting.md` 的动作桥执行。
- **叙事光**：复杂光线、昼夜切换、情绪转折或跨片段同场景时，写明主/辅/轮廓光的画内来源、方向、明暗目的与跨片段连续性。资产图用可读性优先的标准光；剧情镜用有画内或世界来源的叙事光。暗部必须有叙事目的，不得用死黑或滤镜替代布光。
- **动作拆分**：打斗、追逐、抢夺、跌落、复杂肢体接触或多人同步动作按“起势 → 位移 → 接触或落空 → 受力反应 → 结果”拆分；动作密度结合因果环节、人物数量、持续时间和摄影机运动判断；超出模型稳定能力时拆镜，或改用反应、遮挡和画外声音。

### 风格一致性检查

风格检查写入唯一总控卡逐段执行区，不增加第 16 列。逐场记录色彩、光影、构图/景别、镜头运动、标志机制、跨镜一致性并绑定镜号及可见证据。只采用服务剧情的风格机制，不规定每集固定大师元素数量，也不用统一慢推或死黑代替风格；每项机制都必须能回答“为这个镜头的什么叙事职责服务”，跨镜一致由文字合同和生成后场景锚点帧复核。

## 开场、转场与角色表演控制

### 开场镜头合同

每集第一个可观看节拍必须把 `script_contract.opening_contract` 转译为镜头，而非只在台词或旁白中声明。第 1 集必须直接兑现规划 `OPEN001`；后续集可用剧本已解释的变体，但首镜仍要建立与项目承诺的关系。开场类型只确定观众首先被什么抓住，仍须服务人物目标、阻力和后续兑现：

| 主开场机制 | 首个可观察承诺 | 镜头设计重点 | 禁止替代 |
|---|---|---|---|
| 悬疑问题 | 可被看见的异常、缺口或未解问题 | 线索可读、视点克制、人物对异常作出行动或错误判断 | 用模糊滤镜、惊吓音效代替线索 |
| 世界观震撼 | 规则、尺度或秩序与人物处境的碰撞 | 奇观必须落到人物目标、代价或行动 | 只有空镜和设定说明 |
| 人物塑造 | 人物独有策略、习惯或失控裂缝 | 先让人物做选择，再解释背景 | 靠旁白贴标签 |
| 视觉奇观 | 一个无法被普通画面替代的视觉事件 | 构图、尺度、反应和后果连续出现 | 只展示漂亮场景 |
| 冲突驱动 | 双方目标立刻相撞 | 明确谁要什么、谁阻止、第一轮反馈是什么 | 无来源的争吵或突发事件 |

每个开场至少在总控卡按「开场承诺与情绪曲线」登记，并核对开场镜头确属剧本合同的开场场次、是该场第一个承担开场职责的镜头，其余各项能指出实际画面证据。不套固定秒数，按实际时长把开场作为首个完整叙事节拍。

开场按已确认 opening contract 执行；只有明确选用黄金三秒机制时才参考该事件检查。任何题材都须尽早建立观众可读的问题、人物、奇观或冲突。结尾必须完成结果、反应和落点；除已规划无缝 Loop 外，不得只回到与开头相似的画面。

### 转场设计合同

转场是两个镜头或两个 SEG 之间的叙事动作，不是后期遮掩错误。每个 `SEAMxxx` 选一个主转场、必要时附声音桥，不得把多种无关技巧堆在同一切点。跨 SEG 转场采用“双锚单主导”：上段尾部把画面送到可剪切状态，下段开头从该状态迅速接入。相邻 SEG 分开独立生成，双侧 cue 都必须自洽写清画面、方向、速度、遮挡、动作相位、落点，不得写“同上”“相同”“保持上一段”“自然接上”等需读另一段 Prompt 才能理解的省略词。

分镜阶段先做一次 seam-first 设计再定稿逐段执行区：逐个边界判 `continuous`/`elliptical`，选唯一主锚点，写清出点与入点动作相位。连续边界优先用上段尾态可继承的动作、视线、道具接触、屏幕方向或遮挡物；省略边界优先用相似构图、物件、声音或明确叙事动机。

衔接卡必须先选 `seam_mode`：`continuous` 用于同一行动、空间或无跳跃的时间推进，`elliptical` 用于明确的时间/空间/认知跳跃。全量枚举见「片段衔接（SEAM）合同」，机器字段见 `manifests.md`，本节只列硬门：`continuous` 的 `permitted_deltas` 必须为空；`elliptical` 至少登记一项允许变化，且只验收不变量与计划变化。连续动作优先动作匹配、遮挡切或甩镜同向；跨时空优先相似构图、物件/声音匹配或有动机硬切。无法满足锚点回分镜；视频已生成时关键问题阻断合格接受、非关键偏差须明确接受；返修建议不授权执行，须等用户修改要求与新的生成确认，声音桥不得掩盖未允许的身份、动作相位或光位错误。

七类转场锚点与双侧 cue 写法（一表合并；出点/入点锚点即 cue 的匹配对象）：

| 转场类型 | 出点/入点锚点（适用场景） | `outgoing_prompt_cue` 写什么 | `incoming_prompt_pickup` 写什么 |
|---|---|---|---|
| 动作匹配 `action_match`（连续行动、交接、反击） | 同一动作相位、方向、速度或受力结果 | 动作切到未完成相位、方向、速度、受力点 | 从略微推进的相位开始，完成结果，不重做起势 |
| 遮挡切 `occlusion_cut`（过门、掠物、交错） | 前景遮挡物的方向、面积和解除时机 | 哪个前景从哪侧进入、遮挡面积、遮满时机 | 从哪侧遮挡中开场，遮挡如何迅速解除并露出新主体 |
| 相似构图 `graphic_match`（时空跳跃、意义对照） | 画面形状、主体位置、视觉重心或色块关系 | 形状、主体位置、色块或视觉重心如何占满尾帧 | 以对应形状/色块/重心开场，并立刻揭示新时空或新意义 |
| 甩镜同向 `whip_pan_match`（失控、追逐、能量转移） | 同向运动、模糊强度和入画落点 | 摄影机甩动方向、模糊强度、切出前画面被什么吞没 | 从对应方向的运动模糊进入，短时间内停到新景别和新信息 |
| 视线/物件匹配 `eyeline_match|object_match`（对话、线索、联想） | 视线目标或道具形态、位置、接触关系 | 视线目标或物件接触点在尾帧的位置 | 从目标物/接触点开场，说明看见者或持有者如何变化 |
| 声音桥 `sound_bridge`（时间/空间转换、余韵；默认只辅助视觉转场） | 声音来源、进入/退出点和画面关系；BGM 写可复用的乐器/节奏/音量/情绪职责 | 台词尾音、环境声、拟音或 BGM 的出点；台词尾音只写尾音性质和结束时机、不复制完整台词；BGM 只在剧情需要时写可复用的具体描述 | 声音从 0 秒继续，但只写非语义尾音、呼吸、环境声或拟音；BGM 逐字复用上一段描述，不把上一段完整台词再写一遍；画面动作仍要有具体入点 |
| 有动机硬切/叠化 `motivated_hard_cut|dissolve`（不应伪装连续性的转场） | 明确的策略、信息或时间关系 | 上一段以明确结果、反应或信息落点收住 | 下一段快速建立新时空和变化原因，不伪装为连续动作 |

`outgoing_prompt_cue` 与 `incoming_prompt_pickup` 成对但不重复：前者写出点前什么出画、遮挡、甩动、视线、物件接触或声音延续；后者写下段 0 秒从哪个屏幕边缘、运动模糊、遮挡物、物件位置、动作相位或声音桥进入，再落到本段主体或信息。下段开头不得另写转场名或重复上段运镜，只用可独立理解的具体画面接住该 `SEAMxxx` 主锚点。摄影机运动方向必须转译成屏幕入画方向（例：上段“向右甩镜至运动模糊，把门框遮满画面”，下段写“迅速从画面左边运动模糊和门框遮挡中接入，遮挡解除后停到新主体”），不得只写“同向甩镜接上”。方向必须拆开写清：摄影机运动方向、模糊或遮挡物流动方向、主体入画/出画侧、停在哪个景别和位置；按该接缝实际画面填写、不套固定方向，无法稳定判断时改用遮挡切、物件匹配、视线匹配或有动机硬切。

高风险边界（角色太多、同一动作难由下段 0 秒承接、场景/光位跨度大、上段尾帧无法作真实图片输入，或预定 `dissolve` 但成片工具只支持普通拼接）必须预设计桥接镜头或独立 `bridge SEG` 再推导时间。真正重叠两侧画面的视觉转场消耗两侧有效帧，叠加类光效或声音桥不改主时间轴；必须在 `duration_s` 和接缝卡提前写清，不得到成片阶段用效果遮掩跳变。桥接优先手部接触、门/墙/衣料/前景遮挡、关键道具特写、同向甩镜、视线目标或声音尾音，且必须承担剧情信息或情绪余波，不得空转场。

### 角色表演谱与情绪曲线

关键表演镜头在总控卡逐段执行区和 `performance_scores` 中用时间段表演谱。先在 `performance_coverage` 声明哪些镜头必须有表演谱；确无关键表演时用 `not_applicable` 并说明理由。每拍用相对镜头的 `start_ms/end_ms`，首尾连续、不重叠、不超该镜时长；台词只在其触发或改变表演时出现。逐拍登记十列表（列序即编写顺序）：时间段｜发生原因/策略｜基准状态｜情绪状态与变化｜可见脸部动作｜目光与身体｜声音/呼吸/停顿｜台词触发｜听者反应｜结束状态。

- `cause` 必须来自台词、动作、道具、信息或对方反应，不能只写“情绪来了”。
- 每拍 `baseline_state` 写动作发生前观众可见/可听的状态；第一拍继承镜头入态，第二拍起逐字承接上一拍 `end_state`。变化太复杂时拆拍，不得用“继续上一状态”绕过。
- 有明确听者、对手或共同在场角色时，`listener_response.mode` 用 `covered`，逐人写 `character_id`、反应时机、可见反应和尾态；独白、无人回应或本拍不适用时用 `not_applicable` 并写具体原因。听者不得只作静止背景，反应须改变距离、视线、动作、认知或下一轮策略中至少一项。
- 先写观众都看得见的脸部、目光、手势、姿势和呼吸，用自然语言描述强度与时机；编号化面部动作编码不单独传意、不替代自然语言。非人、遮脸、远景或无法辨认面部的镜头只写可见行为，不伪造面部精度。
- 一拍只突出一个主要变化；复杂情绪拆成连续拍点。先用 `emotion_curve_coverage` 列出承担转折的角色或写不适用原因；每条曲线写清 `character_id`、入场状态、压力来源、场次级触发、前后状态、可见证据、关系后果、尾态，分别与项目级曲线、场景攻防、BGM 曲线对应，但不得让 BGM 或色调替代人物变化。
- 说话前的口唇、下颌、眉眼和身体预备与语气一致；台词结束后的闭口、视线、呼吸或姿势必须成为下一拍可继承的状态。

## 片段衔接（SEAM）合同

跨片段连续性不另建账本文件：角色身份/状态、服装伤痕、位置朝向、轴线、手持物、道具状态、场景光线、环境声与音乐的逐 SEG 首尾状态写进导演总控卡逐段执行区的首态/尾态两格（必填，完整写明），机器字段登记在 `storyboard_ep_N.json.seams[]`；时间范围与实际时长以引擎 pack 值为准，不手工誊写。

每个跨片段接缝必须建立唯一 `SEAMxxx` 片段衔接卡，显式写出“上一片段结尾状态 → 本片段 0 秒开场状态”，字段一行枚举：上一段计划尾态/本段 0 秒开场状态/相关高光 KF、角色屏幕位置/姿势/朝向/视线/`state_id`、道具持有者/可见面/开合破损/手部接触、主光方向/色温/曝光/SCN 版本/固定背景锚点、摄影机轴线侧/机位高度/景别/观察方向/角度/运动家族、动作向量/速度/接触/动作相位、预定切法/转场锚点/允许变化/首尾窗口核验、`outgoing_prompt_cue`/`incoming_prompt_pickup`、声音桥与 fallback。实际 `tail/start/scene/character_state/prop_state FRM` ID 由视频阶段生成后写入 `continuity_ep_N.json`（schema 读 `manifests.md`），分镜阶段不得伪造。硬门：

- 连续动作在适合衔接的可见动作相位切出，下一段从同一相位或略微推进切入，禁止动作重做或回弹；预定切法取「转场设计合同」七类锚点之一，不得写“自然衔接”“后期看情况”。
- continuous 后段编译前先查看前段实物并锁定 `adopted_cut_out`（源视频 SHA、时间码、对应帧及 SHA），后段输入与最终 trim 同一出点；改出点使入站帧/后段绑定/确认/剪辑依赖全部失效；窗口不足、无剪切点或验证不通过时关键接缝标 blocked，不得以 best available cut 或文件边界兜底，非关键偏差按质量门由用户接受。
- BGM 仅在剧情需要同一情绪或同一声源跨段时使用，写成可逐字复用的具体描述并标声音桥入/出点。
- `outgoing_prompt_cue` 与 `incoming_prompt_pickup` 必须共享同一 `transition_anchor`，禁止双转场、反向运镜或动作重复。
- 若连续承接所选工具无法接收 tail FRM，必须改分段方案或返回用户重新选择可接收图片的工具方案，不得静默降级。

SEAM 衔接卡按上方字段同一顺序登记进 `seams[]`（SEAM ID 起、fallback 止），不另立字段定义。若文字继承无法稳定保持同一画面，不追求伪像素连续，把边界设计成有动机的剪辑；定稿前逐个接缝做“硬切预演”：普通拼接会跳变就改出入点、加桥接段或改明确省略剪辑，不把问题留给成片阶段。

资产到镜头/片段的映射与 KF 需求只存在于 `asset_usage_plan`、`reference_input_plan` 与关键帧需求机器字段，渲染面唯一出口是阅读稿附录 B，不另建内部映射表；状态引用 `project_data_card.json`，镜头只补本镜光位/布置增量。

## 参考资料与参考视频

分镜阶段接收用户图片、视频、脚本或风格参考时，先按 `manifests.md` 的 `source_manifest.json` 分类并写明采用什么、不采用什么；跨阶段冲突优先级仍按 `control-contracts.md`。

针对外部运镜模板类资料：

- 采用：逐镜“景别 + 机位 + 运镜 + 动作”的结构、跟拍/环绕/升降/手持/焦点转移/甩镜/匹配剪辑等候选，以及动作匹配切镜和接缝重复帧排查思路。
- 不采用：默认 `4K/60fps`、固定三秒定格、所有动作都缓慢、每句最多两种运镜等与当前工具 schema 或剧情职责冲突的模板；最终参数以实际工具能力和项目节奏为准。
- 组合名称不能直接复制成模糊 Prompt。必须拆为相邻镜头，或在模型已验证、路径简单时拆成同镜先后两段运动。

参考视频必须拆成六项可迁移导演信息：

```text
reference_structure：段落结构、信息顺序、切点逻辑
reference_pov：机位、景别、视角和观察者身份
reference_motion：主体或环境的可见运动、摄影机轨迹、速度和节奏
reference_emotion_arc：情绪起点、升级、翻转和回报
reference_audio_logic：台词、环境声、拟音、音乐和声音桥关系
reference_risk：需剥离的品牌、人物身份、字幕、口号、水印、平台 UI 和未授权内容
```

只迁移已声明的结构、视角、运动、情绪或声音机制，不复刻原人物、场景、品牌和文字。

## 与关键帧和视频阶段的边界

分镜阶段不生成关键帧、不写最终视频 Prompt，只产出稳定 ID、十五列画面与声音设计、总控卡逐段执行区（首尾状态、SEAM 衔接与生成风险）、必需图片职责、关键帧需求机器字段、人声设计和生成后 FRM 抽帧计划；产物清单以 `control-contracts.md` 跨阶段交接表为权威，此处不重复枚举。

只有被选为集级高光的 SEG 才需要高光 KF。状态变化（服装、妆发、伤痕、伪装、装具，或已升级 PROP 道具的开合、破损、内容物、归属、可见面）会复现时，必须在该 SEG 参考计划中列出 approved 状态资产，依据可来自共享资产、本集资产或其他分集已 approved 的复用资产；一次性道具状态只进入镜头动作和 Prompt。非首段还要消费上一段已验收连续性抽帧组。人声必须写明主体、音色锚点、类型、逐字文本和发声窗口；出镜对白要求口型，其余人声要求画面人物不开口。

## 分镜内容人工复核

在完整分镜表与关键帧需求决策完成后、用户确认前，以及分镜返修重新提交前，必须完成 `references/skill-details.md`「阶段内容硬门 · storyboard」的两项语义审校（beat 核销、世界事实出处、台词逐字与覆盖等确定性部分已由节奏引擎与 lint 强制，人工不重复），按下述实际观看过程执行。

主 Agent 在初稿后独立重新读取源剧本和实际分镜，先按观众顺序顺读一场，再逐镜核对：必要事件/台词和证据何时被感知；从前画面到后画面的空间/路线是否连续；已声明串并行与演读估计是否可信；等待/停留在看什么；道具、身份、状态和声音如何进入当前实际设计。

顺读同时逐镜核查反应有源、证据可达、指称有锚。发现问题先改设计/时间输入、重跑引擎与 lint，再重新顺读复核；无问题用盖章命令绑定当前源/设计/时间输入版本：

```bash
# 先无旗标运行：结构门预检 + 审校清单指针（不写文件）
python scripts/stamp_review.py --project-root <项目根> --episode ep_N
# 真人完成两项语义审校且无未解决问题后：
python scripts/stamp_review.py --project-root <项目根> --episode ep_N --i-did-the-review
```

`content_review` 只由 `stamp_review.py` 写入（命令内部用 `full_review_inputs()` 算三元指纹，禁止手填或手写脚本计算）；结构门未过或 `open_issues` 非空时命令拒绝盖章。不同类型无需同样运镜、声音、反应或镜长分布，不填逐镜自证通过表。未解决问题或绑定过期不能推进；程序通过只证明声明一致，不能证明摄影物理可达、动作时间真实或审美合格。

## 存储与阶段确认

本阶段产物统一进入当前 `ep_N` 的分镜目录；路径、命名和 `storyboard_ep_N.json` schema 只读取 `manifests.md`。

落盘前跑 `python scripts/drama_lint.py <skill-root> --project-root <project> --stage storyboard`，0 error 才准落盘（结构、枚举、核销、对账等确定性事实统一由它核验，不在此抄写机器码）；语义层面的顺读与三锚审校按「分镜内容人工复核」执行，不按密度、分布或长镜例外配额准出。

状态写为 `awaiting_confirmation` 并跑内部结构检查，有问题先修复，不单独输出阶段报告。通过后只提供用户可见分镜 Markdown（每个文件配一句简短说明）并在聊天中给镜头方案摘要，链接用真实可访问路径且仅限用户可见稿；不点名内部执行技术、机器字段、衔接卡、执行区、哈希或内部文件。按 `language_contract.output_language` 用语义完整的确认句请用户确认（礼貌清晰、不套固定模板）：需要修改请直接指出，明确确认后才开始生成关键帧。展示通用规则以 skill-details「阶段可见交付速记卡」为权威。

收到修改意见时只修订分镜：改镜头职责、时间轴、轴线、接缝或大范围执行合同的重大修改重新提供完整受影响文件；局部文字或单镜微调只提供修改文件、修改前后和影响范围。只有用户明确确认后才进入 `keyframes.md`。
