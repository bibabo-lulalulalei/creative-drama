# 分镜阶段 Ref

在项目级故事包、当前集详细剧本和资产分别确认后读取本文件，只处理当前集。

## 本 Ref 关键要求

- 分镜只规划镜头、片段、连续性、已确认资产编排和关键帧需求，不生成关键帧、视频或最终 Prompt；正式分镜覆盖当前确认范围内全部剧情。
- 阅读稿结构、`density_profile` 选择与镜数推导：见「用户可见分镜阅读稿」「动态镜头数量」。
- 关键帧总量与选点（实际需求统计、不规划首尾帧）：见「关键帧需求决策」。
- `reference_input_plan` 数组、锚图充分性闸门与 `asset_usage_plan` 对账：见「视频参考输入计划」「资产使用对账（asset_usage_plan）」。
- planned SEAM 是生成前目标；真实 FRM、observed seam 和剪切点只能在视频阶段记录。
- 时间来自本次拍法的过程估计；程序累计并核一致性，不查动作或节拍秒数，不以精度证明真实性。

## 目标

把 `current_episode` 已确认的完整剧本和当前集采用资产逐场转换为可直接指导视频生成和生成后抽帧的分镜交付包。正式交付必须覆盖当前集全部剧情，不得只提供样例、部分镜头、简略提纲或夹带后续集镜头。

本阶段只规划镜头、片段、连续性、已确认资产编排和关键帧需求，不生成角色图、场景图、道具图、音色、关键帧或视频。必须引用 approved 人物/状态、场景、道具、音色和 `STYLE001` 全局 moodboard；按实际用途规划高光 KF，无独立用途时记录零需求并完成该阶段确认，同时说明为什么这些时刻值得成为关键帧，规划视频必需图片职责和生成后 FRM 抽取职责。

每集唯一导演总控卡锁表达策略并解释“为什么这样看、如何剪、如何连续”，分镜主表写“观众看到什么”；最终视频 Prompt 只在 `video.md` 编译。分镜阶段不得写伪最终 Prompt。

分镜阶段只能继承已确认视觉锚点；`style_contract` 缺少可执行风格机制时必须停止并返回 `planning.md` 补齐、递增 revision 和重新确认，不得在分镜阶段自行补选风格。已确认风格存在但需要诊断漂移时，才读取 `电影大师风格库.md`，且只用于解释和校准原有光线、色彩、构图、材质和节奏机制。本文件规定事实、交付结构和执行边界；边界内的镜头职责、观看方式、摄影和剪辑由导演针对当前内容独立设计，不把示例或分类当作必选方案。

写具体分镜时，先执行本文件、`scriptwriter.md`、`assets.md`、`manifests.md` 和 `control-contracts.md`。四个创作参考库只读取与当前分镜问题直接相关的部分：用 `剧作方法与类型库.md` 校准场景功能、攻防关系、信息释放和必要场面；用 `题材亮点与传播库.md` 校准开场钩子、反转、爽点/泪点、传播句和片段节拍；用 `题材受众库.md` 校准观看焦点、情绪回报、平台观看场景和表达禁区；用 `电影大师风格库.md` 校准光线、色彩、构图、材质、声音和节奏机制。不得因分镜阶段读取候选库而改写已确认剧情、结局、人物身份、受众定位、风格合同或资产版本。

## 输入条件

必须具备：

- 已确认并存入 `01_剧本/` 的 `剧本_全局设定与分集总纲.md`、全剧完整剧本和 `项目_事实与假设.md`（读取其已验证事实、未知项、推进假设与项目惯例分栏，分镜不得与其冲突；发现冲突时返回剧本阶段修订）；合并文件必须同时包含“全局故事圣经”和“分集推进总纲”两章。另需已确认并存入 `episodes/ep_N/01_剧本/` 的完整剧本和 `script_contract_ep_N.json`（关系张力从 `script_contract.relationship_tension` 读取，人物状态先取本集 usage 分卡的状态投影，分卡不足时按 ID 定点窄读数据卡 `state_timeline`）。
- 已确认的 `00_制作控制/project_data_card.json`；本集所有出场角色、角色当前状态、需要建立 SCN 的主要场景、已升级为 PROP 的关键/复现道具及声音主体均能解析到稳定 ID 与 approved 当前版本。一次性物件只进入分镜和 Prompt，不要求建立 PROP 资产。
- 已确认且已向用户展示或明确标注复用的当前集人物、场景、道具、音色和风格资产；资产必须来自当前集新增项、共享 approved 库或已完成分集的 approved 复用项，不得引用尚未生成的未来集资产。
- 已确认的项目固定画幅。
- 已确定且已经按 `planning.md` 完成参数确认表的视频模型与片段时长上限；本阶段只继承，不自主切换。
- 用户原始指令、后续修改、原台词、必须出现项和禁用项。

剧本存在未写出的剧情、场次、台词或世界物理事实（季节、节日、时辰、天气、温度）时，返回剧本阶段补齐，不得由分镜阶段猜测。分镜表、总控卡、执行表中出现的任何季节、天气、温度、时辰、节日类感官细节（如霜、雪、雨、暑、腊、三伏、清明），必须能引用 `inherited_world_facts` 中的一条；无出处的世界细节视同猜测剧情，必须删除或返回剧本阶段确认。把剧本的文学性感官描写（如“夜凉”）落实为具体视觉元素时，先核对该具体元素是否与世界事实冲突，再落笔。

## 分镜产物分层

内部生成唯一导演总控卡、十五列分镜表、视频片段执行表、连续性账本、关键帧需求清单和结构化索引；面向用户展示分镜阅读稿及随阅读稿同批提交的确认文件（转换差异台账、因果链摘要、资产使用摘要，见「用户可见分镜阅读稿」），不点名其余内部制作支撑物、哈希、路径或检查过程。不得用参数确认表中的五列分镜预览表/剧情节奏预览表替代详细分镜。

各文档职责：

- **导演总控卡**：拆镜前唯一的导演决策中心，统一锁定本集视觉叙事、核心意象、场面调度、节奏波形、表演、声音与风格系统；不得另建导演阐述卡或强风格系统卡。
- **完整分镜表**：一行一镜，固定十五列，包含镜头职责、画面、声音、运镜、连续性和抽帧承接。
- **视频片段执行表**：一行一 `SEGxxx`，记录模型调用容器、片段内时间轴、切镜触发、首尾状态、承接方式和生成风险。
- **连续性账本**：追踪角色、道具、空间、轴线、光线、动作、声音和世界事实（季节/节日/时辰/天气，全片一致，从剧本继承不得改动）的跨镜头、跨片段连续性。
- **关键帧需求清单**：把已确认基础资产映射到镜头和视频片段，并定义每张待生成关键帧的职责、构图、状态和连续性。
- **转换差异台账**：逐条登记剧本每个动作/事件的去向（保留/压缩/移动/删除及理由），随阅读稿一起提交用户确认。
- **因果链台账与摘要**：`causal_ledger` 登记跨镜头因果链（触发→证据→反应→结果）与可见性合同（内部 JSON）；并渲染用户可读的 `分镜_因果链摘要_ep_N.md`，随阅读稿、转换差异台账、资产使用摘要同批提交用户确认。

## 工作顺序

读取按 `SKILL.md` 分阶段读取协议与阶段路由执行：读本阶段对应原始章节，不凭上下文残余编译；lint 报错用 `build_lint_contract.py --code <检查码>` 依码查询文件与行范围，导航与规则均为现场生成、只解释客观检查，不能代替摄影教学；上下文压缩后按 `recovery.md` 恢复，先核真实时长合同、源 revision/SHA 和确认来源。

1. 从当前已确认剧本建立源事件与 line_id 索引，整理必要事实、状态和人声；不先锁镜数、SEG 数或秒数。
2. 在唯一导演总控卡明确整场观看关系、观众视点、调度、摄影和剪辑意图；简单设计简单写，复杂空间按风险展开。
3. 形成镜头起始画面、连续发展、人物/物件过程、证据显露、切点和末态。一个 SHOT 是一次连续观察；景别或焦点变化本身不必拆镜，不连续机位须明示切点。
4. 根据已经形成的动作、对白、证据阅读、反应、摄影过程和有意停留估计过程时长，声明起点、先后与并行。允许迭代，不能先发布锁定时间再补摄影理由。
5. 由 timeline_core 累计：每镜取所有过程结束的最大值，镜头按正式顺序累计。保留等待/空隙，不自动紧排、删事件、改语速或缩短。规划初估不进入核算。
6. 在真实合法切点声明镜头组，用 pack 核真实能力；内容时长保持原值，请求时长按接口整数合同向上承载。非零技术尾余量须有末镜末态的非人声延续设计，不新增剧情。
7. 登记多对多 beat_coverage、因果/资产/连续继承与真实 KF 需求；实际出点及对应帧在生成后锁定，不能预造未知 FRM。
8. 独立重新读取源剧本和实际分镜，按观众顺序检查整场，再核空间、表演时间、证据、停留及跨 SEG 继承。解决具体问题后绑定本次设计投影和源版本，提交既有分镜确认。
9. 机器工序固定（命令见「节奏流水线」）：改设计只改导演设计与 `rhythm_input`，再 allocate → pack → lint 0 error → 五项人工复核 → `stamp_review.py` 盖章；镜长/区间/依据/SEG 装箱/请求秒/尾余量/`design_sha256` 只由 allocate/pack 写，禁止逆向手填；`content_review` 只由盖章命令写。

## 节奏类型与镜头数量推导算法

先确定观众需要看见、听见和持续观察的内容，再选择连续观察或切换视点。事件与镜头多对多：一个镜头可承接多个事件，同一事件可以跨镜；不以动作/反应计数决定镜数。

`density_profile` 仅可选描述内容负载，不决定秒数、镜数或摄影方法。静止、重复、长观察、极短切点、低信息和无人声均可成立。删除测试要同时考虑空间、压力、时间体验和有意停留，不能只数新信息。必要事实、台词、因果与已确认意图不得因估时偏差被删改。

开场按照当前故事的观看承诺设计，不设固定几秒内的事件数或首镜长度。真实用户明确要求的开场形式按其来源继承。

## 节奏设计

节奏来自观众如何经历事件、等待、证据、反应与摄影过程。先写拍法再估过程，不用规划估时分配场次或镜头额度；beat_type、intensity、speech_pace 都是可选注释，改动它们不改变时间结果。

### 时间推导与真实约束

规划估时是设计前预测；内容计划时长是本次设计的累计估计；请求时长是接口申请长度；媒体实测时长只来自实际文件 probe。累计值不得称为“真实需要”或摄影物理证明。初估偏差不触发准出错误、分数或免责说明，也不自动覆盖已确认 planning。

用户未限定时长则保留初估记录，更新 episode 的 planned_content_duration_s 并展示当前设计计划。真实 exact/target_band 合同由确认 ID 回溯，在独立约束核对层说明冲突，不反推逐镜预算；确需改内容/拍法或目标，由用户按既有流程取舍，不自动压短。

### 源覆盖与先后并行

非人声过程可回指 beat、chain 或 asset_state；after 固定表示本事件开始不早于引用事件结束，可跨镜。程序核声明的依赖、环和引用，不能猜未声明的物理互斥。空隙、有意等待、静止观察不自动删除。具体估计是否可信，回到本次摄影与表演顺读审校。

### shot 机读字段

时间输入、派生结果与设计投影见 manifests 的 rhythm_input/storyboard 合同。duration_basis 是结构化最大结束事件依据；camera_family 可选，只作执行注释；不设固定机位占比、平均镜长、极值分布、角色时间地板或标签时长表。

## 每集导演总控卡

详细拆镜前只生成一份 `episodes/ep_N/02_分镜/导演总控卡_ep_N.md`，同时承担导演阐述、导演控制与风格系统职责，不得再创建平行决策卡。**字段清单（视觉叙事策略/开场承诺与情绪曲线/核心意象/场面调度总纲/节奏设计/节奏波形推导/视觉风格系统/亮点转译）、九步推导顺序与逐字段写作职责以「导演总控卡字段合同」节为唯一权威**，此处不重复。总控卡不能只列形容词：每项必须绑定场次、镜号范围或剧情触发点，并在完整分镜表和 `storyboard_ep_N.json.director_control_card` 中可追溯。

### 亮点绑定检查

分镜前读取本集 `script_contract.highlight_ledger`，按 `manifests.md` 的 schema 在 `storyboard_ep_N.json.highlight_bindings` 中逐项绑定。每个 `role=primary` 的亮点须绑定其兑现、结果/反应及后续影响；同一长镜可承担多个职责，跨集余震用 `deferred_aftereffect_ref` 追溯，不为字段凑额外镜头。对应可观察阶段必须写清。绑定必须填写视觉、表演、声音和视频编译说明，某一维度不适用时写清理由，不能统一填写“加强氛围”。任何剧本主要亮点找不到镜头，先返回剧本调整或重拆分镜，不得直接删除。

每个主要亮点按“触发 -> 变化 -> 反馈 -> 结果”推导，不从“需要一个高光画面”倒推装饰性镜头：

1. **触发**：读取 `setup_evidence` 和当前场次前态，选择真正迫使人物或局势改变的台词、证据、动作或规则事件，并绑定观众可见/可听的镜头。
2. **变化**：写清触发后谁采取了什么不可忽略的策略，人物位置、道具控制权、信息归属、关系或危险如何发生可见变化；只写情绪形容词不成立。
3. **反馈**：给出对手、听者、环境或规则的即时回应，让观众确认变化被世界接住。反馈必须改变下一拍策略或认知，不能只补一个无后果惊讶特写。
4. **结果**：写清本场或后续场次留下的代价、权力重排、选择后果或余震。结果可延迟到后续集，但必须通过 `deferred_aftereffect_ref` 指向明确回收点。

四步按顺序写入该亮点的 `causal_chain` 并绑定 SHOT；再把变化/兑现镜头映射到 `payoff_shot_ids`，反馈镜头映射到 `reaction_shot_ids`，结果或余震映射到 `aftereffect_shot_ids` 或跨集引用。同一 SHOT 可以承担相邻两步，但必须分别写出可观察状态；若缺触发、反馈或结果，返回剧本补因果，不得用慢动作、强音乐、发光或群众惊叹替代。

### 受众执行检查

分镜只能继承已确认 `drama_plan.json.audience_plan`，不得重新选择受众、平台或地域。在 `storyboard_ep_N.json.audience_execution` 中按 `manifests.md` 分别登记观看焦点、情绪回报、平台观看场景和表达禁区的执行合同，并把每项绑定到真实场次或镜头。四项都必须可追溯；仅写“符合受众”“适合平台”或重新引用受众库标签不算落地。

## 导演总控卡字段合同

> 本节规定每集正式拆分镜前必须完成的唯一导演判断，以及这些判断如何进入逐镜表和视频 Prompt。不得另建第二份导演控制包或强风格系统卡，也不把整张总控卡塞进每个 Prompt。

### 职责边界

- `导演总控卡_ep_N.md`：每集唯一整体创作判断，先于逐镜表完成，并在同一文件内把判断落实为每个 SEG 和 SHOT 的调度、布光、表演、声音、动作与剪辑合同。
- `storyboard_ep_N.json`：保存总控卡文件指针和可执行字段，不复制长篇说明。
- `video.md`：只编译已确认导演总控卡和分镜，不重新发明导演方案。

### 每集导演总控卡

固定文件：`episodes/ep_N/02_分镜/导演总控卡_ep_N.md`。至少包含：

- **视觉叙事策略**：回答观众如何被安排去看，包括主要观察距离、主客观视角、空间压力、运动与静止分工、何时拒绝特写、何时让环境压过人物。禁止只写“电影感、压迫感、高级感”。
- **开场承诺与情绪曲线**：继承 `script_contract.opening_contract`，写清首个叙事节拍如何被看见、谁先反应、什么动作或信息使其升级、在哪个场次兑现或延续；再把项目级 `emotion_design` 细化为关键角色的入场状态、压力来源、转折触发、可见证据、关系后果和尾态。
- **核心意象**：按实际用途选择道具、动作、空间、色彩或声音母题，记录“首次含义 -> 变奏 -> 高潮重释 -> 结尾余韵”。每次出现必须增加信息或改变意义；无变化的装饰不算核心意象。
- **场面调度总纲**：继承人物关系张力表，说明权力差、信息差和情感差如何通过距离、屏幕位置、纵深、遮挡、出入口和道具控制权变化。允许反讽调度，不能机械套“强者站高、弱者站低”。
- **节奏设计**：标记需要快切、连续表演、停顿、长镜或突然中断的段落及戏剧原因。快切用于信息压缩或失控，长镜用于让选择和反应无法逃避；不得用速度掩盖场景没有转折。
- **节奏波形推导**：记录必要内容、观看意图、切镜或连续观察选择与从具体过程推导的时间；波形和强度序列仅为可选描述，不预分配额度。波形从不可移动节点与主重拍的关系推导命名（如“蓄压 -> 刺点 -> 回落”“结果前置 -> 倒推线索 -> 原因揭示”），不自建固定菜单逐一点菜——菜单式选择会替代从剧情节点推导，实测产出趋同；不得固定切成 `0-3 / 3-7 / 7-11.5 / 11.5-14 / 14-15`。
- **视觉风格系统**：媒介形态、构图骨架、光线方向、色彩关系、材质、镜头质感、字体/版式、明确剥离项。它是总控卡的一部分，不单独维护风格系统卡。
- **亮点转译**：逐项读取本集 `script_contract.highlight_ledger`，写清观众先看到什么、哪个动作兑现、表演如何泄露真实意图、声音何时进出、哪个镜头保留余震。信息重释重证据和反应，关系攻防重距离/遮挡/道具控制权，专业能力重流程和策略修正，母题重重复变奏，表演瞬间重表面策略与泄露动作，情绪余震重高潮后的结果镜头。

### 总控卡逐字段推导方法

按下列顺序从上游事实推导，不允许先写形容词再找镜头佐证：

1. **建立输入表**：读取 `creative_proposition`、`opening_contract`、`highlight_ledger`、`script_contract.relationship_tension`（关系张力）、场次 entry/exit state、`emotion_design`、`rhythm_design`、`style_contract`、本集 usage 分卡投影的数据卡空间/状态（分卡不足时按 ID 定点窄读数据卡）和用户镜头禁令。每条输入标记来源场次；互相冲突时回到最早权威阶段，不在总控卡中私自折中。
2. **推导观察者立场**：先问观众应比谁知道得多、与谁同处压力、何时需要看清证据。由答案决定主客观视角、主要观察距离、环境与人物的画面占比，再绑定场次范围；这形成“视觉叙事策略”。
3. **推导核心意象**：从会重复出现且意义会改变的动作、道具、空间、色彩或声音中选择实际需要的对象，分别写首次含义、变奏触发、高潮重释和结尾余韵。删掉后不影响理解或意义不变化的对象不选。
4. **推导场面调度**：把每个关系节点的权力差、信息差、情感差翻译成世界坐标中的距离、纵深、遮挡、出入口、视线和道具控制权；先写 T0，再只记录触发后的 T1/T2 变化。机位随后服务调度，不允许为了构图暗中移动人物或房间。
5. **推导节奏与表演**：从不可移动节点和主重拍分配快切、连续表演、停顿和静默；再对承担转折的角色写“表面策略 -> 内在压力 -> 泄露动作 -> 对方反馈 -> 尾态”。没有因果触发的表情、呼吸或停顿删除。
6. **推导声音**：先锁基础环境声，再为会改变信息的动作配置叙事声，只在主观感知触发时加入情绪性声音；最后决定 BGM 入退、静默和声音桥。若声音与对白争夺同一信息，把非主信息后移或降低，不同时强调。
7. **推导色彩和风格**：逐项继承 `style_contract`，先写基础光源、主辅色、材质和构图骨架，再只在有世界内原因或剧情触发时写变化。无法指出光源、时间、天气、实景灯、服装或空间原因的自动变色删除。
8. **绑定执行范围**：每项决策必须落到场次、SEG、SHOT 范围或明确触发点，并在逐段执行区写首态、尾态、删除损失和专项合同。若一项无法绑定任何镜头，它不是本集执行决策，应删除或返回上游补依据。
9. **一致性检查**：逐项问“它服务哪个剧情问题、在哪一镜可见、变化由什么触发、视频 Prompt 需要继承哪部分”。四问任一无答案时重写；不同字段要求互斥动作、光线、声音或观看立场时，以核心证明和用户锁定项为先，不能同时保留。

### 表演指导合同

AI 表演使用可观察层次，不依赖抽象形容词或只有微表情。每个关键镜头至少写清：镜号、角色、表面策略、内在压力、可见情绪层次、主要脸部/目光/肢体/呼吸变化、触发点、尾态和禁止表演。

- 表面策略决定人物在做什么；内在压力解释动作为什么泄露。
- 微表情只作增强，关键信息同时由动作、距离、道具、声音或结果承担。
- 表演变化按观看顺序清楚展开；连续镜头可以承载多个变化，是否切镜由观察关系与动作完整性决定。
- 有听者时单独写听者反应及尾态，不能只细化说话者。
- 禁止“夸张震惊、持续流泪、机械点头、全员同一表情”等默认失控表演。
- 关键表演镜头可绑定 `performance_scores` 和 `performance_coverage`，但不替代自然语言动作因果。

### 声音设计方案

每集先写整体声音命题，再逐段落实三层声音：

- **基础环境声**：房间底噪、空调、电流、远处车流等，用于空间和连续性，不抢对白。
- **叙事性环境声**：钟声、雨声、脚步、门锁、机器停转等，每次出现必须改变信息或预期。
- **情绪性主观声**：心跳、耳鸣、闷化、呼吸放大等，只在人物感知被触发时短暂进入，并写退出点。

BGM 不得持续填满，也不得只写“低频 BGM”“紧张音乐”“悬疑感音乐”。每条 BGM 写清入点、退点、乐器/音色、速度或节奏、音量、质地、情绪职责和对白避让；跨 SEG 延续时，下一段复用上一段已确认 BGM 描述或 `bgm_descriptor`。

- 静默写明移除哪些声音、保留哪些身体或空间声、持续范围、人物感知和结束触发。
- 完全静默只在世界逻辑或主观听觉成立时使用；通常保留呼吸、布料、空间反射更可信。
- 声音桥登记来源镜头、目标镜头、声音主体、跨越时长、叙事作用和淡入淡出。优先使用环境声、拟音、动作声或非语义人声尾音；音乐桥只在剧情确实需要时使用。台词尾音只写声尾、气口或混响状态，不复制完整台词，不得写“自然衔接”。

### 色彩叙事合同

色彩首先是项目已确认风格的子系统，其次才承担本集变化。禁止把冷蓝、暖橙、红色等机械等同于固定情绪。

色彩脚本写清基础主色、辅色、禁用色/冲突色、人物色彩归属、变化触发、光影路径和高潮状态。色彩变化必须能在光源、时间、天气、实景灯、服装、人物移动或空间转换中解释；认知改变不等于画面自动变色。关键段记录基准主辅色、色温/对比、肤色与主体分离、可见触发、跨镜继承或允许偏移，不要求固定色值。

### Prompt 编译

- 视频 Prompt 不照抄十五列分镜表；以分镜阅读稿的逐镜语言为骨架，抽取景别、机位、运镜、时长、声音、动作桥、连续性和抽帧承接等硬信息，结合 `reference_input_plan` 的真实图片职责，改写为 `video.md` 的项目语言导演交付包（五段式）；交付包连同真实媒体及职责实际交给 `h3-prompt-writing` Skill 判断模式、参考用法并编写提交给模型的 H3 成稿。每个镜头恰好编译一次。
- 每个 SEG 只采用与该段直接相关的导演总控卡内容：视觉策略、节奏原则、色彩基线、人物色彩归属、场景光源、核心意象、道具状态、表演节拍、三层声音、BGM 入退点、静默、声音桥、禁止表演、禁止色彩跳变和尾态。
- 阅读稿、十五列表和 JSON 不一致时，先回分镜修订；视频阶段不得自行取舍。
- 编译时凡镜头命中 `causal_ledger` 的证据/反应位，必须把该链 `visibility_contract` 随镜头一并交给视频阶段（转写规则见 `video.md`「导演交付包（五段式）」节）。

## 场次、片段与镜头

“场次、视频片段、镜头”不得混为一层：

- **场次**：连续戏剧空间或连续戏剧行动，使用 `E{集号}S{场号}`，例如 `E01S01`。
- **视频片段**：一次视频模型调用容器，使用 `SEG001`、`SEG002`；它可以包含一个或多个完整镜头。
- **镜头**：一次不间断观看位置，使用 `E01S01-SHOT001`；单个镜头不得跨两个视频片段。

模型时长只决定提交方式，不反向决定剧情节奏。不得为了填满模型上限把无关镜头塞进同一片段，也不得把重复裁切、数字推拉或无信息变化的构图算作新镜头。

群众/群体出现在分镜中时，先判断它是已登记的稳定群体还是一次性匿名背景人群。稳定群体的 CHR 作为一个集体 actor ID 写入该镜 `actors`，不得为匿名成员虚构单体 CHR；具名、发言或承担独立因果动作的成员另列单体 CHR。逐镜调度另写实际可见人数、前中后景分布、站位区域、运动方向和群体反应时序；群像画像只锁群体构成和视觉特征，不替代逐镜调度或 SCN 空间布局。需要跨镜维持成员位置/服饰/人数时，在 `reference_input_plan` 指定可见布局锚点；非首镜和 `continuous` 接缝按真实 FRM/SCN 锚图合同补齐。

## 片段与时长

- 镜头内容时间由同源过程累计，不要求等于规划初估。各镜头内容区间按正式顺序相接；镜内过程可以并行或有意留空。
- SEG 是一次生成容器；内容时长保留小数，请求时长按 h3.json 的整数能力承载，tail_handle_s 记录差值。余量只延续既有末态，不补戏、不延长或重复台词。
- 合法组边界由导演确定；超能力即报告具体冲突，保留原设计，不自动切镜、重排、改语速或换模型。
- 真实钩子、动作承接、自然转场、结果或余韵都可以承担段尾；不为技术切段强造悬念或停留秒数。
- 一镜到底只登记一个 SHOT，路线、观察与停留按内容展开，无节点数量配额。用户锁定的一镜到底不得静默改成剪辑。

### 尾态选择算法

先看下一段是否继续同一行动/空间，再选择 continuous_motion、cuttable_completion、stable_hold 或 loop_continuation。写清可见动作相位、方向、接触、声音与下一段如何继续；不套百分比或固定尾停。停留本身有观看作用即可保留。

### 真正一镜到底的场面调度算法

先明确起始画面、连续可通行路线、观察对象、遮挡/出入口、轴线及终点；复杂走位按「调度、布光与动作合同」写清世界坐标，简单固定观察不填复杂坐标。顺读每个位置到下一个位置，必要过程完成后估时；无法连续通过时设计明示切点，用户锁定连续观察时说明冲突。

## 高密度剧情与运镜

分镜阶段要把镜头机制写成叙事功能，不把紧凑误解为机械碎切。连续微事件可以合并为剧情动作组：一个连续动作组可承载多个微事件，但必须在同一行写完整“切入触发、画面发起或变化、主体/环境/物件反馈、结果变化和切出落点”；没有人物动作时，按实际画面过程填写，不能只写抽象标签或“镜头跟随”。

高密度段先弄清戏剧过程和空间事实，再决定观众如何经历它；保留完整动作因果与观众所需信息，不把技术切段误当成创作方案。

## 动态镜头数量

镜头密度从内容节点和完整动作推导；每镜通常服务一个可观察的信息、动作、反应或关系变化，具体秒数由对白朗读、动作起势、动作完成、反应停顿和切点决定。所有密度类型都用删除测试、动作完整性和观看关系证明镜头必要性；不因某个 SEG 恰为 15 秒而增加最低镜数。任何类型都不得为达到数量拆断完整动作，也不得把慢推、发光、凝视、轻微呼吸、重复反应或无信息变化的数字裁切算作镜头变化。

- 镜头必须足以清楚表达当前片段实际承担的钩子、目标、阻力、策略变化、高潮或反转、反应和收束。
- 关键职责被一句台词或静止画面含糊带过时，重新设计观看过程，判断镜内展开或切镜能否让所需事实清楚成立。
- 删除后不影响剧情、关系、信息或连续性的镜头应合并；单一状态、动作或静止观察能否持续，按本场观看意图审校，不凭数量判断。
- 不为镜头数量碎切，不用慢动作、重复反应或无意义空镜填时长。
- 一镜到底只能登记一个镜头，且必须满足真实连续拍摄定义；镜内仍须包含连续变化的摄影机路线、主体行动、关系、空间或信息节点。
- 镜头可由一个或多个连续摄影阶段构成，阶段可以在移动、停顿、改变方向、改变观察对象或焦点中自然演进；不要求一镜只出现一种运镜，也不以增加运动次数作为丰富度目标。片段内允许切镜，每个切点应有可理解的观看或叙事作用。
- 人声按已确认内容需要使用：出镜对白、旁白、画外音或内心独白按剧情选择，句句推动剧情、关系、信息或反应。每句可跨相邻镜头连续，但不能靠拖长停顿填时长，也不能靠加速语速塞进过短镜头。字幕生成、样式和烧录只继承 `delivery.md`；视频模型阶段仍禁止画面字幕和自动转写。

## 动作桥与观看关系

每个跨镜动作和每个切点都按以下链条设计：

```text
前镜状态
-> 动作发起
-> 运动路径
-> 合理切点或镜内调度
-> 后镜续接
-> 接触/反馈
-> 结果
```

每次切镜必须明确回答“为什么现在切”“用什么承接前一镜”“切后增加了什么新信息”。承接锚点只能来自动作、方向、主体位置、视线、形状、光色、声音、文字、遮挡或产品状态中的实际可见/可听事实。动作桥示例包括“拿取 -> 移向入口 -> 接触 -> 收纳结果”“铺垫 -> 触发特效 -> 环境响应 -> 结果停留”（涂抹、上脸等同类连续操作同构，按同链路补位移与反馈节点）。不得从动作发起直接跳到结果，也不得让手、人物、产品或道具在切后无路径换位。

## 单镜因果检查

先对整场核人物目标、阻力、策略、反馈和局势变化，再看各镜实际承担哪一部分。并非每镜都要完成整套戏剧链；空间观察、环境、静默、反应或有意重复可以独立成立。关键反应有来源、证据可达、指称有锚；相应因果台账与源覆盖仍按原合同登记。

## 运镜与镜头差异化

导演先判断整段内容最值得如何被观看，再设计镜头。画面变化可以由摄影机、人物、物件、空间、光线、遮挡、声音或剪辑共同形成；不要求运动围绕人物，也不要求每镜都发生变化。运镜描述应让人能想象镜头的起始画面、过程中发生的变化和最终画面；根据方案需要写明摄影机位置/路径、朝向、速度质感、焦点和停留，但不为未使用的维度填参数。复合运动可以按真实先后写成连续阶段，不必压成单一运镜名称。

导演可以从不同视点构思：摄影机观察、接近、等待、离开或重新发现画面中的对象；也可以让观众注意到原本不在主体上的空间、物件、光影或环境变化。这些只是创作可能性，不构成待勾选的镜头清单。运动名称用于准确表达已经选定的拍法，不用来推导剧情或替代画面描述。

运镜、镜头、焦点和剪辑术语是准确表达方案的词汇，不是从剧情类型查找拍法的索引。不要先选一个名词再给它配戏；先形成完整的画面设想，再选择最贴切的语言描述。允许组合已知手法，也允许写出混合、非典型或不易归入单一类别的摄影过程。

`camera_family` 是可选粗略执行注释，不代替实际摄影过程；不以运动占比证明质量。固定镜、同质速度或重复构图是否有效，按当前观看意图独立审校，不为标签调整拍法。

视频工具对不同摄影设计的执行稳定性可能不同；这属于方案定稿后的实现判断，不形成运镜家族清单或创作限额。

### 运镜的动力学命题

需要运动时，先问摄影机为何此刻接近、离开、跟随、落后、等待或改变观察对象。速度、力度和稳定性来自这条具体路线与场面关系，不从 beat 标签或强度对位；静止也可承担压力和时间体验。

整场相似的摄影质感可以是有意选择。发现单调时回到观看过程找具体问题，不按原型表补急推、甩镜或快慢配额；技术风险不能静默改掉已确认意图。

### 镜内运镜编排

先用自然语言形成起始画面、连续发展与最终画面，再根据已形成过程添加必要的局部时间标记。过门/车、镜面或屏幕、多人交叉、手与道具操作、绕障碍和跨轴等风险需要更细说明；长短或 beat 标签不触发事件数量要求。

多个摄影阶段可以同镜连续发生；路线不连续时明示切镜。编译保留真实先后、速度质感、焦点和有意停留，不把它们压成一个标签。采用 POV 时写清所属视点和实际可见身体部分，不能同镜无因跳为自拍或外部机位。

## 对白时长预算

所有实际人声都回指稳定 line_id，以本次演读的导演估计或实存本句音频测量登记为 utterance。估计含本次设计的呼吸/停顿，不自动加固定起势/句后秒数；音色样音不是本句时长证据，不为估时调用 TTS。

speech 与动作、摄影、阅读、反应根据已形成设计安排先后或并行，每镜取最大结束点；不把它们一律相加。连续一句跨镜分片须恰好覆盖完整 utterance 且在集绝对时间首尾连续，不逐镜重启或补停顿。优先避免跨独立 SEG 拆连续发声，确需跨 SEG 时要有真实可执行声音承接方案。

无人声、环境声、静默和无 BGM 都合法；不以人声占比、汉字速度或单句字数判空转。已确认台词逐字保留，窗口不足返回具体设计，不加速或删字。人声主体、类型和口型职责保持原合同；导演包可用现有花括号表示源文本，H3 的实际发声块以并列 Skill 为准。

## 用户可见分镜阅读稿

`分镜_阅读稿_ep_N.md` 必须使用适合用户审查的顺序，不展示内部 JSON、哈希、字段名或校验结果。结构固定为：`## 第X集：[可读标题]` → `### 本集故事提要`（一段话：主线/冲突/高潮/钩子）→ 每章 `### 第N章：[章节名]（本章时长 / 起止）` 配一行叙事功能引用 → 每片段 `#### 片段N：起止时间（含镜数）` 下逐行列镜头：`**镜头K (绝对时间)**：[景别｜视点｜摄影设计｜机位/角度] 首镜给可见信息事件、中镜写过程变化、末镜写结果代价与尾态承接`。

- 章节按照剧本的章节与场次映射排列，不能只写“第一章、第二章”的空标题。
- 片段起止时间一律写引擎 `pack` 校验与写回后的内容计划值：非 15 秒段是正常形态；段不足上限无需解释，顶满模型上限（如恰好 15 秒）反而必须能用镜时长之和解释。但单段不得低于 `tools/video/h3.json` 能力档案的 `min_duration_s`（4 秒，`max_duration_s` 15 秒，仅整数秒），过短段必须合并或重划。
- 每个片段必须按“动态镜头数量”列出足量分镜，镜头时间首尾相接并覆盖完整片段。
- 每个镜头行必须包含：镜头编号、绝对时间、景别、视点、摄影过程、画面动作、声音、人声文本或“无”、切入/切出方式。摄影过程按该镜实际设计填写；静止镜头可说明构图与画面内变化。
- 听得见的人声一律写成 `说话人：{原文}`，例如 `旁白：{门已经开了}`；音效用 `<具体声音>`；BGM 用 `()` 或 `（）`；标题、品牌字、时间地点等画面文字用中文引号 `“”`。字幕源使用 `【】`，只在用户明确要求字幕时登记，并明确不由视频模型渲染。
- 分镜阅读稿可以保留自然语言章名、片段名和故事提要，但不得省略完整镜头列表，不得用参数确认表的剧情预览替代正式分镜。

### 各列要求

- **场次**：稳定 ID 使用 `E{集号}S{场号}`，并保留剧本中的人读编号。
- **视频片段**：稳定 ID 使用 `SEG001`、`SEG002`；同一片段内镜头总时长不得超过所选模型上限。
- **镜号**：稳定 ID 使用 `E01S01-SHOT001`，末尾序号在当前场内连续、不重复、不跳号。
- **镜头职责**：写**可验证**的剪辑职责——判据是能否指出删除损失：删掉这一镜观众将失去什么具体信息/因果/关系变化（“删后观众不知道钥匙在爸手里”合格；“推进剧情”“承载叙事功能”不合格——封词挡不住同义词平移，判据是删除损失具体可指）。
- **时长**：写绝对起止时间和本镜持续秒数，与台词、动作、停顿和切点匹配。
- **画面描述**：写清主体、空间位置、朝向、视线、动作起点、轨迹、反馈、结果和剧情变化。
- **景别**：明确大特写、特写、近景、中景、全景、远景、大远景、过肩或 POV。
- **机位/角度**：明确摄影机高度、观察方向、主客观视角和镜头感。
- **光影氛围**：明确日夜、内外景、主辅光方向、色温、明暗层次、材质反射、天气和情绪效果。
- **对白·旁白**：写明说话人、声音类型和完整文本；用户文本逐字按原顺序保留。
- **音效**：环境声和拟音使用 `<具体声音>`，BGM 使用 `(具体音乐)`，写清进入、持续、淡出或承接时机。
- **摄影过程**：写清观众实际看到的画面如何开始、变化和结束；按需要描述机位路径、朝向、运动质感、焦点变化、停留与剪切。多阶段设计按时间顺序完整表达，不强行归并成一个运镜标签；高动作/钩子镜可用「镜内运镜编排」写法（带镜内时间标记的运镜事件，见「运镜与镜头差异化」节）。
- **切入/切出动机**：登记为 `cut_motivation` 八枚举之一，lint 按下列枚举校验：`match_on_action` 动作、`eyeline` 视线、`occlusion` 遮挡、`sound_bridge` 声音、`reaction` 反应、`spatial` 空间、`information` 信息、`motivated_hard_cut` 有动机硬切；物件引导的切点按驱动实质归 `eyeline`（视线/物件匹配）或 `information`。
- **连续性要点**：记录屏幕位置、视线、轴线、动作方向、道具状态、光位、环境声和台词尾音。
- **抽帧/承接要求**：说明生成前关键帧目标和生成后实际抽帧时刻；两者不得互相覆盖。

|---|---|---:|---|---:|---|---|---|---|---|---|---|---|
| SEG001（分镜01） | 00:00-00:13 | 13s | E01S01-SHOT001 至 E01S01-SHOT003 | 3；`edited` | `dialogue_emotional` / `cuttable_completion` | 完成施压、摊牌和第一轮追问 | 逐条列出 SHOT001-SHOT003 的绝对时间、景别、机位、摄影过程、动作桥、切入触发、可选摄影标签、焦点变化、新增信息和切出落点 | 主角低头看手机，房间冷光 | 主角抬头看向门口，手机仍在手中 | 起始片段；生成后抽取场景锚点与尾帧 | 按真实输入路由：高光 KF + 出场 CHR + 当前 SCN/PROP/STYLE 必需图片；接口支持音频输入时再加已批准 VOICE；后续片段按 seam_mode 决定是否加入上一段视频和 tail FRM | 近景口型、手机文字、冷光稳定 |

每个非首段在“与上一片段衔接方法”中写入入段承接；每个非尾段在该片段尾状态和片段内镜头执行表的末镜切出落点中写入出段转场。二者必须来自同一个 `SEAMxxx`，不能各自发明转场。

### 节奏流水线（rhythm_input → 引擎 → 写回）

先在时间输入登记已经形成的过程与语音估计，再依次执行：

```bash
python scripts/rhythm_engine.py shot-count --project-root <root> --input <input>
python scripts/rhythm_engine.py allocate --project-root <root> --input <input> --storyboard <storyboard> --write
python scripts/rhythm_engine.py pack --project-root <root> --input <input> --storyboard <storyboard> --write
```

shot-count 只报事实与源引用；allocate 只写派生镜长/区间/依据并同步十五列时间；pack 只核合法组、真实请求能力与技术余量。任何错误不部分写回。分组或设计变化按实际依赖失效，不能只凭相同 SEG 序号继承旧 KF/输入/审校/绑定。

### 视频参考输入计划

每个 `SEGxxx` 必须在 `storyboard_ep_N.json.segments[].reference_input_plan` 中写入视频阶段的图片输入计划数组。它不是最终 Prompt，也不是已传图证据；它用于提前规定“要传哪些图、按什么职责传、开头如何定位、哪些内容必须剥离”。数组可以为空，但只表示当前片段没有任何真实图片输入：模式与参考使用方式由视频阶段实际调用 `h3-prompt-writing` 判断，不在此从空数组推断；非首段仅当 planned `SEAM=elliptical`，且当前新起点不需要图片锚点时才可为空。`continuous` 非首段必须规划上一段真实 tail FRM。视频阶段真实调用时仍以 `video_manifest_ep_N.json.reference_inputs` 和工具 schema 为准，但不得无理由删除分镜已列为必需的输入职责。

每条计划至少写：

```json
{
  "order": 1,
  "role": "previous_tail_as_start_frame|previous_scene_anchor_reference|previous_character_state_reference|previous_prop_state_reference|segment_highlight_reference|identity_reference|character_state_reference|scene_layout|prop_structure|prop_state_reference|style_reference",
  "planned_source": "KF001|FRM003|CHR001_v01|SCN001_v01|PROP001_v01|STYLE001_v01|用户素材 SRC001",
  "opening_binding": "[project-language binding for localized marker <图片1>/<IMG1> and its reference duty]",
  "adopt": "[project-language adopted subject, state, space, material, light, or style facts]",
  "exclude": "[project-language excluded subtitles, QR codes, watermarks, UI text, unrelated background, or unrelated people]",
  "required": true
}
```

- `order` 是计划顺序；视频阶段若工具实际上传顺序调整，必须同步改写最终 Prompt 的图片编号标记和 `reference_inputs[].order`，不能照搬旧编号。
- 第一段不规划生成式首帧关键帧；视频从已批准资产、已规划高光关键帧（若有）和文字动作合同启动，生成后再抽取真实 `start FRM` 作为事实记录。
- 非首段先读取对应 `SEAMxxx.seam_mode`。`continuous` 时必须把上一段锁定 `adopted_cut_out` 对应、已保存登记的真实 `tail FRM` 作为 `previous_tail_as_start_frame` 并优先放在首位；这是排他出点前最后保留帧，非文件物理末帧。出点或对应帧缺失时停止下一段编译并先补齐，不得用上一段视频、其他帧或高光 KF 冒充；字段按 `manifests.md` 合同登记。`elliptical` 时根据转场锚点和新起点选择当前场景、角色状态、道具或其他真实参考，不要求把上一段 tail FRM 当作 0 秒画面。
- **锚图充分性闸门**：规划 `continuous` 非首段的输入前，先读该 `SEAMxxx` 的 `required_invariants` 与 `proof_requirement`（转场设计合同），并对照上一段末镜景别与画面内容：凡末镜为中景以下（近景/特写/大特写），或 tail 画面不含全部不变量主体（多人布局、群体衣着、远景人物、画外陈设）时，`reference_input_plan` 必须增加一条 `previous_scene_anchor_reference` 条目，`planned_source` 写“上一段真实场景帧，视频阶段生成后补抽登记”（分镜阶段不得伪造 FRM ID），`required: true`，`opening_binding` 与 `exclude` 按本条上方 schema 照常填写，并在 `adopt` 中写明该帧承载哪些布局/衣着事实；视频阶段补抽登记后将该条 `planned_source` 回写为真实 FRM ID。未通过本闸门的 SEG 不得提交分镜用户确认。连续性账本“同场景/角色状态/道具延续时补 scene、character_state、prop_state FRM”覆盖三类帧，本闸门是其中 scene FRM 义务在 `continuous` 接缝上的强制化触发条款，两处对 scene FRM 的登记必须一致。
- 当前镜头或片段使用的角色状态、以及已升级为 PROP 且会复现的道具状态，必须提前解析到 `project_data_card.json` 的 `state_id` 和 approved 状态资产；查找范围包含共享资产库、本集 `episode_assets` 和其他分集已 approved 且在当前集登记为 `reused_episode_assets` 的资产。`reference_input_plan` 里用 `character_state_reference` 或 `prop_state_reference` 指向对应状态图，不能只写角色基准图、道具基准图再靠文字描述需复现状态。一次性道具状态只写入镜头动作和视频 Prompt 意图，不升级为 PROP 输入。
- 场景参考只锁空间、灯光、陈设和布局；风格参考只锁色彩、材质、光线、构图、景深和颗粒/线条语言，不承载剧情人物或道具；道具参考只锁结构、尺寸、材质、当前状态和可见面；不得把不同职责的图片混写成同一个主体。
- 任何用户或外部图片都必须写 `adopt/exclude`。图片中的字幕、二维码、水印、平台界面、无关人物、镜面文字和背景杂物默认剥离，除非用户明确要求保留且权限、剧情和平台风险均已确认。

### 资产使用对账（asset_usage_plan）

`storyboard_ep_N.json` 顶层必须登记 `asset_usage_plan`：它是资产需求清单的结构化同源数据，资产需求清单 Markdown 和视频片段执行表"必需图片输入"列都由它渲染，不得手工另写造成三方分叉。

```json
"asset_usage_plan": [
  {"asset_id": "PROP003", "version": "v01", "segments": ["SEG001", "SEG002", "SEG016"], "reason": "毛驴：赶路/拴喂/骑逃全程伴随主角"},
  {"asset_id": "STYLE001", "version": "v01", "segments": ["*"], "reason": "全局风格 moodboard，每段必传"}
]
```

- `segments` 列出该资产必须显式传入的 `SEGxxx`；`["*"]` 表示全部片段（供 STYLE001、贯穿主场景等全局资产使用）。
- 登记即声明"此资产在这些片段必须显式传入"，lint 双向对账：登记了但某段 `reference_input_plan` 未计划传入是 error；某段计划使用了未登记的绑定是 warning，临时增补必须回头补登。若判断某段靠上一段尾帧携带即可，不登记该段即可——对账强制的是声明与执行一致，不强制必须声明。
- 只登记需要显式图片输入的资产；一次性物件不升级为 PROP，也不进本表。

### 世界事实承接合同（inherited_world_facts）

`storyboard_ep_N.json` 顶层必须登记 `inherited_world_facts`：从剧本继承的季节、节日、时辰、天气等世界物理事实，全片一致，分镜不得改动。

```json
"inherited_world_facts": [
  {"fact_id": "WF01", "category": "festival", "statement": "时为中元节（农历七月十五）", "source": "剧本1-5"},
  {"fact_id": "WF02", "category": "season", "statement": "初秋，夜凉有露", "source": "剧本1-4/1-9"}
]
```

- `category` 枚举：`season|festival|date|time_of_day|weather|location_fact|other`；每条必须写明 `source`（剧本场次/行）。
- 分镜表、总控卡、执行表中的任何季节/天气/温度/时辰/节日类感官细节必须能引用本表一条；lint 强制本表存在且要素齐全，语义矛盾（新增细节与继承事实冲突）由剧本-分镜对照审校步骤核查。

### 转换差异台账（beat_coverage）

`storyboard_ep_N.json` 顶层必须登记 `beat_coverage`：剧本每条动作/事件的去向，同时渲染为用户可读的 `分镜_转换差异台账_ep_N.md` 随阅读稿提交确认。

```json
"beat_coverage": [
  {"beat_id": "1-8-a", "scene": "1-8", "summary": "谭九出门小解", "disposition": "kept", "target_shots": ["E01S08-SHOT001"], "reason": ""},
  {"beat_id": "1-9-a", "scene": "1-9", "summary": "谭九靠墙根躺下", "disposition": "compressed", "target_shots": ["E01S09-SHOT002"], "reason": "压缩为一个动作提示"}
]
```

- `disposition` 枚举：`kept|compressed|moved|dropped`。`kept/compressed/moved` 必须给出 `target_shots`（真实存在的镜头）；`dropped` 需具体理由及指向当前源版本的明确修订/用户确认，不能单填理由解除缺失。
- **过渡性动机动作**（解释角色为何在某处、为何处于某状态的动作，如小解、添灯、拢火、栓门）默认不得 `dropped`，只能 `compressed` 为视觉提示——这类动作不推动冲突，在戏剧节点拆节拍时最容易被当成冗余删掉，而观众恰恰靠它理解空间与动机。
- "必须覆盖全部剧情"靠这张表核销：每条剧本 beat 都有登记行，处置行与已确认 script.events 双向对账；非 dropped 目标须在时间项以 source_refs 回指源事件，无登记即漏拆。

### 关键帧需求决策

关键帧需求清单在分镜阶段完成，由主 Agent 根据已确认剧本、导演总控卡、十五列分镜、片段执行表和连续性账本决定。用户只确认可读分镜稿和镜头方案；确认后关键帧阶段按清单生成，不再临时挑普通画面代替。若关键帧阶段发现分镜选点缺少剧情峰值、缺状态资产或画面任务混杂，返回分镜或资产阶段修正。

关键帧按实际高光、状态、构图和执行风险选择，无固定张数、单段配额或从时长反推峰值。用 `kf-count --storyboard <file>` 统计正式需求、生成项与复用项；没有独立用途可为零，并保留需求审查和阶段确认。首尾实际事实来自生成后 FRM，continuous 的后段编译前须锁定 adopted_cut_out 和对应帧。

优先生成关键帧的场景：

- 信息揭露、身份暴露、证据露出、文字证据可读、误会被推翻或观众认知改变。
- 角色做出不可逆选择、抢夺/推开/跪下/拔刀/按下发送等动作落点，或动作前一拍已经无法回头。
- 两人关系发生空间性变化：堵门、逼近、退到墙边、遮挡出口、夺走道具、站位高低翻转。
- 角色状态或已升级为 PROP 的道具状态会延续到后续片段：换装、受伤、血迹、开合、破损、易主、内容物露出、屏幕/信件/牌匾出现文字。一次性道具状态变化不触发资产补图。
- 多人同框、复杂遮挡、POV、过肩、镜面、门窗前后景、低光或强色温变化，视频容易漂移。
- 片段中后部承担悬念、危险逼近、声音桥或状态变化时，优先选择能让观众读懂结果和代价的高光瞬间；下一段承接仍以真实 tail FRM 为准。

通常不单独生成关键帧的场景：

- 删除后不影响剧情理解的纯氛围、纯运镜、纯场景展示或装饰性空镜。
- 只有“看向远方、低头沉思、站在原地”等弱动作，且没有新信息、道具状态或关系变化。
- 已由人物、场景、道具资产稳定覆盖的外观展示镜头。
- 可由视频 Prompt 稳定完成的简单动作过程，例如普通走路、坐下、转头、拿起杯子。
- 同一片段内重复的反应特写；除非第二次反应带来新的认知、选择或关系后果。

每张待生成关键帧在需求清单中写清：所属 `SEG` 和镜头、高光序号、准确时间点、单一戏剧任务、选择理由、画面焦点、主要人物屏幕位置和关系、必须传入的角色/状态/场景/道具/风格参考、画面内文字要求、从上一镜继承什么、给下一镜留下什么。画面任务不能同时塞入身份介绍、情绪展示、证据特写和动作高潮；冲突过多时增加第二张高光关键帧，或回到分镜拆镜。

### 因果链台账（causal_ledger）

`beat_coverage` 回答「每条剧本 beat 去了哪」；`causal_ledger` 回答「**跨镜头的因果链条是否闭合**」。它要截住的问题是**因果断点**：观众在某个观看点上用来理解「为什么会这样」所需的事实，在该时间点既不可见也不可得——要么从未被任何镜头建立，要么虽建立过但当前调度把它遮挡/改写，要么以指称（人称、方位、物品名）出现而没有视觉锚点承接。典型事故形态：剧本写「捂嘴进门，满堂哄笑」，分镜忠实 staging 了捂嘴这个遮挡动作，却没给「肿唇」留可见通道——触发反应的证据被遮挡，哄笑、模仿和明知故问全部失去画面依据。

判定断点的三个锚（审校与台账共用，据此前推，不靠感觉）：

1. **反应必有源**：任何反应类画面（哄笑、围观、震惊、害怕、态度转变、明知故问）都必须能指出一个先建立或同镜可见的触发事实；
2. **证据必可达**：链条依赖的证据在消费它的镜头时间点必须可见或可听，调度（遮挡、景别、焦外、背身）不得把它切断；
3. **指称必有锚**：台词/叙述中的指称在观众侧必须有已建立的视觉锚点或明确的延迟兑现登记。

断点分类学（`breakpoint_risk` 取值，审校归类与台账登记共用）：

| 类型 | 定义 |
|---|---|
| C1 反应无源 | 反应类镜头无已建立的可见/可听触发 |
| C2 证据遮断 | 调度（遮挡/景别/焦外/背身）把下游依赖的证据切断 |
| C3 状态无源/无果 | 状态变化无原因镜头，或原因已演但结果永不出现 |
| C4 指称悬空 | 台词指称无视觉锚点且未登记延迟兑现 |
| C5 动作无果 | 剧情节拍依赖的动作没有反馈/结果镜头 |

台账只登记**含反应/态度转变/证据依赖的链**，不全量复制 beat；schema 与各字段权威定义见 `manifests.md`。在完整分镜表与关键帧需求决策完成后、剧本-分镜对照审校与用户确认前，按以下顺序推导：

1. 逐镜扫 `causal_role`：凡 `reaction|result` 镜，必须有链可归；归不进既有链就新建。
2. 每条链倒查三锚：触发事实是否已建立（前序镜头/资产状态/世界事实）？证据在反应镜时间点是否按 `visibility_contract` 可见？结果是否有落点镜头（可跨 SEG；跨集登记 `cross_episode_refs`）？
3. 台词指称单独过一遍：每个非常规指称登记锚点镜头或延迟兑现。
4. 链合并与拆分：同一触发引发多次反应只建一条链；一个镜头可出现在多条链、一条链的多个角色位。
5. 与 `highlight_bindings` 对账：被亮点覆盖的链只写 `highlight_binding_ref`，不重复登记四步。
6. 关键帧联动：`visibility_contract` 关键的证据镜头列入 KF 优选（适用上文关键帧需求决策的「证据露出」条款）。
7. 跨 SEG 的 `visibility_contract` 条款在分镜定稿时同步派生写入对应 `SEAMxxx.required_invariants`；台账仍是唯一权威，SEAM 卡为派生引用，lint 对账两处一致。

台账同时渲染为用户可读的 `分镜_因果链摘要_ep_N.md`（一两屏可读，每链三列：链｜触发→证据→反应→结果｜可见性合同），随分镜阅读稿、转换差异台账、资产使用摘要同批提交用户确认——它是用户发现「反应无视觉依据」类错误的入口。剧本-分镜对照审校第⑤项（见 `references/skill-details.md`「阶段内容硬门 · storyboard」五项编号清单）逐条对照本台账核查。

### 片段内镜头执行表要求

逐片段另列“片段内时间 / 镜号 / 景别 / 机位 / 前镜状态 / 动作发起 / 摄影过程 / 合理切点或镜内调度 / 后镜续接 / 接触或反馈 / 结果 / 新增信息 / 可选摄影标签 / 焦点变化 / 切出落点”。它必须与完整分镜表一一对应，确保同一片段里的多个镜头不会在视频阶段被合并成一个长画面。

- 每个时间段首尾相接，总和严格等于该片段实际时长。
- 每个镜头都有切入触发和切出落点。
- 相邻镜头在观看距离、构图、视点、摄影过程、画面内变化或节奏上形成有意图的关系；不要求每镜更换运镜类别。
- 每个片段呈现与剧情负载相称的可观察变化；单镜片段可通过摄影、表演、空间、光线、声音或信息变化承载过程，不要求凑足变化次数。
- 片段边界必须落在镜头结束处，下一片段从新镜头开始，不重复上一片段已完成动作。
- 摄影过程不能只填“电影感”或“镜头移动”。应具体写出画面经历和摄影机如何实现它；例如从什么画面开始，沿何种路径或以何种方式改变，过程中什么进入/离开视野，最后停在哪里。示例用于说明描述精度，不作为构图或运镜模板。

## 导演总控卡的逐段执行区

在唯一 `导演总控卡_ep_N.md` 内逐片段填写以下执行区，不另建 `分镜_导演控制包.md`：

| 片段 | 戏剧目标 | 首态 | 尾态 | 镜头职责与删除损失 | 世界坐标/轴线 | 光源锁 | 声音交接 | 专项合同 |
|---|---|---|---|---|---|---|---|---|
| 逐 SEG 一行 | 可观察的戏剧目标 | 片段开始的角色/道具/空间/声音状态 | 片段结束的对应状态 | 逐镜写“删除后观众不知道什么” | 轴线、屏幕侧、视线与摄影机活动区 | 光源来源/方向/色温/变化 | 台词尾音、环境声、BGM 交接 | 无 / 轴线 / 叙事光 / 动作拆分 |

- **叙事节拍**：按下节字段记录钩子、欲望、阻力、策略变化、权力转折、代价、信息差和兑现/悬念，并绑定证据镜头。
- **片段吸引力与段尾功能**：每个 SEG 必须让观众有可指出的观看动力（目标/阻碍、动作变化、信息揭示、关系或情绪张力、兑现、仍在进行的行动或真实悬念）和明确的段尾功能（结果、动作承接、暂缓、转场或钩子），写入逐段执行区；悬念必须由真实已建动作或问题落地，不能为技术分段伪造。相邻 SEG 合看时必须检查前段留下的动作/问题由后段承接、兑现或有意转向，不能因切段造成断裂。
- **台词证据链**：把关键身份、指控、承诺、能力、秘密和判断绑定到前置来源、可见证据镜头及其剧情后果；角色撒谎或误判时明确标记。涉及关键台词的链条用 `causal_chain_ref: CLxxx` 挂到 `causal_ledger`：证据镜头引用与可见性合同以台账为唯一权威，本条目只保留台词真假/误判标记、剧本来源场次与后果语义，不再列证据镜头号；纯画面链只进台账。
- **场面调度**：双人以上交互、走位、遮挡、道具传递、追逐或打斗，按「调度、布光与动作合同」先固定世界坐标与 180 度轴，写进十五列与逐段执行区，不另立账本。
- **布光**：复杂光线、昼夜切换、情绪转折或跨片段同场景，按「调度、布光与动作合同」写清每个光源的来源、方向、色温、照亮区域和首尾连续性。
- **表演指导**：从导演总控卡继承本集表演总纲，再逐镜落实；同一镜有多角色时每个角色单独一行。

| 镜号 | 角色 | 表面策略 | 内在压力 | 情绪层次 | 微表情目标 | 肢体语言 | 呼吸节奏 | 禁止表演 |
|---|---|---|---|---|---|---|---|---|
| 逐镜一行（多角色各占一行） | 写人物在做什么 | 动作为何泄露 | 基准态与变化 | 一个主要可见脸部动作 | 一个主要肢体动作 | 停顿与节奏 | 该镜禁止的失控表演 |

逐镜声音必须能回指导演总控卡的三层环境声和 BGM 曲线；静默写清移除哪些声音、持续多久、结束触发是什么。逐镜色彩与光线必须回指色彩叙事合同的基准色或触发节点，不得只写“冷色高级感”。
- **动作设计**：打斗、追逐、抢夺、跌落、复杂接触或多人同步动作按「调度、布光与动作合同」的“起势 -> 位移 -> 接触/落空 -> 反应 -> 结果”拆拍；超出生成稳定性时拆镜或改用反应、遮挡、声音暗示。
- **剪辑动机**：每个切点必须由 `cut_motivation` 八枚举之一驱动（同本表「切入/切出动机」的 `CUT_MOTIVATIONS`）：动作、视线、遮挡、声音、反应、空间、信息或有动机硬切；“为了丰富镜头”不是动机。
- **片段内镜头执行表**：按上文「片段内镜头执行表要求」的固定十五列逐片段列出（定义与各列要求见该节，不另建第二份列清单），确保分镜表中的每个镜头恰好一次编译进视频 Prompt，不遗漏、不重复，也不合并成无节点长镜头。

### 叙事节拍与证据链

每场或每个可生成片段按字段一行枚举记录（人工总控卡填写模板，非机器 JSON schema；机器字段以 `manifests/storyboard.md` 为准）：`scene_id`、`source_form`（`script|outline|sketch|oral`）、`assumptions`、`hook`、`want`、`obstacle`、`strategy_shift`、`power_turn`、`cost`、`information_gap`、`entry_state`、`exit_state`、`cliffhanger_or_payoff`、`evidence_shots`、`dialogue_evidence_map`。

字段必须对应画面、动作、台词或声音中的可观察事实。关键身份、指控、承诺、能力和结论继承 `scriptwriter.md` 的证据链，再绑定实际揭示镜头及其后果；不得只写“反转很强”“推进剧情”。`dialogue_evidence_map` 每条登记 `causal_chain_ref: CLxxx` 挂到 `causal_ledger` 对应链；证据镜头引用与可见性合同以台账为唯一权威，此处不再列证据镜头号。

### 调度、布光与动作合同

这三类设计直接写进十五列分镜表与 `导演总控卡_ep_N.md` 逐段执行区，不另立 JSON 账本：

- **调度先于机位**：双人以上交互、走位、遮挡、道具传递、追逐或打斗时，先固定世界坐标（屏幕左右、纵深、视线、遮挡、出入画）和轴线关系，再选机位；换机位后按世界坐标重新计算屏幕关系，不得为保持画面左右而暗中移动人物或房间。跳轴、换手、瞬移的修正路径按 `troubleshooting.md` 的动作桥执行。
- **叙事光**：复杂光线、昼夜切换、情绪转折或跨片段同场景时，写明主/辅/轮廓光的画内来源、方向、明暗目的与跨片段连续性。资产图使用可读性优先的标准光；剧情镜使用有画内或世界来源的叙事光。暗部必须有叙事目的，不能用死黑或滤镜替代布光。
- **动作拆分**：打斗、追逐、抢夺、跌落、复杂肢体接触或多人同步动作按“起势 → 位移 → 接触或落空 → 受力反应 → 结果”拆分；动作密度结合因果环节、人物数量、持续时间和摄影机运动判断；超出模型稳定能力时拆镜，或改用反应、遮挡和画外声音。

### 风格一致性检查

风格检查写入唯一 `导演总控卡_ep_N.md` 的逐段执行区，不增加第 16 列。逐场记录色彩、光影、构图/景别、镜头运动、标志机制和跨镜一致性，并绑定镜号及可见证据。只采用服务剧情的风格机制，不规定每集固定出现多少大师元素，也不能用统一慢推或死黑代替风格；色彩、光源、构图、运动和标志机制都必须能回答“为这个镜头的什么叙事职责服务”，跨镜一致由文字合同和生成后场景锚点帧复核。

## 开场、转场与角色表演控制

### 开场镜头合同

每集第一个可观看节拍必须把 `script_contract.opening_contract` 转译为镜头，而非只在台词或旁白中声明。第 1 集必须直接兑现规划 `OPEN001`；后续集可采用剧本中已解释的变体，但仍要在首镜建立与项目承诺的关系。开场类型只确定观众首先被什么抓住，仍必须服务人物目标、阻力和后续兑现：

| 主开场机制 | 首个可观察承诺 | 镜头设计重点 | 禁止替代 |
|---|---|---|---|
| 悬疑问题 | 可被看见的异常、缺口或未解问题 | 线索可读、视点克制、人物对异常作出行动或错误判断 | 用模糊滤镜、惊吓音效代替线索 |
| 世界观震撼 | 规则、尺度或秩序与人物处境的碰撞 | 奇观必须落到人物目标、代价或行动 | 只有空镜和设定说明 |
| 人物塑造 | 人物独有策略、习惯或失控裂缝 | 先让人物做选择，再解释背景 | 靠旁白贴标签 |
| 视觉奇观 | 一个无法被普通画面替代的视觉事件 | 构图、尺度、反应和后果连续出现 | 只展示漂亮场景 |
| 冲突驱动 | 双方目标立刻相撞 | 明确谁要什么、谁阻止、第一轮反馈是什么 | 无来源的争吵或突发事件 |

每个开场至少在导演总控卡登记：首个时间范围、第一可见承诺、人物或世界的即时反应、升级触发，以及本集兑现或悬念延续的场次；并核对开场镜头确实属于剧本合同的开场场次、是该场次第一个承担开场职责的镜头，其余各项都能指出实际画面证据。短片不套固定秒数；按实际时长把开场作为首个完整叙事节拍。

开场按已确认 opening contract 执行；只有明确选用黄金三秒机制时才参考该事件检查。任何题材都须尽早建立观众可读的问题、人物、奇观或冲突，但不由精确时长触发固定事件数。最终结尾必须完成结果、反应和落点；除已规划无缝 Loop 外，不得只是回到与开头相似的画面。

### 转场设计合同

转场是两个镜头或两个 SEG 之间的叙事动作，不是后期遮掩错误。每个 `SEAMxxx` 选一个主转场，必要时可附声音桥，但不能把多种无关技巧堆在同一切点。跨 SEG 转场必须采用“双锚单主导”：上一段尾部负责把画面送到可剪切状态，下一段开头负责从该状态迅速接入。由于相邻 SEG 实际上是分开独立生成，双侧 cue 都必须自洽写清画面、方向、速度、遮挡、动作相位和落点，不得写“同上”“相同”“保持上一段”“自然接上”等需要读取另一段 Prompt 才能理解的省略词。

分镜阶段必须先做一次 seam-first 设计，再定稿视频片段执行表：逐个边界判断它是 `continuous` 还是 `elliptical`，选择唯一主锚点，并写清出点动作相位与入点动作相位。连续边界优先使用上一段实际尾态可继承的动作、视线、道具接触、屏幕方向或遮挡物；省略边界优先使用相似构图、物件、声音或明确叙事动机。不要把“自然衔接”“后期看情况”写成转场策略。

衔接卡必须先选 `seam_mode`：`continuous` 用于同一行动、空间或无跳跃的时间推进，`elliptical` 用于明确的时间/空间/认知跳跃。再填 `transition_anchor`（匹配什么）、`outgoing_prompt_cue`（末镜如何把动作/运镜/声音送出）、`incoming_prompt_pickup`（下一段 0 秒如何接住同一锚点）、`required_invariants`（无论切法不可变的事实）、`permitted_deltas`（计划允许变化的维度）、`proof_requirement`（首尾窗口核验方式）。`continuous` 的 `permitted_deltas` 必须为空；`elliptical` 至少登记一项允许变化，且只验收不变量与计划变化。连续动作优先动作匹配、遮挡切或甩镜同向；跨时空优先相似构图、物件/声音匹配或有动机硬切。无法满足锚点时回到分镜；视频已生成时关键问题阻断合格接受、非关键偏差须明确接受；返修建议不授权执行，须等用户要求修改及新的生成确认，不能让声音桥掩盖未允许的身份、动作相位或光位错误。

七类转场锚点与双侧 cue 写法（一表合并；出点/入点锚点即 cue 的匹配对象）：

| 转场类型 | 出点/入点锚点（适用场景） | `outgoing_prompt_cue` 写什么 | `incoming_prompt_pickup` 写什么 |
|---|---|---|---|
| 动作匹配 `action_match`（连续行动、交接、反击） | 同一动作相位、方向、速度或受力结果 | 动作切到未完成相位、方向、速度、受力点 | 从略微推进的相位开始，完成结果，不重做起势 |
| 遮挡切 `occlusion_cut`（过门、掠物、交错） | 前景遮挡物的方向、面积和解除时机 | 哪个前景从哪侧进入、遮挡面积、遮满时机 | 从哪侧遮挡中开场，遮挡如何迅速解除并露出新主体 |
| 相似构图 `graphic_match`（时空跳跃、意义对照） | 画面形状、主体位置、视觉重心或色块关系 | 形状、主体位置、色块或视觉重心如何占满尾帧 | 以对应形状/色块/重心开场，并立刻揭示新时空或新意义 |
| 甩镜同向 `whip_pan_match`（失控、追逐、能量转移） | 同向运动、模糊强度和入画落点 | 摄影机甩动方向、模糊强度、切出前画面被什么吞没 | 从对应方向的运动模糊进入，短时间内停到新景别和新信息 |
| 视线/物件匹配 `eyeline_match|object_match`（对话、线索、联想） | 视线目标或道具形态、位置、接触关系 | 视线目标或物件接触点在尾帧的位置 | 从目标物/接触点开场，说明看见者或持有者如何变化 |
| 声音桥 `sound_bridge`（时间/空间转换、余韵；默认只辅助视觉转场） | 声音来源、进入/退出点和画面关系；台词尾音只写声尾性质，不复制完整台词；BGM 写可复用的乐器/节奏/音量/情绪职责 | 台词尾音、环境声、拟音或 BGM 的出点；台词尾音只写尾音性质和结束时机；BGM 只在剧情需要时写可复用的具体描述 | 声音从 0 秒继续，但只写非语义尾音、呼吸、环境声或拟音；BGM 逐字复用上一段描述，不把上一段完整台词再写一遍；画面动作仍要有具体入点 |
| 有动机硬切/叠化 `motivated_hard_cut|dissolve`（不应伪装连续性的转场） | 明确的策略、信息或时间关系 | 上一段以明确结果、反应或信息落点收住 | 下一段快速建立新时空和变化原因，不伪装为连续动作 |

`outgoing_prompt_cue` 与 `incoming_prompt_pickup` 必须成对但不重复：前者写“上一段计划出点前发生什么出画、遮挡、甩动、视线、物件接触或声音延续”；后者写“下一段 0 秒从哪个屏幕边缘、哪种运动模糊、哪个遮挡物、哪个物件位置、哪个动作相位或哪个声音桥快速进入，随后按实际动作与观察过程落到本段主体或信息”。下一段开头不得再写一个新的转场名或完整重复上一段运镜，只能用可独立理解的具体画面接住该 `SEAMxxx` 的主锚点并继续剧情。衔接卡必须把摄影机运动方向转译成屏幕入画方向：例如上一段“向右甩镜至运动模糊，把门框遮满画面”，下一段应写“迅速从画面左边运动模糊和门框遮挡中接入，遮挡解除后停到新主体”，而不是只写“同向甩镜接上”。

方向必须拆开写清：摄影机运动方向、画面中模糊或遮挡物的流动方向、主体从哪一侧入画或出画、停在哪个景别和位置。不得只写“同向运动”。具体左右、上下、前后按该接缝实际画面设计填写，不套固定方向；若方向无法稳定判断，改用遮挡切、物件匹配、视线匹配或有动机硬切。

高风险边界必须预先设计桥接方案：当角色太多、同一动作难以由下一段 0 秒稳定承接、场景/光位跨度大、上一段尾帧无法作为真实图片输入，或预定为 `dissolve` 但当前成片工具只支持普通拼接时，按具体观看需要设计桥接镜头或独立 `bridge SEG`，再推导时间。真正重叠两侧画面的视觉转场会消耗两侧有效帧，叠加类光效或声音桥不改变主时间轴；分镜必须在 `duration_s` 和接缝卡中提前写清，不能到成片阶段用效果遮掩未设计的跳变。桥接镜头优先使用手部接触、门/墙/衣料/前景遮挡、关键道具特写、同向甩镜、视线目标或声音尾音；它必须承担剧情信息或情绪余波，不能只是空转场。

### 角色表演谱与情绪曲线

关键表演镜头在导演总控卡逐段执行区和 `performance_scores` 中使用时间段表演谱。先在 `performance_coverage` 声明哪些镜头必须有表演谱；确实没有关键表演时使用 `not_applicable` 并说明为什么。每拍使用相对镜头的 `start_ms/end_ms`，首尾连续、不重叠、不得超过该镜时长；内容按“发生原因 -> 基准状态 -> 人物策略 -> 可见脸部动作 -> 目光与身体 -> 声音/呼吸/停顿 -> 听者反应 -> 结束状态”编写；台词只在其触发或改变表演时出现。逐拍登记用十列表：时间段｜发生原因/策略｜基准状态｜情绪状态与变化｜可见脸部动作｜目光与身体｜声音/呼吸/停顿｜台词触发｜听者反应｜结束状态。

- `cause` 必须来自台词、动作、道具、信息或对方反应，不能只写“情绪来了”。
- 每拍 `baseline_state` 写动作发生前观众能够看到或听到的状态；第一拍继承镜头入态，第二拍起必须逐字承接上一拍 `end_state`。变化太复杂时拆拍，不允许用“继续上一状态”绕过。
- 有明确听者、对手或共同在场角色时，`listener_response.mode` 使用 `covered`，逐人写 `character_id`、反应发生时机、可见反应和尾态；独白、无人回应或本拍确实不适用时使用 `not_applicable` 并写具体原因。听者不能只作为静止背景，反应应改变距离、视线、动作、认知或下一轮策略中的至少一项。
- 先写任何观众都看得见的脸部、目光、手势、姿势和呼吸，用自然语言描述强度与时机；编号化面部动作编码不单独传意、不替代自然语言。非人、遮脸、远景或无法辨认面部的镜头只写可见行为，不伪造面部精度。
- 一拍只突出一个主要变化；复杂情绪拆成连续拍点。先用 `emotion_curve_coverage` 列出承担转折的角色，或写不适用原因；每条曲线写清 `character_id`、入场状态、压力来源、场次级触发、前后状态、可见证据、关系后果和尾态，分别与项目级曲线、场景攻防和 BGM 曲线对应，但不得让 BGM 或色调替代人物变化。
- 说话前的口唇、下颌、眉眼和身体预备应与语气一致；台词结束后的闭口、视线、呼吸或姿势也必须成为下一拍可继承的状态。

## 连续性账本与片段衔接卡

逐视频片段记录：

| 片段 | 时间范围 | 实际时长 | 首状态 | 尾状态 | 角色与造型 | 道具 | 场景/光线 | 动作趋势 | 声音承接 | 上一段抽帧与承接方法 |
|---|---|---:|---|---|---|---|---|---|---|---|
| 逐 SEG 一行 | 绝对时间 | 引擎 pack 值 | 完整写明 | 完整写明 | 脸部/发型/服装/伤痕/位置/朝向/视线 | 持有者、可见面、开合/破损 | 场景时间/天气/主光/色温/固定背景锚点 | 动作向量、速度、下一拍 | 台词尾音、环境声、BGM 入出点 | 首段写抽帧计划；非首段写法见下方硬门 |

追踪角色身份/状态、服装伤痕、位置朝向、轴线、手持物、道具状态、场景光线、环境声和音乐。**“上一段抽帧与承接方法”列必填**：首段写抽帧计划；`continuous` 非首段写上一段连续性抽帧组如何作为真实图片输入，其中 tail FRM 是 0 秒首帧视觉基准，同场景/角色状态/道具延续时加 scene、character_state、prop_state FRM；`elliptical` 非首段写清时间/空间/认知跳跃、允许变化、新起点及转场锚点，不强制 tail FRM。若连续承接所选工具无法接收 tail FRM，必须改分段方案或返回用户重新选择可接收图片的工具方案，不得静默降级。

每个跨片段接缝必须建立唯一 `SEAMxxx` 片段衔接卡，显式写出“上一片段结尾状态 → 本片段 0 秒开场状态”，字段一行枚举：上一段计划尾态/本段 0 秒开场状态/相关高光 KF、角色屏幕位置/姿势/朝向/视线/`state_id`、道具持有者/可见面/开合破损/手部接触、主光方向/色温/曝光/SCN 版本/固定背景锚点、摄影机轴线侧/机位高度/景别/观察方向/角度/运动家族、动作向量/速度/接触/动作相位、预定切法/转场锚点/允许变化/首尾窗口核验、`outgoing_prompt_cue`/`incoming_prompt_pickup`、声音桥与 fallback。实际 `tail/start/scene/character_state/prop_state FRM` ID 由视频阶段生成后写入 `continuity_ep_N.json`（schema 读 `manifests.md`），分镜阶段不得伪造。硬门：

- 连续动作在适合衔接的可见动作相位切出，下一段从同一相位或略微推进切入，禁止动作重做或回弹。
- 预定切法取动作匹配/视线匹配/物件匹配/遮挡切/相似构图/甩镜同向/叠化/声音桥/有动机硬切之一，不得写“自然衔接”“后期看情况”。
- continuous 后段编译前先查看前段实物并锁定 `adopted_cut_out`（源视频 SHA、时间码、对应帧及 SHA），后段输入与最终 trim 同一出点；改出点使入站帧/后段绑定/确认/剪辑依赖全部失效；窗口不足、无剪切点或验证不通过时关键接缝标 blocked，不得以 best available cut 或文件边界兜底，非关键偏差按质量门由用户接受。
- BGM 仅在剧情需要同一情绪或同一声源跨段时使用，写成可逐字复用的具体描述并标声音桥入/出点。
- `outgoing_prompt_cue` 与 `incoming_prompt_pickup` 必须共享同一 `transition_anchor`，禁止双转场、反向运镜或动作重复。

衔接卡完整字段另以一行清单追加存档：`SEAM ID / 上一片段 / 下一片段 / 上一段计划尾态 / 本段 0 秒开场状态 / 相关高光 KF / 预定切法 / 转场锚点 / 出段 Prompt cue / 入段 Prompt pickup / 允许变化 / 核验要求 / 尾部窗口帧数 / 头部窗口帧数 / 动作相位 / 屏幕位置与方向 / 摄影机角度与运动 / 道具接触 / SCN 与轴线光位 / 声音桥 / fallback`。

若文字继承无法稳定保持同一画面，不追求伪像素连续；应把边界设计成遮挡切、甩镜、动作匹配、视线匹配、物件匹配、桥接镜头或明确换机位，让差异成为有动机的剪辑。分镜定稿前逐个接缝做“硬切预演”：如果按普通拼接直接相接会显得跳变，就必须修改出入点、增加桥接段或改为明确省略剪辑，不能把问题留给成片阶段。

## 参考资料与参考视频

分镜阶段接收用户图片、视频、脚本或风格参考时，先按 `manifests.md` 的 `source_manifest.json` 分类并写明采用什么、不采用什么；跨阶段冲突优先级仍按 `control-contracts.md`。

针对外部运镜模板类资料：

- 采用：逐镜“景别 + 机位 + 运镜 + 动作”的结构、跟拍/环绕/升降/手持/焦点转移/甩镜/匹配剪辑等候选，以及动作匹配切镜和接缝重复帧排查思路。
- 不采用：默认 `4K/60fps`、固定三秒定格、所有动作都缓慢、每句最多两种运镜等与当前工具 schema 或剧情职责冲突的模板；最终参数以实际工具能力和项目节奏为准。
- 组合名称不能直接复制成模糊 Prompt。必须拆为相邻镜头，或在模型已验证、路径简单时拆成同镜先后两段运动。

参考视频必须拆成六项可迁移导演信息：

```text
reference_structure：段落结构、信息顺序、切点逻辑
reference_pov：机位、景别、视角和观察者身份
reference_motion：主体或环境的可见运动、摄影机轨迹、速度和节奏
reference_emotion_arc：情绪起点、升级、翻转和回报
reference_audio_logic：台词、环境声、拟音、音乐和声音桥关系
reference_risk：需剥离的品牌、人物身份、字幕、口号、水印、平台 UI 和未授权内容
```

只迁移已声明的结构、视角、运动、情绪或声音机制，不复刻原人物、场景、品牌和文字。

## 与关键帧和视频阶段的边界

分镜阶段不生成关键帧、不写最终视频 Prompt，只产出稳定 ID、十五列画面与声音设计、片段内镜头执行表、首尾状态、衔接方法、必需图片职责、关键帧需求清单、人声设计和生成后 FRM 抽帧计划；产物清单以 `control-contracts.md` 跨阶段交接表为权威，此处不重复枚举。

只有被选为集级高光的 SEG 才需要高光 KF。状态变化（服装、妆发、伤痕、伪装、装具，或已升级 PROP 道具的开合、破损、内容物、归属、可见面）会复现时，必须在该 SEG 参考计划中列出 approved 状态资产，依据可来自共享资产、本集资产或其他分集已 approved 的复用资产；一次性道具状态只进入镜头动作和 Prompt。非首段还要消费上一段已验收连续性抽帧组。人声必须写明主体、音色锚点、类型、逐字文本和发声窗口；出镜对白要求口型，其余人声要求画面人物不开口。

### 分镜内容人工复核

在完整分镜表与关键帧需求决策完成后、用户确认前，以及分镜返修重新提交前，必须读取并完成 `references/skill-details.md`「阶段内容硬门 · storyboard」中的五项剧本-分镜对照审校，再按下述实际观看过程复核。

主 Agent 在初稿后独立重新读取源剧本和实际分镜，先按观众顺序顺读一场，再逐镜核对：必要事件/台词和证据何时被感知；从前画面到后画面的空间/路线是否连续；已声明串并行与演读估计是否可信；等待/停留在看什么；道具、身份、状态和声音如何进入当前实际设计。

对照世界事实及 causal_ledger 的反应有源、证据可达、指称有锚。发现问题先改设计/时间输入、重跑引擎与 lint，再重新逐项复核；无问题用盖章命令绑定当前源/设计/时间输入版本：

```bash
# 先无旗标运行：结构门预检 + 打印五项复核清单（不写文件）
python scripts/stamp_review.py --project-root <项目根> --episode ep_N
# 真人逐项复核完且无未解决问题后：
python scripts/stamp_review.py --project-root <项目根> --episode ep_N --i-did-the-review
```

`content_review` 只由 `stamp_review.py` 写入（命令内部用 `full_review_inputs()` 算三元指纹，禁止手填或手写脚本计算）；结构门未过或 `open_issues` 非空时命令拒绝盖章。不同类型无需同样运镜、声音、反应或镜长分布，不填逐镜自证通过表。未解决问题或绑定过期不能推进；程序通过只证明声明一致，不能证明摄影物理可达、动作时间真实或审美合格。

## 存储与阶段确认

本阶段产物统一进入当前 `ep_N` 的分镜目录；路径、命名和 `storyboard_ep_N.json` schema 只读取 `manifests.md`。

落盘前检查：

- 当前确认范围内全部剧本场次和剧情均已进入分镜表；导演总控卡可追溯到关系矩阵、镜号或剧情触发点。
- 每镜有职责、切入/切出动机、连续性、抽帧/承接要求，以及可理解的摄影过程和可见画面发展；有意停留时写清其观看对象与作用，相邻镜头有意图上的关系。
- 核心表演镜头有原因、基准态、可见动作、目光/身体、声音/停顿、听者反应和尾态；声音与色彩符合本集总合同。
- 出镜对白、旁白、画外音和内心独白均绑定镜头、声音主体、类型与发声窗口；用户原台词逐字、按原顺序进入对应镜头。
- 机器结构门（十五列与时间戳、总时长/单段 4–15 秒整数区间（上下限读 `tools/video/h3.json` capabilities）、片段执行表一一对应、`storyboard_ep_N.json` 顶层字段与非空数组、planned SEAM、`causal_ledger` 登记与摘要渲染、关键帧清单与 approved 资产/数据卡 revision 一致等）由 `python scripts/drama_lint.py <skill-root> --project-root <project> --stage storyboard` 统一核验；落盘前必须 0 error，不在此抄写机器码。镜头划分、摄影路线、有意停留和复杂调度的人审按「分镜内容人工复核」执行，不按密度、分布或长镜例外配额准出。

将分镜阶段及目标分集状态写为 `awaiting_confirmation`，运行内部结构检查；存在问题时先修复，不单独输出阶段报告。通过后向用户提供全部可审查的分镜类用户可见 Markdown 文件，每个文件配一句简短说明，并在聊天中简要输出镜头方案摘要；文件链接使用真实可访问路径，链接范围仅限用户可见分镜稿。不得在聊天说明中展开或点名内部执行技术、代码逻辑、机器字段、自动检查原文、连续性账本、片段衔接卡、导演总控卡内部执行区、关键帧需求清单、结构化索引、哈希或任何内部文件，并按 `language_contract.output_language` 使用不固定但语义完整的确认句：请用户确认分镜是否需要修改；需要修改则直接指出；确认无误则用明确肯定回复；收到确认后才开始生成关键帧。确认句要礼貌清晰，避免每阶段重复同一句模板。

收到修改意见时只修订分镜。改变镜头职责、时间轴、轴线、接缝或大范围执行合同的重大修改重新提供完整受影响文件；局部文字或单镜微调只提供修改文件、修改前后和影响范围。只有用户明确确认后才进入 `keyframes.md`。
