# 分镜阶段 Ref

本入口只定位当前工作。创作、时间登记、SEG 执行和最终审校各有一份权威方法；不把完整交付 schema 当作创作前置。

## 本 Ref 关键要求

- 正式分镜覆盖当前集已确认的全部剧情；候选可以逐场保存，只有完整交付才进入阶段确认。
- 继承用户锁定项、源台词、人物/世界事实、风格和 approved 当前资产，不在分镜重选或补造上游。
- 先形成连续观看与摄影，再按实际过程估时、安排技术片段。程序只做身份投影、核算、合并和检查，创意决定由导演作出。
- 本阶段规划关键帧、图片职责和 planned SEAM；实际生图、视频、真实 FRM 提取和 H3 成稿在各自后续阶段执行。

## 目标

把 `current_episode` 已确认的完整剧本与采用资产转为可执行的完整分镜：唯一导演总控卡、十五列分镜正文及结构化索引。文字分镜、摄影方案和局部评阅按用户范围完成，不为文字成果建立生产 JSON 或生成资产。

## 输入条件

正式生产采用以下已确认输入；按当前场和实际依赖取材：

- `01_剧本/剧本_全局设定与分集总纲.md`（含全局故事圣经、分集推进总纲）、全剧完整剧本、`项目_事实与假设.md` 的已验证事实/未知项/推进假设/项目惯例分栏；本集 `episodes/ep_N/01_剧本/` 的完整剧本和 `script_contract_ep_N.json`。关系张力取 `relationship_tension`，事实冲突返回剧本修订。
- `project_data_card.json` 和本集 usage 状态投影；不足时按 ID 取 `state_timeline`。出场角色、当前状态、需要稳定复现的 SCN/PROP 与声音主体均有稳定 ID；一次性物件只进画面，不升级 PROP。
- 当前集已展示、已批准或明确登记复用的人物/状态、场景、道具、音色及 `STYLE001` 风格资产。来源可为共享库、本集新增或已完成分集的 approved 复用项，不使用未来集尚未生成资产。
- 已确认固定画幅、`planning.md` 参数确认表中的视频模型与能力上限，以及用户原始要求、修改、原台词、必须出现项和禁用项。

`style_contract` 缺少可执行风格机制时，返回规划补齐、递增 revision 并重新确认；已有风格只作校准，不在此重选。缺少会改变剧情、场次、台词或世界物理事实的内容时，返回剧本补齐。世界感官细节的出处与文学描写转画面边界见 `storyboard-timing.md`「世界事实承接合同」。创作库仅用于当前具体问题，不改已确认事实或方向。

## 分镜产物分层

| 产物 | 唯一职责 |
| --- | --- |
| 导演总控卡 | 整集观看与拍法基准；按真实 SEG 只补必要执行变化，见 `storyboard-design.md` 与 `storyboard-segments.md` |
| 十五列完整分镜表 | 一镜一行；最终同文件含故事提要、章节/片段导航与附录 A/B，见 `storyboard-review.md`；五列预览不替代它 |
| storyboard/rhythm_input | 镜头、源处置、时间输入、片段、图片/KF 与 SEAM 的机器索引；字段缺用法才查 schema |
| 本场输入与 `.draft` | 可恢复的创作候选；汇总后不成为新增正式交付件 |

## 工作顺序

1. **本场创作并保存**：首次构思通读已确认整集剧本，建立观看意图；以后按场使用源事实与相邻交界。运行 `prepare_storyboard.py --project-root <root> --episode ep_N` 取下一场，缺全局约束加 `--include-global`，交界不明加 `--neighbors`。按 `storyboard-design.md` 设计本场观看、切点和摄影，按 `storyboard-draft.md` 写十五列、镜头及时间语义并 `save`。已有导演卡就继承其拍法。
2. **汇总与核算**：所有场候选保存后 `assemble` 成原标准三件产物，按 `storyboard-timing.md` 的命令执行 allocate → pack。能力冲突返回具体设计或用户取舍，程序不压短、切碎或换模型。
3. **SEG 执行增量**：使用 pack 的真实身份，按 `storyboard-segments.md` 完成该段图片职责、资产/KF、亮点/受众与 SEAM 绑定。共同身份、光线和声音只保存一份，局部只写变化；参考计划全部明确后再次 pack，同源更新资产聚合与附录。
4. **完整交付与审校**：按 `storyboard-review.md` 补齐故事提要与章节/片段导航，附录由 pack 同源渲染；按完整观看顺序对照源稿连看、修具体断点，再盖章、展示并等待用户确认。候选保存不触发整阶段检查或阶段批准。
