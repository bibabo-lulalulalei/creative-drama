# 成片、字幕与交付 Ref

> 本文件统一负责成片拼接、最终音轨、字幕文本、SRT、字幕烧录、客观可交付检查和正式交付。工具链与参数以 `local-runtime.md` 和 `tools/video/ffmpeg_tool.py` 的本地能力为准。

## 第一部分：成片拼接、最终音轨与交付

本部分负责成片拼接策略、最终音轨策略、客观可交付检查和交付；字幕文本、SRT、烧录参数与字幕处理读取本文件第二部分。主 Agent 按已确认剪辑策略直接执行拼接、裁剪、混音、mux 与字幕烧录，完成客观检查与最终审看；需要释放等待或处理独立任务时才可选委派。

### 权威引用

- accepted SEG、各段冻结快照（有效区间）与尾帧承接：`video.md`。
- SRT、客观检查命令、字幕参数和烧录处理：本文件第二部分。
- 本地工具链与参数：`local-runtime.md` 与 `tools/README.md`。
- 成片路径、命名：`manifests.md` 统一目录；`delivery_manifest_ep_N.json` schema：`manifests.md`。
- 重试预算、缺陷编号和返回层级：`troubleshooting.md`。
- 跨阶段确认、版本失效、交付原则与拼接状态迁移（含 `proceed_assembly` 授权边界）：`control-contracts.md`。

### 目标与边界

把全部已确认片段按绝对时间轴和冻结快照中的有效区间拼成无字幕母版，保留可用原生人声，按全片时间线实现已确认的环境声、拟音和 BGM cue，完成最终混音、适用的字幕链路与客观媒体检查后正式交付；内容顺看由人工完成，主 Agent 观察结论只作对话说明，不阻断交付。BGM 的戏剧弧线在规划/分镜阶段设计，素材/音源与 cue 在剪辑画面锁定后按全片统一铺设和混音；不要把每个 SEG 独立生成的相似 BGM 当作连续配乐。若工具未证明能分离混合音轨，按不可分轨处理，不登记虚构 stems。每集只交付一个最终视频版本：字幕关闭时交付无字幕成片；用户明确开启字幕时，以无字幕母版为内部烧录源，只交付字幕版。

主 Agent 不做生成后机器质检；程序只做**确定性可交付检查**（媒体有效性、时长闭合、字幕对齐、单一交付版本）与**客观事实核对**（拼接顺序、片段版本、台词文本来源），这些客观检查失败才置 `blocked` 不得交付。内容层面的观察（剧情、表演、身份、连续性、接缝观感）只在展示时如实说明，不阻断交付；是否返修由用户主动决定。发现意外字幕、随机文字、水印或 UI 残留，用 `ffmpeg_tool.py erase`（固定区域 delogo 擦除）清理并以 probe/播放验证；擦不净或移动文字按返修重生流程处理，需要视频重生时必须按授权与确认流程，不能自动重生。

Seed Audio 资产始终作为声音身份标准：Ref2VA 模式且声部有 approved 样音时必传已批准 VOICE wav 音色参考（视频阶段 lint 硬门）；非音频模式或无 approved 样音时由同一 VOICE 的固定 `voice_anchor` 约束。已生成视频中的原生人声默认保留：最终阶段观察到静音、漏句、错人、声线漂移或口型职责错误时不自动返回视频阶段、不自动返修，向用户说明并记录返修建议，由用户主动决定是否返修。

### 输入门禁

必须具备：

- 已确认的片段顺序、绝对时间轴、视频文件和 `video_manifest_ep_N.json`。
- 每个采用 SEG 已真实生成、保存、登记并完成用户可见交付。
- 主 Agent 已按 `control-contracts.md` 取得用户选择 `proceed_assembly`；视频生成确认或普通聊天肯定不能替代。
- 相邻片段的接缝剪点以各段冻结快照 `request_snapshot` 的 `content_duration_s/tail_handle_s` 为准（无尾余量即整段有效）；找不到理想切点时采用 best available cut 并在对话中注明，接缝观感问题只作给用户的说明，不阻断成片。
- 需要各集 `asset_usage_ep_N.json` 分卡与跨集一致性结论；分卡无法解析的身份/状态事实按 ID 定点窄读项目数据卡与共享资产登记，不全文预载。
- 已确认 `drama_plan.delivery_settings` 中的字幕开关、片头片尾、BGM、`audio_policy` 和交付范围；任一项缺失时返回规划阶段补齐，不得在成片阶段临时决定。只有 `audio_policy` 已明确给出目标响度时才按该值锁定；未给出时保留可用原生响度，只处理片段间明显响度突变，不在成片阶段临时发明 LUFS 数值。

SRT、烧录参数和字幕版必须在最终音轨锁定后按本文件第二部分生成（字幕开启时先运行 `python scripts/read_reference.py --stage delivery --condition subtitle_requested` 补读第二部分），不得作为进入本阶段的前置产物。

缺片段、错序、未确认版本、损坏文件或时间轴重叠时不得进入成片。关键证据不清、动作/因果断裂、台词事实错误、角色或道具状态跳变、重要空间关系错误和接缝观感问题记录为内部返修线索并在交付时向用户说明，不阻断成片，用户主动要求时才返修。

### 拼接与最终音轨

每段有效区间已冻结在 `request_snapshot`：有 `tail_handle_s` 时取 `[0, content_duration_s]`，无尾余量时整段有效。最终剪辑按该区间用 `ffmpeg_tool trim <mp4> <out> <start> <end>` 重编码，不重新挑物理尾帧，也无指纹合同复核。改选尾帧只影响下段图片输入与交付包说明，不改变本段冻结区间。媒体实测用于最终验收，不覆盖规划预测。


1. 按片段编号和绝对时间顺序拼接，不得调序、遗漏或重复。
2. 使用各段冻结快照的有效区间；找不到理想切点时按 best available cut 取当前最稳定切点并在对话中注明，不用文件物理边界兜底。
3. 各片段媒体参数不一致时，先统一分辨率、画幅、帧率、编码和色彩空间。
4. 保留已生成的原生人声；只有工具实际提供独立音轨时才对环境声、拟音和 BGM 分轨处理，不可分轨按「目标与边界」处理、不登记虚构 stems。`bgm_policy=none` 时全片不添加 BGM。人声保持清晰前景，避免片段间响度突变。
5. 声音桥按 seam 观察记录执行，不得用声音掩盖身份、动作、构图或光位错误。
6. 处理响度、混音、mux 等客观交付问题；同时核验人声类型、主体、文本、顺序、口型职责是否符合已确认设计。内容问题不在成片阶段擅自改写，返回责任阶段或向用户呈现偏差。
7. 完成全部声音处理后锁定“最终音轨 vNN”；任何后续音频修改都会使 SRT 和字幕烧录产物失效。

用户要求修复缺失人声时，先核实工具是否具备所需局部音频处理或视频重生成能力并说明边界，再完成相应授权与确认；VOICE 样音不能直接充当正文对白。不得自动整段替换原生人声。

### 成片执行顺序

成片按以下编号流程执行：

1. 回读采用片段、冻结快照有效区间、状态和版本。
2. 主 Agent 把已取得的拼接确认按 `manifests.md` 写入 `delivery_manifest_ep_N.json.assembly_confirmation`，再锁定片段顺序、有效区间、声音桥、已确认 `audio_policy`、字幕开关、输出版本和允许调用的媒体处理能力；仅当 `audio_policy` 明确给出目标响度时才把该数值写入执行包。随后按 `delegation.md` 下发 `final_media_execution` 执行包。
3. 主 Agent 或可选执行者按各段冻结快照的有效区间（best available cut 已在对话中注明，照注明执行），用 `ffmpeg_tool trim` 生成对应 SEG 的有效区间文件，随后使用 `ffmpeg_tool concat` 拼接无字幕母版；存在独立音轨时使用 ffmpeg 混音与音视频封装能力，不能把视频拼接冒充混音。可选执行者只写指定输出并返回事实，创作策略和交付仍由主 Agent 负责。
4. 处理完成后用 `ffmpeg_tool probe` 探测母版，stdout 直读确认有效视频流、音轨和媒体参数，并把调用事实用 `stamp_confirmation.py --op-append` 写入操作日志；不再产出固定命名的质检 JSON 报告。字幕开启时烧录后对字幕版重复探测。
5. 锁定最终音轨后，执行本文件第二部分：
   - 字幕关闭：只做无字幕母版客观可交付检查。
   - 字幕开启：执行 SRT 整理、无字幕母版客观检查、烧录和字幕版客观检查。
6. 若本文件第二部分需要字幕烧录或其他媒体变更工具，主 Agent 按已确认策略直接执行并完成相应客观检查；最终观看结果交给人工审查。
7. 人工审看与程序检查分开：主 Agent 把成片路径交给用户观看，观察结论只作展示说明，不阻断交付，用户主动要求时才返修；客观导出异常可用 probe stdout 快速核对文件可播放、总时长和画幅。
8. 更新 `delivery_manifest_ep_N.json`，运行 `drama_lint.py --stage final`。
9. 由主 Agent 只交付字幕策略对应的唯一最终视频（版本规则见「目标与边界」，内部无字幕母版不得作为第二个版本交付），把该版本落盘路径与可解码检查结果作为交付凭据等待用户确认。

调用前必须确认系统 PATH 中有 ffmpeg/ffprobe（burn 需 libass 构建）。ffmpeg 缺失时停止，报告缺失能力与已落盘产物，不得伪造调用或宣布成片成功。本地媒体处理为同步执行：命令返回 0 且输出文件存在即视为完成。

### 客观可交付检查

不设固定命名的质检报告文件，证据来自 `ffmpeg_tool probe` 的 stdout 直读与真实播放，调用事实走操作日志：

| 检查 | 字幕关闭 | 字幕开启 | 通过条件 |
|---|---|---|---|
| 无字幕母版 | 必须 | 必须 | 文件存在、可解码、可播放、有视频流 |
| 字幕对齐 | 不适用 | 字幕开启时必须 | 仅用于生成字幕文件，不评价剧情或口型 |
| SRT 与烧录参数 | 不适用 | 字幕开启时必须 | 字幕文件存在，烧录任务完成 |
| 字幕版 | 不适用 | 字幕开启时必须 | 文件存在、可解码、可播放、有视频流 |

客观检查不设置固定轮次数或主观评分；内容问题只在对话中向用户说明，不构成机器门。字幕关闭时，无字幕成片只须满足媒体有效性等客观硬门。字幕开启时，字幕版必须通过本文件第二部分的字幕对齐、文本一致性、SRT 与烧录客观硬门；失败时阻断字幕版并修复字幕链，不得把内部无字幕母版改成交付替代品，也不得同时交付两个版本。

成片客观交付硬门以上表通过条件为准，并追加两项实测判断：总时长与采用片段数量大体相符（明显 0 秒/空文件/只含音频时阻断）、画幅方向和编码可被本地工具链识别。硬门失败时只修复导出、下载、mux、字幕烧录或文件损坏等媒体交付问题，不得因此自动调用视频生成/编辑工具。

### 平台适配

平台规格、审核规则、推荐时长和 UI 安全区会变化。需要平台版本时查询当前官方或可靠来源，记录日期和链接，再建立 `platform_delivery_profile`：

```json
{
  "platform": "",
  "verified_at": "YYYY-MM-DD",
  "sources": [],
  "aspect_ratio": "",
  "duration_limit": "",
  "safe_area": {},
  "subtitle_policy": "",
  "cover_spec": "",
  "title_and_tags": "",
  "content_constraints": [],
  "output_version": ""
}
```

同一母版产生不同平台版本时分别导出和验收，不直接拉伸或裁掉关键人物、道具及字幕。

### 最终状态

- `可交付成片`：最终版本已生成，文件存在、可解码、可播放，并具备当前环境交付所需字段。
- `候选成片`：可播放但仍缺少非阻断记录，或存在已记录的内容/审美/连续性风险等待用户判断。
- `未完成/待验证`：缺生成、拼接、下载、可播放文件或任一客观交付硬门证据。

对应机器状态以 `manifests.md` 的 `status` 三态枚举为准，与上述三档一一对应。运行最终交付检查时，每集 `delivery_manifest` 不得为 `blocked`（仅限客观检查失败）；候选可展示并明确内容风险，deliverable 只要求客观硬门通过，内容观察不阻断状态。

内部可交付不等于用户确认。

### 存储与交付

路径、命名、比例编码、版本后缀和 `delivery_manifest_ep_N.json` schema 只读取 `manifests.md`。SRT、字幕 JSON、烧录参数、字幕对齐报告和字幕开启时的无字幕母版均为内部制作与追溯文件，不进入 `outputs`（每集唯一最终视频规则见「目标与边界」）。重导出建立新 `_vNN`，不得覆盖已确认成片。

交付前更新 delivery manifest（成片清单、客观检查结论），将成片阶段及 `current_episode` 状态写为 `awaiting_confirmation`，运行当前集最终结构检查，并确保状态登记与真实文件一致。通过后立即展示当前集字幕策略对应的唯一最终视频；只把该版本写入交付清单并回读成功。收到修改意见时返回当前集最早受影响阶段处理并重新展示；只有用户明确确认后才完成当前集交付。多集项目在当前集确认后，才把下一集设为 `current_episode` 并进入其详细剧本阶段；最后一集确认后才完成整个项目。

## 第二部分：字幕生成与烧录

字幕工具链以 `local-runtime.md` 与 `tools/video/ffmpeg_tool.py burn` 为准；本文件中的业务流程不得覆盖工具实际参数。

本部分是字幕文本、SRT、烧录参数和字幕处理的唯一权威；成片触发条件、最终音轨和交付状态由本文件第一部分规定。

### 权威引用

- 最终音轨、成片触发条件与交付状态：本文件第一部分；路径、命名与 `delivery_manifest_ep_N.json` 字段：`manifests.md`。
- 正确台词来自 `scriptwriter.md` 与分集 `script_contract`；媒体与文本客观检查基于 `ffmpeg_tool probe` 真实探测结果、真实文件与人工核对记录；最终结构门禁为 `scripts/drama_lint.py`，失败升级见 `troubleshooting.md`。

### 默认策略

- 字幕默认关闭。只有用户明确要求字幕、双语字幕、逐句字幕、caption 或字幕版成片时才开启字幕链路。
- 所有视频生成工具调用固定 `video_generation_subtitles: false`，禁止模型直接生成逐句字幕或自动转写文字。
- 成片阶段先锁定已采用片段与最终原声音轨，再生成字幕。
- 默认逐集只交付无字幕成片；若视频生成结果里出现字幕、随机文字、水印或平台 UI 残留，按返修重生成该片段（Prompt 明示不要字幕/文字/水印）并验证后再交付，无残留则直接交付。用户明确要求字幕时，生成内部 SRT、字幕 JSON 和烧录记录，但只交付字幕烧录版；内部无字幕母版和字幕辅助文件都不作为第二份用户交付。字幕烧录统一使用 `ffmpeg_tool burn`，不使用 FFmpeg 手动烧录字幕。
- 字幕文本与时间来自已确认剧本的 `speech_lines`：本地无 ASR，字幕 SRT 由剧本台词稿整理，时间轴按成片实际口播对齐。任何自动转写文本都不得覆盖已确认台词。

### 全交付链工具职责（本地 ffmpeg 链路）

下表覆盖本文件两个部分。有效区间裁剪和视频拼接只在第一部分执行一次；第二部分直接消费已锁定的无字幕母版。

| 环节 | 本地工具 | 职责 |
|---|---|---|
| 有效区间裁剪 | `ffmpeg_tool trim` | 按冻结快照有效区间生成各 SEG 的裁剪文件 |
| 视频拼接 | `ffmpeg_tool concat` | 按已确认顺序硬切拼接有效区间并保留原声音轨；片段统一重编码为 24fps（与 output_fps 默认一致） |
| 媒体探测 | `ffmpeg_tool probe` | 探测无字幕母版和字幕烧录版的时长、分辨率、帧率、流信息 |
| 字幕文本整理 | 主 Agent 依据 `script_contract` 的 `source_text` 现场去标点 | 从已锁定剧本台词稿整理逐句字幕文本与时间轴，本地无 ASR 转写 |
| 时间轴对齐 | 主 Agent 对照成片口播 | 按成片实际口播校核每条字幕起止时间，失败则重看片段调整；不改交付版本 |
| 客观可交付检查 | `ffmpeg_tool probe` + 真实播放 | 检查媒体参数、文件完整性、音轨及适用的 SRT 结构、时码和无标点规则 |
| 字幕烧录 | `ffmpeg_tool burn` | 字体/字号/颜色等样式默认值以工具内置（对齐豆包交付合同，见 `tools/video/ffmpeg_tool.py burn --help`，不在此抄写）；位置策略：9:16 显式 `--pos lower_third`，16:9 用默认 `bottom` |
| 客观检查 | `ffmpeg_tool probe` + 实际播放 | 以真实探测结果检查文件是否可交付 |

核心分工：主 Agent 整理字幕和剪辑策略并直接执行媒体工具，需要委派时使用 delegation.md 的最小交接；客观检查的权威来源是实际 ffmpeg 探测 stdout，必须真实调用、现场直读，不得用伪造输出替代真实探测。

本地工具为同步执行，不产生异步 `task_id`。每次探测/裁剪/拼接/烧录的调用事实用 `stamp_confirmation.py --op-append` 写入操作日志（直接 `--append`，内部校验和回读），行内至少包含工具、操作名、关键参数、返回码与输出文件：

```json
{
  "tool": "tools/video/ffmpeg_tool.py",
  "operation": "probe|trim|concat|burn",
  "command": "python tools/video/ffmpeg_tool.py probe ...",
  "returncode": 0,
  "output_file": ""
}
```

probe stdout 必须含 `duration_s/width/height/fps/video_stream_count/audio_stream_count`；烧录记录必须引用输入 SRT、字体字号、位置参数与输出文件。

### 台词与字幕文本合同

台词只保存一层文本：用户原文 `source_text` 逐字保留（审计溯源，永不改写）。视频 Prompt 发声块、语音分片、字幕正文和全部机器校验都从 `source_text` 现场派生——去掉标点、引号和空格后比对，字词与顺序不得改写；带规范标点的阅读面同样由 `source_text` 现场渲染。旧字段退役规则见 `manifests.md` 迁移条款。

问句、感叹和语义停顿在阅读面（`source_text` 的规范标点渲染）中保留正常标点；模型执行另写入 `delivery_intent`、`pause_plan`、`emotion` 和 `emphasis_words`，避免只依赖标点控制表演。

```json
{
  "speaker": "林远",
  "type": "on_screen_dialogue",
  "source_text": "顾长渊，本宫今日来，不是跟你拜堂的。",
  "delivery_intent": "冷静拒绝",
  "pause_plan": ["顾长渊 后短停", "今日来 后短停"],
  "emphasis_words": ["不是", "拜堂"]
}
```

### 七步流程

#### 1. 消费已锁定的无字幕母版

本部分不再次裁剪或拼接 SEG。直接使用第一部分按冻结快照有效区间生成、完成混音并锁定最终音轨的无字幕母版；任何片段顺序、剪切点或音轨变化都会使后续 SRT 和字幕烧录产物失效。

#### 2. 从剧本台词稿整理字幕初稿

本地无 ASR 能力，字幕文本直接来自已确认剧本：读取本集 `script_contract_ep_N.json` 的 `speech_lines[]`，按说话人、句序取出 `source_text` 并现场去标点，结合片段绝对时间轴与镜头时长估算每条字幕的起止时间，生成 SRT 初稿。

```bash
# 字幕初稿由剧本台词稿生成后，用 ffprobe 核对母版实际时长，防止时间轴越界
python tools/video/ffmpeg_tool.py probe episodes/ep_N/05_成片/[项目名]_成片_[比例]_无字幕_vNN_ep_N.mp4
```

初稿保存为可追溯的 SRT，并记录生成依据（`script_contract` 版本、片段顺序表、每条的估算依据）。任何自动转写文本都不得覆盖已确认 `source_text`。

#### 3. 时间轴按成片口播对齐

主 Agent 对照无字幕母版的实际口播，逐条校核字幕起止时间：对每条字幕抽首帧、中间帧和尾帧，确认字幕出现与消失是否贴合说话节奏。

- 起止时间整体错位、句序与实际口播不符或时间范围无效：按片段实际口播校正后重新生成 SRT；无法确定时回到分镜核对语气与停顿。
- 单字、同音字、专名差异由创作者定向试听判断。
- 无论时间轴如何校正，字幕正文都来自已批准 `source_text` 的去标点派生。

把输入文件、母版、校核结果和阻断原因保存到 `质检_字幕对齐_vNN_ep_N.json`。

#### 4. 回填正确文本并规范化

1. 按说话人、句序和语义把字幕条目对应到已确认 `speech_lines`。
2. 字幕正文一律由 `source_text` 现场去标点派生，不引入任何转写文本。
3. 相邻同说话人短句时间间隔小于 `0.5` 秒时可以合并；开始时间取第一句，结束时间取最后一句。
4. 单句超过 `18-20` 个汉字时优先在语义停顿处换成两行，保持同一时间区间；只有能可靠切分词级时间时才拆成两个独立字幕事件。
5. 每条字幕建议持续 `1.5-5` 秒。超出范围时先重新核对台词分句与口播；不得凭感觉平移时间戳。
6. 对齐失败时回到分镜核对台词与停顿，或按片段实际口播重新校正，禁止手工猜测整体偏移量。

默认输出：

```text
episodes/ep_N/05_成片/字幕_时间轴_vNN_ep_N.srt
```

```srt
1
00:00:00,240 --> 00:00:03,160
顾长渊 本宫今日来 不是跟你拜堂的

2
00:00:03,160 --> 00:00:05,480
这只杯子 你认得吧 五天前
```

#### 5. 客观可交付检查

对无字幕母版执行 `ffmpeg_tool probe` 并实际播放，stdout 现场直读、调用事实写入操作日志，不另存固定命名的质检 JSON。检查文件存在性、时长、比例、帧率、视频流和音轨；字幕开启时还检查 SRT 结构、时码、无标点规则及其与 `source_text` 去标点派生的逐字一致性，并在烧录后对字幕版重复探测与播放。期望时长取 `delivery_manifest_ep_N.json.duration_s`，期望画幅取已确认 `scale_plan.aspect_ratio`，期望帧率取已确认 `delivery_settings.output_fps`，不得由执行者临时填写或从待验媒体反推。时长、比例和帧率容差分别不得超过 `0.5` 秒、`0.01` 相对误差和 `0.1` fps，且必须为有限非负数。确定性错误阻断，字幕持续时间、单行长度和阅读速度异常进入人工复核。

#### 6. 固定字幕参数并烧录

默认使用 `ffmpeg_tool burn`。参数以工具实际参数为准，视觉结果固定为：

| 成片比例 | 位置预设 | 位置参数 | 字号 | 字体 | 颜色 |
|---|---|---:|---:|---|---|
| `9:16` | `lower_third` | `--pos lower_third`（画面 70% 高度） | `36px` | 思源黑体 | 白色 |
| `16:9` | `bottom` | `--pos bottom`（底部居中） | `36px` | 思源黑体 | 白色 |

其他比例默认使用 `--pos bottom / 36px / 思源黑体 / 白色`，并通过代表帧检查安全区。用户明确要求其他样式时必须重新确认；未确认不得动态改变字体、字号、颜色或位置。

本地 SRT 直接作为 `burn` 的字幕输入，无需转成公网 URL 或字幕对象数组。SRT 是正式交付与文本事实源。

```bash
python tools/video/ffmpeg_tool.py burn   episodes/ep_N/05_成片/[项目名]_成片_[比例]_无字幕_vNN_ep_N.mp4   episodes/ep_N/05_成片/字幕_时间轴_vNN_ep_N.srt   episodes/ep_N/05_成片/[项目名]_成片_[比例]_字幕烧录_vNN_ep_N.mp4   --size 36 --pos lower_third
```

横屏把 `--pos` 改为 `bottom`。命令返回 0 且输出文件存在即可解码，即为烧录成功。

#### 7. 烧录处理

1. 从无字幕母版抽取包含人物、关键道具和平台 UI 风险的代表帧。
2. 用最长字幕、生僻字、数字和英文生成短样片，确认思源黑体字符覆盖。
3. 抽取每条字幕的首帧、中间帧和尾帧，检查越界、遮脸、遮嘴、遮关键道具、平台 UI 冲突和换行。
4. 任一字幕不合格时，优先调整断句、字号或位置参数并重新烧录。

### 硬门

- 字幕文本来源记录、规范化 SRT、烧录参数和字幕烧录成片均已落盘并可追溯。
- 无字幕母版与字幕烧录版均经 `ffmpeg_tool probe` 真实探测（stdout 直读、操作日志留痕，返回码为 0、操作名匹配）并实际播放验证。
- 字幕对齐报告不得为 `blocked`。
- 字幕字体、字号、颜色与位置固定项与本文件「固定字幕参数并烧录」参数表完全一致，不得偏离。
- 字幕文本与已确认 `source_text` 的去标点派生逐字一致。
- 字幕文本不含标点；逗号、顿号、分号和冒号已替换为单个空格，其余指定标点已删除。
- 字幕起止时间按成片实际口播校核，未被整体平移或凭感觉猜测；合并只使用首句开始和末句结束。
- 字幕合并、换行及建议显示时长按本文件“回填正确文本并规范化”执行，显示建议不改变实际口播时间。
- 字幕底部、描边和阴影全部位于实测安全区内，不遮脸、嘴、关键道具、线索文字或平台 UI。
- 最终烧录成片保留无字幕母版的音轨，不因字幕烧录发生音画漂移。
- 用户明确选择无字幕时，记录该选择并跳过 SRT 和烧录步骤。
