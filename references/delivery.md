# 成片、字幕与交付 Ref

> 本文件统一负责成片拼接、最终音轨、字幕文本、SRT、字幕烧录、基础可交付检查和正式交付。工具链与参数以 `local-runtime.md` 和 `tools/video/ffmpeg_tool.py` 的本地能力为准。

## 第一部分：成片拼接、最终音轨与交付

本部分负责成片拼接策略、最终音轨策略、基础可交付检查和交付；字幕文本、SRT、烧录参数与字幕处理读取本文件第二部分。实际拼接、裁剪、混音、mux、字幕烧录等会产出或修改媒体文件的工具调用必须按 `delegation.md` 委派执行，主 Agent 负责按 Skill 锁定执行包、收口、基础可交付检查和交付。

### 权威引用

- accepted SEG、FRM、verified seam 和剪切点：`video.md`。
- SRT、基础可交付检查命令、字幕参数和烧录处理：本文件第二部分。
- 本地工具链与参数：`local-runtime.md` 与 `tools/README.md`。
- 成片路径、命名和 `delivery_manifest_ep_N.json` schema：`manifests.md`。
- 重试预算、缺陷编号和返回层级：`troubleshooting.md`。
- 跨阶段确认、版本失效和交付原则：`control-contracts.md`。
- 进入成片拼接的状态迁移、选项和授权边界：`control-contracts.md`。

### 目标与边界

把全部已确认片段按绝对时间轴和已核验剪点拼成无字幕母版，保留可用原生人声，按全片时间线实现已确认的环境声、拟音和 BGM cue，完成最终混音、适用的字幕链路、媒体有效性与内容质量检查后正式交付。BGM 的戏剧弧线在规划/分镜阶段设计，素材/音源与 cue 在剪辑画面锁定后按全片统一铺设和混音；不要把每个 SEG 独立生成的相似 BGM 当作连续配乐。若工具未证明能分离混合音轨，按不可分轨处理，不登记虚构 stems。每集只交付一个最终视频版本：字幕关闭时交付无字幕成片；用户明确开启字幕时，以无字幕母版为内部烧录源，只交付字幕版。

本阶段不做阻断式主观内容质检（构图、表演、审美、节奏等人工判断项由用户验收时直接提出）；本阶段的质量门只做**确定性可交付检查**（媒体有效性、时长闭合、字幕对齐、单一交付版本）与**客观事实核对**（拼接顺序、片段版本、台词文本来源）。发现关键剧情/证据/动作/身份/台词/连续性问题时，阻断合格交付并定位责任阶段；轻微且不影响理解的偏差可展示给用户，明确接受后作为带偏差版本交付。发现意外字幕、随机文字、水印或 UI 残留，用 `ffmpeg_tool.py erase`（固定区域 delogo 擦除）清理并抽帧验证；擦不净或移动文字按返修重生流程处理，需要视频重生时必须按授权与确认流程，不能自动重生。

Seed Audio 资产始终作为声音身份标准：音频输入不可用时由同一 VOICE 的固定 `voice_anchor` 约束；支持后必须传入已批准 VOICE。已生成视频中的原生人声默认保留，不因最终阶段观察到静音、漏句、错人、声线漂移、类型或口型职责错误而自动返回视频阶段；这些问题只记录为用户主动修改时的线索。

### 输入门禁

必须具备：

- 已确认的片段顺序、绝对时间轴、视频文件和 `video_manifest_ep_N.json`。
- 完整模式每个采用 SEG 已真实生成、保存、登记并完成用户可见交付；轻量模式只要求唯一生成视频已保存并登记，不先执行片段交付。
- 完整模式下，主 Agent 已按 `control-contracts.md` 取得用户选择 `proceed_assembly`；视频生成确认或普通聊天肯定不能替代。轻量模式只有一条最终视频，不执行拼接，因此不要求该确认。
- 完整模式需要 `continuity_ep_N.json` 和相邻片段的 seam 检查。关键接缝必须有支持剧情因果、动作相位、身份和空间理解的可用剪点；关键接缝无法验证或冲突时不得合格交付。只有非关键、不会影响观看理解的偏差可经用户明确接受后带偏差交付。轻量模式只有一个最终视频，不要求分段接缝记录。
- 完整模式需要当前项目数据卡、共享资产登记和跨集一致性结论；轻量模式不要求这些完整模式上游文件。
- 已确认 `drama_plan.delivery_settings` 中的字幕开关、片头片尾、BGM、`audio_policy` 和交付范围；任一项缺失时返回规划阶段补齐，不得在成片阶段临时决定。只有 `audio_policy` 已明确给出目标响度时才按该值锁定；未给出时保留可用原生响度，只处理片段间明显响度突变，不在成片阶段临时发明 LUFS 数值。

SRT、烧录参数和字幕版必须在最终音轨锁定后按本文件第二部分生成，不得作为进入本阶段的前置产物。

缺片段、错序、未确认版本、损坏文件或时间轴重叠时不得进入成片。关键证据不清、动作/因果断裂、台词事实错误、角色或道具状态跳变、重要空间关系错误和关键接缝失败也阻断合格交付。文件可播放、字段齐全或 lint 通过都不能单独证明质量通过。

### 拼接与最终音轨

1. 按片段编号和绝对时间顺序拼接，不得调序、遗漏或重复。
2. 使用 `video.md` 已记录并核验的切出/切入点；关键接缝无有效剪点时返回上游定位，不用 best available cut 掩盖断裂。
3. 各片段媒体参数不一致时，先统一分辨率、画幅、帧率、编码和色彩空间。
4. 保留已生成的原生人声；只有工具实际提供独立音轨时才对环境声、拟音和 BGM 分轨处理。混合音轨按混合音轨处理，不登记虚构 stems。`bgm_policy=none` 时全片不添加 BGM。人声保持清晰前景，避免片段间响度突变。
5. 声音桥按 verified seam 执行，不得用声音掩盖身份、动作、构图或光位错误。
6. 处理响度、混音、mux 等客观交付问题；同时核验人声类型、主体、文本、顺序、口型职责是否符合已确认设计。内容问题不在成片阶段擅自改写，返回责任阶段或向用户呈现偏差。
7. 完成全部声音处理后锁定“最终音轨 vNN”；任何后续音频修改都会使 SRT 和字幕烧录产物失效。

只有用户明确提出修改并重新确认，才允许使用已批准 Seed Audio 做局部缺失人声修复；不得在最终阶段自动整段替换原生人声。

### 成片执行顺序

以下编号流程用于完整模式。轻量模式直接把唯一生成视频作为无字幕成片：字幕关闭时只做基础可交付检查并交付；字幕开启时把它作为内部烧录源，完成字幕链后只检查并交付字幕版。轻量模式不执行片段拼接、接缝读取或拼接确认。

1. 回读采用片段、verified seam、状态和版本。
2. 主 Agent 把已取得的拼接确认按 `manifests.md` 写入 `delivery_manifest_ep_N.json.assembly_confirmation`，再锁定片段顺序、有效切出/切入点、声音桥、已确认 `audio_policy`、字幕开关、输出版本和允许调用的媒体处理能力；仅当 `audio_policy` 明确给出目标响度时才把该数值写入执行包。随后按 `delegation.md` 下发 `final_media_execution` 执行包。
3. subagent 先检查已验证接缝的最终切点：存在已验证最终切点的关键接缝，先按切点用 `ffmpeg_tool trim` 生成对应 SEG 的有效区间文件再拼接；无安全切点的接缝仍整段拼接并按偏差流程处理。随后使用 `ffmpeg_tool concat` 拼接无字幕母版；存在独立音轨时使用 ffmpeg 混音与音视频封装能力，不能把视频拼接冒充混音。subagent 只写白名单输出并返回结果，不决定剪辑策略、不交付用户、不写交付记录。
4. 主 Agent 收回后用 `ffmpeg_tool probe` 探测母版，确认有效视频流、音轨和媒体参数，并把探测结果（路径、输入哈希、命令与返回码、实测媒体参数）保存到 `质检_媒体探测_无字幕_vNN_ep_N.json`；字幕开启时烧录后对字幕版重复探测并保存 `质检_媒体探测_字幕版_vNN_ep_N.json`。
5. 锁定最终音轨后，执行本文件第二部分：
   - 字幕关闭：只做无字幕母版基础可交付检查。
   - 字幕开启：执行 SRT 整理、无字幕母版基础可交付检查、烧录和字幕版基础可交付检查。
6. 若本文件第二部分需要字幕烧录或其他媒体变更工具，主 Agent 继续用锁定执行包委派 subagent 执行实际媒体变更，回收后只做基础可交付检查。
7. 不做阻断式最终内容质检；如需内部记录，可快速记录文件可播放、总时长、画幅和明显客观导出异常。
8. 更新 `delivery_manifest_ep_N.json`，运行 `drama_lint.py --stage final`。
9. 由主 Agent 只交付一个最终视频：字幕关闭时交付无字幕成片，字幕开启时交付字幕版；把该最终版本的落盘路径与可解码检查结果作为交付凭据等待用户确认。内部无字幕母版不得作为第二个版本交付。

调用前必须确认系统 PATH 中有 ffmpeg/ffprobe（burn 需 libass 构建）。ffmpeg 缺失时停止，报告缺失能力与已落盘产物，不得伪造调用或宣布成片成功。本地媒体处理为同步执行：命令返回 0 且输出文件存在即视为完成。

### 基础可交付检查

基础可交付状态只允许 `deliverable|blocked`：

| 检查 | 字幕关闭 | 字幕开启 | 通过条件 |
|---|---|---|---|
| 无字幕母版 basic | 必须 | 必须 | 文件存在、可解码、可播放、有视频流 |
| 字幕对齐 | 不适用 | 字幕开启时必须 | 仅用于生成字幕文件，不评价剧情或口型 |
| SRT 与烧录参数 | 不适用 | 字幕开启时必须 | 字幕文件存在，烧录任务完成 |
| 字幕版 basic | 不适用 | 字幕开启时必须 | 文件存在、可解码、可播放、有视频流 |

不执行三级人工质检，也不因剧情、节奏、身份、状态、声音、口型、接缝或审美判断阻断当前已选择版本的交付；这些观察如已发现，只能静默记录为用户主动修改时的返修线索。字幕关闭时，无字幕成片通过基础可交付检查即可交付。字幕开启时，字幕版必须通过本文件第二部分的字幕对齐、文本一致性、SRT 与烧录客观硬门；失败时阻断字幕版并修复字幕链，不得把内部无字幕母版改成交付替代品，也不得同时交付两个版本。

成片客观交付硬门即上表"基础可交付检查"的通过条件（文件存在、可解码、可从头播放到结束、有视频流；总时长与采用片段数量大体相符，明显 0 秒/空文件/只含音频时阻断；画幅方向和编码可被本地工具链识别），不再另列第二份清单。若客观交付硬门失败，只修复导出、下载、mux、字幕烧录或文件损坏等媒体交付问题；不得因此自动调用视频生成/编辑工具。

### 平台适配

平台规格、审核规则、推荐时长和 UI 安全区会变化。需要平台版本时查询当前官方或可靠来源，记录日期和链接，再建立 `platform_delivery_profile`：

```json
{
  "platform": "",
  "verified_at": "YYYY-MM-DD",
  "sources": [],
  "aspect_ratio": "",
  "duration_limit": "",
  "safe_area": {},
  "subtitle_policy": "",
  "cover_spec": "",
  "title_and_tags": "",
  "content_constraints": [],
  "output_version": ""
}
```

同一母版产生不同平台版本时分别导出和验收，不直接拉伸或裁掉关键人物、道具及字幕。

### 最终状态

- `可交付成片`：最终版本已生成，文件存在、可解码、可播放，并具备当前环境交付所需字段。
- `候选成片`：可播放但仍缺少非阻断记录，或存在已记录的内容/审美/连续性风险等待用户判断。
- `未完成/待验证`：缺生成、拼接、下载、可播放文件或任一客观交付硬门证据。

对应机器状态固定为：`可交付成片 = deliverable`、`候选成片 = candidate`、`未完成/待验证 = blocked`。运行最终交付检查时，每集 `delivery_manifest` 必须为 `deliverable|candidate`，不得要求内容质检通过后才交付。

内部可交付不等于用户确认；最终渲染文件不可播放时禁止标记为 `可交付成片`。

### 存储与交付

路径、命名、比例编码、版本后缀、报告文件和 `delivery_manifest_ep_N.json` schema 只读取 `manifests.md`。每集 `outputs` 必须且只能包含一个最终视频：字幕关闭时为无字幕成片，字幕开启时为字幕版。SRT、字幕 JSON、烧录参数、检查报告和字幕开启时的无字幕母版均为内部制作与追溯文件，不作为额外交付物，不进入 `outputs`、本地交付（落盘＋路径） 或 落盘检查。重导出建立新 `_vNN`，不得覆盖已确认成片。

交付前更新成片清单、基础可交付记录和 delivery manifest，将成片阶段及 `current_episode` 状态写为 `awaiting_confirmation`，运行当前集最终结构检查，并确保内部记录与真实文件一致。通过后立即展示当前集字幕策略对应的唯一最终视频；只把该版本写入 落盘检查 并回读成功。收到修改意见时返回当前集最早受影响阶段处理并重新展示；只有用户明确确认后才完成当前集交付。多集项目在当前集确认后，才把下一集设为 `current_episode` 并进入其详细剧本阶段；最后一集确认后才完成整个项目。

## 第二部分：字幕生成与烧录

字幕工具链以 `local-runtime.md` 与 `tools/video/ffmpeg_tool.py burn` 为准；本文件中的业务流程不得覆盖工具实际参数。

本部分是字幕文本、SRT、烧录参数和字幕处理的唯一权威；成片触发条件、最终音轨和交付状态由本文件第一部分规定。

### 权威引用

- 最终音轨、成片触发条件和交付状态：本文件第一部分。
- 文件路径、命名及 `delivery_manifest_ep_N.json`：`manifests.md`。
- 媒体与文本基础可交付检查：`ffmpeg_tool probe` 结果、真实文件与人工核对记录；最终结构门禁：`scripts/drama_lint.py`。

> **引用关系**：正确台词来自 `scriptwriter.md` 和分集 `script_contract`；成片入口与交付状态见本文件第一部分；文件路径、基础可交付记录引用和字段见 `manifests.md`；媒体与文本基础检查基于真实 ffmpeg 探测结果和人工核对记录，失败升级见 `troubleshooting.md`。

### 默认策略

- 字幕默认关闭。只有用户明确要求字幕、双语字幕、逐句字幕、caption 或字幕版成片时才开启字幕链路。
- 所有视频生成工具调用固定 `video_generation_subtitles: false`，禁止模型直接生成逐句字幕或自动转写文字。
- 成片阶段先锁定已采用片段与最终原声音轨，再生成字幕。
- 默认逐集只交付无字幕成片；若视频生成结果里出现字幕、随机文字、水印或平台 UI 残留，按返修重生成该片段（Prompt 明示不要字幕/文字/水印）并验证后再交付，无残留则直接交付。用户明确要求字幕时，生成内部 SRT、字幕 JSON 和烧录记录，但只交付字幕烧录版；内部无字幕母版和字幕辅助文件都不作为第二份用户交付。字幕烧录统一使用 `ffmpeg_tool burn`，不使用 FFmpeg 手动烧录字幕。
- 字幕文本与时间来自已确认剧本的 `speech_lines`：本地无 ASR，字幕 SRT 由剧本台词稿整理，时间轴按成片实际口播对齐。任何自动转写文本都不得覆盖已确认台词。

### 全交付链工具职责（本地 ffmpeg 链路）

下表覆盖本文件两个部分。有效区间裁剪和视频拼接只在第一部分执行一次；第二部分直接消费已锁定的无字幕母版。

| 环节 | 本地工具 | 职责 |
|---|---|---|
| 有效区间裁剪 | `ffmpeg_tool trim` | 按 verified cut 生成各 SEG 的有效区间文件 |
| 视频拼接 | `ffmpeg_tool concat` | 按已确认顺序硬切拼接有效区间并保留原声音轨；片段统一重编码为 24fps（与 output_fps 默认一致） |
| 媒体探测 | `ffmpeg_tool probe` | 探测无字幕母版和字幕烧录版的时长、分辨率、帧率、流信息 |
| 字幕文本整理 | 主 Agent 依据 `script_contract` 的 `spoken_text` | 从已锁定剧本台词稿整理逐句字幕文本与时间轴，本地无 ASR 转写 |
| 时间轴对齐 | 主 Agent 对照成片口播 | 按成片实际口播校核每条字幕起止时间，失败则重看片段调整；不改交付版本 |
| 基础可交付检查 | `ffmpeg_tool probe` + 真实播放 | 检查媒体参数、文件完整性、音轨及适用的 SRT 结构、时码和无标点规则 |
| 字幕烧录 | `ffmpeg_tool burn` | 固定 36px 思源黑体白色字幕；9:16 用 `--pos lower_third`，16:9 用 `--pos bottom` |
| 基础检查 | `ffmpeg_tool probe` + 实际播放/抽帧 | 以真实探测结果检查文件是否可交付 |

核心分工：主 Agent 执行探测和字幕文本整理，并按 `delegation.md` 委派裁剪、拼接、混音和字幕烧录等媒体变更；基础可交付检查的权威来源是实际 ffmpeg 探测结果，必须保存命令、输出与实际文件哈希。不得用伪造报告替代真实探测。

本地工具为同步执行，不产生异步 `task_id`。每次探测/裁剪/拼接/烧录必须保存调用记录，至少包含命令、关键参数、返回码与输出文件：

```json
{
  "tool": "tools/video/ffmpeg_tool.py",
  "operation": "probe|trim|concat|burn",
  "command": "python tools/video/ffmpeg_tool.py probe ...",
  "returncode": 0,
  "output_file": "",
  "input_sha256": {}
}
```

探测记录必须包含 `duration_s/width/height/fps/video_stream_count/audio_stream_count`；烧录记录必须引用输入 SRT、字体字号、位置参数与输出文件哈希。

### 台词与字幕文本合同

从剧本第一次写出台词时就保存三层文本：用户原文 `source_text` 逐字保留；带规范标点的 `display_text` 用于剧本正文和人工阅读；`spoken_text` 用于视频 Prompt、语音校验和字幕正文。`display_text` 与 `spoken_text` 只能调整标点、引号和空格，字词与顺序不得改写。`spoken_text` 按以下规则规范化：

| 原符号 | 处理 |
|---|---|
| `。？！…….!?` | 删除 |
| `，、；：,;:` | 替换为一个半角空格 |
| `——` | 替换为一个半角空格 |
| 中文/英文引号、书名号、圆括号 | 删除 |
| 句首、句尾空格 | 删除 |
| 连续多个空格 | 合并为一个半角空格 |

问句、感叹和语义停顿在 `display_text` 中保留正常标点；模型执行另写入 `delivery_intent`、`pause_plan`、`emotion` 和 `emphasis_words`，避免只依赖标点控制表演。

```json
{
  "speaker": "林远",
  "type": "on_screen_dialogue",
  "source_text": "顾长渊，本宫今日来，不是跟你拜堂的。",
  "display_text": "顾长渊，本宫今日来，不是跟你拜堂的。",
  "spoken_text": "顾长渊 本宫今日来 不是跟你拜堂的",
  "delivery_intent": "冷静拒绝",
  "pause_plan": ["顾长渊 后短停", "今日来 后短停"],
  "emphasis_words": ["不是", "拜堂"],
  "subtitle_text": "顾长渊 本宫今日来 不是跟你拜堂的"
}
```

### 七步流程

#### 1. 消费已锁定的无字幕母版

本部分不再次裁剪或拼接 SEG。直接使用第一部分按 verified cut 生成、完成混音并锁定最终音轨的无字幕母版；任何片段顺序、剪切点或音轨变化都会使后续 SRT 和字幕烧录产物失效。

#### 2. 从剧本台词稿整理字幕初稿

本地无 ASR 能力，字幕文本直接来自已确认剧本：读取本集 `script_contract_ep_N.json` 的 `speech_lines[]`，按说话人、句序取出 `spoken_text`，结合片段绝对时间轴与镜头时长估算每条字幕的起止时间，生成 SRT 初稿。

```bash
# 字幕初稿由剧本台词稿生成后，用 ffprobe 核对母版实际时长，防止时间轴越界
python tools/video/ffmpeg_tool.py probe episodes/ep_N/05_成片/拼接_原音轨_vNN_ep_N.mp4
```

初稿保存为可追溯的 SRT，并记录生成依据（`script_contract` 版本、片段顺序表、每条的估算依据）。任何自动转写文本都不得覆盖已确认 `spoken_text`。

#### 3. 时间轴按成片口播对齐

主 Agent 对照无字幕母版的实际口播，逐条校核字幕起止时间：对每条字幕抽首帧、中间帧和尾帧，确认字幕出现与消失是否贴合说话节奏。

- 起止时间整体错位、句序与实际口播不符或时间范围无效：按片段实际口播校正后重新生成 SRT；无法确定时回到分镜核对语气与停顿。
- 单字、同音字、专名差异由创作者定向试听判断。
- 无论时间轴如何校正，字幕正文都来自已批准 `spoken_text`。

把输入文件、母版、校核结果和阻断原因保存到 `质检_字幕对齐_vNN_ep_N.json`。

#### 4. 回填正确文本并规范化

1. 按说话人、句序和语义把字幕条目对应到已确认 `speech_lines`。
2. 字幕正文一律使用 `spoken_text` 原文，不引入任何转写文本。
3. 相邻同说话人短句时间间隔小于 `0.5` 秒时可以合并；开始时间取第一句，结束时间取最后一句。
4. 单句超过 `18-20` 个汉字时优先在语义停顿处换成两行，保持同一时间区间；只有能可靠切分词级时间时才拆成两个独立字幕事件。
5. 每条字幕建议持续 `1.5-5` 秒。超出范围时先重新核对台词分句与口播；不得凭感觉平移时间戳。
6. 对齐失败时回到分镜核对台词与停顿，或按片段实际口播重新校正，禁止手工猜测整体偏移量。

默认输出：

```text
episodes/ep_N/05_成片/字幕_时间轴_vNN_ep_N.srt
```

```srt
1
00:00:00,240 --> 00:00:03,160
顾长渊 本宫今日来 不是跟你拜堂的

2
00:00:03,160 --> 00:00:05,480
这只杯子 你认得吧 五天前
```

#### 5. 基础可交付检查

先对无字幕母版执行 `ffmpeg_tool probe` 并实际播放，再把文件路径、输入哈希、命令与返回码、期望值、实测值和结论保存到 `质检_基础_无字幕_vNN_ep_N.json`。检查文件存在性、时长、比例、帧率、视频流和音轨；字幕开启时还检查 SRT 结构、时码、无标点规则及其与 `spoken_text` 的逐字一致性，并在烧录后对字幕版重复探测与播放。期望时长取 `delivery_manifest_ep_N.json.duration_s`，期望画幅取已确认 `scale_plan.aspect_ratio`，期望帧率取已确认 `delivery_settings.output_fps`，不得由执行者临时填写或从待验媒体反推。时长、比例和帧率容差分别不得超过 `0.5` 秒、`0.01` 相对误差和 `0.1` fps，且必须为有限非负数。确定性错误阻断，字幕持续时间、单行长度和阅读速度异常进入人工复核。

#### 6. 固定字幕参数并烧录

默认使用 `ffmpeg_tool burn`。参数以工具实际参数为准，视觉结果固定为：

| 成片比例 | 位置预设 | 位置参数 | 字号 | 字体 | 颜色 |
|---|---|---:|---:|---|---|
| `9:16` | `lower_third` | `--pos lower_third`（画面 70% 高度） | `36px` | 思源黑体 | 白色 |
| `16:9` | `bottom` | `--pos bottom`（底部居中） | `36px` | 思源黑体 | 白色 |

其他比例默认使用 `--pos bottom / 36px / 思源黑体 / 白色`，并通过代表帧检查安全区。用户明确要求其他样式时必须重新确认；未确认不得动态改变字体、字号、颜色或位置。

本地 SRT 直接作为 `burn` 的字幕输入，无需转成公网 URL 或字幕对象数组。SRT 是正式交付与文本事实源。

```bash
python tools/video/ffmpeg_tool.py burn   episodes/ep_N/05_成片/拼接_原音轨_vNN_ep_N.mp4   episodes/ep_N/05_成片/字幕_时间轴_vNN_ep_N.srt   episodes/ep_N/05_成片/成片_字幕_vNN_ep_N.mp4   --size 36 --pos lower_third
```

横屏把 `--pos` 改为 `bottom`。命令返回 0 且输出文件存在即可解码，即为烧录成功。

#### 7. 烧录处理

1. 从无字幕母版抽取包含人物、关键道具和平台 UI 风险的代表帧。
2. 用最长字幕、生僻字、数字和英文生成短样片，确认思源黑体字符覆盖。
3. 抽取每条字幕的首帧、中间帧和尾帧，检查越界、遮脸、遮嘴、遮关键道具、平台 UI 冲突和换行。
4. 任一字幕不合格时，优先调整断句、字号或位置参数并重新烧录。

### 硬门

- 字幕文本来源记录、规范化 SRT、烧录参数和字幕烧录成片均已落盘并可追溯。
- 无字幕母版与字幕烧录版均有 `ffmpeg_tool probe` 真实记录和基础可交付检查报告；返回码为 0、操作名匹配。
- 字幕对齐报告不得为 `blocked`。
- 字幕固定使用思源黑体、36px、白色；9:16 使用 `--pos lower_third`，16:9 使用 `--pos bottom`。
- 字幕文本与已确认 `spoken_text` 逐字一致。
- 字幕文本不含标点；逗号、顿号、分号和冒号已替换为单个空格，其余指定标点已删除。
- 字幕起止时间按成片实际口播校核，未被整体平移或凭感觉猜测；合并只使用首句开始和末句结束。
- 相邻同说话人短句只有在间隔小于 `0.5` 秒时合并。
- 每条建议 `1.5-5` 秒，单行建议不超过 `18-20` 个汉字；超长优先换行。
- 字幕底部、描边和阴影全部位于实测安全区内，不遮脸、嘴、关键道具、线索文字或平台 UI。
- 最终烧录成片保留无字幕母版的音轨，不因字幕烧录发生音画漂移。
- 用户明确选择无字幕时，记录该选择并跳过 SRT 和烧录步骤。
