# 分镜片段执行设计

用于镜头、时间和实际 SEG 身份确定后的执行增量。只登记已有导演选择，不重新创作整场或填满所有可选标签。

## 片段规划与机器合同

`SEGxxx` 级规划不另建执行表文件：时间范围、实际时长、包含镜头、`density_profile`/`tail_mode` 由节奏引擎 `allocate`/`pack` 渲染进 `storyboard_ep_N.json.segments[]`，首尾状态、片段职责、生成风险与入段承接写进导演总控卡逐段执行区，图片输入职责以 `reference_input_plan` 为唯一清单。每个非首段在执行区“入段承接与 SEAM”写入入段承接；每个非尾段的出段转场落在末镜切出落点（十五列切入/切出动机）。二者必须来自同一个 `SEAMxxx`，不能各自发明转场。

## 导演总控卡的逐段执行区

整场镜头成立、时间与分组确定后，在同一导演卡内按 SEG 记执行增量，不另建执行表或连续性账本。复用本场已写明的身份、空间、光源和声音基准，只补该段首尾变化、实际入段关系与必要生成风险。

每段以 `### SEGxxx` 标题标识，方便视频阶段定点取材；段内简单片段用短句即可，复杂空间或跨段动作才展开轴线、道具接触、动作相位、方向、速度和声音交接。正式 SEAM 的机器字段写在 `storyboard_ep_N.json.seams[]`，不在 Markdown 再复制一遍全字段。

镜头职责、表演和风格已在本场或逐镜源中表达时不重写。每个 SEG 是技术容器，无须各自完成“钩子—升级—兑现—收束”，不为技术段尾突然停住、换表情或加转场；相邻片段合起来仍是原来那场观看。

### 叙事节拍与证据链

继承剧本的目标、阻力、信息差与必要证据，只在导演卡补“观众何时、从哪里感知它”的设计。相关镜号足以追溯时，不重填一套场次或 SEG 的戏剧字段。

### 尾态选择算法

先看下一段是否继续同一行动/空间，再选择 continuous_motion、cuttable_completion、stable_hold 或 loop_continuation。写清可见动作相位、方向、接触、声音与下一段如何继续；不套百分比或固定尾停。停留本身有观看作用即可保留。

真实钩子、动作承接、自然转场、结果或余韵都可以承担段尾；不为技术切段强造悬念或停留秒数。

## 亮点绑定检查

本场构思继承 `script_contract.highlight_ledger` 中实际相关的亮点，先确定观众如何感知它；pack 后把已形成的真实镜头绑定到 `storyboard_ep_N.json.highlight_bindings`，字段缺方法再查 schema。每个 `role=primary` 的亮点须绑定真实兑现镜头；反应、结果或后续影响按剧本实际设计登记，同一长镜可承担多个职责。没有反应或余震时对应数组可空，不强造跨集 `deferred_aftereffect_ref`，不为字段凑镜头。对应可观察阶段必须写清；各维度只写实际设计，不用“加强氛围”替代。任何剧本主要亮点找不到镜头，先返回剧本调整或重拆分镜，不得直接删除。

从已确认剧本理解亮点的实际因果，不从“需要一个高光画面”倒推装饰镜头。下列是分析维度，不要求每个亮点齐全或各拍一镜：

1. **触发**：读取 `setup_evidence` 和当前场次前态，选择真正迫使人物或局势改变的台词、证据、动作或规则事件，并绑定观众可见/可听的镜头。
2. **变化**：写清触发后谁采取了什么不可忽略的策略，人物位置、道具控制权、信息归属、关系或危险如何发生可见变化；只写情绪形容词不成立。
3. **反馈**：给出对手、听者、环境或规则的即时回应，让观众确认变化被世界接住。反馈可以是抵抗、继续原行为、没有回应或延迟显现的后果，按剧本保留；不为补齐链条强加即时反应或惊讶特写。
4. **结果**：写清本场或后续场次留下的代价、权力重排、选择后果或余震。剧本实际安排跨集回收时再通过 `deferred_aftereffect_ref` 追溯；没有余震设计则不补。

把源稿实际存在的因果写入 `causal_chain` 并绑定真实 SHOT；变化/兑现镜头映射到 `payoff_shot_ids`，实际反馈或余波才填 `reaction_shot_ids`、`aftereffect_shot_ids` 或跨集引用。反应可能是提前察觉、同镜行为或延迟后果，不强判必须在兑现之后；对应项不存在可空。只有已确认因果确实无法理解时才回源修，不因缺少反应/余震字段补戏，也不用慢动作、强音乐或群众惊叹代替设计。

## 受众执行检查

分镜继承已确认 `drama_plan.json.audience_plan`，不重选受众、平台或地域。模型只为观看焦点、情绪回报、平台观看场景和表达禁区选择真实 `scene_or_shot_ids`；`assemble` 从当前规划复制四项 `source_field`、合同原句及规划版本，不要求模型逐字重抄。显式提供的值与源冲突时程序拒绝合并，不能以“符合受众”或受众库标签代替真实落点。

## 图片、资产与关键帧

### 视频参考输入计划

每个 `SEGxxx` 必须在 `storyboard_ep_N.json.segments[].reference_input_plan` 写图片输入计划数组（传哪些图、职责、开头定位、剥离什么），它不是最终 Prompt 或已传图证据。数组可空仅表示该片段无真实图片输入，用法由视频阶段调 `h3-prompt-writing` 判断、不从空数组推断；非首段仅当 planned `SEAM=elliptical` 且新起点无需图片锚点时可空（`continuous` 非首段 tail FRM 义务见下条）。视频阶段以 `video_manifest_ep_N.json.reference_inputs` 与工具 schema 为准，不得无理由删除已声明的必需输入职责。

字段结构与 `role` 枚举以 `manifests.md` 的 `reference_input_plan` 为唯一清单，下列只讲分镜侧判断规则。

- `order` 只登记计划顺序；实际上传、H3 编号与媒体登记按 `video.md`「图片输入合同」同步。
- 第一段不规划生成式首帧关键帧；视频从已批准资产、已规划高光 KF（若有）和文字动作合同启动，不建生成后首帧注册表。
- 非首段先读 `SEAMxxx.seam_mode`：`continuous` 规划上一段真实 tail FRM 承接义务，`elliptical` 按新起点选择真实参考、不强制 tail FRM。分镜不伪造未知 FRM；实际稳定帧选点、时间码、首位输入及缺失阻断按 `video.md`「入站连续性」和「长视频逐段连续继承算法」执行。
- **锚图充分性闸门**：规划 `continuous` 非首段输入前，先读该 `SEAMxxx` 的 `required_invariants` 与 `proof_requirement` 对照上段末镜：末镜比中景更紧（近景/特写/大特写），或 tail 不含全部不变量主体（多人布局、群体衣着、远景人物、画外陈设），计划必须加一条 `previous_scene_anchor_reference`：`planned_source` 写“上一段真实场景帧，视频阶段生成后按需补提取并登记”（分镜阶段不得伪造 FRM ID），`required: true`，`opening_binding`/`exclude` 按 `manifests.md` 填，`adopt` 写明承载的布局/衣着事实；视频阶段补提取后把真实 FRM 文件登记进 `reference_inputs`。未过闸的 SEG 不得提交确认。本闸是衔接卡 scene FRM 义务在 `continuous` 接缝的强制触发，两处登记一致。
- 会复现的角色状态与 PROP 道具状态必须解析到 `project_data_card.json` 的 `state_id` 与 approved 资产（共享库、本集 `episode_assets`、已登记 `reused_episode_assets`），计划用 `character_state_reference`/`prop_state_reference` 指向状态图，不得只给基准图加文字描述；一次性道具状态只进镜头动作与 Prompt，不升级 PROP 输入。
- 场景参考只锁空间、灯光、陈设、布局；风格参考只锁色彩、材质、光线、构图、景深、颗粒/线条语言，不承载剧情人物或道具；道具参考只锁结构、尺寸、材质、当前状态、可见面；不同职责的图片不得混写为同一主体。
- 任何用户或外部图片必须写 `adopt/exclude`；字幕、二维码、水印、平台界面、无关人物、镜面文字、背景杂物默认剥离，除非用户明确要求保留且权限、剧情、平台风险均已确认。

### 资产使用对账（asset_usage_plan）

模型决定每段实际需要显式传入的图片资产，写在该段 `reference_input_plan`；只靠上段尾帧承担的事实不再叠加声明旧图，一次性物件不升级资产。每段参考计划都必须是明确的 `[]` 或真实计划，尚未决定时保留缺项，不以空数组伪装完成。

所有段计划明确后，再运行 `pack --write` 从真实计划聚合 `asset_usage_plan`，同源渲染分镜表附录 B；临时增补图片职责后重跑，不手写第二份对账表。既有人工计划不会被静默改写，仍须与逐段参考计划双向一致。对账两方向均由最终结构检查约束；`["*"]` 的既有全段声明和其他字段结构见 schema。

### 关键帧需求决策

关键帧需求由主 Agent 依已确认剧本、总控卡逐段执行区与十五列分镜决定；用户只确认可读分镜稿与镜头方案，关键帧阶段按清单生成，不临时挑普通画面代替；选点不符合已声明用途、缺必要状态资产或同帧事实互相冲突时回对应源修正，不因缺峰值否定有效的状态/构图/风险需求。

关键帧按实际高光、状态、构图、执行风险选择，无固定张数、单段配额或时长反推。用 `kf-count --storyboard <file>` 统计正式需求、生成项与复用项；无独立用途可为零，仍保留需求审查与阶段确认。首尾事实以生成后 FRM 为准（continuous 后段 tail FRM 选点见「片段衔接（SEAM）合同」）。

优先生成关键帧的场景：

- 信息揭露、身份暴露、证据露出、文字证据可读、误会被推翻或观众认知改变。
- 角色不可逆选择的动作落点（抢夺/推开/跪下/拔刀/按下发送），或动作前一拍已无法回头。
- 两人关系发生空间性变化：堵门、逼近、退到墙边、遮挡出口、夺走道具、站位高低翻转。
- 角色或已升级 PROP 的状态会延续到后续片段（状态资产义务见「视频参考输入计划」）：列入 KF 优选；一次性道具状态变化不触发补图。
- 多人同框、复杂遮挡、POV、过肩、镜面、门窗前后景、低光或强色温变化，视频容易漂移。
- 片段中后部承担悬念、危险逼近、声音桥或状态变化时，优选让观众读懂结果与代价的高光瞬间；下段承接按「片段衔接（SEAM）合同」 tail FRM 规则。

通常不单独生成关键帧的场景：

- 删除后不影响剧情理解的纯氛围、纯运镜、纯场景展示或装饰性空镜。
- 只有“看向远方、低头沉思、站在原地”等弱动作，且无新信息、道具状态或关系变化。
- 已由人物、场景、道具资产稳定覆盖的外观展示镜头。
- 视频 Prompt 可稳定完成的简单动作（普通走路、坐下、转头、拿起杯子）。
- 同片段重复的反应特写；除非第二次反应带来新认知、选择或关系后果。

每张待生成 KF 在清单写清：所属 `SEG` 和镜头、高光序号、选定时间点、主要用途与理由、画面焦点、必要人物关系、必需参考、剧情文字及需继承的状态。高光、状态、构图或执行风险均可成立；同帧可自然包含辅助信息，不强拆任务。只有事实无法在同一瞬间成立时才修选点或设计，不为表格拆镜。

## 片段衔接（SEAM）合同

镜头与切点确定后，跨 SEG 边界在 `storyboard_ep_N.json.seams[]` 登记唯一 `SEAMxxx`，保存两侧计划状态、观察关系、不变量、允许变化与出入画面。它记录已有剪辑决定，不是另一次创作工序；导演卡只写必要执行增量。

- `continuous` 继续同一行动、空间或时间，`permitted_deltas` 为空；跨镜的方向、视线、动作相位、接触与速度保持可理解。后镜可以略推进相位，不重做已完成动作。
- `elliptical` 明确允许的时间/空间/认知变化，保留必要不变量；普通硬切和省略可以自然，不伪装为像素连续。
- 两侧 cue 共享 `transition_anchor`，各自写清执行画面，避免重复运镜、双转场、反向动作或段尾强行收住。
- continuous 的实际稳定帧选点、真实文件/时间码登记及工具不能接收尾帧时的阻断按 `video.md`「入站连续性」和「长视频逐段连续继承算法」执行；分镜只记录该承接义务，不提前伪造 FRM。
- 同一声音确需跨段时才设计声音桥，给实际入退点；音乐描述可复用，不为接缝补无关声音。

定稿时把边界放回整场普通硬切连看：若注意力、情绪或空间关系突断，修具体切点与两侧过程，不默认加匹配、遮挡或 bridge SEG。实际媒体的 tail 选点与 trim 在视频阶段按冻结内容时长和真实画面处理；生成观察不授权自动返修。

资产映射与 KF 需求仍只登记在 `asset_usage_plan`、`reference_input_plan` 和关键帧需求中；已有源事实不复制到第二套接缝账本。

## 与关键帧和视频阶段的边界

本阶段只决定哪些真实资产与 KF 用于何种观看和执行职责。后续按已确认清单生产，不临时改选用途、增删镜头或补写剧情；最终 H3 编译沿 `video.md`「导演输入与可选交付包」。

人声在源分镜写明主体、类型、逐字文本与发声窗口，音色按 voice_id 解析；出镜对白要求口型，旁白/画外音/内心独白要求画面人物不开口。实际声音媒体输入与生成合同由 `video.md`「人声与文字合同」维护。
